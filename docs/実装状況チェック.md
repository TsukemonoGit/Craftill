## 5. 問題あり（重要度順）

各項目の本文は**調査時点（修正前）**の記述である。現在の対応状況は、見出し直後の「状態」行を優先する。

### P-01 状態機械が未使用で、UI が会計状態を直接書き換えている（Critical / A-4）

- `status.swift:64` の `move()`、`status.swift:186` の `apply()`、`status.swift:192` の `markSatsConfirmed()`、`status.swift:226` の `SaleContextStore` が定義されているが、アプリ本体から呼ばれていない。
- `UI/Appviewmodel.swift:470-528` で `saleState` を直接代入している。`proceedToPayment()`、`chooseCash()`、`chooseSats()`、`reselectMethod()`、`approveSats()` などが該当する。
- 仕様 A-4 は「状態の遷移はロジック側が判断する。画面（UI）は会計状態を直接書き換えない」と明記している。
- 影響: 遷移図にない操作をコードから実行でき、状態復元も検証を通らない。会計状態の整合性を保証できない。
- 修正: `SaleContext` を唯一の状態源にし、UI は `move()` の返り値だけを見て遷移する。`SaleContextStore` で保存・復元する。

### P-02 DB 保存失敗時にメモリだけが進み、巻き戻されない（Critical / A-4、A-7）

- `UI/Appviewmodel.swift:566-601` の `complete()` は、`commitSale()` で `inventory`・`sales`・`saleItems`・`movements` を変更した後に `persistCommit()` を呼ぶ。失敗してもメッセージを出すだけで、メモリの販売・在庫はそのまま、`saleState = .done` にもなる。
- `performVoidSale()`（`UI/Appviewmodel.swift:633-658`）と `performStockAdjustment()`（`UI/Appviewmodel.swift:667-681`）も同じ構造。後者は `try?` で保存失敗を握りつぶす。
- マスタ編集の各 `save` も `try?` が多く（`UI/Appviewmodel.swift:697-812`）、失敗が画面に出ない。
- 影響: ディスク不足・DB ロック・スキーマ不整合などが起きたとき、画面上は販売完了・在庫減算済みなのに、再起動すると販売記録が消える／在庫だけ合わない、という状態になり得る。
- 修正: 先に DB トランザクションを確定し、成功後にメモリへ反映する。または変更前スナップショットを保持して失敗時に完全に戻す。`try?` をやめ、失敗時は完了扱いにしない。

### P-03 商品追加が非トランザクションで、ID 衝突も検査していない（High / A-1、A-7）

- `UI/Appviewmodel.swift:761-795` は、`types[ti].nextNo += 1` の後に `save(type:)`、`save(product:)`、`save(movement:)` を別々に実行している。
- 同じ箇所で、採番した `newId` が既存 `inventory` に存在するかの検査がない。`basic.swift:594` の `addProduct()` には検査があるが、UI からは使われていない。
- 影響: 種類の保存だけ成功して商品が失敗すると `next_no` だけ進む。逆に商品だけ成功すると `next_no` が古いまま残り、次回同じ ID を採番して上書きする危険がある。初期在庫ログだけ欠ける可能性もある。
- 修正: `basic.swift` の検証済みロジックを UI から使い、商品・`next_no`・初期在庫ログを 1 トランザクションで保存する。

### P-04 画像なしの判定と、画像欠落時の代替表示が仕様と違う（High / A-1、A-2）

> **状態: ✅ Linux で修正済み（未ビルド）。** `Product.hasBundledImage` で実ファイルを判定し、`productsWithoutImage`・商品タイル・カートのフォールバックを修正した。A-17 の画像同梱自体は未対応。

- `UI/Appviewmodel.swift:816` の `productsWithoutImage` は `imageRef == nil` だけを見ている。しかし初期データは `imageRef: "\(id).jpg"` を設定しており（`Persistence.swift:257-316`）、実際の画像ファイルは同梱されていない。そのため「画像なし ID 一覧」に本来出すべき商品が出ない。
- `UI/Components.swift:481-484` は `imageRef != nil` なら `ProductImageView` を表示する。ファイルが存在しない場合は `PlaceholderImage(label: "画像")` になる（`UI/Components.swift:239-245`）。商品名・属性の文字表示にならない。
- カート行も同じで、`imageRef` が非 nil の欠落画像は「画像」または「野良」のプレースホルダーになる（`UI/Components.swift:540-545`）。
- 影響: A-1「画像がない商品は商品名・属性の文字表示」、A-1「画像が同梱されていない登録商品の ID 一覧」を満たさない。C-6 #10、#47 も未達。
- 修正: `Bundle.main.url` で実在確認した結果を「画像なし」判定に使う。`ProductImageView` に商品名・属性を渡し、欠落時はそれを表示する。初期データの `imageRef` を nil にするか、実画像を同梱する。

- 修正: 商品マスタ CSV と `originals/` を入力に、検証・サムネイル生成・Web 用生成・対応表・ハッシュ版識別子を出力する macOS スクリプトを追加する。
