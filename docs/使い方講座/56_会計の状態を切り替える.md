A-4 の状態は **8 つ** です。`中断`（`suspended`）を忘れやすい准备金場所は `base/2` の

```
待機中 → スキャン中 → 支払方法選択 → 現金入力中 ─┐
                  ↑         └──────→ sats待ち ──┼→ 完了 → 待機中
                  └──────── 戻る ───────────────┘
      COMPLEXな注（A-4 の図）：
        sats待ち → 併用現金入力中 → 完了
        どこからでも → 中断 → 待機中
```

## わざと間違う①: View に `state = .idle` と書く

いちばんよく書くとおりな例がこれです。子 View から `state` を直接書いてしまう例です。

```swiftui NG
struct CashInputView: View {
    @Binding var state: SaleState

    var body: some View {
        VStack {
            Text("現金入力中")
            Button("受取額を確定（完了）") { state = .done }   // ← 直接代入
            Button("中断") { state = .idle }                  // ← 確認も PIN もない
        }
    }
}
```

**何が壊れているか**

- A-4 の図に **無い遷移ができてしまう**。たとえば完了画面に
  `Button("sats待ちへ戻る") { state = .satsWaiting }` を置けば、
  **清算済みの会計が sats 待ちに戻ります**。
- `中断` が `state = .idle` だけなので、**確認ダイアログ（A-4・C-6 #51）と
  PIN（A-19-2）が-cigaretteします**。
- View ごとに！所以、書いた人によって挙動が違います。

「遷移できるined」を **画面ではなくロジックに置き**、画面は `Button` からイベントを送るだけにします。

## 1. 遷移の返り値を4つの case にする

```swift 断片
enum Move: Equatable {
    case allowed(SaleState)                       // このまま遷移してよい
    case needsConfirm(ConfirmReason, SaleState)   // 確認が済んだら nextState へ
    case needsPIN(ConfirmReason, SaleState)       // PIN ＋ 確認が済んだら nextState へ
    case rejected(String)                         // 遷移できない
}
```

UI はこの 4 つだけを見ればよいので、**「遷移できない理由」も画面のメッセージにできます**。

> `rejected` にタイトルが無いのは、「許可されない操作」のメッセージだからです。
> `ConfirmReason(title: "操作できません", message: …)` として取り出せます。

## わざと間違う②: `allowed` しか返さない

「遷移表は作った」と考えて **確認も PIN も付けずに素通りさせる**版。

```swift NG
// わざと間違う版：needsConfirm / needsPIN が無い
func moveV2(_ e: String, in ctx: SaleContext) -> Move {
    switch ctx.state {
    case .idle:      return e == "add" ? .allowed(.scanning) : .rejected("この状態ではできません")
    case .scanning:  return e == "toPayment" ? .allowed(.choosingPayment) : .allowed(.suspended)
    case .choosingPayment:
        if e == "back" { return .allowed(.scanning) }
        if e == "cash" { return .allowed(.cashInput) }
        return .allowed(.satsWaiting)
    case .cashInput:      return .allowed(.done)
    case .satsWaiting:    return .allowed(.done)          // ★ 確認なし・現金分の判定なし
    case .mixedCashInput: return .allowed(.done)
    case .done:           return e == "backToIdle" ? .allowed(.idle) : .rejected("完了した会計は中断できません")
    case .suspended:      return .allowed(.idle)
    }
}
```

これを「sats単価あり × 2 ＋ 野良（現金分）」のカートで動かすと:

```
=== わざと間違う版：needsConfirm / needsPIN が無い ===
  合計: Totals(sats: 1000, cashForSats: 400, cash: 1000)
  satsWaiting ＋ 済ボタン → allowed(done)
  → 現金分 400円 があるのに、そのまま allowed(done) にしてしまう
  問題1: 確認ダイアログがない（C-6 #23）
  問題2: 現金分があるのに mixedCashInput を経由しない（C-6 #77）
  問題3: 併用現金入力中の中断に PIN がない（A-19-2）
```

**3 つとも受け入れテストに反します。**

| 問題 | 違反しているもの |
| --- | --- |
| 確認ダイアログがない | C-6 #23「確認ダイアログを経ずに完了しない」 |
| 現金分があるのに `done` へ | C-6 #77「済ボタン承認後に**併用現金入力中**へ遷移し、完了しない」 |
| 中断に PIN がない | A-4 / A-11 / A-19-2 |

### 直し方: 返り値を4_case に、`suspend` の中身で PIN を分ける

```swift 断片
case .satsWaiting:
    switch e {
    case .tapDone:
        // 現金分の有無で遷移先が変わる（A-4、C-6 #23・#77）
        let t = ctx.cart.totals()
        return t.cashForSats == 0
            ? .needsConfirm(tapDoneReason(in: ctx), .done)
            : .needsConfirm(tapDoneReason(in: ctx), .mixedCashInput)
    case .changeMethod: return .allowed(.choosingPayment)   // A-19-8：2段の1つめ
    case .suspend:      return .needsConfirm(cancelReason(in: ctx), .suspended)
    default:            return .rejected("請求額が決まったので、方法や商品は変えられません")
    }

case .mixedCashInput:
    switch e {
    case .confirmMixedCash(let received):
        let due = ctx.cart.totals().cashForSats          // ★ 請求額は現金分だけ
        guard received >= due else {
            return .rejected("受取額が現金分（\(due)円）未満です")
        }
        return .allowed(.done)
    case .suspend:
        return .needsPIN(pinReason(), .suspended)        // sats確認済み → PIN必須
    default: return .rejected("請求額が決まったので、方法や商品は変えられません")
    }
```

**`satsConfirmedAt` ひとつで、PIN の要否が決まります**（A-19-2）。

| | `satsConfirmedAt` | 中断の返り値 | 在庫 |
| --- | --- | --- | --- |
| スキャン中・現金入力中・sats待ち | `nil` | `.needsConfirm` | 触らない |
| 併用現金入力中 | あり | `.needsPIN` | 触らない |

## わざと間違う③: 併用現金入力中の確定で「全行の円合計」を使う

最容易な Copies 間違いです。`cashInput` の判定をそのまま `mixedCashInput` に流用します。

```swift NG
// わざと間違う版：全行の円合計で判定してしまう
func wrongMixedConfirm(received: Int, cart: [CartLine]) -> Move {
    let due = cart.totals().cash          // ★ 全行の円合計。sats 分まで二重に要求する
    return received >= due ? .allowed(.done) : .rejected("受取額が請求額（\(due)円）未満です")
}
```

```
=== わざと間違う版：併用現金入力中の判定 ===
  合計: Totals(sats: 1000, cashForSats: 400, cash: 1000)　請求は現金分 400円 だけ
  客が 400円 出した → rejected(受取額が請求額（1000円）未満です)
  → 正しい処理なら完了するのに、sats 分の 600円 まで要求している（C-6 #77 に反する）
```

**何が壊れているか**

A-6-1 はこう書いています。

> sats払いのsatsは、**sats単価のある行のsats合計**。円は、**sats単価のない行の円合計**

つまり sats 分は WoS から受け取っているので、**現金では二度と受け取らない**。
`cash`（全行の円合計）を使うと、**sats 分まで現金でも二重に要求してしまう**。客とお店の両方が損をします。

3つの値を混同しないように、**名前と式を結び付けて覚えて**ください。

| 名前 | 式 | どこで使う |
| --- | --- | --- |
| `totals.sats` | sats単価のある行の `単価 × 数量` の合計 | 請求sats額・`total_sats` |
| `totals.cashForSats` | sats単価のない行の `単価 × 数量` の合計 | **併用会計の現金分の請求額** |
| `totals.cash` | 全行の `単価 × 数量` の合計 | 全額現金のときの請求額 |

## 2. 画面側は `move(...)` の返り値を見るだけ

```swiftui NG
struct RegisterRootView: View {
    @State private var ctx = SaleContext()
    @State private var pending: ConfirmReason?
    @State private var pendingPIN = false
    @State private var message = ""
    @State private var received = ""

    var body: some View {
        NavigationStack {
            VStack(spacing: 12) {
                Text("いま: \(ctx.state.rawValue)").font(.caption)
                switch ctx.state {
                case .idle, .scanning:      ScanView(ctx: $ctx)
                case .choosingPayment:     PaymentSelectView(ctx: $ctx)
                case .cashInput:           CashInputView(ctx: $ctx)
                case .satsWaiting:         SatsWaitingView(ctx: $ctx)
                case .mixedCashInput:      MixedCashInputView(ctx: $ctx)
                case .suspended:           SuspendedView(ctx: $ctx)
                case .done:                DoneView(ctx: $ctx)
                }
                Text(message).font(.caption).foregroundStyle(.secondary)
            }
            .padding()
            // needsConfirm のときだけ出る（C-6 #51）
            .alert("?", isPresented: Binding(
                get: { pending != nil }, set: { if !$0 { pending = nil } })) {
                Button("はい") { applyPending() }
                Button("キャンセル", role: .cancel) { pending = nil; message = "何もしませんでした" }
            } message: {
                VStack {
                    Text(pending?.title ?? "")
                    Text(pending?.message ?? "")
                }
            }
        }
    }

    /// すべてのボタンはここを通る。UI は遷移先を自分で決めていない（A-19-9 #9）
    func send(_ e: SaleEvent) {
        let m = move(e, in: ctx)
        switch m {
        case .allowed:
            apply(m, to: &ctx); message = ""
        case .needsConfirm(let r, _):
            pending = r                                  // 出る＝確認が要る時だけ
        case .needsPIN(let r, _):
            pending = r; pendingPIN = true                // PIN 入力之后再出
        case .rejected(let why):
            message = why
        }
    }

    func applyPending() {
        guard let m = moveWasNeedsAuth else { return }
        apply(m, to: &ctx)
        pending = nil
        if ctx.state == .suspended { suspendSaleNow() }   // A-19-2 の記録
        if ctx.state == .done { commitSaleNow() }        // A-4 のトランザクション
    }

    var moveWasNeedsAuth: Move? = nil
}
```

**要点は3つです。**

1. **ボタンは全部 `send(_:)` を通る**。`ctx.state = ...` を UI からは書いていない
2. **確認ダイアログは常時付けておいて、出るかは `pending` で決める**。
   `needsConfirm` が返ってきたときだけ `pending` に入れる
3. **在庫・販売記録には `move` が触らない**。`state == .done` になったら
   `commitSale`、`state == .suspended` になったら `suspendSale` を呼ぶ（A-19-2 / A-19-3）

## 3. 通しの確認

下のコードを、**土台（`base/Types.swift` の型 ＋ `base/3_標準ロジック.md` ＋
`base/6_会計の状態機械.md` の §1〜§6）の下に続けて置いて**、`swift` で動かします。

```swift
// ════════ 通しの確認（会計の状態機械・A-4）════════

let now = Date(timeIntervalSince1970: 1_700_000_000)
let correctPIN = "1234"

func p0(_ s: String) { print("  " + s) }

/// Move を1行で表示する
func show(_ m: Move) -> String {
    switch m {
    case .allowed(let s):
        return "allowed(→\(s.rawValue))"
    case .needsConfirm(let r, let s):
        return "needsConfirm(\(r.title) → \(s.rawValue))"
    case .needsPIN(let r, let s):
        return "needsPIN(\(r.title) → \(s.rawValue))"
    case .rejected(let m):
        return "rejected(\(m))"
    }
}

/// イベントを1つ処理する。**`allowed` のときだけ状態を更新する**
@discardableResult
func tap(_ e: SaleEvent, in ctx: inout SaleContext) -> Move {
    let m = move(e, in: ctx)
    p0("\(ctx.state.rawValue) ＋ \(e) → " + show(m))
    if case .allowed = m { apply(m, to: &ctx) }
    return m
}

/// 確認ダイアログで「はい」を押した。PIN が要るときは PIN も確認する
func confirmOK(_ m: Move, in ctx: inout SaleContext, pin: String = "1234") {
    switch m {
    case .needsConfirm:
        apply(m, to: &ctx)
        p0("   → 確認ダイアログで「はい」→ \(ctx.state.rawValue)")
    case .needsPIN:
        guard pin == correctPIN else {
            p0("   → PIN が違う。**何も変わらない**（\(ctx.state.rawValue) のまま）")
            return
        }
        apply(m, to: &ctx)
        p0("   → PIN \(pin) を確認 → \(ctx.state.rawValue)")
    default:
        p0("   → 確認すべきではない（\(show(m))）")
    }
}

// ── 前提：sats単価あり1行・なし1行のカート ──
let st = Product(id: "ST-001", typeId: "sticker", name: "ステッカー まる",
                 priceJpy: 300, priceSats: 500, stock: 10, attr1: nil, attr2: nil, attr3: nil,
                 imageRef: nil, isPublic: true, updatedAt: nil)
let adhoc = CartLine.adhoc(id: "ADHOC-1", name: "野良（雑誌）", priceJpy: 400, priceSats: nil, qty: 1)
let twoStickers = [CartLine(product: st, qty: 2)]

print("【1】待機中の禁止操作（A-4 の表「中断 不可」）")
var c = SaleContext()
p0("合計: " + String(describing: twoStickers.totals()))
tap(.suspend, in: &c)                  // rejected
tap(.addItem, in: &c)                  // rejected（最初の1個は addFirstItem）

print("【2】最初の商品追加 → スキャン中")
c.cart = twoStickers
tap(.addFirstItem, in: &c)

print("【3】商品追加と取消（取消で空なら待機中へ・A-4）")
c.cart = [CartLine(product: st, qty: 2), adhoc]      // 2行にしておく
tap(.addItem, in: &c)
tap(.removeItem, in: &c)               // あと1行あるので、ここではスキャン中のまま
p0("   行数: \(c.cart.count)")
c.cart = []
tap(.removeItem, in: &c)               // カートが空 → 待機中へ

print("【4】会計へ進む → 支払方法選択")
c.cart = twoStickers
tap(.addFirstItem, in: &c)
p0("   合計: " + String(describing: c.cart.totals()))
tap(.toPaymentSelection, in: &c)

print("【5】sats単価のない行しかないときは sats払い不可（A-4 の遷移条件）")
var c2 = SaleContext(cart: [adhoc])
tap(.addFirstItem, in: &c2)
tap(.toPaymentSelection, in: &c2)
tap(.chooseSats, in: &c2)
tap(.chooseCash, in: &c2)

print("【6】sats待ち → 済ボタン（現金分0 → done）")
var c3 = SaleContext(cart: twoStickers)
_ = tap(.addFirstItem, in: &c3)
_ = tap(.toPaymentSelection, in: &c3)
_ = tap(.chooseSats, in: &c3)
p0("   合計: " + String(describing: c3.cart.totals()))
let mDone = tap(.tapDone, in: &c3)     // needsConfirm（確認ダイアログを経ずに完了しない・C-6 #23）
p0("   この時点ではまだ \(c3.state.rawValue)（確認していないので遷移していない）")
confirmOK(mDone, in: &c3)

print("【7】sats待ち → 方法選び直し → 現金（併用にならない・C-6 #83 / A-19-8）")
var c3b = SaleContext(cart: twoStickers)
_ = tap(.addFirstItem, in: &c3b)
_ = tap(.toPaymentSelection, in: &c3b)
_ = tap(.chooseSats, in: &c3b)
tap(.changeMethod, in: &c3b)           // → 支払方法選択（A-19-8 の2段の1つめ）
tap(.chooseCash, in: &c3b)             // → 現金入力中
tap(.confirmCash(600), in: &c3b)       // 全行の円合計 600 で確定
p0("   method = " + resolveMethod(chooseSats: false, cart: c3b.cart).rawValue + "（併用にならない）")

print("【8】現金入力中の確定（受取額不足は rejected）")
var c4 = SaleContext(cart: twoStickers)
_ = tap(.addFirstItem, in: &c4)
_ = tap(.toPaymentSelection, in: &c4)
_ = tap(.chooseCash, in: &c4)
tap(.confirmCash(500), in: &c4)         // 請求額600 未満
tap(.confirmCash(1000), in: &c4)        // 完了

print("【9】完了から中断はできない（A-4 の表）")
tap(.suspend, in: &c4)
tap(.backToIdle, in: &c4)

print("【10】併用会計：現金分あり → 済ボタンで mixedCashInput（C-6 #77）")
var c5 = SaleContext(cart: twoStickers + [adhoc])
_ = tap(.addFirstItem, in: &c5)
_ = tap(.toPaymentSelection, in: &c5)
_ = tap(.chooseSats, in: &c5)
p0("   合計: " + String(describing: c5.cart.totals()))
let mMixed = tap(.tapDone, in: &c5)    // 現金分があるので mixedCashInput へ
confirmOK(mMixed, in: &c5)
markSatsConfirmed(&c5, at: now)

print("【11】併用現金入力中の確定は「現金分だけ」（C-6 #77）")
tap(.confirmMixedCash(300), in: &c5)    // 現金分400 未満
tap(.confirmMixedCash(400), in: &c5)    // 完了
p0("   method = " + resolveMethod(chooseSats: true, cart: c5.cart).rawValue)

print("【12】中断の2通り（A-19-2）")
var c6 = SaleContext(cart: twoStickers)
_ = tap(.addFirstItem, in: &c6)
confirmOK(tap(.suspend, in: &c6), in: &c6)      // sats未確認 → needsConfirm（PIN不要）
tap(.backToIdle, in: &c6)

var c7 = SaleContext(state: .mixedCashInput, cart: twoStickers + [adhoc])
c7.satsConfirmedAt = now
let mPin = tap(.suspend, in: &c7)               // sats確認済み → needsPIN（記録を残す）
confirmOK(mPin, in: &c7, pin: "0000")           // PIN が違う → 何も変わらない
confirmOK(mPin, in: &c7)                        // 正しい PIN

print("【13】済ボタン承認後の請求sats額は固定される（C-6 #78）")
var c8 = SaleContext(state: .satsWaiting, cart: twoStickers)
markSatsConfirmed(&c8, at: now)
p0("   confirmedSats = \(c8.confirmedSats.map(String.init) ?? "nil") / satsConfirmedAt = \(c8.satsConfirmedAt.map { DayKey.string(from: $0) } ?? "nil")")
c8.cart = [CartLine(product: st, qty: 5)]
p0("   confirmedSats = \(c8.confirmedSats.map(String.init) ?? "nil")（カートは5枚に変わったが確定値はそのまま）")

print("【14】状態をまるごと保存・復元できる（C-6 #2・#78）")
let saved = c8
var restored = SaleContext()
restored.state = saved.state
restored.cart = saved.cart
restored.satsConfirmedAt = saved.satsConfirmedAt
restored.confirmedSats = saved.confirmedSats
p0("   復元後の状態: \(restored.state.rawValue) / satsConfirmedAt あり: \(restored.satsConfirmedAt != nil) / confirmedSats: \(restored.confirmedSats.map(String.init) ?? "nil")")
p0("   一致: \(restored == saved)")
```

**期待される出力**:
```
【1】待機中の禁止操作（A-4 の表「中断 不可」）
  合計: Totals(sats: 1000, cashForSats: 0, cash: 600)
  idle ＋ suspend → rejected(中断できません（カートが空です）)
  idle ＋ addItem → rejected(待機中は「スキャン中」です。商品をスキャンしてください)
【2】最初の商品追加 → スキャン中
  idle ＋ addFirstItem → allowed(→scanning)
【3】商品追加と取消（取消で空なら待機中へ・A-4）
  scanning ＋ addItem → allowed(→scanning)
  scanning ＋ removeItem → allowed(→scanning)
     行数: 2
  scanning ＋ removeItem → allowed(→idle)
【4】会計へ進む → 支払方法選択
  idle ＋ addFirstItem → allowed(→scanning)
     合計: Totals(sats: 1000, cashForSats: 0, cash: 600)
  scanning ＋ toPaymentSelection → allowed(→choosingPayment)
【5】sats単価のない行しかないときは sats払い不可（A-4 の遷移条件）
  idle ＋ addFirstItem → allowed(→scanning)
  scanning ＋ toPaymentSelection → allowed(→choosingPayment)
  choosingPayment ＋ chooseSats → rejected(sats単価のある商品がありません。現金でお支払いください)
  choosingPayment ＋ chooseCash → allowed(→cashInput)
```

## ポイント

- 会計の状態は **8 つ**。`中断`（`suspended`）を落とさない（A-4）
- **UI は `move(...)` の返り値を見るだけ**。`state` を直接書き換えない（A-19-9 #9）
- `Move` の 4 つの返り値：`allowed` / `needsConfirm` / `needsPIN` / `rejected`
- **PIN の要否は `satsConfirmedAt` ひとつ**で決まる（A-19-2）
- **在庫を戻す条件は `completedAt` があることだけ**（A-19-3）。中断では戻さない
- 済ボタンは必ず確認を挟む（C-6 #23）。遷移先は現金分の有無で変わる（C-6 #77）
- 請求額は **`cashInput` は `totals.cash`、`mixedCashInput` は `totals.cashForSats`**。混ぜない（A-6-1）
- 方法選び直しは **2 段**（A-19-8）。済ボタン承認前は `confirmedSats` が `nil` なので併用にならない（C-6 #83）
- 販売記録と在庫は `move` の外側で、`state` が変わったタイミングで呼ぶ
- 画面遷移（`NavigationStack` / `.sheet`）は `61_画面遷移とモーダルを使う.md`
