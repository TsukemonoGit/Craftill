## レッスン1: Swiftの基本を一通り

以降のレッスンで使う部品だけを、1つのブック（Playgrounds）に順に書いて動かす。
Playgroundsのチュートリアルを進めてもよい。ここでは**このアプリで使うものだけ**に絞る。

### ① 変数と定数

```swift
let shopName = "ステッカー屋"   // let = 後から変えられない（定数）
var count = 0                   // var = 後から変えられる（変数）
count = count + 1
count += 1                      // 「足して代入」。上と同じ意味

let priceJpy: Int = 300         // 型を明示する書き方（Int = 整数）
let name: String = "ステッカー"  // String = 文字列

print(shopName, count, priceJpy, name)
print("\(name) は ¥\(priceJpy)")  // \( ) で文字列の中に値を埋め込む
```
- `let` を基本にし、変わる物だけ `var` にする
- 主な型: `Int`（整数）/ `String`（文字列）/ `Bool`（true / false）

### ② if（条件分岐）

```swift
let stock = 0

if stock > 0 {
    print("買える")
} else {
    print("SOLD OUT")
}
```
- 比較: `==`（等しい）`!=`（等しくない）`>` `<` `>=` `<=`
- 「かつ」は `&&`、「または」は `||`

### ③ 配列と for（繰り返し）

```swift
let prices = [300, 300, 800]

var sum = 0
for p in prices {      // 1個ずつ p に入れて繰り返す
    sum += p
}
print(sum)             // 1400
print(prices.count)    // 3（個数）
```

### ④ 関数

```swift
func addTax(_ price: Int) -> Int {   // (引数) -> 返す型
    return price * 110 / 100
}

print(addTax(300))   // 330
```
- `func 名前(引数) -> 返す型 { ... }`
- `_` を付けると呼ぶとき引数名を書かなくてよい（`addTax(300)`）

### ⑤ 構造体（struct）

```swift
struct Item {
    let name: String
    let priceJpy: Int
}

let a = Item(name: "ステッカー", priceJpy: 300)
print(a.name, a.priceJpy)   // .（ドット）で中身を取り出す
```
- 関連する値を1つにまとめる型。`Item(...)` で作る

### ⑥ enum（選択肢）

```swift
enum Pay {
    case cash
    case lightning
}

let pay = Pay.cash

switch pay {
case .cash:      print("現金")
case .lightning: print("ライトニング")
}
```
- 決まった選択肢のどれか1つ、を表す型。`switch` で分岐する
- `switch` はすべての `case` を書く必要がある

### ⑦ オプショナル（nil かもしれない値）

```swift
let satsPrice: Int? = nil     // Int? = 「Int か nil（値なし）」

if let s = satsPrice {        // 値があるときだけ中に入る
    print("\(s) sats")
} else {
    print("sats単価なし")
}

let shown = satsPrice ?? 0    // nil のときの代わりの値
print(shown)                  // 0
```
- `?` を付けた型は nil になりうる。使う前に `if let` か `??` で確認する

**できた合図**: ①〜⑦の各 `print` が、コメントに書いた結果と同じになる。

## レッスン2: 商品モデルを作る

このアプリで扱う「商品」と「在庫の持ち方」を型にする。以降のレッスンはすべてこの型を使う。

```swift
struct Product {
    let id: String
    let typeId: String       // 種類ID（"sticker" など）
    let name: String
    let priceJpy: Int
    let priceSats: Int?    // sats単価。nil = sats単価なし（現金のみ）
    var stock: Int?        // 在庫数。nil = 在庫を数えない
}

enum StockMode {
    case counted   // 数量管理型（在庫数を数える）
    case unique    // 一点物型（1点のみ）
    case none      // 在庫管理なし
}

// 作る
let sticker = Product(id: "ST-001", typeId: "sticker", name: "ステッカー まる",
                      priceJpy: 300, priceSats: 500, stock: 10)

print(sticker.id)          // ST-001
print(sticker.priceSats as Any)   // Optional(500)（Any への明示的な変換で警告を防ぐ）

// 在庫を1つ減らす（stock は var なので変えられる）
var item = sticker
if let s = item.stock {
    item.stock = s - 1
}
print(item.stock as Any)          // Optional(9)（Any への明示的な変換で警告を防ぐ）

// StockMode を switch で使う
let mode = StockMode.unique
switch mode {
case .counted: print("数量管理型")
case .unique:  print("一点物型")
case .none:    print("在庫管理なし")
}
```
- `let` のプロパティは作成後に変更できない。在庫だけ変わるので `stock` のみ `var`
- `Int?` はレッスン1⑦のオプショナル。`priceSats` は sats単価がない商品で `nil`、`stock` は在庫を数えない商品で `nil`
- `let id: String` / `let name: String` は `let id, name: String` と1行にまとめて書いてもよい
- `Product(...)` の引数は、プロパティを書いた順（id → typeId → name → priceJpy → priceSats → stock）で渡す
- `print` でオプショナルを出すと `Optional(500)` と表示される。中身だけ出す方法はレッスン4・25で扱う

**できた合図**: `ST-001` / `Optional(500)` / `Optional(9)` / `一点物型` が出る。

### カートの1行（`CartLine`）— これ以降、全レッスン共通

**これ以降のカートに関するレッスンは、この定義をそのまま使います。** レッスンごとに形が変わると、レッスン間のコピペが壊れるため、1か所で決めて全員で共有します。

```swift
/// カートの1行。保存先の sale_items（A-13）と1対1で対応する形。
/// 在庫（stock）は持たない。現在の在庫は常に在庫表 products 側で見る（A-7）。
struct CartLine: Codable {
    let id: String          // 登録商品は商品ID、野良は "ADHOC-1" など
    let typeId: String?     // 登録商品は種類ID、野良は nil
    let name: String        // カートに入れた時点の商品名（= name_snapshot）
    let unitPriceJpy: Int   // カートに入れた時点の円単価（= unit_price_jpy）
    let unitPriceSats: Int? // カートに入れた時点のsats単価。nil = 現金で受け取る
    var qty: Int
    let isAdhoc: Bool       // 野良かどうか
}

/// 登録商品からカートの行を作る（商品名と価格を「その時点」で写す）
func line(_ p: Product, qty: Int) -> CartLine {
    CartLine(id: p.id, typeId: p.typeId, name: p.name,
             unitPriceJpy: p.priceJpy, unitPriceSats: p.priceSats,
             qty: qty, isAdhoc: false)
}
```

この形にした理由（`../siyou.md` より）:

| 方針 | 根拠 |
| --- | --- |
| **在庫を持たない** | 現在庫は端末内DBが唯一の正（A-7）。古い在庫をカートに持ち込むと二重管理になる |
| **商品名と価格を写して持つ** | 販売時点の値が残る（A-13 の `name_snapshot`・`unit_price_jpy`） |
| **`isAdhoc` で野良を表す** | 野良は商品マスタに無いので `typeId`・`product_id` を持たない（A-1、A-13 の `item_type`） |
| **平坦で持つ** | 4つの追加経路（QR・手動・商品パネル・野良）が、同じ1つの型で並ぶ（A-2） |

> `Product` を丸ごと `CartLine` に入れて持つ形もあるが、在庫・画像・属性まで一緒にコピーされ、野良（商品マスタに無いもの）を表せません。「在庫は在庫表で引く」という A-7 とも合いません。

## レッスン3: テスト商品を配列で用意する

**配列**＝同じ型のものを順番に並べたもの。`[ ]` で囲み `,` で区切る。
`[Product]` は「**Product の配列**」という意味。

```swift
let products: [Product] = [
    Product(id: "ST-001", typeId: "sticker",   name: "ステッカー まる",     priceJpy: 300, priceSats: 500,  stock: 10),
    Product(id: "ST-003", typeId: "sticker",   name: "ステッカー しかく",   priceJpy: 300, priceSats: nil,  stock: 10),
    Product(id: "KH-001", typeId: "keyholder", name: "キーホルダー 01", priceJpy: 800, priceSats: 1200, stock: 1),
    Product(id: "KH-008", typeId: "keyholder", name: "キーホルダー 08", priceJpy: 800, priceSats: 1200, stock: 1),
]

print(products.count)   // 4（何個あるか）

for p in products {     // 1個ずつ取り出して繰り返す
    print(p.id, p.name, p.priceJpy)
}
```
- `products.count` … 配列の中身の**数**
- `for p in products { ... }` … 1つずつ `p` に入れて中を繰り返す（`for` 文）

**できた合図**: `4` と、4商品のID・名前・値段が並んで出る。

## レッスン4: 合計の2行を出す関数

**関数**＝処理をまとめて名付けたもの。`func 名前(引数) -> 返す型 { ... }`。
ここでは「商品の並び」を渡すと「①sats額 ②sats払い時の現金分 ③現金払いの合計」を返す関数を作る（`../開発/5_画面構成.md` の合計）。

```swift
func totals(_ items: [Product]) -> (sats: Int, jpyForSats: Int, cashJpy: Int) {
    var sats = 0
    var jpyForSats = 0
    var cashJpy = 0
    for p in items {
        if let s = p.priceSats {      // sats単価がある行
            sats += s                  //   → sats合計に足す
        } else {                      // sats単価がない行
            jpyForSats += p.priceJpy   //   → sats払い時の現金分に足す
        }
        cashJpy += p.priceJpy          // 現金払いの合計には全部足す
    }
    return (sats, jpyForSats, cashJpy)
}

// 例: ST-001 と ST-003 を買ったとき
let t = totals([products[0], products[1]])
print("sats払い: \(t.sats) sats + ¥\(t.jpyForSats)")
print("現金払い: ¥\(t.cashJpy)")
```
- `var` で用意した `0` に `+=` で足していく（`+=` は「足して代入」）
- `if let` で sats単価の有無を分ける（`01_初心者メモ.md` 参照）

**できた合図**: ST-001（sats500）＋ST-003（satsなし¥300）で
`sats払い: 500 sats + ¥300` / `現金払い: ¥600` が出る。

## レッスン5: ID正規化（`"kh8"` → `"KH-008"`）

入力したIDを**決まった形**に直す。今回は「英字（接頭辞）＋3桁ゼロ埋め」。

```swift
import Foundation  // String(format:) を使うため

func normalizeID(_ raw: String) -> String {
    let upper  = raw.uppercased()                 // 小文字→大文字
    let letters = upper.filter { $0.isLetter }    // 英字だけ取り出す
    let digits  = upper.filter { $0.isNumber }    // 数字だけ取り出す
    let n = Int(digits) ?? 0                       // 数字にする（空なら0）
    return letters + "-" + String(format: "%03d", n) // 3桁ゼロ埋め
}

print(normalizeID("kh8"))     // KH-008
print(normalizeID("KH-020"))  // KH-020
print(normalizeID("st 1"))    // ST-001
```
- `.filter { }` … 条件に合う文字だけ残す
- `String(format: "%03d", n)` … 3桁にゼロ埋め（8 → 008）
- 全角の英字対応などは**後で**でよい（今は半角前提）

**できた合図**: `KH-008` / `KH-020` / `ST-001` が出る。

## レッスン6: 会計状態の enum と遷移

会計の「今どの段階か」を enum で表す（`../siyou.md` A-4）。`switch` で分岐する。

```swift
enum SaleState {
    case idle          // 待機中
    case scanning      // スキャン中
    case choosingPayment  // 支払方法選択
    case cashInput     // 現金入力中
    case satsWaiting   // sats待ち
    case done          // 完了
}

func describe(_ state: SaleState) -> String {
    switch state {
    case .idle:            return "レジ待機中"
    case .scanning:        return "商品をスキャン中"
    case .choosingPayment: return "支払方法を選んでください"
    case .cashInput:       return "現金を受け取り中"
    case .satsWaiting:     return "satsの入金待ち"
    case .done:            return "会計完了"
    }
}

print(describe(.scanning))
```
- `switch` … 選択肢ごとに処理を分ける。`enum` と相性がよい
- `.scanning` は `SaleState.scanning` の省略形

**できた合図**: `商品をスキャン中` が出る。

## レッスン7: SwiftUIでレジ画面を1枚

左に商品、右にカートという2列を出す（`../開発/5_画面構成.md` の図）。

レッスン1〜6は関数を作って `print` で結果をコンソールに見るだけだったので、画面を出す必要がなく、書いてすぐ実行できる**ブック**で足りていた。
このレッスンで初めて**画面（UI）**を出す。画面を出すのは、最終的に作る**アプリ**の役目なので、ここからアプリで作る。
ただしブックとアプリでは画面の出し方が違う。同じ画面（`RegisterView`）を**両方で表示**して、それぞれのやり方と違いを押さえる。

### ① ブックで表示する
`PlaygroundSupport` で画面を表示できる（`01_初心者メモ.md` の**ブック**で）。

```swift
import SwiftUI
import PlaygroundSupport

struct RegisterView: View {
    let cart = ["ST-001 ステッカー まる", "KH-008 キーホルダー 08"]
    var body: some View {
        HStack {
            VStack(alignment: .leading) {          // 左: 商品
                Text("商品").font(.headline)
                Text("ST-001 ステッカー まる")
                Text("KH-008 キーホルダー 08")
            }
            .padding()
            Divider()
            VStack(alignment: .leading) {          // 右: カート
                Text("カート").font(.headline)
                ForEach(cart, id: \.self) { Text($0) }
                Text("合計 ¥1100").bold()
            }
            .padding()
        }
        .frame(width: 600, height: 320)
    }
}

PlaygroundPage.current.setLiveView(RegisterView())
```
- `HStack` … 横に並べる。`VStack` … 縦に並べる
- `ForEach` … 配列を1つずつ表示する
- `PlaygroundPage.current.setLiveView(...)` … 作った画面を表示する（Playground専用）

### ② アプリで表示する
これから本番で使うのはこちら。`PlaygroundSupport` と `setLiveView` を消し、代わりに **`@main` の入口**を付ける。起動すると画面が自動で出る（`01_初心者メモ.md` の**アプリ**で）。

```swift
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            RegisterView()   // ← 起動時にこれが自動で出る
        }
    }
}

struct RegisterView: View {
    let cart = ["ST-001 ステッカー まる", "KH-008 キーホルダー 08"]
    var body: some View {
        HStack {
            VStack(alignment: .leading) {          // 左: 商品
                Text("商品").font(.headline)
                Text("ST-001 ステッカー まる")
                Text("KH-008 キーホルダー 08")
            }
            .padding()
            Divider()
            VStack(alignment: .leading) {          // 右: カート
                Text("カート").font(.headline)
                ForEach(cart, id: \.self) { Text($0) }
                Text("合計 ¥1100").bold()
            }
            .padding()
        }
        .frame(width: 600, height: 320)
    }
}
```
- `@main struct ...App` … アプリの**入口**（起動時に `WindowGroup` の中身が出る）
- `WindowGroup { RegisterView() }` … 出す画面を指定する

| | ① ブック | ② アプリ |
| --- | --- | --- |
| import | `SwiftUI` + `PlaygroundSupport` | `SwiftUI` だけ |
| 画面の出し方 | `setLiveView(...)` を書いた時 | `@main` から起動時に自動 |
| トップレベル | 書ける | 書けない（型の中だけ） |
| 用途 | 手軽に試す練習用 | **最終的にこれで作る** |

**注意**: ②は**アプリを新規作成**して書く。ブックのファイル（レッスン1〜8を追記してきたもの）には**そのまま足せない**（トップレベル禁止。`01_初心者メモ.md` のつまずき①）。`RegisterView` は共通なので、入口だけ差し替えるイメージ。

**できた合図**: どちらでも、左に商品、右にカートが横並びで表示される。

## レッスン8: データを保存してアプリを閉じても消えないようにする（永続化）

ここまでのレッスンでは、プログラムを実行している間だけメモリ上に存在するデータを扱ってきた。
このレッスンでは、アプリを一度終了したり電源を切ったりしてもデータが消えないように、端末のストレージへ保存（永続化）して復元する手順を1ステップずつ組み立てていく。

---

### VS CodeのSwift環境（Linuxコンテナ・Docker等）における保存先の仕組み

* **macOSとの保存先の違い**: macOSの標準アプリ（plistファイル等）とは異なり、Linux環境のSwift（CoreFoundation / Foundation）では、通常 `~/.local/share/` や、実行中のユーザーのホームディレクトリ配下の隠しディレクトリにデータベースやplistとして書き込まれる。
* **スクリプト実行時の挙動**: ターミナルで `swift ファイル名.swift` と直接スクリプト形式で実行した場合、プロセスごとに一時的な領域が使われるか、同じユーザーセッション内であれば同じ領域を共有する。そのため、2回目の実行時にデータが残っていて復元成功している。

---

### ステップ1: 必要な道具箱の読み込みと、保存するデータの形（構造体）を決める

まずは、ファイルの冒頭で標準ライブラリ（道具箱）を読み込み、保存したいデータ（カートの1行分）の設計図を作る。

保存したいデータ（カートの1行分）の設計図は、**レッスン2 で定義した `CartLine` をそのまま使います**。ここで定義し直さないこと。

```swift
import Foundation

// レッスン2 で定義済みのものを使う。
//   struct CartLine: Codable { id / typeId / name / unitPriceJpy / unitPriceSats / qty / isAdhoc }
// Codable が付いていれば、保存・復元に必要な情報はすべて揃っています。
```

> `Codable` が無い構造体は `JSONEncoder` に渡せません。また、**保存したあとに項目を増やすと過去のJSONが読めなくなります**（→ `try?` が失敗を隠して、カートが空に見える。末尾の注意参照）。形を足すなら `CodingKeys` の `decodeIfPresent` を使い、既定値を埋める形にします。

* **`import Foundation`**: Swiftでファイルを扱ったり、エンコード処理をしたり、`UserDefaults` や `NSHomeDirectory()` を使うための基本的な道具箱を読み込む命令。これがないと保存・復元の機能が使えない。
* **`Codable`**: Swiftの構造体を、保存用のデータ形式（JSON）に変換したり、逆に元に戻したりするためのプロトコル（印）。これがないと `UserDefaults` に保存できない。

### ステップ3: データをJSONに変換して保存する

作成した構造体の配列はそのままではストレージに入れられないため、`JSONEncoder` を使ってバイナリデータ（JSON形式の `Data` 型）に変換し、`UserDefaults`（キー・バリュー形式の保存領域）に書き込む。

```swift
let encoder = JSONEncoder()
guard let data = try? encoder.encode(lines) else {
    fatalError("エンコード失敗")
}

let userDefaults = UserDefaults.standard
userDefaults.set(data, forKey: "cart")
print("保存した")

```

* **`JSONEncoder()`**: Swiftの構造体配列を、保存用のバイナリデータに変換する機械。
* **`try?`（オプショナル try）**: 失敗するかもしれない処理（エラーを投げるかもしれない処理）を実行し、失敗したときにプログラムをクラッシュさせるのではなく、安全に `nil`（値なし）を返すための書き方。
* **`guard let ... else { fatalError(...) }`**: 変換が成功（`nil` 以外）したときだけ先に進み、失敗したらその場でプログラムを安全に止める仕組み。
* **`UserDefaults.standard`**: アプリの軽量なデータを端末に保存するための標準ストレージ領域。
* **`userDefaults.set(data, forKey: "cart")`**: `"cart"` という名前（キー）をつけて、変換したデータをストレージに書き込む。

---

### ステップ4: 保存したデータを取り出して復元する

ストレージに保存したデータを `"cart"` というキーで呼び出し、今度は `JSONDecoder` を使って元の Swift の構造体配列に組み立て直す。

```swift
guard let savedData = userDefaults.data(forKey: "cart") else {
    fatalError("保存データなし")
}

do {
    let restored = try JSONDecoder().decode([CartLine].self, from: savedData)
    print("復元成功: \(restored)")
} catch {
    print("デコード失敗: \(error)")
}

```

* **`userDefaults.data(forKey: "cart")`**: 指定したキーに保存されているバイナリデータを取得する。
* **`try`（通常の try）**: エラーを投げる可能性がある処理を安全に実行するための基本の書き方。失敗したときにプログラム全体がクラッシュするのを防ぐため、必ず `do-catch` 構文の `do` の中に入れてエラーを受け止める必要がある。
* **`JSONDecoder().decode(...)`**: 取得したバイナリデータを読み込み、元の `[CartLine]` 型の配列に復元する。
* **`do-catch`**: デコード時に予期せぬエラーが起きてもアプリがクラッシュせず、エラー内容をキャッチして安全に対処するための構文。

---

### ステップ5: 保存場所（ストレージの基盤）を確認する

VS CodeのSwift環境（Linuxコンテナ・Docker等）で実行している場合、データがどこに書き込まれているのかを `NSHomeDirectory()` で確認する。

```swift
print("Home Directory: \(NSHomeDirectory())")

```

* **`NSHomeDirectory()`**: 現在の実行プロセスにおけるユーザーのホームディレクトリの絶対パス文字列（Linux環境の場合は `/home/codespace` 等）を取得・出力し、ストレージの保存基盤を確認する。

### まとめと、触ってはいけない場所

- 保存は `JSONEncoder` でJSONにして `UserDefaults` に書き、復元は `JSONDecoder` で読み戻す。
- **復元できない理由の多くは「保存した時の形と、復元する時の形が違う」こと**です。

実際に起こる例:

```swift
// 保存した時（レッスン8 の初期版）
struct CartLine: Codable { var id: String; var name: String; var priceJpy: Int; var qty: Int }
// → {"id":"KH-002","name":"キーホルダー 02","priceJpy":800,"qty":1}

// その後 isAdhoc と priceSats を追加して復元した場合
struct CartLine: Codable {
    var id: String; var name: String; var priceJpy: Int; var priceSats: Int?
    var qty: Int; var isAdhoc: Bool
}
try? JSONDecoder().decode([CartLine].self, from: data)   // → nil（キー不足）
```

`Codable` は「キーが足りなければ失敗」とします。そして `try?` はその失敗を **nil に変えて黙る** ので、結果として**カートが空に戻ったように見える**だけのバグになります（`49_エラー処理を書く.md` の「`try?` は理由を消してしまう」）。

**対策**: ① 復元は `do-catch` で失敗理由まで読む（`19_会計状態をまるごと保存する.md`）。② 過去のデータにも対応したい場合は `init(from decoder:)` を自前で書いて、`decodeIfPresent` で既定値を埋める。

### 最終的な完成コード

ステップ1〜5をすべて繋げた、レッスン8の完全なコード。

```swift
import Foundation

// 1. 保存・復元する形（レッスン2 の CartLine）
struct CartLine: Codable {
    let id: String
    let typeId: String?
    let name: String
    let unitPriceJpy: Int
    let unitPriceSats: Int?
    var qty: Int
    let isAdhoc: Bool
}

// 2. 保存するデータを作る
let lines = [CartLine(id: "ST-001", typeId: "sticker", name: "ステッカー まる",
                      unitPriceJpy: 300, unitPriceSats: 500, qty: 2, isAdhoc: false)]

// 3. エンコードと保存
let encoder = JSONEncoder()
guard let data = try? encoder.encode(lines) else {
    fatalError("エンコード失敗")
}

let userDefaults = UserDefaults.standard
userDefaults.set(data, forKey: "cart")
print("保存した")

// 4. 保存データの取り出し（復元）
guard let savedData = userDefaults.data(forKey: "cart") else {
    fatalError("保存データなし")
}

// 5. デコード（構造体への復元）とエラーハンドリング
do {
    let restored = try JSONDecoder().decode([CartLine].self, from: savedData)
    print("復元成功: \(restored)")
} catch {
    print("デコード失敗: \(error)")
}

// 6. 実行基盤のホームディレクトリ確認
print("Home Directory: \(NSHomeDirectory())")

```
