# 追加レッスン: カートへ追加する（種類ごとの追加ルール）

元: `../siyou.md` A-1、受け入れテスト C-6 #6・#7・#33
`02_練習メニュー.md` の「7. カートへ追加する」。

商品をカートに追加したときのルールは、**商品の「種類」ごとに変わります**（A-1）。

| 種類 | `stock_mode` | 追加したとき |
| --- | --- | --- |
| 数量管理型 | `counted` | すでに入っていれば数量+1。**在庫を超えたらエラー** |
| 一点物型 | `unique` | **常に数量1**。すでに入っているならエラー |
| 在庫管理なし型 | `none` | 上限なく+1 |
| 野良商品 | （種類を持たない） | 上限なく+1（A-1） |

>  `28` / `29` / `30` は、この表の1項目ずつを見るレッスンです。
> 判定のコードはここでは書きません。**`base/5_カート編集.md` の正を使います**。

## わざと間違う①: `Product` に `stockMode` を持たせる

「どの種類か」を商品に持たせるのが、いちばん自然な書き方に見えます。

```swift NG
// わざと間違う版①：Product に stockMode を持たせる
struct WrongProduct {
    let id: String
    let typeId: String
    var stock: Int?
    var stockMode: StockMode     // ★ 商品にも持たせてしまう
}
func wrongAdd(_ p: WrongProduct, to cart: inout [CartLine]) -> String {
    if p.stockMode != .none, let s = p.stock, s == 0 {
        return "SOLD OUT"
    }
    return "追加しました"
}
```

**何が壊れているか**

A-1 の表で「在庫の扱い」を決めているのは **種類** です。

```
種類 ProductType ── 在庫の扱い・ID形式・カート挙動・属性
商品 Product    ── 商品ID・商品名・価格・属性の値・画像・公開状態
```

商品に `stockMode` を持たせると、**同じ情報が2か所**にできます。
そこで **片方だけ直される**と、

| 状況 | 起きること |
| --- | --- |
| `productTypes` を差し替えた | 商品は古い `stockMode` を持ち続けるので、**在庫の判定が間違う** |
| CSV で商品だけ取り直した | **商品と種類で別の値になる** |

> **`StockMode` は `ProductType` だけが持ちます**（`base/2` の P5 / A-19-9）。
> `Product` は `typeId` で引きます。

```swift 断片
// 正しいWay：種類から引く（A-1）
let mode = inventory[i].stockMode(in: types)
```

## わざと間違う②: 商品パネル・QR・手動入力で別の判定を使う

A-1 はこう書いています。

> **追加経路によらず**、カート挙動（一点物型の重複エラー、数量管理型の在庫超過エラー等）は同一。

そこで 商品パネルと QR で別の判定を書いてしまいます。

```swift NG
// わざと間違う版②：経路ごとに別の判定
func addFromPanel(_ p: Product, to cart: inout [CartLine]) -> String {
    // 商品パネル：在庫0と重複だけ見る
    if p.stock == 0 { return "SOLD OUT" }
    if cart.contains(where: { $0.id == p.id }) { return "カートに追加済みです" }
    cart.append(CartLine(product: p, qty: 1))
    return "追加"
}

func addFromQR(_ id: String, cart: inout [CartLine], inventory: [Product]) -> String {
    guard let p = inventory.first(where: { $0.id == id }) else { return "見つかりません" }
    // QR：在庫の上限だけ見る（重複を見ない）
    if let i = cart.firstIndex(where: { $0.id == id }), let s = p.stock, cart[i].qty + 1 > s {
        return "在庫超過"
    }
    cart.append(CartLine(product: p, qty: 1))   // ★ すでに入っていても別の行が増える
    return "追加"
}
```

**何が壊れているか**

| 経路 | 一点物の重複 | 在庫超過 | 結果 |
| --- | --- | --- | --- |
| 商品パネル | 見る | **見ない** | 在庫を超える追加が通る |
| QR | **見ない** | 見る | 一点物を2行入れてしまう |
| 手動入力 | … | … | 3つの経路にそれぞれ別のバグ |

**追加経路は3つある**（A-4：QR読み取り、ID手動入力、商品パネル、野良追加）。
**判定は1か所**で、全経路がそれを通るようにします。

```swift 断片
// 正しい形（A-1「追加経路によらず」）
let check = addCheck(product: p, qty: 1, cart: cart, inventory: inventory, types: types)
guard case .ok = check else {
    return .rejected(addCheckMessage(check, productName: p.name))
}
```

## 1. 判定と実行を分ける

`base/5` §1 の3つの関数を使います。

| 関数 | 役割 |
| --- | --- |
| `addCheck(product:qty:cart:inventory:types:)` | **能不能加"的だけ**を見る。`cart` は書き換えない |
| `addCheckMessage(_:productName:)` | 画面に出す1文に翻訳する |
| `add(product:qty:cart:inventory:types:)` | 判定を通してから実際に足す |

**判定だけを先に使う**のがミソです。商品パネルは「押せるか」の判定だけ欲しいので、
`addCheck` だけ呼びます（`30_SOLD OUTを判定する.md`）。

```swift 断片
// 判定だけ使う（商品パネルのボタンが無効かどうか）
if case .ok = addCheck(product: p, qty: 1, cart: cart, inventory: inventory, types: types) {
    // 押せる
} else {
    // 押せない・SOLD OUT
}
```

## ポイント

- **在庫の扱いは `ProductType` が決める**。`Product` に `stockMode` を持たせない（A-1、A-19-9）
- **判定は1か所**。商品パネル・QR・手動入力・野良追加が全部 `addCheck` を通る（A-1）
- `addCheck` は **何も書き換えない**。判定と実行を分ける
- **在庫0は追加経路によらず不可**（A-1）。`isSoldOut` は在庫管理なし型に `false` を返す
- 一点物型は **同一会計で2回** 追加できない（C-6 #6）。数量は常に1
- 数量管理型は **すでに入っている分を足した** 総数で比べる（C-6 #7）
- 在庫管理なし型・野良は **上限なし**（A-1）
- 判定のメッセージは `addCheckMessage` が1文に翻訳する。UI 側で文言を作らない
- 編集（＋／－／削除）は `09_カートを編集する.md`。追加と編集は別のファイル
