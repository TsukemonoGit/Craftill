# 33. お釣りと確定ボタンを作る

元: `../siyou.md` A-5（現金決済）、A-6-1（現金分）

**正は `base/6_会計の状態機械.md` §7 の `SaleContext.cashDueJpy` と、§4 の `move` です。**

**ゴール**: 現金の**受取額**と**お釣り**を計算する。お釣り = 受取額 − 請求額。
受取額が請求額未満の間は**確定できない**。1,000 / 5,000 / 10,000 円ボタンで受取額を増やす。

**このレッスンの主題は「請求額をどこから取るか」です。**
現金だけの会計と、sats払いの**併用**では、**請求額が違います**（A-6-1）。
自前で `cart.reduce` すると、**併用のときに sats 分まで現金で要求します**。

---

## まず土台をペーストする

1. `base/Types.swift` の**型だけ**
2. `base/6_会計の状態機械.md` の §1（`Move`）〜§5（確認ダイアログ）と §7（`cashDueJpy`）

> **`SaleContext` / `SaleState` / `Move` / `cart.reduce` を書き写さないでください。**
> 請求額は **`ctx.cashDueJpy`** が決めます。

## わざと間違う①: 請求額を自前で `reduce` する

```swift NG
// わざと間違う版①：全行の円合計を請求額にする
let totalJpy = cart.reduce(0) { $0 + $1.unitPriceJpy * $1.qty }
var cash = CashInput(totalJpy: totalJpy)
```

**現金だけの会計では、これで合っています。** だから**テストが通ってしまいます**。

壊れるのは**併用**のときです。ST-001（300円 / 500 sats）1個と ST-003（300円 / **sats単価なし**）1個の会計を考えます。

| | 全行の円合計（`reduce`） | 現金分（`cashForSats`） |
| --- | --- | --- |
| 金額 | **600円** | **300円** |

sats 分の 300円 は **WoS で受け取ります**。なのに `reduce` は 600円 を要求します。
**客は 300円 を二重に払うことになります**（C-6 #77）。

**正は1か所。** `base/6` §7 の `cashDueJpy` が、状態を見て決めます。

```swift 断片
// base/6_会計の状態機械.md §7 の正
var cashDueJpy: Int {
    switch state {
    case .satsWaiting, .mixedCashInput: return cart.totals().cashForSats
    default:                            return cart.totals().cash
    }
}
```

| 状態 | 請求額 |
| --- | --- |
| `cashInput`（現金だけ） | **全行の円合計**（`totals().cash`） |
| `mixedCashInput`（併用） | **現金分だけ**（`totals().cashForSats`） |

**画面はこの1つだけを見ます。** `state` で分岐を書き直さないでください。

## わざと間違う②: お釣りを「保存する値」だと思う

```swift NG
// わざと間違う版②：入力中にお釣りを変数へ入れて、そのまま保存する
var changeJpy = 0
cash.add(1000)
changeJpy = cash.receivedJpy - totalJpy      // ← 受取が足りないとマイナス
save(changeJpy)                              // ← マイナスのお釣りが保存される
```

**入力中のお釣りは、まだ確定していません。** 受取額が足りなければマイナスです。
保存してよいのは **確定したときの `receivedJpy` と `changeJpy`** だけ（A-5、A-13）。

**正**: 入力中は**計算するだけ**。画面に出すときは 0 未満を出さない。

```swift 断片
/// お釣り。請求額に届くまでは 0（画面用）
func changeJpy(received: Int, due: Int) -> Int { max(0, received - due) }
```

`base/3` §2 の `buildSale` は、確定した `receivedJpy` から `changeJpy` を**保存用に1回だけ**計算します。

```swift 断片
// base/3_標準ロジック.md §2 の正
if method == .cash || method == .mixed {
    sale.receivedJpy = receivedJpy
    if let r = receivedJpy, let req = sale.totalJpy { sale.changeJpy = r - req }
}
```

## わざと間違う③: ボタンの `disabled` だけで守る

```swift NG
// わざと間違う版③：画面の disabled だけを頼りにする
Button("確定") { confirm(cash.receivedJpy) }
    .disabled(!cash.canConfirm)      // ← これだけ
```

`disabled` は**見た目**です。値が別の経路（キーボード入力・復元・テスト）から来たら守れません。

**正は `move` が拒否する。** 画面の `disabled` は**その上に重ねる**だけです。

```swift 断片
// base/6_会計の状態機械.md §4 の正
case .cashInput:
    switch e {
    case .confirmCash(let received):
        let due = ctx.cashDueJpy                         // 全行の円合計（§7）
        guard received >= due else {
            return .rejected("受取額が請求額（\(due)円）未満です")
        }
        return .allowed(.done)
    ...
    }
```

**同じ規則が2か所（画面と `move`）にありますが、金額の出どころは1つ（`cashDueJpy`）**です。
ここが大事です。規則が2か所でも、**判断の材料が1つ**なら食い違いません。

## 1. 通しの確認

下のコードを、**土台（`base/Types.swift` の型 ＋ `base/6` §1〜§5・§7）の下に続けて置いて**、
`swift` で動かします。

```swift
// ════════ 通しの確認（お釣りと確定ボタン・A-5 / A-6-1）════════

func p33(_ s: String) { print("  " + s) }

/// 現金入力の**画面の状態**。持つのは「受取額」だけ。
/// **請求額（due）は持たない。** `ctx.cashDueJpy` から毎回もらう（base/6 §7）
struct CashInput {
    var receivedJpy: Int = 0
    mutating func add(_ yen: Int) { receivedJpy += yen }
    mutating func clear() { receivedJpy = 0 }
}

/// お釣り。請求額に届くまでは 0（画面用）
func changeJpy(received: Int, due: Int) -> Int { max(0, received - due) }

/// 確定ボタンの enabled（画面用）
func canConfirm(received: Int, due: Int) -> Bool { received >= due }

func describe33(_ m: Move) -> String {
    switch m {
    case .allowed(let s):            return "allowed → \(s.rawValue)"
    case .needsConfirm(_, let s):    return "needsConfirm → \(s.rawValue)"
    case .needsPIN(_, let s):        return "needsPIN → \(s.rawValue)"
    case .rejected(let message):     return "rejected: \(message)"
    }
}

let quickButtons = [1000, 5000, 10000]   // 1,000 / 5,000 / 10,000 円

let products33: [Product] = [
    Product(id: "ST-001", typeId: "sticker", name: "ステッカー まる", priceJpy: 300, priceSats: 500, stock: 10),
    Product(id: "ST-003", typeId: "sticker", name: "ステッカー しかく", priceJpy: 300, priceSats: nil, stock: 10),
    Product(id: "KH-001", typeId: "keyholder", name: "キーホルダー 01", priceJpy: 800, priceSats: 1200, stock: 1),
]
func line33(_ id: String, _ qty: Int) -> CartLine {
    CartLine(product: products33.first { $0.id == id }!, qty: qty)
}

print("【1】現金だけの会計: 請求額 = 全行の円合計（A-5）")
let ctxCash = SaleContext(state: .cashInput,
                          cart: [line33("ST-001", 2), line33("KH-001", 1)])
p33("state=\(ctxCash.state.rawValue) / cashDueJpy=\(ctxCash.cashDueJpy)")

var cash33 = CashInput()
p33("受取 ¥\(cash33.receivedJpy) / お釣り ¥\(changeJpy(received: cash33.receivedJpy, due: ctxCash.cashDueJpy)) / 確定 \(canConfirm(received: cash33.receivedJpy, due: ctxCash.cashDueJpy))")

cash33.add(quickButtons[0])          // 1,000円
p33("1,000円 → 受取 ¥\(cash33.receivedJpy) / お釣り ¥\(changeJpy(received: cash33.receivedJpy, due: ctxCash.cashDueJpy)) / 確定 \(canConfirm(received: cash33.receivedJpy, due: ctxCash.cashDueJpy))")

cash33.add(quickButtons[0])          // もう一度 1,000円
p33("1,000円 → 受取 ¥\(cash33.receivedJpy) / お釣り ¥\(changeJpy(received: cash33.receivedJpy, due: ctxCash.cashDueJpy)) / 確定 \(canConfirm(received: cash33.receivedJpy, due: ctxCash.cashDueJpy))")

print("【2】併用の会計: 請求額は「現金分」だけ（A-6-1）")
let ctxMixed = SaleContext(state: .mixedCashInput,
                           cart: [line33("ST-001", 1), line33("ST-003", 1)])
let t33 = ctxMixed.cart.totals()
p33("totals: sats=\(t33.sats) / cashForSats=\(t33.cashForSats) / cash=\(t33.cash)")
p33("cashDueJpy=\(ctxMixed.cashDueJpy) ← 現金分だけ")
p33("わざと間違うと: 全行の円合計=\(ctxMixed.cart.reduce(0) { $0 + $1.unitPriceJpy * $1.qty }) ← sats分まで要求する")

print("【3】受取額が足りないと move が拒否する（画面の disabled の下でも守る）")
let freshCash = SaleContext(state: .cashInput, cart: ctxCash.cart)
p33("1,000円で確定 → " + describe33(move(.confirmCash(1000), in: freshCash)))
p33("1,400円で確定 → " + describe33(move(.confirmCash(1400), in: freshCash)))
p33("2,000円で確定 → " + describe33(move(.confirmCash(2000), in: freshCash)))

print("【4】併用は「現金分」で判定する（同じ 300円 でも意味が違う）")
p33("299円で確定 → " + describe33(move(.confirmMixedCash(299), in: ctxMixed)))
p33("300円で確定 → " + describe33(move(.confirmMixedCash(300), in: ctxMixed)))
p33("600円で確定 → " + describe33(move(.confirmMixedCash(600), in: ctxMixed)))

print("【5】確定した受取額とお釣りが、保存する値（A-13）")
let received33 = cash33.receivedJpy
let due33 = ctxCash.cashDueJpy
p33("receivedJpy=\(received33) / changeJpy=\(changeJpy(received: received33, due: due33))")
p33("入力中の changeJpy は保存しない。確定時の1回だけ保存する")
```

**期待される出力**:
```
【1】現金だけの会計: 請求額 = 全行の円合計（A-5）
  state=cashInput / cashDueJpy=1400
  受取 ¥0 / お釣り ¥0 / 確定 false
  1,000円 → 受取 ¥1000 / お釣り ¥0 / 確定 false
  1,000円 → 受取 ¥2000 / お釣り ¥600 / 確定 true
【2】併用の会計: 請求額は「現金分」だけ（A-6-1）
  totals: sats=500 / cashForSats=300 / cash=600
  cashDueJpy=300 ← 現金分だけ
  わざと間違うと: 全行の円合計=600 ← sats分まで要求する
【3】受取額が足りないと move が拒否する（画面の disabled の下でも守る）
  1,000円で確定 → rejected: 受取額が請求額（1400円）未満です
  1,400円で確定 → allowed → done
  2,000円で確定 → allowed → done
【4】併用は「現金分」で判定する（同じ 300円 でも意味が違う）
  299円で確定 → rejected: 受取額が現金分（300円）未満です
  300円で確定 → allowed → done
  600円で確定 → allowed → done
【5】確定した受取額とお釣りが、保存する値（A-13）
  receivedJpy=2000 / changeJpy=600
  入力中の changeJpy は保存しない。確定時の1回だけ保存する
```

---

## できた合図

- **請求額は `ctx.cashDueJpy` の1か所**から取る。`cart.reduce` を書かない
- 現金だけの会計（`cashInput`）の請求額は **1,400円**（300×2 + 800×1）
- **併用（`mixedCashInput`）の請求額は 300円**（現金分だけ）。全行の円合計は 600円
- お釣り = 受取額 − 請求額。**足りない間は 0**（マイナスを出さない）
- **足りないと `move` が `rejected`** を返す。`disabled` はその上に重ねるだけ
- 併用の判定は **299円で拒否 / 300円で許可**（600円でも許可）
- 保存するのは **確定した `receivedJpy` と `changeJpy`**。入力中のお釣りは保存しない

## まとめ

- **請求額は `ctx.cashDueJpy`**（`base/6` §7）。状態で分岐を書き直さない
- `cashInput` → 全行の円合計 / `mixedCashInput` → **現金分だけ**（A-6-1）
- **お釣り = 受取額 − 請求額**。入力中は計算するだけ。0 未満は出さない
- **確定の可否は `move` が決める**。画面の `disabled` は重ねるだけ
- **保存するのは確定時の `receivedJpy` / `changeJpy`**（A-13）
- 1,000 / 5,000 / 10,000 円ボタンは受取額に足すだけ
