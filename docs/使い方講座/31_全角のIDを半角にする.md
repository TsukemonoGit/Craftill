# 追加レッスン: 手動入力のIDを正規化する

元: `../siyou.md` A-2（手動入力）、受け入れテスト C-6 #5・#28・#69
`../siyou.md` A-19-10（ID の採番規則）
`02_練習メニュー.md` の「31. 全角のIDを半角にする」。

手動入力のIDを正規形に直します。
例: `ｋｈ８` → `KH-008`。

手順は7つです。**最後の「見つからない」は `base/5` の判定に任せます**。

| # | 手順 | 例 |
| --- | --- | --- |
| ① | 全角英数字 → 半角 | `ｋｈ８` → `kh8` |
| ② | 小文字 → 大文字 | `kh8` → `KH8` |
| ③ | 空白を除去 | `st 1` → `ST1` |
| ④ | 接頭辞と番号に分ける | `ST1` → `ST` / `1` |
| ⑤ | 接頭辞を**種類定義**と照合 | `ST` → `sticker`（`idDigits = 3`） |
| ⑥ | 番号を**種類の桁数**でゼロ埋め | `1` → `001` |
| ⑦ | **在庫表に存在するか**を `addCheck` で見る | `KH-008` → ある／`KH-099` → 無い |

## わざと間違う: ①〜⑥ だけやって、「在庫表に無い」を無視する

正規化はできている。でも **そのIDの商品が存在するか**を見ていない、という実装です。

```swift NG
// わざと間違う版：正規化だけして、そのままカートに足す
func addByTypingV1(_ raw: String, cart: inout [CartLine], inventory: [Product]) -> String {
    guard let id = normalizeProductID(raw) else { return "IDの形式が違います" }
    // ★ 存在確認をしていない。次で append する。
    cart.append(CartLine(id: id, typeId: "?", name: "?", unitPriceJpy: 0,
                         unitPriceSats: nil, qty: 1, isAdhoc: false))
    return "追加しました"
}
```

**何が壊れているか**

C-6 #5 はこう書いています。

> **存在しないIDの手動入力でエラーになり、カートが変化しない**

上の実装は `KH-099`（商品マスタに無い）でもカートに **空の行**を足します。
商品名も単価も偽物です（`name: "?"`, `unitPriceJpy: 0`）。
合計も壊れます（`CartLine.subtotalJpy` が 0 なので合計は合っても、行の内容が嘘）。

**C-6 #5 の受け入れテストに反しています**。

**直し方**: 正規化は「**文字列の形を整えるだけ**」。そのあとは `base/5` の `add` に渡します。

```swift 断片
/// 手動入力で商品を1つ追加する。正規化 → 在庫表を引く → base/5 の add を通す。
func addByTyping(_ raw: String, cart: inout [CartLine],
                 inventory: [Product], types: [ProductType]) -> CartEdit {
    guard let id = normalizeProductID(raw) else {
        return .rejected("IDの形式が違います。例: KH-008")
    }
    guard let product = inventory.first(where: { $0.id == id }) else {
        return .rejected("\(id) は商品マスタにありません")
    }
    return add(product: product, qty: 1, cart: &cart, inventory: inventory, types: types)
}
```

これで **4つの受け入れテストが同時に満たされます**。

| C-6 | 内容 | どこで満たされるか |
| --- | --- | --- |
| #5 | 存在しないIDでエラー、カート不変 | `guard let product = ...` |
| #28 | `kh8`・全角でも正しい商品を追加 | ①〜⑥ の正規化 |
| #69 | 桁数違い（`st 1` → `ST-001`）も直る | ⑤ の `idDigits` |
| #35 | 4経路が同じ判定を通る | `base/5` の `addCheck`（A-1） |

## 1. 正規形に直す関数

手順①〜⑥です。**在庫表はここでは見ません**（正規化は文字列の形を整えるだけ）。

```swift 断片
/// 入力したIDを正規形（例: KH-008）に直す。
/// 接頭辞が種類定義になければ nil。**在庫表は見ていない**（⑦ は `addByTyping` が担当）
func normalizeProductID(_ raw: String, types: [ProductType]) -> String? {
    // ① 全角→半角
    let half = raw.applyingTransform(.fullwidthToHalfwidth, reverse: false) ?? raw
    // ② 小文字→大文字
    let upper = half.uppercased()
    // ③ 空白を除去（空白も ① で半角になっている）
    let noSpace = upper.filter { !$0.isWhitespace }
    // ④ 英字（接頭辞）と数字（番号）に分ける（ハイフン `-` も落ちる）
    let prefix = String(noSpace.filter { $0.isLetter })
    let digitText = String(noSpace.filter { $0.isNumber })
    guard !prefix.isEmpty, !digitText.isEmpty else { return nil }

    // ⑤ 接頭辞を種類定義と照合する（ここが独自ルール）
    guard let pt = types.first(where: { $0.idPrefix == prefix }) else { return nil }

    // ⑥ 番号を整数にして、**種類の桁数**でゼロ埋め
    guard let n = Int(digitText) else { return nil }
    return prefix + "-" + String(repeating: "0", count: max(0, pt.idDigits - String(n).count)) + String(n)
}
```

**⑦ を混ぜないのがポイント**です。正規化は「**入力された文字列が正しか**」を、
在庫表の引き当ては「**その商品が存在するか**」を、それぞれ見ます。

> **なぜ `String(format: "%03d", n)` を使わないのか** … `idDigits` が3のときは同じですが、
> 桁数が変わると壊れます。`idDigits` に従って**桁数を数える**ほうが仕様（A-1）に従います。
> `IdSequencer.pad`（`base/Types.swift`）と同じ考え方です。

## 考えてみる（答えはない）

1. `normalizeProductID("ST-1000")` は `idDigits = 3` なので `ST-1000` がそのまま返ります。
   桁数を**超えた**番号です。C-6 #69 は「**桁数違いも直る**」と書いてありますが、
   「超える」場合を弾くのか、`ST-1000` のまま通すのか、仕様（A-1・A-2）からは決まりません。
   どちらが安全側で、それはどこで判定しますか。
2. `addByTyping` は `add` に `qty: 1` を固定で渡します。**在庫管理なし型**の商品を
   手動入力で `qty: 5` 追加したいとき、`addByTyping` をどう変えますか。
3. CSV 取り込み（A-1）は**補正しません**（`31` のポイント）。
   なのに手動入力は補正する。両者の**商品IDの表記がずれると**、C-6 #69 の
   「正規化した商品と登録商品の商品IDが一致する」が通らなくなります。
   CSV 側の商品IDを**必ず正規形**にする仕組みは、どこに置くべきですか。

## ポイント

- 手動入力は**補正する**（①全角→半角、②大文字、③空白除去、⑥ゼロ埋め）。
  **CSV 取り込みは補正しない**、という違いに注意
- 接頭辞は**種類定義の `idPrefix`**、桁数は**種類定義の `idDigits`** に従う（A-1）
- 知らない接頭辞（種類が無い）は `nil`。**存在しないIDはカートに追加しない**（C-6 #5）
- **正規化（①〜⑥）と在庫表の引き当ては混ぜない**。前者は `normalizeProductID`、
  後者は `addByTyping`
- 正規化の後ろは必ず **`base/5` の `add`** を通す。**追加経路は1か所**（A-1）
- `.applyingTransform` を使わない場合も、全角「０〜９ Ａ〜Ｚ ａ〜ｚ」を辞書で置き換えれば同じことができる
- 番号のゼロ埋めは **`IdSequencer.pad` と同じ**考え方で数える
