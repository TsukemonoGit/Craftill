# 追加レッスン: 在庫を減らす（完了処理のトランザクション）【大問】

元: `../siyou.md` A-4, A-7
`02_練習メニュー.md` の「8. 在庫を減らす」。

会計を**完了**したときだけ、在庫を減らす。処理は次の順で、**一連（1つのまとまり）**として行う（A-4）。

**① 在庫検証 → ② 在庫減算 → ③ 販売確定 → ④ 在庫変動ログ**

- 減らすのは**在庫管理ありの登録商品だけ**（`counted`・`unique`）。在庫管理なし型 `none`・野良商品は対象外（A-7）。
- **中断**や**商品取消**では減算しない。
- 途中で在庫不足が見つかったら、**何も反映せず全体を失敗**させる（ロールバックの考え方）。

> ここは**純ロジック**なので **ブック（Book）** で書ける。画面（SwiftUI）は **アプリ（App）** で作る（`01_初心者メモ.md`）。
> このファイルだけで完結。冒頭のコードをそのままPlaygroundsに貼り、その下に続けて書けば動く。

## この大問で使う文法

| 文法 | 使う場面 |
|---|---|
| `Optional`（`?`）と `if let` / `guard let` | 在庫が nil の商品の扱い |
| `inout` と `&` | 関数の中で呼び出し元の変数を書き換える |
| `for ... where` | 条件に合う要素だけ回す |
| `filter` / `reduce` | 同じ商品の数量を合算する |
| `enum` と関連値 | 成功・失敗を1つの型で返す |

## 小問1: 在庫を検証するだけの関数

まず「減らしてよいか」だけを調べる。問題があれば理由を返す。

- 在庫数は、カートの商品情報ではなく**在庫表（`inventory`）の現在値**で見る。
- 同じ商品が複数行に分かれていても、**合計数量**で判定する。

```swift
/// 在庫不足があれば理由（文字列）を返す。問題なければ nil。
func checkStock(_ cart: [CartLine], inventory: [Product]) -> String? {
    // 在庫管理ありの行だけを順に見る
    for line in cart where line.product.stockMode != .none {
        let id = line.product.id

        // 在庫表にない商品（野良）は対象外
        guard let current = inventory.first(where: { $0.id == id }),
              let stock = current.stock else { continue }

        // 同じ商品の数量をカート全体で合算
        let total = cart
            .filter { $0.product.id == id }
            .reduce(0) { $0 + $1.qty }

        if total > stock {
            return "在庫不足: \(current.name)（在庫 \(stock)、必要 \(total)）"
        }
    }
    return nil
}
```

- `String?` は「理由があるかも、なければ nil」という型
- 見つかった時点で `return` して抜ける
- `for ... where` は、条件に合う要素だけを回す
- `reduce(0) { $0 + $1.qty }` は、初期値 0 から `qty` を順に足していく

## 小問2: 完了処理（在庫検証→減算→確定→ログ）

検証がすべて通ったときだけ、まとめて反映する。`inout` で在庫表とログを書き換える。

```swift
enum CompleteResult {
    case success(lines: [String])   // 成功（変化のメモ）
    case failure(String)            // 失敗（理由）
}

func completeSale(saleId: String,
                  cart: [CartLine],
                  inventory: inout [Product],         // 在庫表（products 相当）
                  movements: inout [StockMovement]) -> CompleteResult {

    // ① 在庫検証
    if let reason = checkStock(cart, inventory: inventory) {
        return .failure(reason)      // ← ここで止める。まだ何も変えない
    }

    // ②〜④ 検証が全部通ったので、ここから反映
    var memo: [String] = []
    for line in cart {
        let p = line.product

        // 在庫管理なし・野良（在庫表にない）は対象外
        guard p.stockMode != .none,
              let i = inventory.firstIndex(where: { $0.id == p.id }),
              let current = inventory[i].stock else { continue }

        let after = current - line.qty

        inventory[i].stock = after                                           // ② 在庫減算
        memo.append("\(p.name): 在庫 \(current) → \(after)")                  // ③ 販売確定の記録
        movements.append(StockMovement(productId: p.id,                      // ④ 在庫変動ログ
                                       delta: -line.qty,
                                       reason: "sale",
                                       saleId: saleId))
    }
    return .success(lines: memo)
}
```

- `inout` … 関数の中の変更が、呼び出し元の変数に反映される。呼ぶときは `&` を付ける
- `guard ... else { continue }` … 対象外の行は**飛ばす**（early continue）
- `guard` の条件はカンマで複数つなげられる。1つでも満たさなければ `else` に入る
- **検証を先に全部やる**のがミソ。①で失敗したら②以降を実行しない＝ロールバック

## 小問3: 成功する例

```swift
var inventory = products              // 在庫表のコピー（DBの products 相当）
var movements: [StockMovement] = []

let cart = [
    CartLine(product: product("ST-001"), qty: 2),   // まる を2枚
    CartLine(product: product("KH-001"), qty: 1),   // 一点物を1点
]

switch completeSale(saleId: "S-001", cart: cart, inventory: &inventory, movements: &movements) {
case .success(let lines):
    print("完了")
    lines.forEach { print("  \($0)") }
case .failure(let reason):
    print("失敗: \(reason)")
}
print("変動ログ:", movements.map { "\($0.productId) \($0.delta)" })
```

**できた合図**:
```
完了
  ステッカー まる: 在庫 10 → 8
  キーホルダー 01: 在庫 1 → 0
変動ログ: ["ST-001 -2", "KH-001 -1"]
```

## 小問4: 在庫不足でロールバック

一点物（在庫1）を2点入れようとすると、**全体が失敗**し、在庫は**元のまま**。

```swift
var inventory2 = products
var moves2: [StockMovement] = []
let badCart = [
    CartLine(product: product("ST-002"), qty: 1),   // これは足りる
    CartLine(product: product("KH-002"), qty: 2),   // ← 在庫1なのに2
]

switch completeSale(saleId: "S-002", cart: badCart, inventory: &inventory2, movements: &moves2) {
case .success: print("完了")
case .failure(let reason): print("失敗: \(reason)")
}
print("ST-002 の在庫:", inventory2.first { $0.id == "ST-002" }!.stock!)  // 10 のまま（減っていない）
print("変動ログの件数:", moves2.count)                                    // 0（ログも出ない）
```

**できた合図**:
```
失敗: 在庫不足: キーホルダー 02（在庫 1、必要 2）
ST-002 の在庫: 10
変動ログの件数: 0
```
ST-002 は足りていたのに、KH-002 の不足で**丸ごと中止**された＝ロールバック。

## 小問5: 中断・取消では減算しない

中断や商品取消のときは、`completeSale` を**呼ばない**。だから在庫は動かない。
「減算は完了のときだけ」を、関数を呼ぶかどうかで守る。

```swift
enum CartAction {
    case complete   // 会計完了
    case suspend    // 中断
    case cancelItem // 商品取消
}

func handle(_ action: CartAction,
            saleId: String,
            cart: [CartLine],
            inventory: inout [Product],
            movements: inout [StockMovement]) {
    switch action {
    case .complete:
        _ = completeSale(saleId: saleId, cart: cart, inventory: &inventory, movements: &movements)
    case .suspend, .cancelItem:
        break   // 在庫には触れない
    }
}

var inventory3 = products
var moves3: [StockMovement] = []
let cart3 = [CartLine(product: product("ST-003"), qty: 3)]

handle(.suspend, saleId: "S-003", cart: cart3, inventory: &inventory3, movements: &moves3)
print("中断後 ST-003:", inventory3.first { $0.id == "ST-003" }!.stock!)   // 10
handle(.complete, saleId: "S-003", cart: cart3, inventory: &inventory3, movements: &moves3)
print("完了後 ST-003:", inventory3.first { $0.id == "ST-003" }!.stock!)   // 7
```

**できた合図**:
```
中断後 ST-003: 10
完了後 ST-003: 7
```

## 小問6: 同じ商品が複数行にある場合

同じ商品が別々の行に入っていても、合計で判定される。

```swift
var inventory4 = products
var moves4: [StockMovement] = []
let splitCart = [
    CartLine(product: product("KH-003"), qty: 1),   // 1行目で1点
    CartLine(product: product("KH-003"), qty: 1),   // 2行目でも1点（合計2点、在庫は1）
]

switch completeSale(saleId: "S-004", cart: splitCart, inventory: &inventory4, movements: &moves4) {
case .success: print("完了")
case .failure(let reason): print("失敗: \(reason)")
}
print("KH-003 の在庫:", inventory4.first { $0.id == "KH-003" }!.stock!)
```

**できた合図**:
```
失敗: 在庫不足: キーホルダー 03（在庫 1、必要 2）
KH-003 の在庫: 1
```
行ごとに「必要 1」と判定すると、どちらも通ってしまう。合算が必要な理由。

## ポイント

- 完了処理は「**検証 → 反映**」の順。検証で失敗したら何も反映しない
- 在庫の判定は、カートの商品情報ではなく**在庫表の現在値**で行う
- 減算の対象は**在庫管理ありの登録商品だけ**（`counted`・`unique`）。`none`・野良は `guard` で飛ばす
- 在庫を減らしたら、必ず `stock_movements` に `sale` として**記録**する（A-7）
- 中断・取消では `completeSale` を呼ばない
- 本物のアプリでは、この一連をDBの**ひとつのトランザクション**で行う（`../開発/6_データベース.md`）
