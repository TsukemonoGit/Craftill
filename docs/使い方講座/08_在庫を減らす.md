# 追加レッスン: 在庫を減らす（完了処理のトランザクション）【大問】

元: `../siyou.md` A-4, A-7
`02_練習メニュー.md` の「8. 在庫を減らす」。

会計を**完了**したときだけ、在庫を減らす。処理は次の順で、**一連（1つのまとまり）**として行う（A-4）。

**① 在庫検証 → ② 在庫減算 → ③ 販売確定 → ④ 在庫変動ログ**

- 減らすのは**在庫管理ありの登録商品だけ**（`counted`・`unique`）。在庫管理なし型 `none`・野良商品は対象外（A-7）。
- **中断**や**商品取消**では減算しない。
- 途中で在庫不足が見つかったら、**何も反映せず全体を失敗**させる（ロールバックの考え方）。

> ここは**純ロジック**なので **ブック（Book）** で書ける。画面（SwiftUI）は **アプリ（App）** で作る（`01_初心者メモ.md`）。
> このファイルだけで完結。冒頭のコードをそのままPlaygroundsに貼り、その下に続けて書けば動く。

## この大問で使う文法

| 文法 | 使う場面 |
|---|---|
| `Optional`（`?`）と `if let` / `guard let` | 在庫が nil の商品の扱い |
| `inout` と `&` | 関数の中で呼び出し元の変数を書き換える |
| `for ... where` | 条件に合う要素だけ回す |
| `filter` / `reduce` | 同じ商品の数量を合算する |
| `map` / `compactMap` / `zip` | 配列から別の配列を作る（関数型の書き方） |
| `enum` と関連値 | 成功・失敗を1つの型で返す |

この大問では、同じ処理を **`for` で書く方法** と **`map` / `filter` / `reduce` で書く方法** の両方を示す。
本編は `for` 版で進める。関数型版は各小問の「別の書き方」にある。どちらで書いた理由も、その節に書く。

### 在庫表とは

**在庫表**は、現在の全商品の在庫数を持つ `[Product]` 配列のこと。型は `products` と同じで、データベースの `products` テーブルに相当する。コード上の変数名は `inventory`。

| 名前 | 中身 | 在庫数が変わるか |
|---|---|---|
| `products` | サンプルの初期データ | 変わらない（`let`） |
| `inventory` | `products` をコピーした作業用の在庫表（`var inventory = products`） | 販売のたびに減る |
| `CartLine.product` | カートに入れた時点の商品情報のコピー | 変わらない（その時点の数字のまま） |

在庫の判定にカート側の `stock` を使うと、次の問題が起きる。

1. 商品Aをカートに入れた時点では、在庫が 3。
2. その後、別の会計で 3 個売れて、在庫表では 0。
3. カート側の `stock` は 3 のままなので、判定が通ってしまう。

そのため、判定と減算は常に最新の値を持つ**在庫表**（`inventory`）側で行う。

## 小問1: 在庫を検証するだけの関数

まず「減らしてよいか」だけを調べる。問題があれば理由を返す。

- 在庫数は、カートの商品情報ではなく**在庫表（`inventory`）の現在値**で見る。
- 同じ商品が複数行に分かれていても、**合計数量**で判定する。

```swift
/// 在庫不足があれば理由（文字列）を返す。問題なければ nil。
func checkStock(_ cart: [CartLine], inventory: [Product]) -> String? {
    // 在庫管理ありの行だけを順に見る
    for line in cart where line.product.stockMode != .none {
        let id = line.product.id

        // 在庫表にない商品（野良）は対象外
        guard let current = inventory.first(where: { $0.id == id }),
              let stock = current.stock else { continue }

        // 同じ商品の数量をカート全体で合算
        let total = cart
            .filter { $0.product.id == id }
            .reduce(0) { $0 + $1.qty }

        if total > stock {
            return "在庫不足: \(current.name)（在庫 \(stock)、必要 \(total)）"
        }
    }
    return nil
}
```

- `String?` は「理由があるかも、なければ nil」という型
- 見つかった時点で `return` して抜ける
- `for ... where` は、条件に合う要素だけを回す
- `reduce(0) { $0 + $1.qty }` は、初期値 0 から `qty` を順に足していく

### 別の書き方: map / filter / reduce 版

```swift
func checkStockFunctional(_ cart: [CartLine], inventory: [Product]) -> String? {
    cart
        .filter { $0.product.stockMode != .none }          // 在庫管理ありの行だけ残す
        .compactMap { line -> String? in                   // 行 → 「不足の理由 or nil」に変換し、nil を捨てる
            let id = line.product.id
            guard let current = inventory.first(where: { $0.id == id }),
                  let stock = current.stock else { return nil }
            let total = cart
                .filter { $0.product.id == id }
                .reduce(0) { $0 + $1.qty }
            return total > stock
                ? "在庫不足: \(current.name)（在庫 \(stock)、必要 \(total)）"
                : nil
        }
        .first                                             // 最初の理由だけ取り出す（なければ nil）
}
```

| | `for` 版（本編） | `map` / `filter` / `reduce` 版 |
|---|---|---|
| 流れ | 1行ずつ見て、不足が見つかった時点で `return` | 「絞る → 変換する → 最初の1件」を順につなぐ |
| 途中で止まるか | 止まる | 止まらない。全行を判定してから `.first` を取る |
| 読み方 | 上から順に追える。`print` を挟んで確認しやすい | 各段が「何をする段か」で読める |
| 向く場面 | 見つけたら即中断したい。手順を1つずつ確認したい | 配列から別の配列・値を作るだけで、途中で止める必要がない |

**本編を `for` 版にした理由**: 「不足を見つけたら即 `return`」が、この関数の主目的である（ロールバックの入口）。早期 `return` は `for` のほうが素直に書ける。
**関数型版の利点**: 判定の各段階（絞る・変換・取り出す）が名前で並ぶ。副作用がなく、テストしやすい。

## 小問2: 完了処理（在庫検証→減算→確定→ログ）

検証がすべて通ったときだけ、まとめて反映する。`inout` で在庫表とログを書き換える。

```swift
enum CompleteResult {
    case success(lines: [String])   // 成功（変化のメモ）
    case failure(String)            // 失敗（理由）
}

func completeSale(saleId: String,
                  cart: [CartLine],
                  inventory: inout [Product],         // 在庫表（products 相当）
                  movements: inout [StockMovement]) -> CompleteResult {

    // ① 在庫検証
    if let reason = checkStock(cart, inventory: inventory) {
        return .failure(reason)      // ← ここで止める。まだ何も変えない
    }

    // ②〜④ 検証が全部通ったので、ここから反映
    var memo: [String] = []
    for line in cart {
        let p = line.product

        // 在庫管理なし・野良（在庫表にない）は対象外
        guard p.stockMode != .none,
              let i = inventory.firstIndex(where: { $0.id == p.id }),
              let current = inventory[i].stock else { continue }

        let after = current - line.qty

        inventory[i].stock = after                                           // ② 在庫減算
        memo.append("\(p.name): 在庫 \(current) → \(after)")                  // ③ 販売確定の記録
        movements.append(StockMovement(productId: p.id,                      // ④ 在庫変動ログ
                                       delta: -line.qty,
                                       reason: "sale",
                                       saleId: saleId))
    }
    return .success(lines: memo)
}
```

- `inout` … 関数の中の変更が、呼び出し元の変数に反映される。呼ぶときは `&` を付ける
- `guard ... else { continue }` … 対象外の行は**飛ばす**（early continue）
- `guard` の条件はカンマで複数つなげられる。1つでも満たさなければ `else` に入る
- **検証を先に全部やる**のがミソ。①で失敗したら②以降を実行しない＝ロールバック

### 別の書き方: 元の在庫表を書き換えず、新しい値を返す版

`inout` を使わず、「新しい在庫表」「ログ」「メモ」を作って返す。元の `inventory` は一切変わらない。

```swift
struct SaleOutcome {
    let inventory: [Product]          // 反映後の在庫表（新しい配列）
    let movements: [StockMovement]    // この販売で増えるログ
    let memo: [String]
}

enum PureResult {
    case success(SaleOutcome)
    case failure(String)
}

func completeSalePure(saleId: String,
                      cart: [CartLine],
                      inventory: [Product]) -> PureResult {

    // ① 在庫検証
    if let reason = checkStock(cart, inventory: inventory) {
        return .failure(reason)
    }

    // 減算の対象になる行（在庫管理あり、かつ在庫表にある）
    let targets = cart.filter { line in
        line.product.stockMode != .none
            && inventory.contains { $0.id == line.product.id }
    }

    // ② 在庫減算: 在庫表の各商品を「減算後の商品」に置き換えた新しい配列
    let newInventory = inventory.map { p -> Product in
        let sold = targets
            .filter { $0.product.id == p.id }
            .reduce(0) { $0 + $1.qty }
        guard sold > 0, let current = p.stock else { return p }
        var updated = p
        updated.stock = current - sold
        return updated
    }

    // ③ 販売確定の記録: 在庫が変わった商品だけメモにする
    let memo = zip(inventory, newInventory).compactMap { old, new -> String? in
        guard let o = old.stock, let n = new.stock, o != n else { return nil }
        return "\(old.name): 在庫 \(o) → \(n)"
    }

    // ④ 在庫変動ログ: 対象の行ごとに1件
    let movements = targets.map {
        StockMovement(productId: $0.product.id, delta: -$0.qty, reason: "sale", saleId: saleId)
    }

    return .success(SaleOutcome(inventory: newInventory, movements: movements, memo: memo))
}
```

使い方（小問3の `cart` を使う）:

```swift
switch completeSalePure(saleId: "S-005", cart: cart, inventory: products) {
case .success(let outcome):
    outcome.memo.forEach { print("  \($0)") }
    print("変動ログ:", outcome.movements.map { "\($0.productId) \($0.delta)" })
    print("元の ST-001 在庫:", products.first { $0.id == "ST-001" }!.stock!)
case .failure(let reason):
    print("失敗: \(reason)")
}
```

**できた合図**:
```
  ステッカー まる: 在庫 10 → 8
  キーホルダー 01: 在庫 1 → 0
変動ログ: ["ST-001 -2", "KH-001 -1"]
元の ST-001 在庫: 10
```

| | `for` + `inout` 版（本編） | `map` / `filter` / `reduce` 版 |
|---|---|---|
| 在庫表の扱い | その場で書き換える | 書き換えず、新しい配列を返す |
| 失敗時 | ①で止めるので、書き換え前に戻る | そもそも元を触らないので、元が残る |
| 呼び出し側 | `&` を付ける。結果を受け取る変数が必要 | 返り値を受け取り、成功したら自分で差し替える |
| メモの出方 | カートの行ごと（同じ商品が2行なら2件、途中経過あり） | 商品ごと（在庫が変わった商品につき1件） |
| コード量 | 短く、手順が1本 | 長い。段階ごとに分かれる |

**本編を `for` + `inout` 版にした理由**:
- 「在庫表を書き換える」「ログに追加する」が、この処理の本体である。本物のアプリのDB更新（`UPDATE` / `INSERT`）に近い形で書ける。
- ②③④を1回のループにまとめられ、初学者が手順を1本で追える。

**関数型版の利点**: 元データが変わらないため、失敗時の巻き戻しを考えなくてよい。入力と出力だけで結果が決まり、テストしやすい。

## 小問4: 在庫不足でロールバック

一点物（在庫1）を2点入れようとすると、**全体が失敗**し、在庫は**元のまま**。

ST-002 は足りていたのに、KH-002 の不足で**丸ごと中止**された＝ロールバック。

## 小問5: 中断・取消では減算しない

中断や商品取消のときは、`completeSale` を**呼ばない**。だから在庫は動かない。
「減算は完了のときだけ」を、関数を呼ぶかどうかで守る。

```swift
enum CartAction {
    case complete   // 会計完了
    case suspend    // 中断
    case cancelItem // 商品取消
}

func handle(_ action: CartAction,
            saleId: String,
            cart: [CartLine],
            inventory: inout [Product],
            movements: inout [StockMovement]) {
    switch action {
    case .complete:
        _ = completeSale(saleId: saleId, cart: cart, inventory: &inventory, movements: &movements)
    case .suspend, .cancelItem:
        break   // 在庫には触れない
    }
}

var inventory3 = products
var moves3: [StockMovement] = []
let cart3 = [CartLine(product: product("ST-003"), qty: 3)]

handle(.suspend, saleId: "S-003", cart: cart3, inventory: &inventory3, movements: &moves3)
print("中断後 ST-003:", inventory3.first { $0.id == "ST-003" }!.stock!)   // 10
handle(.complete, saleId: "S-003", cart: cart3, inventory: &inventory3, movements: &moves3)
print("完了後 ST-003:", inventory3.first { $0.id == "ST-003" }!.stock!)   // 7
```

**できた合図**:
```
中断後 ST-003: 10
完了後 ST-003: 7
```

## ポイント

- 完了処理は「**検証 → 反映**」の順。検証で失敗したら何も反映しない
- 在庫の判定は、カートの商品情報ではなく**在庫表の現在値**で行う
- 減算の対象は**在庫管理ありの登録商品だけ**（`counted`・`unique`）。`none`・野良は `guard` で飛ばす
- 在庫を減らしたら、必ず `stock_movements` に `sale` として**記録**する（A-7）
- 中断・取消では `completeSale` を呼ばない

### `for` と `map` / `filter` / `reduce` の使い分け

| やりたいこと | 向く書き方 |
|---|---|
| 条件に合う要素だけ残す | `filter` |
| 各要素を別の値に変換する | `map`（nil を捨てたいなら `compactMap`） |
| 全要素から1つの値（合計など）を作る | `reduce` |
| 条件に合う最初の1件を探す | `first(where:)` |
| 見つけた時点で処理を打ち切る | `for` + `return` / `break` |
| 配列やログを**その場で書き換える** | `for` + `inout` |
| 元のデータを変えずに、結果だけ新しく作る | `map` / `filter` / `reduce` |

迷ったときの目安: **「配列から別の配列・値を作る」なら `map` / `filter` / `reduce`、「途中で止める」「その場で書き換える」なら `for`**。
