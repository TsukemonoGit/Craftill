# 在庫を減らす

元: `../siyou.md` A-4（単一トランザクション）、A-7（在庫変動ログ）、A-13
`../siyou.md` A-19-1（現在庫の正）、A-19-4（採番規則）、A-19-9（`stockMode` は種類だけ）
受け入れテスト C-6 #4・#7・#73

会計の「完了」は、A-7 の約束どおりに進めなければなりません。

- 完了のときだけ減算する（中断・商品取消では減らさない）
- 減算の対象は**在庫管理ありの登録商品だけ**（`counted`・`unique`）。在庫管理なし型・野良は対象外
- 減算したら `stock_movements` に `sale` として残す
- 4 つの手順は**1つのまとまり**。途中でつまずいたら「何も起こっていない」状態に戻す（A-4）

いちばん効くのは、最後の行です。**在庫は「まとめて」減らす。**

1 行ずつ検証しながら減らすと、途中で「足りない」と分かった瞬間に、あとで戻すものが 3 つ出てきます。

- すでに減らした行の在庫を戻さないといけない
- すでに出した在庫変動ログを消さないといけない
- しかもその理由を、1 件ずつしか返せない（返して、その次の不足でまた止まる）

A-4 が 4 つを「単一トランザクション」でまとめているのは、この 3 つをまとめて回避するためです。

**正は `base/3_標準ロジック.md` §3・§4 にあります。**
このレッスンは、まず **わざと壊して** 症状を見てから、直します。

## 3 つの名前が別物（A-19-9）

Lesson を始める前に、**このレッスンの土台で違う名前を3つ直します。**

| 昔 | 正 | なぜ |
| --- | --- | --- |
| `Product.stockMode` | **`ProductType.stockMode`** | 在庫の扱いは**種類**が決める（A-1、A-19-9） |
| `StockMovement` に `id` が無い | **`id: String`**（`M-{連番:06}`・A-19-4） | エクスポートのソートと `ForEach` に必要 |

| 判定 | 什么问题 |
| --- | --- |
| `stock == nil` | **在庫取值の偶発**に依存する。「種類が `none` なのに `stock` に値がある」‡な状態を弾けない |
| `inventory[i].managesStock(in: types)` | **種類が正**。種類を変えれば全部跟着変わる（A-1） |

## わざと間違う①: 会計のたびに在庫表を作り直す

まず、いちばん自然な書き方として、`completeSale` の中で在庫表を作り直してみます。

```swift NG
// わざと間違う版①：会計ごとに在庫表を作り直している
func completeSaleNaive(saleId: String, cart: [CartLine],
                       products: [Product],
                       movements: inout [StockMovement]) -> [String] {
    var inventory = products     // ★ 1会計ぶんの作業領域になっている
    var memo: [String] = []
    for l in cart {
        guard !l.isAdhoc,
              let i = inventory.firstIndex(where: { $0.id == l.id }),
              let current = inventory[i].stock else { continue }
        inventory[i].stock = current - l.qty
        memo.append("\(l.name): 在庫 \(current) → \(current - l.qty)")
        movements.append(StockMovement(id: "M-?", productId: l.id, delta: -l.qty,
                                       reason: .sale, saleId: saleId, at: Date()))
    }
    return memo
}
```

**症状**: 客Aが `ST-001` を6枚、客Bも同じ商品を6枚買うと、
**ログは2件あるのに、在庫は 10 のまま**です。

こうなった筋書き:

1. 1つめの会計: `inventory = products` で在庫表を作り、`ST-001` を 10 → 4 にして終わる。
2. 関数から返ると `inventory` は消える。**在庫表は「関数の中」だけに存在した**。
3. 2つめの会計: また `products`（= 初期値 10）から作り直し、同様に 10 → 4。
4. どちらの会計も成功。販売は12枚、在庫は10のまま。

> カートに古い在庫を**持たせない**だけでは、問題は起きません（`CartLine` には在庫の項目が無い）。
> 本当の問題は、**在庫表を「1会計ぶんの作業領域」として作ってしまった**ことです。

**正しいルール**: 在庫表は**アプリに1つだけ**あり、減算はそこに対して行う（A-19-1）。
正しくするには、その配列を**関数の外に出して `inout` で渡す**。「在庫表は 1 つだけ」という原則です。

## わざと間違う②: 1行ずつ減算しながら、途中で諦める

判定の場所は直しました。でも減算しながら判定すると、やはり壊れます。

```swift NG
// わざと間違う版②：1行ずつ減算しながら、途中で諦める
func completeSaleNaive2(saleId: String, cart: [CartLine],
                        inventory: inout [Product],
                        movements: inout [StockMovement]) -> [String] {
    var memo: [String] = []
    for l in cart {
        guard !l.isAdhoc,
              let i = inventory.firstIndex(where: { $0.id == l.id }),
              let current = inventory[i].stock else { continue }
        if l.qty > current {
            return ["在庫不足: \(l.name)（在庫 \(current)、必要 \(l.qty)）"]   // ★ 1行ずつ返して止まる
        }
        inventory[i].stock = current - l.qty                                  // ★ もう減らしちゃった
        memo.append("\(l.name): 在庫 \(current) → \(current - l.qty)")
        movements.append(StockMovement(id: "M-?", productId: l.id, delta: -l.qty,
                                       reason: .sale, saleId: saleId, at: Date()))
    }
    return memo
}
```

**症状**: 「完了できない」と言ったのに、**足りている商品の在庫が減ったまま**。ログも残っています。

壊れ方は 3 つあります。どれも元のルール（A-4, A-7）に反しています。

| # | 壊れ方 | なぜ困るか |
| --- | --- | --- |
| 1 | 足りている商品の在庫が減ったまま | 会計は失敗したのに、**1 枚も出ていない**。**棚卸しするまで気づけない** |
| 2 | 在庫変動ログが残った | 「売れた記録」があるのに販売記録がない。**日次集計が合わなくなる** |
| 3 | 理由が **1 件しか返らない** | 客に「もう 1 点だけ増やしてください」と言ったら、さらに不足が出て、そしてまた 1 から |

**直すときの順番は、もう決まっています。**

1. 減算の**対象**を 1 か所で決める
2. 対象を**検証だけ**する（在庫は触らない）
3. 検証が全部通ってから**まとめて反映**する

## わざと間違う③: 在庫管理なし型を `stock == nil` で判定する

```swift NG
// わざと間違う版③：対象判定に 3 つしか無い
func stockTargets(_ cart: [CartLine], in inventory: [Product]) -> [(index: Int, line: CartLine, current: Int)] {
    var targets: [(index: Int, line: CartLine, current: Int)] = []
    for l in cart {
        guard !l.isAdhoc,                                              // ① 野良ではない
              let i = inventory.firstIndex(where: { $0.id == l.id }),  // ② 在庫表に居る
              let current = inventory[i].stock                          // ③ 現在値を取り出す
        else { continue }
        targets.append((index: i, line: l, current: current))
    }
    return targets
}
```

**③ の `stock` を取り出す時点で、在庫管理なし型は弾かれています。**
でもこれは**副作用**です（在庫が `nil` だから落ちている）。

**本当は種類で判定します**（A-19-9）。

```swift 断片
// base/3 §3 の正（guard は4つ）
guard !line.isAdhoc,                                     // ① 野良は対象外（A-1）
      let i = inventory.firstIndex(where: { $0.id == line.id }),  // ② 在庫表に居る
      inventory[i].managesStock(in: types),              // ③ ★ 在庫管理あり（種類が決める・A-19-9）
      let current = inventory[i].stock                   // ④ 現在値を取り出す
```

**副作用で判定すると何が壊れるか**

**仕様書に無い「ニセモノ」を1つ作ります**。

```swift NG
// わざと間違う版③：種類が .none なのに stock に値があるCSV
Product(id: "FR-009", typeId: "free", name: "配布物", priceJpy: 0, priceSats: nil, stock: 5)
```

| | `managesStock`（正） | `stock == nil`（誤り） |
| --- | --- | --- |
| この行 | **対象外**（種類が `none`） | **対象になる** |

**在庫管理なし型は「何個売っても在庫が減らない」**のが定義です（A-1）。
`stock` に値が入ると**その定義を破る**。そして **1か所だけ**直しても、
**他の関数（`addCheck` / `increase` / `voidSale` / `adjustStock`）は `managesStock` を見る**ので、
**片方だけ直した瞬間に挙動がズレます**。

**4 か所を全部直すより、`managesStock` の1か所に集める**（A-19-9）。

## わざと間違う④: `completeSale` だけだと販売記録が無い

検証 → 減算 → ログ の 3 段は正解です。でも **4 つ目の手順が抜けて**います。

```
① 在庫検証 → ② 在庫減算 → ③ 販売確定 → ④ 在庫変動ログ
                          ★ これ
```

`completeSale`（`base/3` §3）は **①・②・④** だけ。
**販売記録（`sales` / `sale_items`）を作りません**。

| # | 起きないこと | 違反 |
| --- | --- | --- |
| 1 | **`sales` が空**。日次集計が **0円** | A-4、A-8 |
| 2 | `sale_id` が**振られない**ので中断・取消が紐づけられない | A-9、A-19-4 |
| 3 | CSV 取り込み直後に**販売と突き合わせられない** | A-8 |

**正は `commitSale`**（`base/3` §4）。A-4 の4手順を1本にまとめています。

```swift 断片
// base/3 §4 の正
func commitSale(cart: [CartLine], inventory: inout [Product], movements: inout [StockMovement],
                sales: inout [Sale], items: inout [SaleItem], ids: inout IdSequencer,
                types: [ProductType], chooseSats: Bool,
                receivedJpy: Int?, confirmedAt: Date?, now: Date) -> CommitResult {
    // ① 在庫検証。1件でも失敗したら、以降の手順を全部飛ばす
    let problems = checkStock(cart, inventory: inventory, types: types)
    guard problems.isEmpty else { return .failure(problems) }

    // ② 販売記録。**検証が通ってから採番する**（失敗した会計で番号を消費しない・A-19-4）
    let built = buildSale(cart: cart, ids: &ids, chooseSats: chooseSats,
                          receivedJpy: receivedJpy, confirmedAt: confirmedAt, now: now)

    // ③ 在庫減算 ＋ ④ 在庫変動ログ
    switch completeSale(saleId: built.sale.id, cart: cart, inventory: &inventory,
                        movements: &movements, ids: &ids, types: types, at: now) {
    case .failure(let rs):
        return .failure(rs)      // 検証済みなのでここには来ない
    case .success(let memo):
        sales.append(built.sale)
        items.append(contentsOf: built.items)
        return .success(sale: built.sale, items: built.items, stockMemo: memo)
    }
}
```

> **② の採番が検証の「後」**なのは、失敗した会計で**販売IDを消費しない**ためです（A-19-4）。

## 1. 正は `base/3` §3 の3段

| 段 | 関数 | すること | 触るもの |
| --- | --- | --- | --- |
| 1 | `stockTargets(_:in:types:)` | **減算の対象**を1か所で決める | **何も触らない** |
| 2 | `checkStock(_:inventory:types:)` | 不足の理由を**全件**集める | **何も触らない** |
| 3 | `completeSale(saleId:cart:inventory:movements:ids:types:at:)` | 検証が終わってから**まとめて**反映 | 在庫・ログ |

**1 段目と 2 段目は `inout` を取りません。** 「判定だけ」の関数は **1行も変えない**のが約束です
（`base/5` §4 の `decrease` と同じ考え方）。

**3 段目の `.failure` で帰る地点は、1 行も書き換える前**。ここが 2 段構えの本体です。

## まとめ: 壊したところと、直したところ

4 つの間違えは、それぞれ 1〜2 行を書き換えるだけで直せます。

| | わざと間違う版 | 正しい版 |
| --- | --- | --- |
| 在庫表 | 会計のたびに `products` から作り直す | アプリに1つだけ持ち、`inout` で渡す |
| 減算のタイミング | 検証しながら 1 行ずつ | 検証が終わってから**まとめて** |
| 理由の返し方 | 1 件ずつ返して止まる | **全件**集めて返す |
| 対象判定 | `stock == nil`（副作用） | **`managesStock(in: types)`**（種類が決める・A-19-9） |
| 手順の数 | 3 段（販売記録が無い） | **4 段**（`commitSale`・A-4） |

## このレッスンで使った文法

- **`inout`** … 呼び出し元の配列を書き換える。`&inventory` と呼ぶ
- **`guard ... else { continue }`** … 対象外の行を**飛ばす**
- **タプル / `StockTarget`** … 「在庫表の位置」と「現在値」を**一緒に**持つ
- **`guard` を並べる** … 条件はカンマ区切り。**1 つでも満たさなければ else**
- **`>` と `>=`** … 在庫ちょうどで通るのは `>` のほう（`>=` だと落ちてしまう）
