## 状況: 守るべき約束

会計の「完了」は、A-7 の約束どおりに進めなければなりません。

- 完了のときだけ減算する（中断・商品取消では減らさない）
- 減算の対象は**在庫管理ありの登録商品だけ**（`counted`・`unique`）。在庫管理なし型 `none`・野良商品は対象外
- 減算したら `stock_movements` に `sale` として残す
- 4 つの手順は**1つのまとまり**。途中でつまずいたら「何も起こっていない」状態に戻す（A-4）

いちばん効くのは、最後の行です。**在庫は「まとめて」減らす。**

1 行ずつ検証しながら減らすと、途中で「足りない」と分かった瞬間に、あとで戻すものが 3 つ出てきます。

- すでに減らした行の在庫を戻さないといけない
- すでに出した在庫変動ログを消さないといけない
- しかもその理由を、1 件ずつしか返せない（返して、その次の不足でまた止まる）

A-4 が 4 つを「単一トランザクション」でまとめているのは、この 3 つをまとめて回避するためです。

このレッスンは、まず **わざと壊して** 症状を見てから、直します。

## 前提データ

```swift
import Foundation

// ── 種類（在庫の扱い）────────────────────
enum StockMode {
    case counted   // 数量管理型（ステッカー）
    case unique    // 一点物型（キーホルダー）
    case none      // 在庫管理なし型
}

// ── 商品1つ分（テーブル products 相当）──
struct Product {
    let id: String
    let typeId: String
    let name: String
    let priceJpy: Int
    let priceSats: Int?
    var stock: Int?         // 在庫（在庫管理なし型は nil）
    let stockMode: StockMode
}

// ── カートの行 ──
struct CartLine {
    let product: Product    // カートに入れた時点の情報（在庫は古い可能性がある）
    var qty: Int
}

// ── 在庫変動ログ1件（テーブル stock_movements 相当）──
struct StockMovement {
    let productId: String
    let delta: Int          // 増減数（- / +）
    let reason: String      // initial / sale / void / adjust
    let saleId: String?     // 販売に関係するときだけ入る
}

// ── 商品サンプル（../開発/6_データベース.md より。以降省略）──
let products: [Product] = [
    Product(id: "ST-001", typeId: "sticker",   name: "ステッカー まる",     priceJpy: 300, priceSats: 500,  stock: 10, stockMode: .counted),
    Product(id: "ST-002", typeId: "sticker",   name: "ステッカー さんかく", priceJpy: 300, priceSats: 500,  stock: 10, stockMode: .counted),
    Product(id: "ST-003", typeId: "sticker",   name: "ステッカー しかく",   priceJpy: 300, priceSats: nil,  stock: 10, stockMode: .counted),
    Product(id: "KH-001", typeId: "keyholder", name: "キーホルダー 01", priceJpy: 800, priceSats: 1200, stock: 1,  stockMode: .unique),
    Product(id: "KH-002", typeId: "keyholder", name: "キーホルダー 02", priceJpy: 800, priceSats: 1200, stock: 1,  stockMode: .unique),
    Product(id: "KH-003", typeId: "keyholder", name: "キーホルダー 03", priceJpy: 800, priceSats: 1200, stock: 1,  stockMode: .unique),
    Product(id: "KH-004", typeId: "keyholder", name: "キーホルダー 04", priceJpy: 800, priceSats: 1200, stock: 1,  stockMode: .unique),
]

// 小さな補助
func product(_ id: String) -> Product { products.first { $0.id == id }! }
func line(_ id: String, _ qty: Int) -> CartLine { CartLine(product: product(id), qty: qty) }
func stockText(_ inventory: [Product], _ id: String) -> String {
    if let s = inventory.first(where: { $0.id == id })?.stock { return String(s) }
    return "なし"
}

// 在庫管理なし型の商品（A-1。減算の対象外）
let noStock = Product(id: "FR-001", typeId: "free", name: "無料配布物", priceJpy: 0, priceSats: nil, stock: nil, stockMode: .none)

// 野良商品（products に居ない ＝ 在庫表に居ない）
let adhoc = Product(id: "ADHOC-1", typeId: "adhoc", name: "野良（販売した本）", priceJpy: 500, priceSats: nil, stock: nil, stockMode: .none)
```

### 在庫表とカートは別物

| 名前 | 中身 | 在庫が変わるか |
| --- | --- | --- |
| `products` | 初期データ（`let`） | 変わらない |
| `inventory` | `products` を写した作業用の在庫表（`var`） | 減算のたびに減る |
| `CartLine.product` | カートに入れた**時点**の商品情報 | 変わらない（その時点の数字のまま） |

`inventory` を `var` で持つのは、Swift の配列が値型だからです（`04-1_Swiftの違い.md` §7）。
`inventory[i].stock = after` と書くと、その 1 件だけが書き換わり、呼び出し元にも反映されます。

## わざと間違う①: カートに入れた時の古い在庫で判定する

まず、いちばん自然な書き方として、`l.product.stock`（カートに入れた時の在庫）で判定する方法を書いてみます。

```swift
func completeSaleNaive(saleId: String, cart: [CartLine],
                       inventory: inout [Product], movements: inout [StockMovement]) -> [String] {
    var memo: [String] = []
    for l in cart {
        // ❌ カートに入れた時の数字（古い）を見ている
        if let stock = l.product.stock, l.qty > stock {
            return ["在庫不足: \(l.product.name)（在庫 \(stock)、必要 \(l.qty)）"]
        }
        guard let i = inventory.firstIndex(where: { $0.id == l.product.id }),
              let current = inventory[i].stock else { continue }
        inventory[i].stock = current - l.qty
        memo.append("\(l.product.name): 在庫 \(current) → \(current - l.qty)")
        movements.append(StockMovement(productId: l.product.id, delta: -l.qty, reason: "sale", saleId: saleId))
    }
    return memo
}

var inv1 = products
var mov1: [StockMovement] = []

// 客Aが ST-001 を6枚買う（在庫 10 → 4）
_ = completeSaleNaive(saleId: "S-A", cart: [line("ST-001", 6)], inventory: &inv1, movements: &mov1)
print("客Aのあと ST-001 の在庫:", stockText(inv1, "ST-001"))

// 客Bも同じ商品を6枚買う（在庫は残り4なのに…）
_ = completeSaleNaive(saleId: "S-B", cart: [line("ST-001", 6)], inventory: &inv1, movements: &mov1)
print("客Bのあと ST-001 の在庫:", stockText(inv1, "ST-001"))
print("ログ:", mov1.map { "\($0.saleId ?? "-"):\($0.productId)\($0.delta)" })
```

**できた合図**:
```
客Aのあと ST-001 の在庫: 4
客Bのあと ST-001 の在庫: -2
ログ: ["S-A:ST-001-6", "S-B:ST-001-6"]
```

**在庫が −2 になりました。** 現物より多い個数を、そのまま在庫として数えている状態です。

こうなった筋書き:

1. 客Aが会計を終える。`ST-001` の在庫は 10 → 4。在庫表は 4。
2. 客Bのカートには、カートに入れた時の商品情報が入っていて、`stock` は **10 のまま**。
3. 判定は `l.product.stock` を見ている → 「在庫 10、必要 6。OK」と通ってしまう。
4. 減算は在庫表に対して行う → 4 − 6 = **−2**。

> これがこわいのは、`checkStock` を直しても `completeSale` を直さなければ直らない、ということです。
> 「検証」と「減算」で**別の場所を見ていた**から起きるバグです。

**正しいルール**: 判定も減算も、**在庫表の現在値**（`inventory`）だけを見る。
カートは「客が買ったもの」の記録であって、「いま何が残っているか」の記録ではありません。

## わざと間違う②: 1行ずつ減算しながら、途中で諦める

判定の場所は直しました。でも減算しながら判定すると、やはり壊れます。

```swift
func completeSaleNaive2(saleId: String, cart: [CartLine],
                        inventory: inout [Product], movements: inout [StockMovement]) -> [String] {
    var memo: [String] = []
    for l in cart {
        guard l.product.stockMode != .none,
              let i = inventory.firstIndex(where: { $0.id == l.product.id }),
              let current = inventory[i].stock else { continue }
        if l.qty > current {
            return ["在庫不足: \(l.product.name)（在庫 \(current)、必要 \(l.qty)）"]
        }
        inventory[i].stock = current - l.qty
        memo.append("\(l.product.name): 在庫 \(current) → \(current - l.qty)")
        movements.append(StockMovement(productId: l.product.id, delta: -l.qty, reason: "sale", saleId: saleId))
    }
    return memo
}

var inv2 = products
var mov2: [StockMovement] = []
// ST-002は足りる / KH-002は足りない / KH-004も足りない
let reasons = completeSaleNaive2(saleId: "S-C",
                                 cart: [line("ST-002", 1), line("KH-002", 2), line("KH-004", 3)],
                                 inventory: &inv2, movements: &mov2)
reasons.forEach { print("完了できない: \($0)") }
print("ST-002 の在庫:", stockText(inv2, "ST-002"))
print("KH-002 の在庫:", stockText(inv2, "KH-002"))
print("ログ:", mov2.map { "\($0.productId)\($0.delta)" })
```

**できた合図**:
```
完了できない: 在庫不足: キーホルダー 02（在庫 1、必要 2）
ST-002 の在庫: 9
KH-002 の在庫: 1
ログ: ["ST-002-1"]
```

「完了できない」と言ったのに、**ST-002 は 1 枚減ったまま**。ログも 1 件残っています。

壊れ方は 3 つあります。どれも元のルール（A-4, A-7）に反しています。

| # | 壊れ方 | なぜ困るか |
| --- | --- | --- |
| 1 | 足りている ST-002 の在庫が減ったまま | 会計は失敗したのに、1 枚出ていない。**棚卸しするまで気づけない** |
| 2 | 在庫変動ログが 1 件残った | 「売れた記録」があるのに販売記録がない。日次集計が合わなくなる |
| 3 | 理由が 1 件しか返らない | 客に「もう 1 点だけ増やしてください」と言ったら、さらに不足が出て、そしてまた 1 から |

A-4 はこう書いています。「完了処理は端末内DBの単一トランザクションで行う」。
要するに、**途中でつまずいたら、何も起こっていない状態に戻ること**です。このコードはそうなっていません。

直すときの順番は、もう決まっています。

1. 減算の**対象**を 1 か所で決める
2. 対象を**検証だけ**する（在庫は触らない）
3. 検証が全部通ってから**まとめて反映**する

## ここからが本番: 2段に分ける

### 1. 減算の対象を 1 か所で決める（`stockTargets`）

> **考えてみる**: 検証する関数と減算する関数で、それぞれに「これは減算の対象か」を書くとどうなる?
> → 片方だけ直したときに **「検証は通るのに減算が足りない」** 状態になります。わざと間違う① がまさにそれです。
> だから判定は 1 か所にまとめます。置き場所は **減算の直前**。

「対象か」を決める基準は 2 つだけです（A-7）。

- `stockMode` が `.none` じゃない（= 在庫管理ありの登録商品）
- 在庫表に居る（= 野良や、DB にないデータは対象ではない）

```swift
/// 減算の対象だけを、在庫表の位置（index）と現在値つきで取り出す。
/// 在庫管理なし型（.none）と在庫表に居ない商品（野良）は含まれない。
func stockTargets(_ cart: [CartLine], in inventory: [Product]) -> [(index: Int, line: CartLine, current: Int)] {
    var targets: [(index: Int, line: CartLine, current: Int)] = []

    for l in cart {
        guard l.product.stockMode != .none,                                   // ① 在庫管理あり
              let i = inventory.firstIndex(where: { $0.id == l.product.id }),  // ② 在庫表に居る
              let current = inventory[i].stock                                 // ③ 現在値を取り出す
        else { continue }                                                      // 対象外はこの行を飛ばす

        targets.append((index: i, line: l, current: current))
    }
    return targets
}
```

読み方:

- `guard` の条件はカンマで 3 つ並べられます。**1 つでも満たさなければ `else`**（＝`continue`）へ進みます。
- `i` は在庫表の位置。あとで `inventory[i].stock = …` のように、1 件だけ書き換えられます。
- `current` は在庫表の**現在値**。カートに入れた時の古い数字は入っていません（わざと間違う① の直し）。
- 返り値はタプルの配列なので、`t.index`・`t.line`・`t.current` のように取り出せます。

### 2. 検証だけする（`checkStock`）

> **考えてみる**: 不足が 3 件あったとき、1 件だけ返して止まるのと、3 件まとめて返すのはどちらが親切?
> → **全部まとめて**返します。この文字列はそのまま画面に出る文言なので。1 件ずつ直すと手戻りが増えるからです。

```swift
/// 在庫不足の理由を**全件**返す。問題なければ空配列。
func checkStock(_ cart: [CartLine], inventory: [Product]) -> [String] {
    var problems: [String] = []
    for t in stockTargets(cart, in: inventory) {
        if t.line.qty > t.current {
            problems.append("在庫不足: \(t.line.product.name)（在庫 \(t.current)、必要 \(t.line.qty)）")
        }
    }
    return problems
}
```

- 判定は `t.current`（在庫表の現在値）との比較だけです。**`>`** に注意。`>=` にすると在庫ちょうどで落ちてしまいます。
- `return` せずに `problems` に積み続けて、全部見てから返します。
- **この関数は在庫を一切触りません。** だから単独で何度でも試せます。

### 3. 検証が終わってから、まとめて反映する（`completeSale`）

```swift
enum CompleteResult {
    case success(lines: [String])   // 成功（在庫がどう変わったか）
    case failure([String])          // 失敗（理由の一覧）
}

/// 会計を完了する。検証 → 在庫減算 → 在庫変動ログ、の順でまとめて行う。
func completeSale(saleId: String, cart: [CartLine],
                  inventory: inout [Product], movements: inout [StockMovement]) -> CompleteResult {
    // ① 検証だけ先に。足りなければ **何も変えずに** 終わる
    let problems = checkStock(cart, inventory: inventory)
    if !problems.isEmpty { return .failure(problems) }

    // ② 検証が終わってから、まとめて反映する
    var memo: [String] = []
    for t in stockTargets(cart, in: inventory) {
        let after = t.current - t.line.qty
        inventory[t.index].stock = after                                      // 在庫減算
        memo.append("\(t.line.product.name): 在庫 \(t.current) → \(after)")     // 変化のメモ
        movements.append(StockMovement(productId: t.line.product.id,          // 在庫変動ログ
                                       delta: -t.line.qty,
                                       reason: "sale",
                                       saleId: saleId))
    }
    return .success(lines: memo)
}
```

- `inventory` と `movements` に `inout` を付けているのは、**呼び出し元の変数を書き換える**ため。呼ぶときは `&inventory` と書きます（`07_追加レッスン.md` と同じ）。
- `.failure` で帰る地点は、**1 行も書き換える前**。ここが 2 段構えの本体です。
- 在庫変動ログも同じループの中で作ります。**減算したのにログが無い**という状態を作らないため（A-7）。ログの作り方は `41_在庫変動ログを記録する.md`。
- `lines` は在庫がどう変わったかのメモ。画面に出す文字列（A-7 の「変化を全て記録」はログ側の話）。

## 確かめる

```swift
var inventory = products              // 在庫表（var なので減らせる）
var movements: [StockMovement] = []   // 在庫変動ログ

// 試験ごとに元に戻したいので用意する
func reset() {
    inventory = products
    movements = []
}

func stocks(_ ids: [String]) -> String {
    ids.map { "\($0)=\(stockText(inventory, $0))" }.joined(separator: " ")
}

func logs() -> String {
    movements.isEmpty ? "なし" : movements.map { "\($0.productId)\($0.delta)" }.joined(separator: " ")
}

func show(_ label: String, _ result: CompleteResult,
          _ ids: [String] = ["ST-001", "ST-002", "ST-003", "KH-001", "KH-002"]) {
    print("[\(label)]")
    switch result {
    case .success(let lines):
        lines.forEach { print("  \($0)") }
    case .failure(let reasons):
        print("  完了できない")
        reasons.forEach { print("  \($0)") }
    }
    print("  在庫: \(stocks(ids))")
    print("  ログ: \(logs())")
}

// 1. ふつうに完了する
reset()
show("1 ふつう", completeSale(saleId: "S-001",
                              cart: [line("ST-001", 2), line("KH-001", 1)],
                              inventory: &inventory, movements: &movements))

// 2. 複数不足。全部まとめて報告して、1件も反映しない
reset()
show("2 複数不足", completeSale(saleId: "S-002",
                                cart: [line("ST-002", 1), line("KH-002", 2), line("KH-004", 3)],
                                inventory: &inventory, movements: &movements))

// 3. 在庫ちょうど（0 になっても通る）
reset()
show("3 在庫ちょうど", completeSale(saleId: "S-003",
                                   cart: [line("ST-003", 10)],
                                   inventory: &inventory, movements: &movements))

// 4. 対象外の行（在庫管理なし・野良）は無視される
reset()
inventory.append(noStock)        // FR-001 だけ在庫表に入れておく
show("4 対象外が混ざる", completeSale(saleId: "S-004",
                                     cart: [line("ST-001", 1),
                                            CartLine(product: noStock, qty: 100),
                                            CartLine(product: adhoc, qty: 5)],
                                     inventory: &inventory, movements: &movements),
      ["ST-001", "FR-001"])

// 5. わざと間違う①を、ちゃんとしたやり方で
reset()
_ = completeSale(saleId: "S-A", cart: [line("ST-001", 6)], inventory: &inventory, movements: &movements)
print("[5 続けて2会計]")
print("  客Aのあと: \(stocks(["ST-001"])) / ログ: \(logs())")
switch completeSale(saleId: "S-B", cart: [line("ST-001", 6)],
                    inventory: &inventory, movements: &movements) {
case .success(let lines):
    lines.forEach { print("  客B: \($0)") }
case .failure(let reasons):
    print("  客B: 完了できない")
    reasons.forEach { print("    \($0)") }
}
print("  客Bのあと: \(stocks(["ST-001"])) / ログ: \(logs())")

// 6. 対象を見る
print("[6 対象]")
let mixed = [line("ST-001", 2), CartLine(product: noStock, qty: 100), CartLine(product: adhoc, qty: 5)]
for t in stockTargets(mixed, in: products) {
    print("  \(t.line.product.name)  在庫表の位置=\(t.index)  現在値=\(t.current)")
}
```

## まとめ: 壊したところと、直したところ

2 つの間違えは、それぞれ 1 行を書き換えるだけで直せます。

| | わざと間違う版 | 正しい版 |
| --- | --- | --- |
| 何を見るか | カートに入れた時の `product.stock`（古い） | 在庫表 `inventory` の現在値 |
| 減算のタイミング | 検証しながら 1 行ずつ | 検証が終わってからまとめて |
| 失敗したとき | 途中まで反映されたまま | 何も変わらない |
| 理由の返し方 | 1 件で `return` | 全件集めてから `return` |

3 つの約束を覚えておいてください。

1. **判定と減算は、同じ場所（在庫表）を見る。** 見る場所が違うと、片方だけ直した瞬間に壊れます。
2. **検証が終わるまで、書き換えない。** これが A-4 の「1トランザクション」を、配列で表したものです。
3. **対象かどうかの判定は 1 か所に書く。** 検証と減算で二重に書かない。

3 つ目がないと、「検証は通ったけど減算しなかった」という、わざと間違う① とよく似たバグが戻ってきます。

| --- | --- | --- |

## つながるレッスン

- **中断・商品取消では減算しない**: `completeSale` を**呼ばない**だけで守れます（`03_レッスン.md` レッスン6、`12_会計を完了させる.md`）。
- **完成した販売を取り消すとき在庫を戻す**: `18_販売を取り消す.md`（`stock_movements` に `void` として `+qty`）。
- **棚卸しで在庫を直す**: `22_在庫を手動調整する.md`（`adjust`）。A-9 の「sats受領済みで中断した会計」は在庫がまだ減っていないので、戻しません。
- **同じ考え方を別のレッスンで使う**: CSV取り込み（`13_商品マスタCSVを取り込む.md` 小問4）も「1 行でもエラーなら全部を入れない」という同じ形です。
- **`inout` を使わず、新しい配列を返す書き方**でも結果は同じです。失敗時に元が残るので、巻き戻しが要らなくなります（`57_総合問題1_ロジックを1本にまとめる.md` 57-5）。
- あと、動かして確かめたくなったら `59_テストを書く.md`（59-1）に同じ検証が `#expect` で書かれてあります。
