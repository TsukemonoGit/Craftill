# 38. 日時をISO8601にする

元: `../siyou.md` A-8, A-13
`../siyou.md` A-19-5（日時の持ち方と「日」の境界）、A-19-4（採番規則）

日時は **ISO 8601（タイムゾーン付き）** で保存します（`../開発/6_データベース.md` の
`at` / `updated_at` / `completed_at` / `imported_at`）。

**変換関数を書かなくていい。** `base/2_型定義.md` に `jsonEncoder` / `jsonDecoder` があります（A-19-5）。

| 層 | 持ち方 | 誰が担当 |
| --- | --- | --- |
| 端末内DB（SQLite） | **`TEXT`**（ISO 8601・タイムゾーン付き） | `47_SQLiteで在庫を保存する.md` |
| **Swift の構造体** | **`Date`** | ここ |
| JSON の境界（保存・送信） | `Date` を ISO 8601 文字列へ変換 | **`jsonEncoder`（`base/2`）** |

**このレッスンは「3 つの層を混ぜない」「『日』の境界は別物」を見るレッスンです。**

## わざと間違う①: 保存形式を 2 つ作る

```swift NG
// わざと間違う版①：日本語日本時間を焼き付けた保存形式を別に作る
func forStorage(_ date: Date) -> String {
    let f = ISO8601DateFormatter()
    f.formatOptions = [.withInternetDateTime]
    f.timeZone = TimeZone(secondsFromGMT: 9 * 3600)      // ★ 日本時間固定
    return f.string(from: date)
}
```

**ちゃんと動きます。** ただ `jsonEncoder`（`.iso8601`）と**別の形式**になります。

| | `forStorage` | `jsonEncoder` |
| --- | --- | --- |
| 出力 | `2026-10-13T10:00:00+09:00` | `2023-11-14T22:13:20Z` |
| オフセット | **+09:00 に固定** | UTC（`Z`） |

**何が壊れるか**

1. **保存先ごとに offset が変わる**。CSV は `+09:00`、JSON は `Z`。
   両方を扱うツール（`39_価格一覧CSVを出力する` / `40_販売記録を書き出す`）で**混ぜ，有的是んだずれる**
2. **往復が壊れる**。`jsonEncoder` で読んだ `Date` を `forStorage` で書くと、
   **読み書きで別の瞬間を指す**ことがある
3. **どれが正か分からない**。「保存形式は1本」という A-19-5 の決定が**実装で破られる**

**正**: `jsonEncoder` / `jsonDecoder` **だけ**を使う（A-19-5）。

```swift 断片
// base/2 の正
let jsonEncoder: JSONEncoder = {
    let e = JSONEncoder()
    e.dateEncodingStrategy = .iso8601      // ★ これが「ISO 8601・タイムゾーン付き」の全部
    return e
}()

let jsonDecoder: JSONDecoder = {
    let d = JSONDecoder()
    d.dateDecodingStrategy = .iso8601
    return d
}()
```

> **`Codable` を持つ型は、`Date` の刑事を 1 つ書けば全部変換されます。**
> `Sale` も `SaleItem` も `StockMovement` も `at` / `completed_at` を自分で変換しません。

## わざと間違う②: `productID` と `reason: String`

```swift NG
// わざと間違う版②：ローカルで型を作り直す
struct StockMovement {
    let id: String
    let productID: String          // ★ base は productId
    let delta: Int
    let reason: String             // ★ base は MovementReason（enum）
    let at: Date
}
```

| # | 問題 | 违反 |
| --- | --- | --- |
| 1 | `productID` は Swift の命名規約に反る | 後述 |
| 2 | `reason: String` にすると **`.sale` が書けない** | A-13 の値域、P6 |
| 3 | `"SALE"` や `"Sale"` を**気づかないまま通す** | — |
| 4 | `switch` の**網羅性が保証されない**（`reason` に値が増えても気づけない） | A-13 |

**命名の見分け方**

| 命名 | 意味 | 例 |
| --- | --- | --- |
| `productId` | **Id**entity（同一性） | `productId` / `saleId` / `typeId` |
| `productID` | **ID**entifier の略に見える | `URL` など**フレームワーク名**だけ |

**後ろに来る名前が名詞なら、`Id`**。`ID` はその後ろの名詞です。

## わざと間違う③: 「日」の境界を UTC で切る

```swift NG
// わざと間違う版③：UTC の日付で「今日」を決める
func isToday(_ date: Date) -> Bool {
    var cal = Calendar(identifier: .gregorian)
    cal.timeZone = TimeZone(secondsFromGMT: 0)         // ★ UTC で切る
    return cal.isDate(date, inSameDayAs: Date())
}
```

**これが A-19-5 が明確に禁じているやつ**です。

> **日次集計の「日」は端末のローカル日付で区切る。**
> UTC の日付で切ると、**0時30分の会計が前日の売上に含まれてしまう**。

| 端末の時刻 | 実際の日付 | UTC の日付 | どちらの集計に入れる？ |
| --- | --- | --- | --- |
| 11/15 00:30（日本） | 11/15 | **11/14** | **11/15**（当日） |

**`DayKey`（`base/2`）は最初からローカル日付です**。`timeZone` を触る必要がありません。

```swift 断片
// base/2 の正
enum DayKey {
    /// **端末のローカル日付**で「YYYYMMDD」を作る（A-19-5）
    static func string(from date: Date) -> String {
        let c = Calendar.current                   // ★ ローカルのまま触らない
        return String(format: "%04d%02d%02d",
                      c.component(.year, from: date),
                      c.component(.month, from: date),
                      c.component(.day, from: date))
    }
    static func isSameDay(_ a: Date, _ b: Date) -> Bool {
        string(from: a) == string(from: b)
    }
}
```

> **`Date` の「保存」と「日」の切り分けは別の話**。
> 保存は ISO 8601（A-19-5 の表）、切り分けは `DayKey`。
> **`DayKey.string` は `at` の保存形式ではない**ことに注意してください。

## 1. `DayKey` は販売IDの採番にも使う（A-19-4 ＋ A-19-5）

販売ID `S-YYYYMMDD-NNN` の `YYYYMMDD` は **`DayKey.string`** と同じ作りです。

```swift 断片
// base/2 の正
mutating func nextSaleID(at date: Date) -> String {
    let day = DayKey.string(from: date)           // ★ ローカル日付
    let n = (saleCounters[day] ?? 0) + 1
    saleCounters[day] = n
    return "S-\(day)-\(pad(n, 3))"
}
```

**販売IDの「日付部分」もローカル日付**です。
UTC だと **0時30分の会計の `sale_id` が前日の番号**になります。

## 2. 通しの確認

下のコードを、**土台（`base/Types.swift` の型 ＋ `jsonEncoder` / `jsonDecoder` / `DayKey`）
の下に続けて置いて**、`swift` で動かします。

```swift
// ════════ 通しの確認（日時・A-8 / A-13 / A-19-5）════════

func p38(_ s: String) { print("  " + s) }

struct AtRaw: Codable { let at: String }

let movement38 = StockMovement(
    id: "M-000001", productId: "ST-001", delta: -2, reason: .sale,
    saleId: "S-20231115-001", at: Date(timeIntervalSince1970: 1_700_000_000))

print("【1】保存形式は1つだけ（A-19-5）")
// ★ JSON 全文は出さない。キー順が保証されないので「期待される出力」に書けない
let data38 = try! jsonEncoder.encode(movement38)
let json38 = String(data: data38, encoding: .utf8)!
let atRaw38 = (try! jsonDecoder.decode(AtRaw.self, from: data38)).at
p38("at の値だけ取り出す: " + atRaw38)
p38("ISO 8601・タイムゾーン付き: " + String(json38.contains("T") && (json38.contains("Z") || json38.contains("+"))))
p38("JSON のキー順は保証されない → 全文を比較に使わない")

print("【2】往復しても同じ時刻（Date → 文字列 → Date）")
let back38 = try! jsonDecoder.decode(StockMovement.self, from: data38)
p38("id=" + back38.id + " delta=" + String(back38.delta) + " reason=" + back38.reason.rawValue)
p38("at が等しい: " + String(back38.at == movement38.at))
p38("±0秒: " + String(abs(back38.at.timeIntervalSince(movement38.at)) < 0.001))

print("【3】Date なら比較・並べ替えができる（文字列では無理）")
let later38 = movement38.at.addingTimeInterval(3600)
p38("あとの日時が新しい: " + String(later38 > movement38.at))
let a38 = String(data: try! jsonEncoder.encode(movement38.at), encoding: .utf8)!
let b38 = String(data: try! jsonEncoder.encode(later38), encoding: .utf8)!
p38("日時だけを文字列に: " + a38 + "  " + b38)
p38("ISO 8601 は辞書順と時刻順が一致する: " + String(b38 > a38))
p38("★ 同じデータでも2回でキー順が変わることがある")
p38("  なので「期待される出力」には JSON 全文を書かない")

print("【4】読めない形式は decoding が失敗する")
struct Bad38: Codable { let at: Date }
let bad38 = Data(#"{"at":"2026/10/13"}"#.utf8)
let readOK38 = (try? jsonDecoder.decode(Bad38.self, from: bad38)) != nil
p38("\"2026/10/13\" を読めたか: " + String(readOK38) + "（false = 拒否した）")

print("【5】「日」の境界は端末のローカル日付（A-19-5 / DayKey）")
let d38 = Date(timeIntervalSince1970: 1_700_000_000)
let sameDay38 = d38.addingTimeInterval(3600)            // 1時間後
let nextDay38 = d38.addingTimeInterval(86400 * 2)       // 2日後
p38("同じ日? " + String(DayKey.isSameDay(d38, sameDay38)) + "（" + DayKey.string(from: d38) + "）")
p38("次の日? " + String(DayKey.isSameDay(d38, nextDay38)) + "（" + DayKey.string(from: nextDay38) + "）")
p38("`DayKey.string` は「日」だけ。日時としては `jsonEncoder` に任せる")

print("【6】販売IDの採番にもローカル日付を使う（A-19-4 / A-19-5）")
var ids38 = IdSequencer()
p38(ids38.nextSaleID(at: d38))
p38(ids38.nextSaleID(at: d38))
p38(ids38.nextSaleID(at: d38.addingTimeInterval(86400 * 2)))
p38("日付が変わるごとに 001 に戻る（A-19-4）")

print("【7】時刻の正は1本（ISO 8601）")
p38("`jsonEncoder` の dateEncodingStrategy は `.iso8601` だけ（base/2）")
p38("日本時間固定の `forStorage` を別に作らない。offset が1つでも違うと往復が壊れる")
```

## できた合図

- **`StockMovement` を `jsonEncoder` で書くと `at` が ISO 8601・タイムゾーン付き**になる
- **`jsonDecoder` で読めば `Date` に戻る**。`at == at` が `true`
- **読めない形式（`2026/10/13`）は decode が失敗する**（`try?` で `nil`）
- **`Date` なら `<` / `>` で比較できる**。ISO 8601 文字列も辞書順と時刻順が一致する
- **同じデータを2回シリアライズするとキー順が変わることがある**。
  **だから「期待される出力」には JSON 全文を書かない**
- **`DayKey.string` はローカル日付**。0時30分の会計も当日に入る（A-19-5）

## ポイント

- **Swift の構造体では `Date`**。SQLite の `TEXT` は**保存するときだけ**（A-19-5）
- **`jsonEncoder` / `jsonDecoder` だけを使う**。日本語日本時間を焼き付けた `forStorage` を**別に作らない**
- **`productId` / `saleId`**。`productID` / `saleID` ではない
- **`reason` は `MovementReason`（enum）**。`String` にしない（A-13、P6）
- **「日」は端末のローカル日付**（`DayKey`）。**UTC で切らない**（A-19-5）
- **JSON のキー順は保証されない**。**期待される出力に JSON 全文を書かない**
- **往復テスト（`Date` → JSON → `Date`）を必ず1回やる**
- **販売IDの `YYYYMMDD` もローカル日付**（A-19-4 ＋ A-19-5）
