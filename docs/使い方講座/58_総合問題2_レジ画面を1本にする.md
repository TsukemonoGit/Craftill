# 総合演習2: レジ画面を1本にする【大問】

元: `../siyou.md` A-3, A-4, A-5, A-6-1, A-7
`../siyou.md` A-19-2（中断）、A-19-4（採番）、A-19-7（集計）、A-19-9 #9（遷移はUIで書かない）
受け入れテスト C-6 #23・#33・#49・#50・#51・#77・#78・#81

SwiftUI で、**レジ画面1枚**に次を統合します。

- **商品パネル**（タップで追加。SOLD OUT は押せない）
- **カート**（数量の＋／−・削除・**合計2行**）
- **支払方法選択**（現金／sats払い）
- **現金会計**（受取額を数字キーで入力 → お釣り）
- **中断**（A-19-2）

**このレッスンは「どれを `base/` の関数に渡すか」だけのレッスンです。**
型・ルール・遷移はすべて `base/` にあります。**ここに同じものを書き直さないでください。**

| 画面の動き | 渡す先 |
| --- | --- |
| 商品をタップ | `add` / `addCheck` / `isSoldOut`（`base/5` §1） |
| ＋／− | `increase` / `decrease`（`base/5` §3・§4） |
| 削除の確認 | `remove` → `performDelete`（`base/5` §5・§6） |
| 合計の2行 | `totalLines`（`base/3` §1）＋ `cart.totals()`（`base/2`） |
| ボタン / 方法選択 / 確定 / 中断 | `move(_:in:)`（`base/6` §4）＋ `apply`（`base/6` §6） |
| 確定 after | `commitSale`（`base/3` §4） |
| 中断 after | `suspendSale`（`base/3` §5-1） |

## わざと間違う①: `Product` に `stockMode` を持たせる

```swift NG
// わざと間違う版①：Product が自分の種類も持つ
struct Product: Identifiable {
    let id: String
    let typeId: String
    let stock: Int?
    let stockMode: StockMode          // ★ 種類が持つべきもの（A-19-9）
}
```

**`stockMode` の持ち主は `ProductType`** です（A-1 の表は「種類」の性質）。

| | `Product.stockMode` | `ProductType.stockMode` |
| --- | --- | --- |
| Reality と食い違うか | **なりうる** | なりえない |
| 検出しやすさ | どこかが `StockMode.unique` を `counted` にしていたら**永久に找不到** | 1か所なので**1行で直る** |

**検出しやすさ**が決め手です。**同じ値を2か所に持つと、片方の間違いはもう片方から検証できません。**

**正**: `p.stockMode(in: types)`（`base/2`）か、`addCheck` に `types` を渡す（`base/5` §1）。

## わざと間違う②: `state` を UI が直接書く

```swift NG
// わざと間違う版②：ボタンが状態を直接代入する
func goToPayment() { if !cart.isEmpty { state = .choosingPayment } }
func chooseCash()  { payBySats = false; receivedJpy = 0; state = .cashInput }
func chooseSats()  {
    payBySats = true; receivedJpy = 0
    if totals.cashForSats == 0 { complete() }   // ★ 遷移表を見ずに分岐する
    else { state = .cashInput }
}
```

**破綻は4つあります。**

| # | 破綻 | 違反 |
| --- | --- | --- |
| 1 | **sats単価の行が1つも無い**のに sats 払いできてしまう | A-4、base/6 §4 `move` |
| 2 | `choosingPayment` で商品を足せてしまう | A-4 の表、`move` の `rejected` |
| 3 | `cashInput` で**方法を選び直せる**（A-19-8 では **2段**に分ける） | A-19-8 |
| 4 | **完了 `.done` からも中断できてしまう** | A-4 の表、`move` の `rejected` |

**`if` を並べた的不是状態機械です。** A-4 の遷移図をそのまま **`switch` の表**に翻訳したものが
`base/6` §4 の `move` です（`56_会計の状態を切り替える.md`）。

## わざと間違う③: 完了が販売記録を作らない

```swift NG
// わざと間違う版③：完了は在庫を減らすだけ
private func complete() -> [String] {
    let targets = stockTargets()
    for t in targets where t.line.qty > t.current {
        problems.append("在庫不足: \(t.line.name)（在庫 \(t.current)、必要 \(t.line.qty)）")
    }
    guard problems.isEmpty else { return problems }
    for t in targets { products[t.index].stock = t.current - t.line.qty }   // ★ 在庫だけ減る
    state = .done
    return []
}
```

**在庫検証と減算そのものは正しい**です。
**足りないのが 2 つ**あります。

| # | 足りないもの | 違反 |
| --- | --- | --- |
| 1 | **販売記録（`sales` / `sale_items`）が作られない** | A-4、A-8 |
| 2 | **`stock_movements` に記録が残らない**（ Appended ログが無い） | A-7、A-19-1 |

**破綻 1 が致命**です。売上集計（`17_集計する.md`）も、
CSV 取り込み・エクスポート（`40_販売記録を書き出す.md`）も、
**すべて `sales` を見ています**。`sales` が空なら、その日の売上は **0円**です。

**正**は `commitSale`（`base/3` §4）です。A-4 の4手順を1本にまとめてあります。

```
① checkStock（1件でも失敗したら以降を全部飛ばす）
② buildSale（**検証が通ってから**販売IDを採番する・A-19-4）
③ completeSale（在庫減算）
④ StockMovement（+ のログ）
```

## わざと間違う④: ＋／− が確認を経ない

```swift NG
// わざと間違う版④：0以下になったら即削除
func changeQty(_ id: String, by delta: Int) {
    guard let i = cart.firstIndex(where: { $0.id == id }) else { return }
    let next = cart[i].qty + delta
    if next <= 0 { cart.remove(at: i) }        // ★ 確認ダイアログを経ない（C-6 #49）
    else { cart[i].qty = next }                // ★ 在庫を見ていない（A-1）
}
```

C-6 #49・#50 は「**数量が0になる操作は確認ダイアログを経る**」「**0にならない増減では出さない**」
の両方を要求します。`remove` と `decrease` がその2つを実装済みです（`base/5` §4・§5）。

## 1. 正: `RegisterCore`（画面から触らないデータ）

`@Observable` を付ける前の、**ロジックだけ**の型です。
画面はこの `struct` の**メソッドだけ**を呼びます（A-19-9 #9）。

```swift
/// レジ画面が持つデータ。**画面（View）は `ctx.state` を直接書かない**（A-19-9 #9）
struct RegisterCore {
    var ctx = SaleContext()               // 会計の状態・カート（A-4）
    var types: [ProductType]
    var inventory: [Product]
    var sales: [Sale] = []
    var items: [SaleItem] = []
    var movements: [StockMovement] = []
    var ids = IdSequencer()

    var receivedJpy = 0                   // 現金入力中のお金（A-5）
    var message = ""                      // rejected の理由（A-19-9 #9）
    var pending: Move? = nil              // needsConfirm / needsPIN のときだけ入る
    var pendingEvent: SaleEvent? = nil    // どのボタンが要求したか（承認の判定に使う）
    var needPIN = false

    /// `.done` / `.suspended` になった瞬間に使う値。**状態を移す前に決めておく**
    private var payMethod: PaymentMethod = .cash
    private var receivedAtCommit: Int? = nil

    // ── A-1 の追加ルールは base/5 §1 に任せる ──
    mutating func tapAdd(_ p: Product) -> CartEdit {
        guard let i = inventory.firstIndex(where: { $0.id == p.id }) else {
            return .rejected("商品がありません")
        }
        return add(product: inventory[i], qty: 1, cart: &ctx.cart,
                   inventory: inventory, types: types)
    }

    // ── A-3 の編集は base/5 §3〜§6 に任せる ──
    mutating func changeQty(_ i: Int, by delta: Int) -> CartEdit {
        let r = delta > 0
            ? increase(at: i, cart: &ctx.cart, inventory: inventory, types: types)
            : decrease(at: i, cart: &ctx.cart, inventory: inventory, types: types)
        if case .rejected(let m) = r { message = m }
        return r
    }

    /// ダイアログで「はい」を押したときの適用（A-19-9 #9）
    mutating func confirmPending(satsConfirmedAt: Date? = nil) {
        guard let m = pending else { return }
        let e = pendingEvent
        pending = nil
        pendingEvent = nil
        needPIN = false
        guard beforeApply(m) else { return }
        apply(m, to: &ctx)
        // 済ボタン承認時だけ、請求sats額を確定させる（C-6 #78、base/6 §6）
        if e == .tapDone, let t = satsConfirmedAt { markSatsConfirmed(&ctx, at: t) }
        afterApply()
    }

    /// ダイアログを閉じただけ。**何も変えない**（A-3）
    mutating func cancelPending() {
        pending = nil
        pendingEvent = nil
        needPIN = false
        message = "何もしませんでした"
    }

    /// すべてのボタンはここを通る。**`ctx.state` を UI からは書かない**（A-19-9 #9）
    @discardableResult
    mutating func send(_ e: SaleEvent, now: Date) -> Move {
        let m = move(e, in: ctx)
        switch m {
        case .allowed:
            message = ""
            pending = nil
            pendingEvent = nil
            guard beforeApply(m) else { return m }
            apply(m, to: &ctx)
            afterApply()
        case .needsConfirm(_, _): pending = m; pendingEvent = e   // 出る＝確認が要る時だけ
        case .needsPIN(_, _):     pending = m; pendingEvent = e; needPIN = true
        case .rejected(let why):  message = why
        }
        return m
    }

    /// ① 状態を移す**前**に在庫検証と受取方法の確定（A-4 の4手順の1番目）
    private mutating func beforeApply(_ m: Move) -> Bool {
        guard let to = m.nextState else { return false }

        if to == .done {
            // ★ A-4 の4手順の1番目。**状態を移す前に**検証する
            let problems = checkStock(ctx.cart, inventory: inventory, types: types)
            guard problems.isEmpty else {
                message = problems.joined(separator: " / ")   // ← ctx を1行も触らない
                return false
            }
            receivedAtCommit = receivedJpy == 0 ? nil : receivedJpy
        }
        // ★ `.done` / `.suspended` では `ctx.method` が nil になるので、**今のうちに**控えておく
        payMethod = ctx.method ?? .cash
        return true
    }

    /// ② `.done` / `.suspended` / `.idle` になったときの副作用
    private mutating func afterApply() {
        if ctx.state == .done { finishCommit() }        // 完了画面（cart と受取額は残す）
        if ctx.state == .suspended { finishSuspend() }  // 中断画面
        if ctx.state == .idle {                          // 待機中へ戻ったときの後片付け
            ctx.cart = []
            receivedJpy = 0
        }
    }

    /// 販売記録・在庫減算・在庫変動ログ（A-4 の4手順 2〜4）
    private mutating func finishCommit() {
        let r = commitSale(cart: ctx.cart, inventory: &inventory, movements: &movements,
                           sales: &sales, items: &items, ids: &ids, types: types,
                           chooseSats: payMethod != .cash,
                           receivedJpy: receivedAtCommit, confirmedAt: nil,
                           now: Date(timeIntervalSince1970: 1_700_000_600))
        switch r {
        case .success(let sale, _, _):
            print("    → \(sale.id) / \(sale.method.rawValue) / 受取 \(sale.receivedJpy.map(String.init) ?? "nil")円")
        case .failure(let why):
            message = why.joined(separator: " / ")
        }
    }

    /// 中断：A-19-2「sats 確認済みなら記録に残す」
    private mutating func finishSuspend() {
        let r = suspendSale(cart: ctx.cart, ids: &ids, correctPIN: "1234", pin: "1234",
                            sales: &sales, items: &items,
                            chooseSats: payMethod != .cash,
                            confirmedAt: ctx.satsConfirmedAt,   // ★ ここで記録に残すか決まる（A-19-2）
                            now: Date(timeIntervalSince1970: 1_700_000_700))
        if case .success(let recorded, _) = r, let s = recorded {
            print("    → 記録に残した \(s.id)（status=\(s.status.rawValue) completedAt=nil）")
        } else {
            print("    → 記録に残さない（sats 未確認の中断・A-19-2）")
        }
    }
}
```

### この 3 段itta構成が要点です

```
send(_:)  ─┬─ move(_:in:)        遷移表を見るだけ（A-4）
           ├─ beforeApply(_:)    ★ 在庫検証 → 失敗なら ctx を1行も触らない
           ├─ apply(_:to:)       状態を移すだけ（base/6 §6）
           └─ afterApply()       ★ .done なら commitSale / .suspended なら suspendSale
```

- **`beforeApply` が `apply` より前**、`afterApply`（副作用）は `apply` の**あと**
- **`ctx.method` は `.done` になると `nil`**（`base/6` §7）。なので**移す前に控えておく**
- **`confirmedAt: ctx.satsConfirmedAt`** が、A-19-2 の「記録に残す／残さない」の**唯一の判定**（A-19-3）

## 2. 画面（View）

`@Observable` を付けた store と、4つのペインです。**ロジックは §1 に全部あります。**

```swiftui
import SwiftUI
import Observation

@Observable
final class RegisterStore {
    var core: RegisterCore
    init(core: RegisterCore) { self.core = core }

    // 画面が読むだけ。**書かない**（A-19-9 #9）
    var state: SaleState { core.ctx.state }
    var cart: [CartLine] { core.ctx.cart }
    var inventory: [Product] { core.inventory }
    var message: String { core.message }

    var total: (satsLine: String, cashLine: String) { totalLines(core.ctx.cart) }   // base/3 §1
    var dueJpy: Int { core.ctx.cashDueJpy }                                        // base/6 §7

    // ボタンはここだけ
    func tap(_ p: Product) { _ = core.tapAdd(p) }
    func tapPlus(_ i: Int) { _ = core.changeQty(i, by: +1) }
    func tapMinus(_ i: Int) { _ = core.changeQty(i, by: -1) }
    func tapDelete(_ i: Int) { _ = core.remove(at: i, cart: core.ctx.cart) }
    func send(_ e: SaleEvent) { _ = core.send(e, now: Date()) }
    func confirmOK() { core.confirmPending(satsConfirmedAt: Date()) }
    func confirmCancel() { core.cancelPending() }
    func pressDigit(_ d: Int) { core.receivedJpy = core.receivedJpy * 10 + d }
    func backspace() { core.receivedJpy /= 10 }

}
```

## 動かし方とできた合図

1. Xcode でアプリを新規作成し、土台（`base/`）を1ファイルに、§1・§2 を順に貼る（`@main` は1つだけ）
2. Run（⌘R）

**できた合図**:

- 左に商品パネル、右にカートと操作エリアが出る
- 商品を3つクリックすると、カートに行が並び、下に**合計2行**が出る
  - 例: KH-001×1 ＋ ST-001×2 ＋ TB-001×1 →
    ```
    sats払い　2200sats ＋ 1000円
    現金　　　2400円
    ```
- 一点物（KH-001）を2回クリックしても増えない。在庫0になった商品は **SOLD OUT** で押せない
- **在庫管理なし型は SOLD OUT にならない**（A-1、B-1）
- 「−」で0になりそうなときは**削除の確認ダイアログ**が出て、**「キャンセル」なら行が残る**
- 「会計へ進む」→「現金」→ 数字キーで受取額を入れると**お釣り**が出る
- 確定すると**販売記録が1件でき、`KH-001` は SOLD OUT になる**
- 「中断」は**確認ダイアログ**が出て、`sats` 未確認なら**記録に残らない**（A-19-2）
- 在庫不足のときは `move` の返り値は `allowed(done)` でも、**実際の状態は `cashInput` のまま**で、
  在庫も販売記録も変わらない（A-4）

## ポイント

- **`Product` に `stockMode` を持たせない**。**種類が持つ**（A-1、A-19-9）
- **`state` を UI が書かない**。`move(_:in:)` → `apply(_:to:)`（A-19-9 #9）
- **`SaleState` は 7 値**。`.suspended` / `.satsWaiting` / `.mixedCashInput` を落とさない（A-4）
- **`switch` を並べたのは状態機械じゃない**。A-4 の遷移図が `move` です
- **完了は `commitSale`**。販売記録・在庫減算・変動ログの**4手順**（A-4、A-7）
- **検証 → 状態 → 副作用** の順。`beforeApply` が `apply` より前（`16_現金の会計画面.md` と同じ）
- **`ctx.method` は `.done` で `nil`**。移す**前**に控えておく（`base/6` §7）
- **`confirmedAt: ctx.satsConfirmedAt`** が中断の記録を分ける**唯一の判定**（A-19-2、A-19-3）
- **＋／−／削除は `base/5`**。確認ダイアログは `CartEdit` の3つの返り値が持つ
- **`needsConfirm` のときは1行も変えていない**。キャンセルしてもそのまま（C-6 #49・#50）
- **合計は `totalLines` / `totals`**。画面は `payBySats` のような真偽値を持たない（`base/6` §7）
- **完了したら `SaleContextStore.clear()`**（A-3）
