# 非同期処理を書く（async / await / Task）

元: `../siyou.md` A-14

**非同期処理**＝「時間のかかる処理を、待っている間に画面を止めずに進める」書き方です。
ここでは、レジで組み立てた**公開用スナップショット**を、公開サイト（B）へ `HTTPS POST` で送る処理を作ります（A-14）。

送信は通信を伴うので、**失敗する可能性**があります。だから「成功したとき」と「失敗したとき（通信エラー）」を**分けて**扱います。

学ぶこと:

- `async` / `await` … 時間のかかる処理を「待つ」
- `Task { }` … 非同期処理を始める
- `try await` … 失敗するかもしれない処理を待つ
- `@MainActor` … 画面に関わる値はメイン（画面用）で書き換える
- 並行処理の基本 … 送信を裏で走らせて、レジ操作を止めない

> スナップショットを**組み立てる**のは純ロジックですが、**実際に送る（HTTPS）**は **アプリ（App）** の役目です。このファイルはアプリとして新規作成し、そのまま貼れば動きます。
> **Svelteとの対比**: `async` / `await` は JavaScript と**ほぼ同じ**です。`Task { }` は「`await` せずに裏で走らせる」イメージ（JSで `fn()` を `await` せず呼ぶのに近い）。

## Bへ送る形（スナップショット）

```swift
struct SnapshotType: Codable {
    let typeId: String
    let name: String
    let stockMode: String
    let attrLabels: [String]
}

struct SnapshotProduct: Codable {
    let productId: String
    let typeId: String
    let name: String
    let priceJpy: Int
    let priceSats: Int?
    let attrs: [String]
    let stock: Int?          // 在庫管理なし型は空（nil）
    let hasImage: Bool       // 画像の有無（imageRef の有無から導出）
}

struct Snapshot: Codable {
    let createdAt: String
    let types: [SnapshotType]
    let products: [SnapshotProduct]
}

/// 公開対象（is_public）の登録商品だけでスナップショットを組み立てる（A-14）。
func makeSnapshot(products: [Product],
                  types: [ProductType],
                  createdAt: String) -> Snapshot {
    let publicProducts = products.filter { $0.isPublic }
    let usedTypeIDs = Set(publicProducts.map { $0.typeId })

    let snapshotTypes = types.filter { usedTypeIDs.contains($0.typeId) }.map { t in
        SnapshotType(typeId: t.typeId, name: t.name,
                     stockMode: t.stockMode.rawValue, attrLabels: t.attrLabels)
    }

    let snapshotProducts = publicProducts.map { p -> SnapshotProduct in
        let attrs = [p.attr1, p.attr2].compactMap { $0 }
        let isNone = types.first { $0.typeId == p.typeId }?.stockMode == .none
        return SnapshotProduct(
            productId: p.id, typeId: p.typeId, name: p.name,
            priceJpy: p.priceJpy, priceSats: p.priceSats,
            attrs: attrs,
            stock: isNone ? nil : p.stock,   // 在庫管理なし型は空
            hasImage: p.imageRef != nil)      // 画像の有無を導出
    }
    return Snapshot(createdAt: createdAt, types: snapshotTypes, products: snapshotProducts)
}

/// スナップショットを JSON データ（送る中身）にする。
func snapshotJSON(_ snapshot: Snapshot) throws -> Data {
    let encoder = JSONEncoder()
    encoder.keyEncodingStrategy = .convertToSnakeCase   // productId → product_id
    return try encoder.encode(snapshot)
}
```

let writeSecret = "WRITE-ONLY-SECRET"

enum SendError: Error {
    case badStatus(Int)   // サーバが 2xx 以外を返した
}

## 1. 送る（async / try await）

`async` を付けた関数は「時間がかかる」印です。中で `await` を使えます。失敗する可能性があるので、`try await` で待ちます。

```swift
/// スナップショットを HTTPS POST で送る（A-14）。
/// - Parameters:
///   - json: 送る JSON データ
///   - url: 送信先
///   - secret: 書き込み専用のシークレット
func sendSnapshot(_ json: Data, to url: URL, secret: String) async throws {
    var request = URLRequest(url: url)
    request.httpMethod = "POST"
    request.setValue("application/json", forHTTPHeaderField: "Content-Type")
    request.setValue(secret, forHTTPHeaderField: "Authorization")  // 認証
    request.httpBody = json

    // ここで「通信の終わり」を待つ。待っている間、画面は止まらない
    let (_, response) = try await URLSession.shared.data(for: request)

    guard let http = response as? HTTPURLResponse else {
        throw SendError.badStatus(-1)
    }
    guard (200..<300).contains(http.statusCode) else {
        throw SendError.badStatus(http.statusCode)   // 2xx以外は失敗
    }
    // ここまで来れば成功
}
```

- `async` … 「この関数は待つことがある」という印。
- `throws` … 「失敗して途中で抜けることがある」という印。
- `try await ...data(for:)` … 通信を投げて、結果が返るまで待つ。通信エラーならここで `throw` される。
- `HTTPURLResponse` … 返ってきた「返事」。`statusCode` が `200〜299` なら成功。

## 2. 結果を成功・失敗で分ける

```swift
enum SendResult {
    case success
    case failure(String)
}

func describe(_ r: SendResult) -> String {
    switch r {
    case .success:          return "公開サイトへ送信しました"
    case .failure(let why): return "送信に失敗: \(why)"
    }
}
```

## 3. 画面から呼ぶ（`.task { }` と `@MainActor`）

画面（SwiftUI）から非同期処理を呼びます。画面が出たら `.task { }` が1回走ります。ボタンからは `Task { }` で始めます。
**画面に関わる値を書き換える関数には `@MainActor`** を付けます（ここで `status` を変えるため）。

```swift
struct SendView: View {
    @State private var status = "未送信"
    @State private var sending = false

    var body: some View {
        VStack(spacing: 16) {
            Text("公開サイトへ送信").font(.headline)
            Text(status).foregroundStyle(.secondary)          // 成功／失敗を表示
            Button("いま送信する") {
                Task { await send() }                          // 非同期処理を始める
            }
            .disabled(sending)                                 // 送信中は押せない
        }
        .padding()
        .frame(width: 380, height: 200)
        .task { await send() }                                 // 画面が出たら1回、自動送信
    }

    /// スナップショットを作って送る。結果を status に反映する。
    @MainActor
    private func send() async {
        sending = true
        defer { sending = false }        // 成功・失敗どちらでも最後に戻す

        do {
            let snapshot = makeSnapshot(products: products, types: productTypes,
                                        createdAt: "2026-10-13T12:00:00+09:00")
            let json = try snapshotJSON(snapshot)
            try await sendSnapshot(json, to: endpoint, secret: writeSecret)  // 待つ
            status = describe(.success)              // 成功
        } catch {
            status = describe(.failure("\(error)"))  // 失敗（通信エラーなど）
        }
    }
}
```

- `Task { await send() }` … ボタンを押した瞬間に非同期処理を始める。`await` で待つが、待っている間も画面は操作できる。
- `.task { ... }` … 画面が出たときに1回実行される。`onAppear` の非同期版。
- `@MainActor` … 「画面用のスレッドで実行する」印。`@State`（`status`）を安全に書き換えられる。
- `do { ... } catch { ... }` … **成功**と**失敗**を分けて扱う。`catch` に落ちてきた `error` に、通信エラーや `badStatus` が入る。

## 4. やれること: 裏で走らせて邪魔しない（並行処理の基本）

会計の完了後に自動送信するときは、**レジ操作を止めない**ように `Task { }` で裏へ流します。

```swift
/// 送信を「裏で」始める。UI は待たない（A-14 の自動送信）。
func queueSnapshotSend() {
    Task {                                    // await せず、裏で走らせる
        do {
            let snapshot = makeSnapshot(products: products, types: productTypes,
                                        createdAt: "2026-10-13T12:00:00+09:00")
            let json = try snapshotJSON(snapshot)
            try await sendSnapshot(json, to: endpoint, secret: writeSecret)
            print("送信OK")
        } catch {
            // 失敗は sync_log に記録するだけ。会計・在庫には影響しない（A-14）
            print("送信失敗:", error)
        }
    }
}
```

複数の処理を**同時に**進めたいときは `async let` を使います（たとえ：本番と予備の2つの宛先へ同じ物を送る）。

```swift
async let a = sendSnapshot(json, to: endpoint, secret: writeSecret)
async let b = sendSnapshot(json, to: endpoint, secret: writeSecret)
_ = try await (a, b)   // 両方の終わりを待つ
```

## できた合図

- 起動すると `.task` が走り、`status` が **送信しました** か **送信に失敗: ...** のどちらかになる
- 「いま送信する」を押すと、また送信が走る（送信中は押せない）
- 通信を切っておくと、`catch` に落ちて **送信に失敗: ...** と出る（成功と失敗が分かれている）
- `ST-003` は `price_sats` のキーが JSON に出ない。`KH-020`（非公開）は送信対象に入らない

---

## ポイント

- `async` は「待つことがある」、`await` は「ここで待つ」、`Task { }` は「始める」。
- 失敗する可能性のある待ちは `try await`。`do / catch` で**成功と失敗を分けて**扱う。
- 通信の本体は `URLSession.shared.data(for:)`。`HTTPURLResponse` の `statusCode` が `200〜299` なら成功。
- 画面の値を変える関数には `@MainActor` を付ける。
- 画面からは `.task { }`（出たら1回）や `Task { }`（ボタン）で呼ぶ。
- 自動送信は裏で走らせ、**レジ操作を止めない**。送信失敗は `sync_log` に記録するだけで、会計・在庫に影響しない（A-14）。
- 全商品を毎回送る方式なので、再試行・順序管理は不要（A-14）。
