## わざと間違う①: `voided` を 1 つの枠にまとめる

A-8 はこう書いています。

> sats受領済みで中断した会計（A-4）は、売上に含めず、**件数・sats合計を別に表示**する

`voided` には **2 種類** あります（A-19-3）。

| 状態 | `completed_at` | 在庫を戻す | A-8 では |
| --- | --- | --- | --- |
| `completed` | あり | ― | 売上 |
| `voided`（販売取消・A-9） | **あり** | **戻す** | 売上に含めない（別集計の指定は**無い**） |
| `voided`（sats受領済みの中断・A-4） | **空** | 戻さない | 売上に含めず、**件数とsats合計を別に出す** |

「`voided` なら売上に含めない」で止めると、**販売取消と中断が同じ枠**に入ります。

```swift NG
// わざと間違う版①：voided を 1 つにまとめる
if sale.status == .voided {
    s.voidedSaleIDs.insert(sale.id)      // ★ 販売取消と中断が同じ箱に入る
    s.voidedSats += sale.totalSats ?? 0
    continue
}
```

**何が壊れるか**

- **販売取消の会計**は「売上に含めたこと」「戻した在庫」と一緒に読めます（A-9 で在庫まで戻しています）
- **sats受領済みの中断**の sats 合計を、**売上の sats 合計と並べて見ること**ができます（A-8 の「別に表示」になる）
- C-6 #81 は「**併用会計を含む**日次集計」で、**円成分と sats 成分を混ぜない**ことを要求しています。
  1 つの枠にまとめると、この検証ができなくなります

**直し方**: `completedAt` の有無で分けます（`base/3` §7）。

```swift 断片
// base/3 §7 の該当部分
if sale.status == .voided {
    if sale.completedAt == nil {
        // sats受領済みの中断（A-4）… A-8 の「別」の枠
        s.suspendedSaleIDs.insert(sale.id)
        s.suspendedSats += sale.totalSats ?? 0
    } else {
        // 販売取消（A-9）… 売上に含めないが、別集計の指定は無い
        s.canceledSaleIDs.insert(sale.id)
    }
    continue
}
```

> **`completedAt` 1つで2種類が分かれます。** `voided` を新しい enum に分けなくていい。
> つまり `SaleStatus` は **`completed` / `voided` の2値のまま**です（A-13）。

## わざと間違う②: 値域を `String` で比べる

```swift NG
// わざと間違う版②：String 比較
if sale.method == "cash" || sale.method == "mixed" { ... }
if item.itemType == "registered" { ... }
if item.paidIn == "sats" { ... }
```

**何が壊れるか**

| # | 問題 |
| --- | --- |
| 1 | `"cash "`（空白つき）や `"Cash"` を**気づかないまま**通す |
| 2 | `PaymentMethod` に enum なら `== .cash` と書けて、**取り違えがコンパイルエラーになる** |
| 3 | `switch` の**網羅性が保証されない**。`PaymentMethod` に値が増えても気づけない |

**直し方**: `base/Types.swift` の enum を使います。

```swift 断片
// base/3 §7 の該当部分
switch sale.method {
case .cash, .mixed: s.cashSaleIDs.insert(sale.id); s.cashJpy += sale.totalJpy ?? 0
case .lightning:    break
}
if sale.method == .lightning || sale.method == .mixed { … }
```

## 1. 円と sats を混ぜない（A-6-1）

集計には **3 つ** の金額があります。**合算しません**。

| 変数 | 式 | どこで使う |
| --- | --- | --- |
| `cashJpy` | `Σ sale.totalJpy`（`cash` は全行の円、`mixed` は現金分） | 現金照合（A-8） |
| `satsAmount` | `Σ sale.totalSats`（`lightning`・`mixed`） | sats照合（A-8） |
| `registeredJpy` / `adhocJpy` | 明細の `paidIn == .jpy` だけを **`unitPriceJpy × qty`** で足す | 内訳（A-8） |

**内訳は明細から出します**。会計からだと、野良と登録を分ける情報がありません。

```swift 断片
// base/3 §7 の該当部分
for item in items {
    guard let sale = sales.first(where: { $0.id == item.saleId }),
          sale.status == .completed else { continue }
    guard item.paidIn == .jpy else { continue }     // 円建ての内訳だけ
    let amount = item.unitPriceJpy * item.qty      // ← 販売時点の単価（A-13）
    if item.itemType == .registered { s.registeredJpy += amount }
    else { s.adhocJpy += amount }
}
```

> **`unitPriceJpy`（販売時点）**を使います。いまの商品マスタの `priceJpy` ではありません。
> CSV 取り込みで価格が改定されていたら、答えが変わってしまいます（A-8）。

## 2. 「1日」は `salesOn(_:in:)` で絞る（A-19-11、A-19-5）

`summarize` は期間を切りません。**呼ぶ側が「その日」を選びます**。
選び方に **1つ注意点**があります。

| 種類 | `completedAt` | 使う日付 |
| --- | --- | --- |
| `completed`（売上） | あり | `completed_at` |
| `voided`（販売取消） | あり | `completed_at` |
| `voided`（**sats受領済みの中断**） | **nil** | **`confirmed_at`** |

**`completedAt` だけで絞ると、sats受領済みの中断がどこにも入りません**。
`completedAt` が `nil` だからです（A-4、A-19-3）。

```swift 断片
// base/3 §6-0（A-19-11）
func saleDay(_ sale: Sale) -> Date? {
    sale.completedAt ?? sale.confirmedAt      // ★ 中断は confirmedAt
}

func salesOn(_ day: Date, in sales: [Sale]) -> [Sale] {
    sales.filter { sale in
        guard let d = saleDay(sale) else { return false }
        return DayKey.isSameDay(d, day)       // ★ ローカル日付（A-19-5）
    }
}

// 使う
let todaySales = salesOn(now, in: sales)
let todayItems = items.filter { i in todaySales.contains { $0.id == i.saleId } }
let s = summarize(todaySales, items: todayItems)
```

**「日」の境界は端末のローカル日付**です。UTC で切ると 0時30分の会計が**前日の売上**に入ります。

## ポイント

- **`DailySummary` は `base/3` §7**。書き直さない
- **`voided` は 2 種類**。`completedAt == nil` が **sats受領済みの中断**（A-19-3、A-19-7）
- 販売取消は売上に含めないが、**別集計の指定は無い**。中断だけが「件数とsats合計を別に出す」（A-8）
- 値域は **enum**（`status` / `method` / `paid_in` / `item_type`）
- 件数は**会計単位**。`Set` で二重に数えない。併用は現金と sats の**両方**に計上する
- **内訳は明細から**。`unitPriceJpy × qty`（販売時点の単価・A-13）
- **円と sats は合算しない**（A-6-1）。`suspendedSats` も売上の sats とは別
- **「1日」はローカル日付**。UTC で切ると 0時30分の会計が前日に落ちる（A-19-5）
- 種類別の内訳は **`42_種類別に集計する.md`**。ここには入れない
- 販売数量（`qty`）は今の `DailySummary` に無い。C-6 #73 の置き場所を決める（A-19-9 #1 と同じ方式）
