# 追加レッスン: 会計状態をまるごと保存する

元: `../siyou.md` A-3、A-10、受け入れテスト C-6 #2・#4・#62・#78
`../siyou.md` A-19-2 / A-19-3 / A-19-5
`02_練習メニュー.md` の「19. 会計状態をまるごと保存する」。

会計の途中経過を**まるごと端末に保存**して、**再起動・強制終了・スリープからの復帰**のあとでも
続きから戻れるようにする練習です（A-3）。

このレッスンが扱うのは **保存と復元だけ**です。
**何を保存するか**は `base/6_会計の状態機械.md` の `SaleContext` が決めています。

---

## まず土台をペーストする

1. `base/Types.swift` の**型だけ**
2. `base/6_会計の状態機械.md` の §1〜§3（`Move` / `SaleContext` / `SaleEvent`）、§7（`method` / `cashDueJpy`）、§8（`SaleContextStore`）

> **`SaleSession` のような別の struct を新しく作らないでください。**
> 保存するものは `SaleContext` そのものです（`base/00_README.md` のルール）。

A-3 の「保存するもの」と、`SaleContext` のフィールドを突き合わせます。

| 保存するもの | `SaleContext` のどこ |
| --- | --- |
| カート（商品・数量・野良の明細を含む） | `cart` |
| 会計状態 | `state` |
| **sats入金の確認済み**（確認時刻を含む） | `satsConfirmedAt` |
| **済ボタンで承認した請求sats額** | `confirmedSats` |
| 支払方法（`cash` / `lightning` / `mixed`） | **`method`（導出）** |
| 請求額（現金・sats・現金分） | **`cashDueJpy` と `totals()`（導出）** |

**導出できるものは保存しません。** 「何が保存の対象か」を切り分けるのがこのレッスンの中心です。

---

## わざと間違う①: 請求額をカートとは別に保存する

A-3 の「保存するもの」をそのまま struct にする、という素直すぎる作り方をします。

```swift NG
// わざと間違う版①：請求額と支払方法を、カートとは別に持つ
struct OldSaleSession: Codable, Equatable {
    var state: SaleState
    var cart: [CartLine]
    var paymentMethod: String?          // ★ String。enum ではない
    var cashRequestJpy: Int             // ★ カートとは別の値
    var requestSats: Int
    var cashPartJpy: Int
    var satsConfirmedAt: String?        // ★ String。ISO 8601 を手で持つ
}
```

ちゃんと保存されているので、一見したら正解に見えます。

```
=== わざと間違う①：請求額を別に持つ ===
  カート: Totals(sats: 1000, cashForSats: 400, cash: 1000)
  保存値: 請求額=400 請求sats=1000 現金分=400
  → 一致しているように見える
  カートから野良の行を1行削ったあと:
  カート: Totals(sats: 1000, cashForSats: 0, cash: 600)
  保存値: 請求額=400 請求sats=1000 現金分=400
  ★ 請求額は古いまま。合計と食い違う
  ★ しかも paymentMethod は String なので、誤った値を入れられます
```

**何が壊れているか**

| # | 問題 |
| --- | --- |
| 1 | **同じものが2つある**。カートと請求額は、必ず同じ値とは限らない |
| 2 | `paymentMethod` が `String` なので、`"mixe"` のような誤った値が入りうる |
| 3 | `satsConfirmedAt` が `String` なので、**タイムゾーンの指定が壊れる**と別の時刻として戻る（A-19-5） |

**直し方**: `SaleContext` を**そのまま**保存します。
`method` と `cashDueJpy` は `base/6` §7 のプロパティで**計算できます**。

```swift 断片
// 支払方法は導出できる（保存しない）
var method: PaymentMethod? {
    switch state {
    case .cashInput:      return .cash
    case .satsWaiting:    return cart.totals().cashForSats == 0 ? .lightning : .mixed
    case .mixedCashInput: return .mixed
    case .idle, .scanning, .choosingPayment, .suspended, .done: return nil
    }
}
```

> **「保存した値」と「いま計算した値」がズレない**ので、ズレが生じたときにすぐ気づけます。
> これは C-1 #4「正データが運用端末内のみ」の対策としても効きます。

## わざと間違う②: `confirmedSats` を保存しない

「済ボタンで承認した請求sats額」を別保存しないと、こうなります。

```swift NG
// わざと間違う版②：承認した請求sats額が保存に含まれない
struct NoConfirmedSats: Codable, Equatable {
    var state: SaleState
    var cart: [CartLine]
    var satsConfirmedAt: Date?
}
```

```
=== わざと間違う版②：承認した請求sats額を保存しない ===
  保存できたか: 復元できた（状態=mixedCashInput）
  復元した時の請求sats額 = 1000 sats
  カートが変わったあと = 2500 sats
  ★ 済ボタンで承認した「1000 sats」と一致しない（C-6 #78 に反する）
  ★ 正しい SaleContext なら confirmedSats が残る
     confirmedSats = 1000
     カートが変わっても confirmedSats = 1000
```

**何が壊れているか**

C-6 #78 はこう書いています。

> 併用会計の状態復元：済ボタン承認後（併用現金入力中）に、強制終了・端末再起動・
> スリープ復帰・レジ⇄WoS往復を行うと、併用現金入力中に復元される。
> **sats待ち画面へ戻らず、再度の済ボタン操作を必要としない。
> 復元後の請求額（現金分）・確認済みの請求sats額が変化しない**

`confirmedSats` は「**そのとき確定した**額」です。カートから計算し直すと、
復元後にカートが動けば**確定した額が変わってしまいます**。

| | 導出できる | 保存が要る |
| --- | --- | --- |
| `method` | 状態から決まる | 不要 |
| `cashDueJpy` / `totals()` | カートから決まる | 不要 |
| **`confirmedSats`** | その瞬間の値 | **必要** |
| **`satsConfirmedAt`** | その瞬間の値 | **必要** |

**「その瞬間の値」だけが保存の対象**、という切り分けです。

## わざと間違う③: `UserDefaults` ＋ `try?`

いちばんよく書かれる保存の書き方です。

```swift NG
// わざと間違う版③：UserDefaults に try? で入れる
func wrongSave(_ ctx: SaleContext, _ data: Data) {
    UserDefaults.standard.set(data, forKey: "saleSession")
}
func wrongLoad() -> SaleContext? {
    guard let d = UserDefaults.standard.data(forKey: "saleSession") else { return nil }
    return try? jsonDecoder.decode(SaleContext.self, from: d)   // ★ 失敗しても nil
}
```

```
=== わざと間違う版③：壊れた保存に気づけない ===
  まだ保存していないとき: nil（正しい）
  保存して読み直: 状態=mixedCashInput
  保存ファイルを壊す: {壊れたJSON
  壊れたあと read: nil → 「会計は無かった」と判断される
  ★ 「保存が壊れました」と「最初から無かった」の区別がつかない
  ★ しかも UserDefaults は強制終了のタイミングで書き込みが失われることがある
```

**何が壊れているか**

| # | 問題 |
| --- | --- |
| 1 | **`try?` が「保存が壊れた」を「保存が無い」に変えてしまう** |
| 2 | 壊れたまま営業を始めると、**スキャン中のカートと完了済み販売の整合が取れなくなる** |
| 3 | `UserDefaults` の書き込みは**強制終了のタイミングで失われることがある**。A-3 が要求する「保持」と矛盾する |

**直し方**: `base/6_会計の状態機械.md` §8 の `SaleContextStore` を使います
（上のコードはそのもの）。中身は3行だけです。

```swift 断片
func save(_ ctx: SaleContext) throws {
    let data = try jsonEncoder.encode(ctx)      // base/2 の encoder（ISO 8601）
    try data.write(to: url, options: .atomic)   // ← 途中で落ちても壊れない
}

func load() throws -> SaleContext? {
    guard FileManager.default.fileExists(atPath: url.path) else { return nil }  // 「無い」
    let data = try Data(contentsOf: url)
    return try jsonDecoder.decode(SaleContext.self, from: data)                  // 「壊れている」は throw
}
```

| # | 決定 | 理由 |
| --- | --- | --- |
| 1 | `.atomic` で書く | 一時ファイルに書いてから入れ替える。途中で強制終了しても**前の内容が残る**（A-3 の保持） |
| 2 | `try?` を使わない | `try?` は「保存が壊れた」を「保存が無い」に変えてしまう |
| 3 | `nil` と `throw` を分ける | 呼び出し側で **「無い」と「壊れている」を別々に扱える**（C-6 #1・#4 の診断） |

## 1. 保存・復元・消す

`SaleContext` は `Codable` なので、そのまま 1 つで保存できます。

```swift 断片
// 更新のたびに呼ぶ
try store.save(ctx)

// 起動時に呼ぶ。throw が来るので do-catch で受ける
do {
    if let restored = try store.load() {
        // 復元した会計で続ける
    } else {
        // 保存は無い → 待機中から始める
    }
} catch {
    // 保存が壊れている → 黙って始めない。案内して終了する
}

// 完了・記録に残らない中断のあと
try store.clear()
```

## 2. 復元したら、検証する

復元できただけで満足してはいけません。**閉店中に在庫が変わっていた**可能性があるからです。

```swift 断片
// 復元したカートを、いまの在庫表で検証する（base/5 の checkStock）
let problems = checkStock(ctx.cart, inventory: inventory, types: types)
if !problems.isEmpty {
    // 問題があるときは、確認せずに完了させない（A-4 のトランザクションと同じ考え方）
    // 在庫0なら「在庫切れ」として行だけ外す、のほうが安全
}
```

> **1 人運用なら閉店中に在庫は変わらない**ので、この検証は二重に守る保険です。
> でも **C-6 #4 はカートの保持を要求している**ので、勝手に削ってはいけません。
> **検証して、削るなら客に確認する**という順番にしてください。

## 3. 通しの確認

下のコードを、**土台（`base/Types.swift` の型 ＋ `base/3_標準ロジック.md` の §1・§3 ＋
`base/6_会計の状態機械.md` の §1〜§3・§7・§8）の下に続けて置いて**、`swift` で動かします。

```swift
// ════════ 通しの確認（会計状態の保存・復元・A-3 / C-6 #78）════════

// ── 保存先（一時フォルダ。実機では cachesDirectory）──
let dir = URL(fileURLWithPath: NSTemporaryDirectory())
    .appendingPathComponent("saleContextDemo")
try? FileManager.default.createDirectory(at: dir, withIntermediateDirectories: true)
let fileURL = dir.appendingPathComponent("saleContext.json")

func p1(_ s: String) { print("  " + s) }
func show1(_ ctx: SaleContext) -> String {
    let t = ctx.cart.totals()
    return "状態=\(ctx.state.rawValue)"
        + " / method=\(ctx.method.map { $0.rawValue } ?? "未選択")"
        + " / 現金で受ける額=\(ctx.cashDueJpy)円"
        + " / 請求sats=\(t.sats)sats 現金分=\(t.cashForSats)円"
        + " / confirmedSats=\(ctx.confirmedSats.map(String.init) ?? "nil")"
}

// ── 前提：sats単価あり1行 ＋ 野良1行 ──
let types: [ProductType] = [
    ProductType(typeId: "sticker", name: "ステッカー", idPrefix: "ST", idDigits: 3,
                stockMode: .counted, attrLabel1: "色", attrLabel2: nil, attrLabel3: nil, updatedAt: nil),
]
var inventory: [Product] = [
    Product(id: "ST-001", typeId: "sticker", name: "ステッカー まる", priceJpy: 300, priceSats: 500,
            stock: 10, attr1: "黄", attr2: nil, attr3: nil, imageRef: nil,
            isPublic: true, updatedAt: nil),
]
let at = Date(timeIntervalSince1970: 1_700_000_000)
let cart = [CartLine(product: inventory[0], qty: 2),
            CartLine.adhoc(id: "ADHOC-1", name: "雑誌", priceJpy: 400, priceSats: nil, qty: 1)]

print("【1】保存する会計：併用現金入力中（sats確認済み・済ボタン承認済み）")
var ctx = SaleContext(state: .mixedCashInput, cart: cart,
                      satsConfirmedAt: at, confirmedSats: cart.totals().sats)
p1(show1(ctx))

print("【2】保存する（.atomic で書く）")
let store = SaleContextStore(url: fileURL)
try store.save(ctx)
p1("保存先: " + fileURL.lastPathComponent)
p1("サイズ: \((try Data(contentsOf: fileURL)).count) バイト")
// ★ JSON のキー順は実行ごとに変わる（Swift の Dictionary は順序保証がない）。
//   だから「保存した JSON 文字列」を期待される出力には書かない。値を比べるときは `==` で比べる。

print("【3】プロセス終了をまねて、新しく読み直す")
// 保存した時とは別のインスタンス（= 別プロセスと同じ）
let reopened = SaleContextStore(url: fileURL)
guard let restored = try reopened.load() else { print("保存が無い"); exit(1) }
p1(show1(restored))
p1("復元前後が一致: \(restored == ctx)")

print("【4】復元後も、済ボタンの承認を求めない（C-6 #78）")
p1("状態が mixedCashInput のまま: \(restored.state == .mixedCashInput)")
p1("sats確認済み: \(restored.satsConfirmedAt != nil)")
p1("承認済みの請求sats額が残っている: \(restored.confirmedSats == ctx.confirmedSats)")
p1("復元後の現金で受ける額は復元前と同じ: \(restored.cashDueJpy == ctx.cashDueJpy)")

print("【5】導出できるものは保存していないのに、復元後に正しい")
p1("method = \(restored.method.map { $0.rawValue } ?? "未選択")（保存はしていない）")
p1("カートから計算した合計 = \(restored.cart.totals())")
p1("カート: " + restored.cart.map { l in "\(l.name)\(l.isAdhoc ? "（野良）" : "")×\(l.qty)" }.joined(separator: " / "))

print("【6】時刻は ISO 8601 で往復している（A-19-5）")
let jsonText = String(data: try Data(contentsOf: fileURL), encoding: .utf8)!
if let r = jsonText.range(of: "\"satsConfirmedAt\":") {
    p1("保存した文字列の satsConfirmedAt = "
       + jsonText[r.upperBound...].prefix(20))
}
p1("復元した Date == 元の Date: \(restored.satsConfirmedAt == ctx.satsConfirmedAt)")

print("【7】保存ファイルを壊す → load() は throw（「無い」とは区別できる）")
try Data("{壊れたJSON".utf8).write(to: fileURL)
do {
    let v = try reopened.load()
    p1("throw されず戻りました: " + (v == nil ? "nil" : "値あり"))
} catch {
    p1("load() が throw した: " + error.localizedDescription)
    p1("→ 「保存が無い」とは区別できた")
}

print("【8】消す（完了・記録に残らない中断のあと）")
try reopened.clear()
p1("消したあと load() = \(String(describing: try reopened.load()))")
p1("ファイルが存在するか: \(FileManager.default.fileExists(atPath: fileURL.path))")

print("【9】復元したカートを在庫表で検証する（checkStock）")
p1("閉店中に在庫が減った場合をまねる")
inventory[0].stock = 1                                   // 在庫 10 → 1
let again = SaleContext(state: .mixedCashInput, cart: cart,
                        satsConfirmedAt: at, confirmedSats: cart.totals().sats)
let problems = checkStock(again.cart, inventory: inventory, types: types)
problems.forEach { p1($0) }
p1("問題なし: \(problems.isEmpty)　→ 検算してから、削るなら客に確認する")
```

  → 「保存が無い」とは区別できた

> **このレッスン執筆中に分かったこと**: 上のコードは、保存した JSON 文字列を
> 途中から表示するのをやめています。**`JSONEncoder` が書き出すキー順は実行ごとに変わります**
> （Swift の `Dictionary` は順序を保証しない）。同じ値を入れても
> `{"state":…,"cart":…}` と `{"cart":…,"state":…}` のどちらで出具る。
> **保存した文字列を期待される出力に書かない**のはこのためです。
> 値を確認したいときは **`==` で比べる**（`SaleContext` は `Equatable`）。

**この出力から読み取れること**:

| # | 確認できること |
| --- | --- |
| 1 | `SaleContext` をそのまま保存して、復元した値と `==` で一致する（C-6 #4） |
| 2 | 野良の明細も復元される（A-3） |
| 3 | 復元後も **`mixedCashInput`** のままで、済ボタン承認は求められない（C-6 #78） |
| 4 | 復元後の請求額（現金分）と `confirmedSats` が復元前と一致する（C-6 #78） |
| 5 | `method` と `cashDueJpy` は保存していなくても復元後に正しい |
| 6 | `satsConfirmedAt` が `Date` なので、ISO 8601 で往復する（A-19-5） |
| 7 | 保存ファイルが壊れていれば **`load()` が throw** する（「無い」とは区別できる） |
| 8 | 復元したカートを在庫表で検証できる（`checkStock`） |

## 考えてみる（答えはない）

1. 壊れた保存ファイルは、`load()` が throw するとして、**営業中にどう案内しますか**。
   客がまだ会計中なら、「カートが消えました」と伝える必要があります。
   ただ、C-6 #4 は**スキャン中のカートの保持**を要求しています。この2つをどう両立させますか。
2. **受取額（入力途中）** は保存していません。併用現金入力中に強制終了すると、
   入力途中の金額は残っていません。実害が出るなら `receivedJpy: Int?` を `SaleContext` に
   足すだけで済むので、`cashInput` と `mixedCashInput` のどちらが要るか判断してください。
3. A-3 は「更新のたびに端末内へ保存」と書いています。1 回の会計で `save` は
   **何回**呼ばれますか？　多すぎれば何が起こりますか。

## ポイント

- 保存するのは **`base/6` の `SaleContext` そのもの**。新しい struct を作らない
- **導出できるものは保存しない**。`method` と `cashDueJpy` は `base/6` §7 で計算する
- **`confirmedSats` と `satsConfirmedAt` は保存する**。「その瞬間の値」だから（C-6 #78）
- ファイルには **`.atomic`** で書く。`try?` で握りつぶさない
