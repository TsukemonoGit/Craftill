## Macのターミナルで実行する

Swift Playgrounds ではペーストで足りる。Macのターミナルでは、`import` で他ファイルを読み込むことはできない。
`base/` のコードと自分のコードを**1本に連結**してから実行する。

```bash
# base の型と自分のコードを連結して実行
cat docs/使い方講座/base/Types.swift my_lesson.swift | swift -
```

- **`swift ファイルA ファイルB` と並べても、最初のファイルしか実行されない。** 必ず `cat ... | swift -` で連結する。
- `swiftc` でコンパイルする場合も、トップレベルの `print` があるファイルを複数並べると `expressions are not allowed at the top level` になる。
- 自分のコードの1行目に `import ../base/Types.swift` のような行は書かない。書くとエラーになる。
- 順序は `base/` → 自分のコード。逆にすると「`cannot find type 'ProductType' in scope`」になる。
- `base/3` など他のファイルも使うときは、そのコードブロックの中身を `Types.swift` の後ろに足す。
- `lesson/` フォルダは**手書きの作業ファイル**（古い型のままのものもある）。教材として読む用で、実行用ではない。

> **Playgrounds でやるのが基本。** ターミナル実行は、`base/` を更新した時の確認用。

## Playgrounds って？
iPadの**Swift練習帳アプリ**。コードを書いて、すぐ実行して、結果を見られる。ファイルを作らなくていい。

1. App Storeで **「Swift Playgrounds」** を入れる
2. アプリを開く → **「新しいプレイグラウンド」→「ブック（Book）」** を選ぶ
3. 画面に出てくる `import SwiftUI` などは**消してOK**（残っていてもよい）
4. コードを書いて、**実行ボタン(▶)** を押す
5. `print("...")` と書くと、書いた文字が下/右の**コンソール**に出る

最初は「テンプレを消して `print("やあ")` と書いて▶」だけで十分。
アプリ内の**「コードを学ぼう」**という初心者コースが一番おすすめ。

### どれを使う？「ブック / アプリ / 教材ブック」
新規作成では **「アプリ」か「ブック」** を選ぶ（「Playground / Blank」ではない）。

| 名前 | 作り方 | 使える？ |
| --- | --- | --- |
| **ブック（Book）** | 新しいプレイグラウンド → ブック | ✅ 自由にコードを書ける。**レッスン・練習はこれ** |
| アプリ（App） | 新しいプレイグラウンド → アプリ | △ 本物のアプリ用。トップレベルに書けない（下の「つまずき①」） |
| 教材ブック（「コードを学ぼう」等） | ホームのBooks | ✕ 穴埋め式。自由なコードは貼れない |

### ブック と アプリ の違い（くわしく）
| | ブック（Book） | アプリ（App） |
| --- | --- | --- |
| 正体 | 1つの**ノート**（ドキュメント） | 1つの**アプリ本体** |
| 上から順に実行 | ✅ される | ✕（関数/structの中だけ） |
| 画面の出し方 | 自分で `setLiveView(...)` を書いた時 | 起動時に**自動**で出る |
| 入口 | 無い | `@main struct ...App: App` |
| 向いてる | 練習・試す・1画面プレビュー | 本物のアプリを作る |

**ブック**: ノート。コードを上から順に実行し、`print` の結果が出る。SwiftUIの画面は `PlaygroundPage.current.setLiveView(QRView())` と書いた時に出る（書かないと出ない）。1ファイルに関数もUIもまとめてOK。

**アプリ**: 入口（`@main`）があり、起動すると画面が自動で出て、動き続ける。`setLiveView` は書かない。
```swift
@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            QRView()   // ← 起動時にこれが自動で出る
        }
    }
}
```

**使い分け**: 今（iPad）は**ブック**（書いてすぐ試せる）。Macで本物のアプリを作る時は**アプリ**。

**Svelteでいうと**: アプリ ≒ アプリ本体／`+page.svelte`（入口が自動で表示）。ブック ≒ 自分で開いて実行するノート（直接の対応は無い）。

### つまずき①: 「Expressions are not allowed at the top level」
- **原因**: 「アプリ（App）」を作ってしまった。アプリのファイルは普通のSwiftファイル扱いで、一番外側（トップレベル）に `print` や `let x = ...` を書けない
- **直し方**: **「ブック（Book）」**で作り直す。ブックはトップレベルに書けて ▶ で動く
- 「トップレベル」＝関数やクラスの中ではなく、**ファイルの一番外側**のこと
- アプリで書きたい時は、コードを `func test() { ... }` に入れて、`ContentView` の `body` などから `test()` と呼ぶ

## `struct Product` って？
**「商品1つ分のデータを入れる箱の“形（ひな形）”」**。
`struct` は「構造体」。こういう項目をまとめて1つの仲間にします、という定義。
例えると**商品カードの雛形**。

```swift
struct Product {
    let id: String        // ID      例: "KH-008"
    let name: String      // 名前    例: "キーホルダー 08"
    let priceJpy: Int     // 円の値段 例: 800
    let priceSats: Int?   // satsの値段 例: 1200
    var stock: Int?       // 在庫     例: 1
}
```

| 書き方 | 意味 |
| --- | --- |
| `id` / `name` | 欄の名前 |
| `: String` | **文字（テキスト）** を入れる欄 |
| `: Int` | **整数（数字）** を入れる欄 |
| `let` | あとから**変えられない** |
| `var` | あとから**変えられる**（在庫は減るので `var`） |
| `: Int?` の `?` | **あるかも / 空っぽかも**（オプショナル。下で説明） |

> 補足: `let id, name: String` は「id と name は両方 String」という**省略した書き方**。上の例は1行ずつ書いた版で意味は同じ。
>
> **実際に使う `Product` は `base/Types.swift` に1つだけある**（`typeId` など項目が増える）。ここは形をつかむための簡略版。`base` と混ぜて貼ると二重定義になるので、レッスンでは `base` の方を使う。

## `Int?` の `?`（オプショナル）って？
**「値が入っているかもしれないし、何も入っていない(nil)かもしれない」** という意味。
- `ST-003` は satsの値段が**空（NULL）**。それが `nil`（ニル＝空っぽ）
- `nil` のときは「sats払いはできない」と判断する

使うときは、空かどうか確認してから取り出す：
```swift
if let sats = product.priceSats {   // 入っていれば取り出す
    print("sats価格は \(sats)")
} else {
    print("この商品はsats払いなし") // 空っぽのとき
}
```

## `guard let` って？
`if let` の親戚で、「**ダメなら先に抜ける**」書き方。
`06_QRを試す.md` に `guard let ciImage = filter.outputImage else { return nil }` として出てくる。

> `if let` / `guard let` / `if var` / `while let` / `if case` の**比較表と例は `01-2_if.md`** にまとめてある。
> ここでは「空かどうかを確認して取り出す書き方が2つある」ことだけ押さえればよい
> （`if let` ＝ `{ }` の中だけで使える／`guard let` ＝ そのあと全部で使える）。

## 関数の戻り値と `->`

### 戻り値なし（`->` を省略）
```swift
func f(_ x: Int) {
    print(x)
}
```

### 戻り値なし（`-> Void` と書いても同じ）
```swift
func f(_ x: Int) -> Void {
    print(x)
}
```

### 戻り値あり（`->` が必須）
```swift
func double(_ x: Int) -> Int {
    return x * 2
}

func double2(_ x: Int) -> Int { x * 2 }   // 式が1つなら return を省略できる
```

### 複数の値を返す（タプル）
```swift
func minMax(_ a: Int, _ b: Int) -> (min: Int, max: Int) {
    return (min(a, b), max(a, b))
}

let r = minMax(3, 5)
print(r.min, r.max)   // 3 5
```

- `->` は「この関数が返す型」を表す
- 何も返さない関数は `->` ごと省略するのが普通の書き方
- レッスン4の `totalLines` は、`(satsLine: String, cashLine: String)` という**タプル**を返す書き方（`totals()` 本体は `Totals` 構造体を返す）


## `enum StockMode` って？
**「決まった選択肢のうち、どれか1つ」** を表す型（`enum`＝列挙型）。
種類を3パターンに限定しておくと、変な値にならず安全。

```swift
enum StockMode {
    case counted   // 数量管理型（ステッカー。在庫を数で持つ）
    case unique    // 一点物型（キーホルダー。在庫は1か0）
    case none      // 在庫管理なし型（今回は使わない）
}
```
使い方: `let mode = StockMode.counted` → 「これは数量管理型」と決まる。

### enum の中にプロパティやメソッドを書ける
他の言語の `enum` は「定数の集まり」で終わりのことが多い。でも **Swiftの `enum` は“型”なので、中にプロパティ（getter）やメソッドを書ける**。
「その状態についての情報は、状態自身に持たせる」という書き方ができる。

> 実際の `SaleState` は `base/Types.swift` に**8状態**ある（`03_レッスン.md` のレッスン6）。ここは説明用に3つだけ書く。

```swift
enum SaleState {
    case idle             // 待機中
    case scanning         // スキャン中
    case done             // 完了

    var label: String {   // ← 中に getter（計算プロパティ）を定義
        switch self {     // self = 今のケース（.idle や .scanning）
        case .idle:     return "レジ待機中"
        case .scanning: return "商品をスキャン中"
        case .done:     return "会計完了"
        }
    }

    func isFinished() -> Bool {   // ← メソッドも書ける
        return self == .done
    }
}

let s = SaleState.scanning
print(s.label)        // 商品をスキャン中（カッコは付けない）
print(s.isFinished()) // false（メソッドはカッコが要る）
```

| 書き方 | 呼び方 | 意味 |
| --- | --- | --- |
| `var label: String { ... }` | `s.label` | **計算プロパティ**（getter）。`= 値` が無く、`{ }` の中を毎回実行して返す |
| `func isFinished() -> Bool { ... }` | `s.isFinished()` | メソッド。カッコを付けて呼ぶ |

- **計算プロパティは必ず `var`**。「再代入できる」という意味ではなく、そういう決まり（`let` は書けない）。読み取りだけなら `get { }` を省略して `{ ... }` と書ける
- 中で使う **`self`** は「今この値を呼んでいる実体」。`s.label` なら `self` は `.scanning`。`switch self` は「自分のケースで分岐する」という意味
- `case .idle:` は `case SaleState.idle:` の省略形

> Svelteでいうと、`var label { ... }` は **getter**（`get label() { ... }`）、`self` は **`this`** のイメージ。

## View（画面）の中の変数はどこに書く？
`struct QRView: View` も `struct Product` と同じ**構造体**。`var body` が「画面に出す中身」。
変数は **`var body` の外（構造体の直下）** に書く。

```swift
struct QRView: View {
    let productID = "KH-008"   // ← ここ（body の外）に変数を書く

    var body: some View {
        Text(productID)        // body の中で使える
    }
}
```

### `let` か `@State` か
| 書き方 | いつ使う | 変えたら画面は更新される？ |
| --- | --- | --- |
| `let productID = "KH-008"` | 決まった値（変わらない） | ー（変えられない） |
| `@State var count = 0` | 途中で変わる値 | ✅ 更新される |

- ふつうの `var` に変わる値を入れても**画面は更新されない**。変わる値は **`@State`**
- `@State` を変えると SwiftUI が `body` をもう一度実行して**画面を描き直す**

```swift
struct CounterView: View {
    @State var count = 0             // 変わる値

    var body: some View {
        VStack {
            Text("\(count)")
            Button("+1") { count += 1 }   // 変えると画面が更新される
        }
    }
}
```

### 書く場所のルール
- `var body` の**上**に書く（プロパティ）
- `body { }` の中に `let x = ...` と書くこともできるが、それは**毎回作り直される一時的な値**
- 画面をまたいで使う値・後で変えたい値は**プロパティ**として外に書く

### QRViewの場合
```swift
struct QRView: View {
    let productID = "KH-008"   // 決まった値 → let

    var body: some View {
        VStack(spacing: 12) {
            Text(productID)
            if let img = makeQR(productID) { ... }
        }
    }
}
```
→ `productID` を1か所にまとめたので、変えたい時は**ここだけ**変更すれば表示とQRの両方に効く。

## 変数の置き場所まとめ
Swiftは「**どこで生きるか**」で変数の種類が分かれる。

| 種類 | 例 | 見える範囲（スコープ） | 寿命（いつ消える） |
| --- | --- | --- | --- |
| 関数の中（ローカル） | `var sum = 0` | その関数の中だけ | 関数が終わると消える |
| 関数の引数 | `func f(_ x: Int)` | その関数の中 | 呼び出しごと |
| データ型のプロパティ | `struct Product { let id: String }` | そのインスタンス | インスタンスが消えるまで |
| Viewのプロパティ | `let productID` / `@State var count` | そのViewの中 | Viewが生きている間（`@State`はSwiftUIが保管） |
| 計算プロパティ | `var subtotal: Int { qty*price }` | その型の中 | 値を持たない（毎回計算） |
| グローバル / `static` | `let taxRate = 0.1` | アプリ全体 | アプリが終わるまで |

**決めている3つの軸**:
- **スコープ** … `{ }` のどこまで見えるか
- **寿命** … いつまで存在するか（ローカルは関数が終わると消える）
- **値型 or 参照型** … `struct` は**渡すとコピー**。だから View の `@State` は、View 本体ではなく **SwiftUI が別に持っている**（`struct` のままだと書き換えられないため）
- 頭に付ける**印**（`@State` / `@Binding` / `@Observable`）で「SwiftUI がどう扱うか」が決まる

> Svelte との対応は `04_Svelteで理解するSwift.md` 参照。

## `$` って？
Swiftの `$` は、使われ方が2種類ある。

| 書き方 | 場所 | 意味 |
| --- | --- | --- |
| `$0` `$1` `$2` | クロージャ（`{ }`）の中 | 引数の**省略記法** |
| `$count` `$name` | SwiftUI（`@State` などの前） | 変数への**つながり（Binding）** |

### ① `$0`（クロージャの引数の省略記法）
**クロージャ**＝`{ }` で囲んだ処理。`filter` や `map` に「各要素にこの処理をして」と渡すときに使う。
`$0` は、クロージャに渡された**1番目の引数**。

```swift
let upper = "KH8"
let letters = upper.filter { $0.isLetter }          // 省略記法
let letters2 = upper.filter { char in char.isLetter } // 同じ意味（引数名を宣言した版）
```
- `filter` は文字列の各文字を1つずつクロージャに渡す。`$0` はそのとき渡されている**1文字**
- `"KH8"` なら `$0` に `"K"` → `"H"` → `"8"` の順に入って実行される
- `upper.isLetter` ではない。`upper`（文字列全体）ではなく、その中の**1文字**が `$0`
- `char in` のような**引数名の宣言を省略できる**のが `$0` の役割

引数が複数あるときは `$0`, `$1`, `$2` と番号が増える。
```swift
[1, 2, 3].reduce(0) { $0 + $1 }   // $0=累計, $1=現在の要素 → 6
```

```swift
let nums = [1, 2, 3, 4]
nums.map { $0 * 2 }          // [2, 4, 6, 8]
nums.filter { $0 % 2 == 0 }  // [2, 4]
nums.sorted { $0 > $1 }      // [4, 3, 2, 1]
```

**ルール**:
- 番号は **0 から**始まる（`$1` から始まらない）
- 1つのクロージャの中で、`char in` のような**宣言と `$0` を混ぜられない**（どちらかに統一）
- 使っていない番号があるとエラーになることがある（`$1` を使うなら `$0` も使う必要がある）
- クロージャの中にクロージャがある場合、`$0` は**いちばん内側**のクロージャの引数
- 処理が長い・意味が分かりにくいときは、`char in` のように**名前を付けた方が読みやすい**

> Svelteでいうと、JSの `arr.filter(x => x > 0)` の `x` を、名前を付けずに `$0` と書くイメージ。

### ② `$名前`（Binding：SwiftUI）
`@State` で作った変数の前に `$` を付けると、**「値」ではなく「その変数へのつながり（Binding）」**になる。
`TextField` のように、**画面側から値を書き換えたい**部品に渡すときに使う。

```swift
struct NameView: View {
    @State var name = ""                    // 変わる値

    var body: some View {
        VStack {
            TextField("名前", text: $name)  // $name = 双方向のつながり（入力すると name が変わる）
            Text("こんにちは \(name)")      // name = ただの値（読むだけ）
        }
    }
}
```

| 書き方 | 渡すもの | できること |
| --- | --- | --- |
| `name` | 値のコピー | 読むだけ |
| `$name` | 変数へのつながり（`Binding`） | 読む＋**書き換える** |

- `TextField` は入力されたら `name` を書き換える必要がある。だから `$name` を渡す
- `Text(name)` は表示するだけなので `$` は要らない
- `Toggle` / `Slider` / `Picker` なども同じく `$変数名` を渡す
- `$` は `@State` のほか `@Binding` などを付けた変数にも使える

> Svelteでいうと、`bind:value={name}` が `TextField("名前", text: $name)` に近い。

## 引数のラベル（`_` や日本語）

Swiftの引数は **`ラベル 内部名: 型`** の順に書ける。
- **ラベル**＝**呼び出す時**に使う名前
- **内部名**＝**関数の中身**で使う名前
- 1つだけ書くと両方同じ。`_` を書くと**ラベル無し**になる。

```swift
func a(_ text: String) {}         // ラベル無し / 内部名 text          → a("KH-008")
func b(text: String) {}           // ラベル=内部名=text               → b(text: "KH-008")
func c(contents text: String) {}  // ラベル=contents / 内部名 text    → c(contents: "KH-008")
```

### 順番は常に固定
**ラベルがあってもなくても、引数の順番は定義した順に固定。** 入れ替えはできない。
```swift
func f(a: Int, b: Int) {}
f(a: 1, b: 2)   // ○
f(b: 2, a: 1)   // ✕ エラー
```
- 全部 `_` にすると呼ぶ時はラベル無しになるが、順番はやっぱり固定（`move(3, 7)` は x=3, y=7）
- **ラベルを付けても順番は自由にならない**

### JSのオブジェクト引数とは違う
JSの `fn({ text, size })` は**プロパティ名で決まり、順番は自由**。Swiftは**位置で決まり、順番は固定**。
ラベルは「何の値か」を分かりやすくするだけで、順番は変えられない。

### いつラベルを付ける／省略するか
個数ではなく**読みやすさ**で決める。Appleの基本は「**1個目は省略（`_`）、2個目以降はラベル**」。
```swift
func add(_ item: String, quantity: Int) {}   // 呼ぶ時: add("りんご", quantity: 3)
```

### なぜラベルと内部名を分けるのか
読み手が違うから。
- **ラベル**＝**呼び出しの文が自然に読める**ように選ぶ
- **内部名**＝**中身で意味が通る**ように選ぶ
```swift
func move(from source: Point, to destination: Point) { ... }
move(from: a, to: b)   // 呼ぶ側は "from a to b" と読める / 中では source, destination
```
同じ名前で足りる時は**1つだけ書く**。

### ラベルには日本語も使える
正確には、**関数名も内部名もラベルも、全部日本語にできる**。ただし普通はコード全体を英語で書く。
そのうえで、**ラベルだけ日本語**（関数名・内部名は英語）にすることもできる。ラベルは呼ぶ側の読みやすさのための名前なので、特にそうしやすい。
```swift
func addProduct(しな id: String, かず num: Int) {
    print("\(id) を \(num) 個")     // 中では英語の id / num を使う
}
addProduct(しな: "KH-008", かず: 1) // ← 呼ぶ時のラベルだけ日本語
```
**デメリット**（混ぜると摩擦が出るので、普通は英語に統一する）:
- Appleの資料・エラー・他人のコードは英語。日本語が混ざると読みにくい
- 日本語と英語が混ざると補完・検索・差分が使いにくい
- 人に見せる時・将来見返す時に困る

**ただし「絶対英語」ではなく慣習**。自分一人だけが読む個人アプリなら、**日本語ラベルもアリ**（読みやすさ優先）。
Appleの資料やサンプルをよく見て作るなら、英語に統一した方がスムーズ。

### コメントは日本語でOK（ラベルとは別）
| | 機械が見る？ | 日本語 |
| --- | --- | --- |
| **コメント** | 見ない（無視される） | ふつうに書く |
| **ラベル** | 見る（識別子） | 慣習的に英語 |

- コメントはコンパイラが無視する**人間向けの文章**。補完・型・実行に出ない → 日本語でOK
- ラベルは**コードの一部（識別子）**。呼び出し・補完・エラー・署名に出る → 混ぜると摩擦

### JSDoc（ドキュメントコメント）とは別
JSのJSDocは**コメント**。Swiftでいう **`///` のドキュメントコメント**が対応する。そこは日本語でOK。
**ラベルはそれとは別**で、呼び出し方そのものを変える**本物のコード**。

```js
// JS: JSDocはコメント。呼び方には影響しない
/**
 * 商品を追加する
 * @param {string} id 商品ID
 * @param {number} num 個数
 */
function addProduct(id, num) {}
addProduct("KH-008", 1)   // 順番で渡す
```

```swift
/// 商品を追加する
/// - Parameters:
///   - id: 商品ID
///   - num: 個数
func addProduct(しな id: String, かず num: Int) {}
addProduct(しな: "KH-008", かず: 1)   // ← ラベルは呼び方を変える本物のコード
```
- JSDoc（＝Swiftの `///`）は**説明を書く場所** → 日本語でOK
- ラベルは**呼び出し構文の一部** → 慣習的に英語

# Swiftのクラッシュパターンと回避方法まとめ

Swift の `do-catch` は、`throws` で投げられたエラーを受け止めるためのもの。
Optional の強制アンラップや配列の範囲外アクセスのように、**プロセスごと落ちる操作は `do-catch` では捕まえられない**。
だから、**クラッシュする操作を事前に避ける**書き方が基本になる。
クラッシュするコードは `// クラッシュ` と記載（実行しない）。

> これは `01_初心者メモ.md` の補足。`!` や `nil` の基本は `01-2_if.md`、`nil` を置ける型は `01-3_型.md`。
> 一覧の番号は、下の見出しの番号と対応している。

## 安全の原則

1. `!` / `try!` / `as!` は原則使わない。使うなら「ここで nil になったら設計が壊れている」と説明できる場所だけ
2. 配列は `indices.contains(i)` / `first` / `last` で範囲を確認する
3. 割り算・剰余の前に、0 でないことを確認する
4. 変換は `as?` / `Int(exactly:)` のように、失敗を値で返すものを使う
5. 再帰には必ず終了条件を書く
6. 外から来た値（CSV・QR・手入力）は、使う前に正規化と検証をする

## 一覧

| # | クラッシュする操作 | 回避 |
| --- | --- | --- |
| 1 | Optionalの `!`（強制取り出し） | `if let` / `guard let` / `??` |

## 1. Optionalの `!`
```swift
let s: Int? = nil

// let a = s!                     // クラッシュ

if let v = s { print(v) }         // 値があるときだけ実行
let b = s ?? 0                    // nil のときの代わりの値

func f(_ x: Int?) {
    guard let v = x else { return }   // nil なら関数を抜ける
    print(v)                          // 以降は v を普通の Int として使える
}
```
- `guard let` は「条件を満たさないときに早めに抜ける」書き方

## 2. 配列の範囲外アクセス
```swift
let arr = [10, 20, 30]
let i = 5

// let a = arr[i]                 // クラッシュ

if arr.indices.contains(i) { print(arr[i]) }   // 範囲確認
print(arr.first ?? 0)                          // 空でも nil が返る

extension Array {
    subscript(safe i: Int) -> Element? {
        indices.contains(i) ? self[i] : nil
    }
}
print(arr[safe: 5] ?? 0)          // 0
```
- Dictionary の `d["x"]` は元から Optional が返るので安全

## 3. 空配列への `removeFirst()` `removeLast()`
```swift
var xs: [Int] = []

// xs.removeFirst()               // クラッシュ
// xs.remove(at: 3)               // クラッシュ（範囲外）

if !xs.isEmpty { xs.removeFirst() }
let last = xs.popLast()           // Optional。空なら nil
```

## 4. Int のオーバーフロー
```swift
let big = Int.max

// let a = big + 1                // クラッシュ

let r = big.addingReportingOverflow(1)
print(r.overflow)                 // true
let w = big &+ 1                  // 折り返してよいときは &+ &- &*
```

## 5. 0除算
```swift
let a = 10
let b = 0

// let c = a / b                  // クラッシュ
// let d = a % b                  // クラッシュ

if b != 0 { print(a / b) }
```
- `Double` の0除算はクラッシュせず、`inf` や `nan` になる

## 6. `Int(Double)` の変換
```swift
let d = Double.nan

// let a = Int(d)                 // クラッシュ（NaN・無限大・Intに入らない大きさ）

if let n = Int(exactly: 3.0) { print(n) }   // 3
let m = Int(exactly: 3.5)                   // nil（小数があるため）
let k = Int(exactly: d)                     // nil
```
- `Int(3.5)` はクラッシュせず `3`（小数点以下を切り捨て）
- 文字列からの変換 `Int("abc")` は Optional が返るので安全（`03_レッスン.md` レッスン5の `Int(digits) ?? 0`）

## 7. `try!`
```swift
// let r = try! someThrowingFunc()     // 失敗するとクラッシュ

do {
    let r = try someThrowingFunc()
    print(r)
} catch {
    print("失敗")
}

let r2 = try? someThrowingFunc()       // 失敗したら nil
```
- `someThrowingFunc` は `throws` の付いた関数（`49_エラー処理を書く.md`）

## 8. `as!`
```swift
let x: Any = "abc"

// let n = x as! Int              // クラッシュ

if let n = x as? Int { print(n) } // 変換できなければ nil
```

## 9. Dictionary のキー重複
```swift
let pairs = [("a", 1), ("a", 2)]

// let d = Dictionary(uniqueKeysWithValues: pairs)    // クラッシュ

let d = Dictionary(pairs, uniquingKeysWith: { first, second in second })
print(d)    // ["a": 2]（重複したときは後の値を採用）
```
- CSVの取り込み（`13_商品マスタCSVを取り込む.md`）で同じIDが2行あるときに該当する

## 10. 範囲の大小
```swift
let lo = 5
let hi = 1

// for i in lo...hi { }           // クラッシュ（下限 > 上限）

if lo <= hi {
    for i in lo...hi { print(i) }
}
// 0..<n は n が 0 でも安全（空の範囲になる）。n が負だとクラッシュ
```

## 11. 文字列の位置
```swift
let s = "abc"
let offset = 10

// let c = s[s.index(s.startIndex, offsetBy: offset)]   // クラッシュ

if offset >= 0 && offset < s.count,
   let idx = s.index(s.startIndex, offsetBy: offset, limitedBy: s.index(before: s.endIndex)) {
    print(s[idx])
} else {
    print("範囲外")
}
```
- `limitedBy:` を付けた形は、上限を超えたとき nil が返る
- ただし `limitedBy: s.endIndex` にすると、`offset == s.count` のときに `endIndex` が返り、`s[idx]` でクラッシュする。**必ず `offset < s.count` を確認**する
- 文字数で扱うなら `Array(s)` にして `chars[offset]` も分かりやすい（大きな文字列ではコピーが発生する）

## 12. `Int!`（暗黙アンラップ）
```swift
var a: Int! = nil
// let b = a + 1                  // クラッシュ

var c: Int? = nil                 // 通常の Optional にして if let / ?? で扱う
```

## 13. `@EnvironmentObject` の渡し忘れ
```swift
// 子の View が @EnvironmentObject var store: Store を宣言しているのに、
// 親が .environmentObject(store) を付けていないと、表示時にクラッシュする

ContentView()
    .environmentObject(store)     // 親で必ず付ける
```
- `@Observable`（`54_@Observableで状態を共有する.md`）の `@Environment` で渡す場合の挙動は不明

## 14. 終わらない再帰
```swift
func countdown(_ n: Int) {
    // countdown(n - 1) だけだと止まらずクラッシュ（スタックオーバーフロー）
    if n <= 0 { return }          // 終了条件
    countdown(n - 1)
}
```

```swift
// fatalError("ここには来ない")          // 常にクラッシュ
// precondition(x > 0, "x は正")        // 条件を満たさないとクラッシュ
// assert(x > 0)                        // デバッグビルドのみクラッシュ
```
- 自分で書くことは少ない。ライブラリのコードに含まれる

# `if let` まとめ（`01_初心者メモ.md` の補足）

`01_初心者メモ.md` の「`Int?` の `?`」「`guard let`」を、例を増やして詳しくしたもの。
`nil` を置ける型の話は `01-3_型.md`、落ちる書き方は `01-1_Swiftのクラッシュ回避まとめ.md`。

## 1. 要点
- `if let` は、nil になりうる値（`?` が付く型 = Optional）から中身を取り出すための書き方
- nil になりえない `Int` / `String` などには使えない（エラーになる）
- Optional はSwiftの多くの場面で返ってくるため、`if let` はよく出てくる

---

## 2. 前提: `Int?` は `Int` とは別の型
```swift
let s: Int? = 5
```
- `s` は「`5` が入った箱」。`5` そのものではない
- 箱は「中身がある」か「空（nil）」のどちらか
- `+` や `>` などの計算・比較は、箱ではなく中身に対して行う
- `Int?` 以外も同じ。`String?` / `[Int]?` / `Product?` など、`型?` はすべて箱

```swift
let a: Int? = 5
// print(a + 1)        // エラー。箱のままでは計算できない
```

---

## 3. 基本の書き方
```swift
let s: Int? = 5

if let v = s {
    print(v + 1)       // 6。v は箱から出した中身（Int）
}
```
読み方: 「`s` に値が入っていれば、その中身を `v` に入れて `{ }` を実行する」

- この `=` は代入（比較は `==`）
- `s` が nil のときは `{ }` を飛ばす
- `v` は `{ }` の中でだけ使える

### `else` を付ける
```swift
let s: Int? = nil

if let v = s {
    print("値あり: \(v)")
} else {
    print("nil だった")      // こちらが実行される
}
```

### 同じ名前で取り出す
```swift
let s: Int? = 5

if let s {                 // if let s = s と同じ意味（Swift 5.7以降）
    print(s + 1)           // 6。この s は Int
}
```

### 複数をまとめる
```swift
let a: Int? = 1
let b: Int? = 2

if let x = a, let y = b {  // 両方に値があるときだけ実行
    print(x + y)           // 3
}

if let v = a, v > 0 {      // 取り出せて、かつ v > 0
    print(v)
}
```
- `,` は「かつ」。左が成り立ったときだけ右を調べる

---

## 4. なぜ変数を作るのか
`if let` の `v` は、箱から出した中身を入れる場所。

### 条件を通っても、型は `Int?` のまま
```swift
let n: Int? = 5

if n != nil {
    // print(n + 1)        // エラー。n はここでも Int?
    print(n! + 1)          // 6。! で取り出す必要がある
}
```
- Swiftは「条件を通ったから nil ではない」と判断して型を `Int` に変えない
- 型を `Int` にするには、`if let` / `guard let` / `!` / `??` のどれかを使う

### Optional の正体は enum
```swift
let s: Int? = 5

switch s {
case .some(let v):         // 中身がある
    print(v + 1)
case .none:                // 空（nil）
    print("nil")
}
```
- `if let v = s { ... } else { ... }` は、この `switch` を短く書いたもの

### 設計意図について
- 変数が `var` のとき、確認してから使うまでの間に値が変わる事故を、取り出した `v` が防ぐという説明がされることが多い
- 公式の設計意図の記述は未確認

---

## 5. 変数が `Int` か `Int?` かで書き方が変わる
```swift
let a: Int = 5
if a > 0 { print(a) }               // OK。if let は不要

let b: Int? = 5
// if b > 0 { }                     // エラー。Int? は > で比較できない
if let v = b, v > 0 { print(v) }    // OK
if (b ?? 0) > 0 { }                 // OK。nil のときは 0 として扱う
if b == 5 { }                       // OK。== と != は Optional のまま使える
```

| 変数の型 | `if n > 0 { }` |
| --- | --- |
| `Int` | そのまま書ける |
| `Int?` | エラー。`if let v = n, v > 0` か `(n ?? 0) > 0` にする |

---

## 6. Optional が返ってくる場面
```swift
let arr = [1, 2, 3]
let dict = ["a": 1]

if let v = arr.first { print(v) }          // 配列の先頭（空なら nil）
if let v = dict["a"] { print(v) }          // Dictionary の検索（なければ nil）
if let v = Int("123") { print(v) }         // 文字列→数値（変換できなければ nil）

let x: Any = 5
if let v = x as? Int { print(v) }          // 型の変換（できなければ nil）

// if let v = try? someThrowingFunc() { }  // try?（失敗したら nil）

if let data = UserDefaults.standard.data(forKey: "cart") { }   // 保存データ（なければ nil）
```
- `03_レッスン.md` のレッスン8（永続化）の復元処理もこの形

### このアプリでの使いどころ
```swift
// Product の priceSats は Int?（sats単価なし = nil）
if let s = p.priceSats {
    sats += s                   // sats単価がある行
} else {
    jpyForSats += p.priceJpy    // sats単価がない行
}
```
- `03_レッスン.md` のレッスン4の `totals()` がこの形
- `stock`（在庫を数えない商品は nil）も同様

---

## 7. 取り出し方の比較
```swift
let s: Int? = 5

if let v = s { print(v) }      // 値があるときだけ実行
let a = s ?? 0                 // nil のときの代わりの値を決める
let b = s!                     // 決めつけて取り出す。nil だとクラッシュ
```

| 書き方 | nil のとき | 用途 |
| --- | --- | --- |
| `if let v = s { }` | `{ }` を飛ばす | 値があるときだけ処理したい |
| `s ?? 0` | 代わりの値を使う | 値がなくても続行したい |
| `s!` | クラッシュ | 絶対に nil でないと言い切れる場合のみ |

---

## 8. 仲間の書き方
### `guard let`（nil なら関数を抜ける）
```swift
func f(_ s: Int?) {
    guard let v = s else {
        print("nil")
        return                 // 必ず関数を抜ける処理を書く
    }
    print(v)                   // ここから下で v を使える
}
```
- `if let` は `{ }` の中でだけ `v` を使える
- `guard let` は、同じ階層の以降の行すべてで `v` を使える

### `if var`（取り出した値を変更したいとき）
```swift
let s: Int? = 5

if var v = s {
    v += 1
    print(v)                   // 6
}
```

### `while let`（nil になるまで繰り返す）
```swift
var stack = [1, 2, 3]

while let x = stack.popLast() {
    print(x)                   // 3, 2, 1
}
```

### `if case`（enum の関連値を取り出す）
```swift
enum Result2 {
    case ok(Int)
    case fail(String)
}

let r = Result2.ok(10)

if case .ok(let v) = r {
    print(v)                   // 10
}
```
- `if let v = s` は `if case .some(let v) = s` を短く書いたもの
- `if case` は Optional 以外の enum にも使える

| 書き方 | 使う場面 |
| --- | --- |
| `if let v = s { }` | 値があるときだけ処理する |
| `guard let v = s else { return }` | 値がなければ関数を抜ける。以降で `v` を使う |
| `if var v = s { }` | 取り出した値を変更する |
| `while let x = ... { }` | nil になるまで繰り返す |
| `if case .xxx(let v) = e { }` | enum の特定のケースのときだけ関連値を取り出す |

---

## 9. TypeScript との違い
```ts
// TypeScript
function f(n: number | null) {
    if (n !== null) {
        console.log(n + 1);    // n は number に絞り込まれる
    }
}
```
```swift
// Swift
func f(_ n: Int?) {
    if n != nil {
        // print(n + 1)        // エラー。絞り込まれない
    }
}
```
- TypeScript は条件で型が絞り込まれる。Swiftは絞り込まれない

# `nil` と型（`01-2_if.md` の補足）

`nil` をどこに置けるか、型がどう決まるかの話。
`if let` の使い方そのものは `01-2_if.md`、用語は `01_初心者メモ.md` を見る。

## 型を書けば入れられる
```swift
let a: Int? = nil        // OK
var b: Int? = nil        // OK。あとで値を入れられる
b = 5
```

## 型を書かないとエラー
```swift
// let c = nil           // エラー。nil だけでは何の型の nil か決まらない
```
- `nil` は「`Int?` の空」「`String?` の空」など、型ごとに別の空
- `: Int?` のように型を書いて、何の Optional かを決める

## 型が決まる場面では、型の指定なしで `nil` を渡せる
```swift
struct Product {
    let id: String
    let priceSats: Int?
}

let p = Product(id: "ST-003", priceSats: nil)    // priceSats は Int? と決まっているので OK
```
- `03_レッスン.md` のレッスン3の `priceSats: nil` がこの形
- 実際に使う `Product` は `base/Types.swift` に1つだけある。ここでは形の説明のために最小限を書いている

## `Int`（`?` なし）には入れられない
```swift
// let d: Int = nil      // エラー
```
- 「値なし」を許したい欄だけ `?` を付ける
- 在庫のように「管理しない種類がある」欄は `stock: Int?` になる（`base/Types.swift` の `Product`）

# 引数の型（`01-3_型.md` の補足）

「`String` と `[String]` の両方を受けたい」など、**引数の型**の書き分け。
TypeScript の `function f(x: string | string[])` に相当する書き方は、次の4つ。

## 1. オーバーロード（同じ名前で引数の型違いの関数を2つ書く）
```swift
func show(_ s: String) {
    show([s])                  // 1つのときは配列にして、もう一方に任せる
}

func show(_ list: [String]) {
    for s in list {
        print(s)
    }
}

show("abc")                    // String の方が呼ばれる
show(["a", "b"])               // [String] の方が呼ばれる
```
- Swiftは、引数の型が違えば同じ名前の関数を複数書ける
- 呼ぶ側は、型を意識せず同じ名前で呼べる
- 実際の処理は片方（配列）に書き、もう片方は変換して渡すだけにする

## 2. 可変長引数（`String...`）
```swift
func show(_ items: String...) {
    for s in items {           // items は [String]
        print(s)
    }
}

show("abc")                    // 1つ
show("a", "b", "c")            // 複数
```
- 呼ぶ側は、値を `,` で並べて渡す
- 配列をそのまま渡すことはできない
```swift
let list = ["a", "b"]
// show(list)                  // エラー
```

## 3. enum を引数にする
```swift
enum StringOrList {
    case one(String)
    case many([String])
}

func show(_ x: StringOrList) {
    switch x {
    case .one(let s):     print(s)
    case .many(let list): list.forEach { print($0) }
    }
}

show(.one("abc"))
show(.many(["a", "b"]))
```
- 呼ぶ側が `.one(...)` / `.many(...)` と書く必要がある

## 4. ジェネリクス（共通の性質で受ける）
```swift
func count<T: Collection>(_ x: T) -> Int {
    x.count
}

print(count("abc"))            // 3（String は文字の集まり）
print(count(["a", "b"]))       // 2
```
- `String` も `[String]` も「Collection（要素の集まり）」という共通の性質を持つ
- 上の例は `String` を文字の集まりとして扱うため、`"abc"` が「1つの文字列」ではなく「3文字」として数えられる
- 「1つの文字列」と「文字列の配列」を区別したい場合には向かない
- ジェネリクスは `51_ジェネリクスを使う.md` で扱う

## 使い分け

| 方法 | 向いている場面 |
| --- | --- |
| オーバーロード | 呼ぶ側を `show("a")` / `show(["a"])` のままにしたい（TypeScript に最も近い） |
| 可変長引数 | 値を直接並べて渡す使い方が中心 |
| enum | 3つ以上の型を区別して扱いたい |
| ジェネリクス | 共通の性質で処理でき、型を区別しなくてよい |

## レッスン1: Swiftの基本を一通り

以降のレッスンで使う部品だけを、1つのブック（Playgrounds）に順に書いて動かす。
Playgroundsのチュートリアルを進めてもよい。ここでは**このアプリで使うものだけ**に絞る。

### ① 変数と定数

```swift
let shopName = "ステッカー屋"   // let = 後から変えられない（定数）
var count = 0                   // var = 後から変えられる（変数）
count = count + 1
count += 1                      // 「足して代入」。上と同じ意味

let priceJpy: Int = 300         // 型を明示する書き方（Int = 整数）
let name: String = "ステッカー"  // String = 文字列

print(shopName, count, priceJpy, name)
print("\(name) は ¥\(priceJpy)")  // \( ) で文字列の中に値を埋め込む
```
- `let` を基本にし、変わる物だけ `var` にする
- 主な型: `Int`（整数）/ `String`（文字列）/ `Bool`（true / false）

### ② if（条件分岐）

```swift
let stock = 0

if stock > 0 {
    print("買える")
} else {
    print("SOLD OUT")
}
```
- 比較: `==`（等しい）`!=`（等しくない）`>` `<` `>=` `<=`
- 「かつ」は `&&`、「または」は `||`

### ③ 配列と for（繰り返し）

```swift
let prices = [300, 300, 800]

var sum = 0
for p in prices {      // 1個ずつ p に入れて繰り返す
    sum += p
}
print(sum)             // 1400
print(prices.count)    // 3（個数）
```

### ④ 関数

```swift
func addTax(_ price: Int) -> Int {   // (引数) -> 返す型
    return price * 110 / 100
}

print(addTax(300))   // 330
```
- `func 名前(引数) -> 返す型 { ... }`
- `_` を付けると呼ぶとき引数名を書かなくてよい（`addTax(300)`）

### ⑤ 構造体（struct）

```swift
struct Item {
    let name: String
    let priceJpy: Int
}

let a = Item(name: "ステッカー", priceJpy: 300)
print(a.name, a.priceJpy)   // .（ドット）で中身を取り出す
```
- 関連する値を1つにまとめる型。`Item(...)` で作る

### ⑥ enum（選択肢）

```swift
enum Pay {
    case cash
    case lightning
}

let pay = Pay.cash

switch pay {
case .cash:      print("現金")
case .lightning: print("ライトニング")
}
```
- 決まった選択肢のどれか1つ、を表す型。`switch` で分岐する
- `switch` はすべての `case` を書く必要がある

### ⑦ オプショナル（nil かもしれない値）

```swift
let satsPrice: Int? = nil     // Int? = 「Int か nil（値なし）」

if let s = satsPrice {        // 値があるときだけ中に入る
    print("\(s) sats")
} else {
    print("sats単価なし")
}

let shown = satsPrice ?? 0    // nil のときの代わりの値
print(shown)                  // 0
```
- `?` を付けた型は nil になりうる。使う前に `if let` か `??` で確認する

**できた合図**: ①〜⑦の各 `print` が、コメントに書いた結果と同じになる。

```swift
// 在庫を1つ減らす（stock は var なので変えられる）
```

## レッスン5: ID正規化（`"kh8"` → `"KH-008"`）

入力したIDを**決まった形**に直す。今回は「英字（接頭辞）＋3桁ゼロ埋め」。

```swift
import Foundation  // String(format:) を使うため

func normalizeID(_ raw: String) -> String {
    let upper  = raw.uppercased()                 // 小文字→大文字
    let letters = upper.filter { $0.isLetter }    // 英字だけ取り出す
    let digits  = upper.filter { $0.isNumber }    // 数字だけ取り出す
    let n = Int(digits) ?? 0                       // 数字にする（空なら0）
    return letters + "-" + String(format: "%03d", n) // 3桁ゼロ埋め
}

print(normalizeID("kh8"))     // KH-008
print(normalizeID("KH-020"))  // KH-020
print(normalizeID("st 1"))    // ST-001
```
- `.filter { }` … 条件に合う文字だけ残す
- `String(format: "%03d", n)` … 3桁にゼロ埋め（8 → 008）
- 全角の英字対応などは**後で**でよい（今は半角前提）

**できた合図**: `KH-008` / `KH-020` / `ST-001` が出る。

## レッスン8: データを保存してアプリを閉じても消えないようにする（永続化）

ここまでのレッスンでは、プログラムを実行している間だけメモリ上に存在するデータを扱ってきた。

### ステップ1: 必要な道具箱の読み込みと、保存するデータの形（構造体）を決める

まずは、ファイルの冒頭で標準ライブラリ（道具箱）を読み込み、保存したいデータ（カートの1行分）の設計図を作る。

```swift
import Foundation

//   struct CartLine: Codable { id / typeId / name / unitPriceJpy / unitPriceSats / qty / isAdhoc }
// Codable が付いていれば、保存・復元に必要な情報はすべて揃っています。
```

> `Codable` が無い構造体は `JSONEncoder` に渡せません。また、**保存したあとに項目を増やすと過去のJSONが読めなくなります**（→ `try?` が失敗を隠して、カートが空に見える。末尾の注意参照）。形を足すなら `CodingKeys` の `decodeIfPresent` を使い、既定値を埋める形にします。

* **`Codable`**: Swiftの構造体を、保存用のデータ形式（JSON）に変換したり、逆に元に戻したりするためのプロトコル（印）。これがないと `UserDefaults` に保存できない。

### ステップ3: データをJSONに変換して保存する

作成した構造体の配列はそのままではストレージに入れられないため、`JSONEncoder` を使ってバイナリデータ（JSON形式の `Data` 型）に変換し、`UserDefaults`（キー・バリュー形式の保存領域）に書き込む。

```swift
let encoder = JSONEncoder()
let userDefaults = UserDefaults.standard

do {
    let data = try encoder.encode(lines)
    userDefaults.set(data, forKey: "cart")
    print("保存した")
} catch {
    print("エンコード失敗: \(error)")
}

```

* **`JSONEncoder()`**: Swiftの構造体配列を、保存用のバイナリデータに変換する機械。
* **`try`**: 失敗するかもしれない処理（エラーを投げるかもしれない処理）を実行する印。失敗したときは `catch` に移る。
* **`do-catch`**: エンコードの失敗を受け止め、`error` として理由を表示する。`fatalError` で落とさない。
* **`UserDefaults.standard`**: アプリの軽量なデータを端末に保存するための標準ストレージ領域。
* **`userDefaults.set(data, forKey: "cart")`**: `"cart"` という名前（キー）をつけて、変換したデータをストレージに書き込む。

> `try?` で受けると、失敗したときに `nil` になるだけで**理由が消えます**。
> 学習中は `do-catch` で `error` を読むほうが、原因を見つけやすいです。

### ステップ4: 保存したデータを取り出して復元する

ストレージに保存したデータを `"cart"` というキーで呼び出し、今度は `JSONDecoder` を使って元の Swift の構造体配列に組み立て直す。

```swift
if let savedData = userDefaults.data(forKey: "cart") {
    do {
        let restored = try JSONDecoder().decode([CartLine].self, from: savedData)
        print("復元成功: \(restored)")
    } catch {
        print("デコード失敗: \(error)")
    }
} else {
    print("保存データなし")
}

```

* **`userDefaults.data(forKey: "cart")`**: 指定したキーに保存されているバイナリデータを、`Data?`（無ければ `nil`）で取得する。
* **`if let`**: 保存データがあるときだけ復元する。無いときは `else` で「保存データなし」と表示する。
* **`try`（通常の try）**: エラーを投げる可能性がある処理を、`do-catch` の中で実行する。失敗してもアプリ全体を落とさず、`catch` で受け止める。
* **`JSONDecoder().decode(...)`**: 取得したバイナリデータを読み込み、元の `[CartLine]` 型の配列に復元する。
* **`do-catch`**: デコード時に予期せぬエラーが起きても、エラー内容を表示して安全に対処するための構文。

### まとめと、触ってはいけない場所

- 保存は `JSONEncoder` でJSONにして `UserDefaults` に書き、復元は `JSONDecoder` で読み戻す。
- **復元できない理由の多くは「保存した時の形と、復元する時の形が違う」こと**です。

実際に起こる例:

```swift
// 保存した時（旧い形のイメージ）
struct OldCartLine: Codable {
    var id: String; var name: String; var priceJpy: Int; var qty: Int
}
// → {"id":"KH-002","name":"キーホルダー 02","priceJpy":800,"qty":1}

// 後から項目を増やした現在の形（イメージ）
struct NewCartLine: Codable {
    var id: String; var name: String; var unitPriceJpy: Int; var unitPriceSats: Int?
    var qty: Int; var isAdhoc: Bool
}
try? JSONDecoder().decode([NewCartLine].self, from: oldData)   // → nil（キー不足）
```

> 実際の `CartLine` は `base/Types.swift` にあります。ここでは「形が変わると読めなくなる」ことだけを見るため、`OldCartLine` / `NewCartLine` という別名で説明しています。

`Codable` は「キーが足りなければ失敗」とします。そして `try?` はその失敗を **nil に変えて黙る** ので、結果として**カートが空に戻ったように見える**だけのバグになります（`49_エラー処理を書く.md` の「`try?` は理由を消してしまう」）。

**対策**: ① 復元は `do-catch` で失敗理由まで読む（`19_会計状態をまるごと保存する.md`）。② 過去のデータにも対応したい場合は `init(from decoder:)` を自前で書いて、`decodeIfPresent` で既定値を埋める。

### 最終的な完成コード

ステップ1〜5をすべて繋げた、レッスン8の完全なコード。
**`CartLine` は `base/Types.swift` のものをそのまま使います**（下のコードは貼り付け済みの前提で、再定義しません）。

```swift
import Foundation

// 1. 保存するデータを作る（CartLine は base/Types.swift のもの）
let lines = [CartLine(id: "ST-001", typeId: "sticker", name: "ステッカー まる",
                      unitPriceJpy: 300, unitPriceSats: 500, qty: 2, isAdhoc: false)]

// 2. エンコードと保存
let encoder = JSONEncoder()
let userDefaults = UserDefaults.standard

do {
    let data = try encoder.encode(lines)
    userDefaults.set(data, forKey: "cart")
    print("保存した")
} catch {
    print("エンコード失敗: \(error)")
}

// 3. 保存データの取り出し（復元）
if let savedData = userDefaults.data(forKey: "cart") {
    // 4. デコード（構造体への復元）とエラーハンドリング
    do {
        let restored = try JSONDecoder().decode([CartLine].self, from: savedData)
        print("復元成功: \(restored)")
    } catch {
        print("デコード失敗: \(error)")
    }
} else {
    print("保存データなし")
}

// 5. 実行基盤のホームディレクトリ確認（Mac / Linux では確認用。Playgrounds では不要）
print("Home Directory: \(NSHomeDirectory())")
```

**できた合図**: `保存した`、`復元成功: [...]`、`Home Directory: ...` の3行が出る（配列の中身は環境で変わる）。
2回目に実行しても `復元成功` が出れば、保存が効いている。

### 補足: VS Code / Linuxコンテナで試す場合

Swift Playgrounds では意識しなくてよいが、Linux の Swift で `UserDefaults` を試すと保存先が気になることがある。

- **macOSとの保存先の違い**: macOSの標準アプリ（plistファイル等）とは異なり、Linux環境のSwift（CoreFoundation / Foundation）では、通常 `~/.local/share/` や、実行中のユーザーのホームディレクトリ配下の隠しディレクトリにデータベースやplistとして書き込まれる。
- **スクリプト実行時の挙動**: ターミナルで `swift ファイル名.swift` と直接スクリプト形式で実行した場合、プロセスごとに一時的な領域が使われるか、同じユーザーセッション内であれば同じ領域を共有する。そのため、2回目の実行時にデータが残っていて復元成功することがある。
- **確認方法**: `print(NSHomeDirectory())` でホームディレクトリを表示し、その下を探す。

> この保存はあくまで学習用。実運用では `SaleContextStore` のように、失敗を `throws` で外へ出し、`.atomic` でファイルに書く。

# Svelte 5で理解するSwift

Svelteが分かる人向けに、Swift / SwiftUI / Xcode を**対応づけて**説明する資料。
「あれはSvelteでいう何？」と思ったらここを見る。

> **このファイルの位置づけ**: `01_初心者メモ.md` の補足（他言語との比較）。
> JS / TS / C# との文法の違いは `04-1_Swiftの違い.md` にまとめてある。
> ここに出てくる SwiftUI のコードは**形の説明用**で、そのまま `swift` コマンドでは動かない。

---

## 一番大事な違い
- Swiftは**全部 `.swift` ファイル**。`.svelte` / `.ts` のような拡張子の分け方は無い
- 役割は**中身**で決まる
  - `struct ○○: View` に従ったもの＝**UI部品**
  - それ以外の `func` / `struct` / `class` / `enum`＝**処理**
- **UIもただのSwiftコード**。境界は「`View` かどうか」だけ

> SwiftUIの View は、Svelteでいう `.svelte` ファイル1個ぶんに近い。
> 上のほうの `let` / `@State` が `<script>`、`var body` の中がマークアップ。

## 対応表（早見）
| Svelte | Swift / SwiftUI |
| --- | --- |
| `.svelte` ファイル | `struct ○○: View { var body: some View }` |
| `.ts` ファイル | 普通の `.swift`（`func` / `class` / `struct`） |
| コンポーネントを入れ子 | Viewの中にViewを入れる |
| `let { prop } = $props()` | Viewのプロパティ `let prop: String`（外から渡す） |
| `bind:value`（双方向） | `@Binding var value` |
| `let count = $state(0)` | `@State var count = 0` |
| 派生値 `let x = $derived(a*2)` | 計算プロパティ `var x: Int { a*2 }` |
| `$effect(() => {})` | `.onChange { }` / `.task { }` / `.onAppear { }` |
| store（`writable`） | `@Observable` クラス（古: `ObservableObject`＋`@Published`） |
| グローバルなstore | 共有した `@Observable` を `@Environment` で配る |

| `<slot/>` | `@ViewBuilder` のクロージャプロパティ |
| `onMount(() => {})` | `.onAppear { }` |

| TSの `interface` | `struct`（データの形） |

| `async/await` | `async/await`（ほぼ同じ） |

# Swiftの違い（JS / TS / C#経験者向け）

Swiftは初めてだが、**JS / TS / C# の経験がある人**向けの、文法の差分チートシート。
Svelteとの対応は `04_Svelteで理解するSwift.md`、Swiftの用語は `01_初心者メモ.md`。

> このファイルのコードは**差分を見せるための断片**です。`a` や `x` などは未定義のまま出てくるので、
> そのまま `swift` で実行するものではありません。

## 1. 演算子の前後の空白
```swift
let c1 = a + b   // OK
let c2 = a+b     // OK
let c3 = a +b    // エラー
```
両側に空白、または両側とも空白なし。C# / JS にはない規則。

## 2. 条件式に括弧は不要。`{ }` は必須
```swift
if x > 0 { print("正") }   // OK
// if (x > 0) print("正")  // エラー（{ } を省略できない）
```
C# は括弧が必須で `{ }` は省略可。Swiftは逆。

### 条件は `,` で並べられる
```swift
if x > 0, y > 0 { print("両方正") }
if x > 0 && y > 0 { print("両方正") }   // 同じ意味
```
- `,` で区切られた各要素が条件1つ。すべて真のときだけ `{ }` が実行される
- 左から順に評価し、偽が出た時点で打ち切る（`&&` と同じ短絡評価）
- `if` / `guard` / `while` で共通の文法
- OR は `,` で書けない。`||` を使う
- `,` と `&&` / `||` は併用できる。1つの要素の中では `&&` / `||` が先に評価される
```swift
if a > 0 || b > 0, c > 0 { }   // (a > 0 || b > 0) かつ c > 0
```
- `,` が `&&` と違う点は、要素に `let`（オプショナルバインディング）を書けること。§6 を参照

## 3. 条件は Bool のみ（truthy / falsy がない）
```swift
let n = 1
// if n { }        // エラー
if n != 0 { }      // OK
```
C# と同じ。JS / TS とは違う。

## 4. 型の暗黙変換がない
```swift
let a: Int = 3
let b: Double = 1.5
// let c = a + b          // エラー
let c = Double(a) + b     // OK
```
C# は `int + double` が通る。Swiftは通らない。

## 5. 型は名前の後ろに書く。引数名は呼び出し時に書く
```swift
let price: Int = 300

func add(price: Int, tax: Int) -> Int { price + tax }
add(price: 300, tax: 30)       // 引数名を書く（C# の名前付き引数は任意。Swiftは基本必須）

func add2(_ price: Int, _ tax: Int) -> Int { price + tax }
add2(300, 30)                  // _ を付けた引数は名前を書かない
```
- 1つの式だけの関数は `return` を省略できる
- C# の `var` は型推論のみ。Swiftの `let` / `var` は「変更できるか」を表す（型推論は両方で効く）

## 6. null がない。代わりにオプショナル
```swift
var s: Int? = nil     // Int? は Int とは別の型
// let t: Int = s     // エラー
if let v = s { print(v) }   // 確認してから取り出す
let w = s ?? 0              // nil のときの代わりの値（C# の ?? と同じ）
let x = s!                  // 強制取り出し。nil だと実行時にクラッシュ
```
- C# の `int?` に近いが、Swiftは参照型（class）も含めて、nil にしたい型にはすべて `?` が必要
- C# の `!` はコンパイラ警告を消すだけ。Swiftの `!` は nil のときクラッシュする

### `if let` と `,`（§2 の条件リスト）
```swift
if let i = idx, i > 0 { print(i) }                  // 取り出して、さらに条件
if let i = idx, let j = jdx, i < j { print(i, j) }  // 取り出しを複数
```
- `let` は条件リストの1要素として書ける。取り出せれば真、nil なら偽
- 前の要素で取り出した変数を、後の要素で使える（上の例では `i`）
- 1つでも偽（または nil）なら `{ }` は実行されない
- `if let` で取り出した変数は `{ }` の中だけで使える。外でも使う場合は `guard let`（§22）

## 7. struct は値型。配列・文字列も値型
```swift
struct P { var n: Int }
var a = P(n: 1)
var b = a        // コピー
b.n = 2
print(a.n)       // 1（a は変わらない）

var xs = [1, 2, 3]
var ys = xs      // 値としてコピーされる
ys.append(4)
print(xs.count)  // 3
```
- struct の値型は C# と同じ
- C# の配列 / `List` は参照型で共有される。Swiftの配列は値型（必要に応じてコピーされる）
- JS のオブジェクト / 配列は参照が共有される

## 8. `let` は中身も変えられない（struct の場合）
```swift
struct P { var n: Int }
let p = P(n: 1)
// p.n = 5        // エラー
```
JS の `const` は中身を変えられる。C# の `readonly` に近いが、Swiftはその変数全体が対象。

## 9. 関数の引数は変更できない（`inout` で参照渡し可能）
```swift
// デフォルトでは引数は let 扱いで変更できない
func f(_ x: Int) {
    // x += 1     // エラー
}

// inout を付けると、呼び出し元の変数を直接書き換えられる（C# の ref と同じ）
func increment(_ x: inout Int) {
    x += 1
}

var num = 10
increment(&num)  // 呼び出し側も & を付けて「書き換えに同意」する必要がある
print(num)       // 11
```
- C# の値型引数はデフォルトでコピーだが、変更したい場合は `ref` を使う。Swift もこれに近く、配列（値型）を関数内で `append` などで書き換えたい場合に `inout` が必須になる。
- JS / TS の配列やオブジェクトは参照型なので、関数内での変更が自動的に呼び出し元に反映されるが、Swift の配列は値型のため、明示的に `inout` を使わないと反映されない。

## 10. enum は「関連値」を持てる。switch は「パターンマッチング」

### enum は関連値（Associated Values）を持てる
C# や TS の enum は単なる数値の別名だが、Swift の enum はケースごとに「異なる型や複数の値」を保持できる（TS の判別共用体 / Union 型に近い）。

```swift
struct Product: Equatable { let name: String }

// カートの1行（形は base/Types.swift の CartLine と同じ）
struct CartLine {
    let id: String
    let typeId: String?
    let name: String
    let unitPriceJpy: Int
    let unitPriceSats: Int?
    var qty: Int
    let isAdhoc: Bool
}

// 追加結果（成功時は商品と数量、失敗時はエラー理由を持つ）
enum AddResult {
    case added(Product, qty: Int)  // 1つ目は型のみ、2つ目は qty というラベル付き
    case failed(String)
}

func message(_ r: AddResult) -> String {
    switch r {
    case .added(let p, let qty):     // 関連値を p と qty として取り出す（値の束縛）
        return "追加: \(p.name) × \(qty)"
    case .failed(let reason):
        return "エラー: \(reason)"
    }
}
```
- `case added(Product, qty: Int)` のように、ケースごとに保持するデータ型を定義できる。
- `switch` 文の中で `let p, let qty` のように書くことで、格納されている値を変数として取り出せる（これを「値の束縛 / バインディング」と呼ぶ）。
- ラベル（`qty:`）は任意だが、意味を明確にしたい場合に付ける。`Product` のように型名だけで意味が明らかな場合は省略されることが多い。

### Swift の switch は「パターンマッチング」
C# や JS の `switch` は「値の一致を判定するだけ」だが、**Swift の `switch` は「データ構造を分解するパターンマッチング」** である。これが最大の違い。

```swift
// ① 値の一致を判定（where 句で中身を見る）
case .added(let p, let qty) where p.name == "りんご" && qty == 3:

// ② 型の一致だけを判定（値は無視）
case .added(_, _):

// ③ 条件付きで判定（where 句）
case .added(let p, let qty) where qty > 0:

// ④ 値を取り出す（バインディング）← これが最も一般的
case .added(let p, let qty):
```

> `case .added(Product(name: "りんご"), qty: 3):` のように書くこともできますが、`Product` が `Equatable` のときだけです。中身を条件で見るなら `where` のほうが分かりやすいです。

これらはすべて「パターン」としての `case` の使い方であり、**`let` の有無で「値の一致」と「値の取り出し」を区別している**。

#### なぜ `let` が必要なのか？
もし `let` なしで `case .added(p, qty):` と書くと、それは「外で宣言した変数 `p` と `qty` の値と一致するか」を判定する意味になる。

```swift
let p = Product(name: "りんご")  // 外で宣言
let qty = 3                      // 外で宣言

switch r {
case .added(p, qty):             // r.added の中身が、外の変数 p と qty と「一致するか」を判定
    print("一致した")
}
```

つまり、**「外で宣言した変数に代入する」方式は、Swift の「パターンマッチングで値を取り出す」機能とは互換性がない**ため、`case` の中で `let` を使って「この case ブロック内だけで使える新しい変数を宣言する」方式になっている。

#### `.` の正体：型名のショートカット
`case .added(let p, let qty):` の `.` は「型名（`AddResult`）の省略」。

```swift
// ① 型名をちゃんと書いた場合
case AddResult.added(let p, let qty):

// ② 型名を省略して . だけ書いた場合（一般的）
case .added(let p, let qty):
```

この2つは完全に同じ意味。`.` は「型名は省略したけど、列挙型のケースを参照しています」という目印。

#### パターンマッチングは switch 以外にも使える
この「パターンマッチング」機能は `switch` 文だけでなく、`if` 文や `guard` 文でも使える。

```swift
// if case（switch の1ケースだけ使う場合）
if case .added(let p, let qty) = r {
    print("追加: \(p.name) × \(qty)")
}

// guard case（早期リターンと組み合わせる場合）
guard case .added(let p, let qty) = r else {
    return
}
```

つまり、**「パターンマッチング」は Swift の言語機能として一般的に使えるものであり、`switch` はその代表的な使い方の1つ**。

### switch の基本ルール
```swift
enum Color { case red, blue }
let c = Color.red
switch c {
case .red:  print("赤")    // 下の case には流れ落ちない
case .blue: print("青")
}
```
- 全ケースを書くか `default:` を付ける。C# の switch 文は網羅を要求しない
- C# と同じく流れ落ちない。ただし `break` は不要（C# は必要）

### switchで複数のケースに同じ処理を書く

#### `,` で並べる
```swift
enum Color { case red, blue, green, yellow }
let c = Color.red

switch c {
case .red, .yellow:      // red または yellow
    print("暖色")
case .blue, .green:      // blue または green
    print("寒色")
}
```

#### 残りをまとめて `default`
```swift
switch c {
case .red:
    print("赤")
default:                 // red 以外すべて
    print("赤以外")
}
```

#### Int の範囲も書ける
```swift
let n = 5

switch n {
case 0:
    print("ゼロ")
case 1...9:              // 1 から 9
    print("1桁")
default:
    print("2桁以上")
}
```
- C# の `case A: case B:` と並べる書き方は、Swiftでは `case .a, .b:` と1行にする
- 1つの `case` には、1つ以上の文が必要

## 11. `++` / `--` がない
```swift
var i = 0
i += 1       // OK
// i++       // エラー
```
C# / JS にはある。

## 12. 文字列は Int の添字で取り出せない
```swift
let s = "abc"
// s[0]                          // エラー（C# の s[0] は通る）
let first = s.first               // Optional("a")
let second = s[s.index(s.startIndex, offsetBy: 1)]   // "b"
```

## 13. 範囲外アクセス・オーバーフローはクラッシュする
```swift
let arr = [1, 2, 3]
// arr[5]    // 実行時にクラッシュ
```
- C# は `IndexOutOfRangeException` で、`try/catch` で受けられる。Swiftの配列の範囲外アクセスによるクラッシュは `do/catch` で受けられない
- `Int` の上限超えも通常の算術演算ではクラッシュする。C# は通常の設定では整数演算が折り返す
- JS は配列の範囲外アクセスで `undefined` になる
- クラッシュする書き方の一覧と回避は `01-1_Swiftのクラッシュ回避まとめ.md`

## 14. 文字列補間は `\( )`
```swift
let name = "A"
print("こんにちは \(name)")     // JS の `${name}` / C# の $"{name}" に相当
```

## 15. 範囲
```swift
for i in 0..<3 { print(i) }    // 0, 1, 2
for i in 0...3 { print(i) }    // 0, 1, 2, 3
```
`for (int i = 0; i < 3; i++)` 形式の `for` はない。

## 16. 命名の慣習
- 型（struct / enum / class）は `UpperCamelCase`: `Product`
- 変数・関数・プロパティは `lowerCamelCase`: `priceJpy`
- C# はメソッドとプロパティが `UpperCamelCase`。Swiftは `lowerCamelCase`

## 17. 行末の `;` は不要
改行が文の区切り。1行に複数の文を書くときだけ `;` を使う。

## 18. エラー処理は `throws` / `try` / `try?` / `try!`
```swift
enum MyError: Error { case bad }

func g(_ x: Int) throws -> Int {
    if x < 0 { throw MyError.bad }
    return x
}
```
- C# / JS は例外を `throw` するだけで、呼び出し側に `try` を書く義務はない。Swiftは `throws` 付きの関数を呼ぶ際、必ず `try`（または `try?` / `try!`）を明示する必要がある。

### 通常の `try`（`do-catch` と組み合わせる）
```swift
do {
    let r = try g(1)       // throws の関数を呼ぶときは try が必須
    print(r)
} catch {
    print("失敗: \(error)") // MyError.bad などがここに入る
}
```

### `try?`（エラー時に `nil` を返す）
```swift
let r1 = try? g(1)   // Int? 型になる。成功時は 1、失敗時は nil
let r2 = try? g(-1)  // nil になる（エラー内容は破棄される）
```
- C# / JS にはない構文。「成功した値」か「失敗して nil」の2択で扱いたい場合に便利。エラーの詳細が不要なときに `do-catch` を省略できる。
- 戻り値の型は自動的に Optional（`Int?` など）になる。

### `try!`（失敗時に強制クラッシュ）
```swift
let r3 = try! g(1)   // Int 型になる。成功時は 1
// let r4 = try! g(-1) // 実行時にクラッシュする
```
- 「この引数なら絶対にエラーにならない」と確信できる場合のみ使用する。C# で例外が来ないとわかっている場合に `catch` を書かないのと似ているが、Swiftでは万が一エラーになるとアプリが落ちるため注意が必要。
- `try!` のようなクラッシュする書き方の一覧は `01-1_Swiftのクラッシュ回避まとめ.md`

## 19. インスタンス生成に `new` は不要
```swift
struct P { var n: Int }
let a = P(n: 1)    // C# の new P(...) に相当
```

## 20. クロージャの `$0` は JavaScript の `a => ...` の `a` に相当

クロージャは、関数に渡す処理を `{ }` で書いたもの。`map`・`filter`・`reduce` などで「渡された値をどう処理するか」を指定するときによく使う。

### JavaScript / TypeScript と Swift の対応

**JavaScript / TypeScript**
```javascript
const nums = [1, 2, 3, 4];

nums.map(a => a * 2);               // [2, 4, 6, 8]
nums.filter(a => a % 2 === 0);      // [2, 4]
nums.reduce((s, a) => s + a, 0);    // 10
[1, 2, 3, 4].sort((a, b) => b - a); // 降順
```

**Swift**
```swift
let nums = [1, 2, 3, 4]

nums.map { $0 * 2 }                 // [2, 4, 6, 8]
nums.filter { $0 % 2 == 0 }         // [2, 4]
nums.reduce(0) { $0 + $1 }          // 10
nums.sorted { $0 > $1 }             // [4, 3, 2, 1]
```

- JSの `a => a * 2` の `a` を、Swiftでは引数名を省略して `$0` と書ける（`{ a in a * 2 }` と名前を付けてもよい）
- `$1` は2番目の引数：`reduce` では現在の要素、`sorted` では比較相手
- 同じクロージャの中で `$0` と `a in` を混ぜない
- 短い処理は `$0`、長い・意味をはっきりさせたい処理は名前を付ける

> `$0`・`$1`・`$2` の詳しい説明、`reduce`/`sorted` の動き、文字列の例、使い分けは
> `01_初心者メモ.md` の「`$` って？」にまとめてある。

## 21. キーパス (`\.`) と `\.self`

SwiftUI の `ForEach` などで見かける `\.` は「キーパス（Key Path）」と呼ばれる機能です。プロパティへの参照を型安全に渡す仕組みです。

### `\.self` の意味
`\.self` は「**その要素そのもの**」を指します。

### 他言語・フレームワークとの対応
| 言語・フレームワーク | 「要素そのもの」 | 特定のプロパティ |
| :--- | :--- | :--- |
| **SwiftUI** | `id: \.self` | `id: \.id` |
| **Svelte** | `{#each items as item (item)}` | `{#each items as item (item.id)}` |
| **React** | `key={item}` | `key={item.id}` |

配列の要素が「追加・削除・並び替え」されたとき、フレームワークが「**どの要素が変わったか**」を特定して、画面の更新を最小限にするために使う。

- `String` / `Int` など基本の型は値そのものが一意なので `\.self`（要素そのもの）を使う
- Svelte の `(item)` の詳しい話は `04_Svelteで理解するSwift.md`
- React の `key={item}` は SwiftUI の `id: \.self` と同じ意味

## 22. `guard`（早期脱出）

### 基本
```swift
guard 条件 else {
    // 条件が false のときだけ実行される
    return   // 必ずスコープを抜ける
}
// 条件が true のときだけここに来る
```
- `if` は「条件が真のとき `{ }` を実行」。`guard` は「条件が偽のとき `{ }` を実行して抜ける」
- 条件の書き方は `if` と同じ（§2 の `,` 条件リスト、§6 の `let` がそのまま使える）
- `else` の `{ }` は必ずスコープを抜ける。抜けないとコンパイルエラー
- 使える文：`return` / `throw` / `fatalError()` など。`continue` / `break` はループ内のみ
- JS / C# の `if (!cond) return;` による早期リターンに相当

### `if let` との違い：変数の有効範囲
```swift
// if let: { } の中だけ
if let v = s {
    print(v)       // OK
}
// print(v)        // エラー

// guard let: guard 以降のスコープ全体
guard let v = s else { return }
print(v)           // OK
```
- `if let` はネストが深くなりやすい
- `guard let` は取り出した変数を後続の処理全体で使えるため、ネストが浅くなる
- `if let` / `guard let` / `if var` / `while let` の比較は `01-2_if.md` §8

### 例：複数条件
```swift
for id in targets {
    guard id > 0,
          let i = inventory.firstIndex(where: { $0.id == id }),
          let current = inventory[i].stock else {
        continue
    }
    print("\(id): 在庫 \(current)")
}
```
- `guard` から `else` の前までが条件。3要素を `,` で並べている
- 1つでも偽（または nil）なら `else { continue }` が実行され、次のループへ進む
- すべて真なら `i` と `current` が `guard` 以降で使える
- 括弧がない代わりに、1要素1行で改行すると区切りが見やすい

# Xcodeでプロジェクト作成（マルチプラットフォーム）

Macが来たら最初にやること。**マルチプラットフォームのAppテンプレート**で作る方針。

> 先に `03_レッスン.md` のレッスン1〜8を済ませておくと、ここで作ったプロジェクトに
> 練習したコードをそのまま持ち込める。

---

## マルチプラットフォームとは
**1つのプロジェクトで、複数のプラットフォーム（iOS/iPadOS/macOS/tvOS/watchOS/visionOS）向けにビルドできる**テンプレート。共通コードを1つ書けば、各プラットフォームで動く。

## なぜこれで作るのか（今回の事情）
- 決定では **macOSのみ**（iPad版は当面作らない = Q19を先送り）
- でもマルチプラットフォームで作っておけば、**Supported Destinations を macOS だけ** にすればよく、**後でiPadを足したくなった時に追加するだけ**
- つまり「今はMacだけ、将来iPadの可能性も潰さない」が両立できる

---

## 作成手順
1. Xcode → **File > New > Project...**
2. 上部のプラットフォーム選択で **「Multiplatform」→「App」**
3. 入力:
   - **Product Name**: レジアプリの名前（例 `Reji`）
   - **Team**: 自分のApple ID（無料。後からでもよい）
   - **Organization Identifier**: 逆ドメイン風（例 `com.example`）
   - **Interface**: **SwiftUI**
   - **Language**: **Swift**
4. 保存場所を選んで作成
5. プロジェクト設定 → **TARGETS → General → 「Supported Destinations」** で対応プラットフォームを調整
   - **macOSを残し、使わないもの（iOS等）は外す**（今はmacOSだけ）
   - 実行先（Run destination）を **「My Mac」** にする（Simulatorではなく）

## コードの共通 / 分岐
- SwiftUIの部分は**そのまま全プラットフォームで共通**
- プラットフォームで違う所だけ `#if` で分ける:
```swift
#if os(macOS)
    // Mac用の処理
#elseif os(iOS)
    // iPad用の処理
#endif
```

## カメラ（QR読取）の注意
QRの**生成・読み取りのコード自体は共通**（CoreImage / Vision）。違うのは**カメラの許可の部分**。
- **macOS**: 既定でApp SandboxがON。カメラを使うには
  - Signing & Capabilities → **App Sandbox → Camera にチェック**（entitlement `com.apple.security.device.camera`）
  - Info に **`NSCameraUsageDescription`**（日本語の説明文）を追加
  - ※ 個人利用で配布しないなら、App Sandbox自体をOFFにする手もある（その場合はInfoだけで動く）
- **iOS/iPadOS**: Info に `NSCameraUsageDescription` を追加

**つまずき**: カメラ起動でクラッシュしたら、ほぼ**許可の設定漏れ**（entitlement か Info.plist）。
→ `37_QRをカメラで読み取る.md`

- Team に**無料のApple ID**を選ぶ。有料のDeveloper Programは**不要**（決定）
- macOSは「Sign to Run Locally」で動く
- **署名の有効期限は7日**として扱う（決定）。切れたら再ビルド/再インストール
- 営業日の前に再導入する日取りを確保する（`../開発/7_注意点と運用.md`）
