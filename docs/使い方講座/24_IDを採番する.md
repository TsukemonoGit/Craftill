商品ID の採番（`<接頭辞>-<番号>`）の考え方を、純ロジックで試します。

**正は `base/2_型定義.md` の `IdSequencer` にあります。**

| --- | --- | --- | --- |

## わざと間違う①: `String(format: "%03d")` を各所で使う

```swift NG
// わざと間違う版①：桁数が 3 で固定されている
func nextID(prefix: String, digits: Int, in productsList: [Product]) -> String? {
    let maxNum = maxNumber(for: prefix, in: productsList)
    let nextNum = maxNum + 1
    let maxByDigits = Int(pow(10.0, Double(digits))) - 1
    if nextNum > maxByDigits { return nil }
    return prefix + "-" + String(format: "%0\(digits)d", nextNum)   // ← 問題
}
```

**`%0\(digits)d` 自体は正しい**です。問題は**これを各所 に書く**こと。

| 場所 | 桁数 |
| --- | --- |
| `products.product_id` | **種類定義の `id_digits`**（種類ごとに違う） |
| `sales.sale_id` | **3**（`S-YYYYMMDD-001`） |
| `sale_items.item_id` | **2**（`…-01`） |
| `stock_movements.id` | **6**（`M-000001`） |
| `sync_log.id` | **6**（`L-000001`） |
| 野良 | **2**（`ADHOC-01`） |

**6 種類の数列で桁数が違います。** `String(format:)` を各所に書くと、
**1 か所だけ 3桁のまま**残ります（`38` の `encoder` の話と同じ）。

**正**は `IdSequencer.pad` **1 か所**です。

```swift 断片
// base/2 の正：pad は 1 か所だけ
private func pad(_ n: Int, _ width: Int) -> String {
    let s = String(n)
    return String(repeating: "0", count: max(0, width - s.count)) + s
}
```

> **`max(0, …)` が無いと壊れます**。`n` が桁数を超えたとき、
> `count` が負になって `String(repeating:count:)` が **クラッシュ**します。
> **`nextProductID` は `pad` を呼ぶ前に桁数を確認しています**（§わざと間違う③）。

## わざと間違う②: 「既存の最大 + 1」を自分で RDP する

```swift NG
// わざと間違う版②：最大番号を求める関数を作る
func maxNumber(for prefix: String, in productsList: [Product]) -> Int {
    var maxNum = 0
    for p in productsList {
        if p.id.hasPrefix(prefix + "-") {
            let parts = p.id.split(separator: "-", omittingEmptySubsequences: true)
            if parts.count == 2 {
                if let num = Int(String(parts[1])) { maxNum = max(maxNum, num) }
            }
        }
    }
    return maxNum
}
```

**正しい**です（`ST-003` → 3、`KH-020` → 20、該当なし → 0）。
**問題は 2 回書くこと**。

**`base/` では `static func`** にして、**採番する側からも使う**ようにしました。

```swift 断片
// base/2 の正
static func maxProductNumber(prefix: String, in products: [Product]) -> Int {
    var maxNum = 0
    for p in products where p.id.hasPrefix(prefix + "-") {
        let parts = p.id.split(separator: "-", omittingEmptySubsequences: true)
        guard parts.count == 2, let n = Int(parts[1]) else { continue }
        maxNum = max(maxNum, n)
    }
    return maxNum
}
```

**`static` にした理由**：`nextProductID` の**内側からも使う**ので、
インスタンスが要らないからです。**最大番号だけ知りたい画面**（`24` の通しの確認）からも呼べます。

## わざと間違う③: 桁数オーバーを `prefix + String(n)` で握りつぶす

```swift NG
// わざと間違う版③：桁数チェックを省く
return prefix + "-" + String(nextNum)          // ST-1000（4桁）が出る
```

**A-18** はこう書いています。

> 番号が桁数を超える場合（例：3桁で1000番）は**エラーとし、採番しない**。

**`ST-1000` を出してはいけません。** 印刷済みの QR ラベルと**不一致**になります
（A-18 の理由：印刷済みの QR ラベル・原本のファイル名との不一致を防ぐため、C-1 #27）。

**正**:

```swift 断片
mutating func nextProductID(type: ProductType, existing: [Product]) -> String? {
    let maxNum = Self.maxProductNumber(prefix: type.idPrefix, in: existing)
    let nextNum = maxNum + 1
    guard String(nextNum).count <= type.idDigits else { return nil }   // ★ 桁数チェック
    return "\(type.idPrefix)-\(pad(nextNum, type.idDigits))"
}
```

**`nil` を返した時は番号を消費しません**（`pad` を呼ぶ前に `return` している。
`nextNum` は**ローカル変数**で、`pad` を呼ぶ前に `return` しています）。

## 1. 販売系の採番との違い

**ここが一番違う点**:

| | 商品ID | 販売ID |
| --- | --- | --- |
| 数列 | **接頭辞ごと**（`ST` / `KH` / `X`） | **日付ごと**（`20231115`） |
| 桁数 | 種類定義の `id_digits` | **3** |
| 採番する場面 | **CSV 取り込み時** | **販売確定時** |
| 失敗したとき | 桁数超過で **`nil`** | **検証不通過で `S-…-002` に飛ぶ** |
| 元データ | 商品マスタ CSV | カート + 在庫表 |

**販売ID は「失敗しても飛ぶ」**のがポイント（A-19-4）。
`commitSale` は**検証に通ってから** `buildSale` を呼ぶので、
**在庫不足の会計では販売IDを消費しません**。下の通しの確認【7】で確認します。

## まとめ

- **ID は 6 種類**。**数列も桁数も全部違う**（A-19-4）
- **商品ID** は `nextProductID(type:existing:)`。**種類定義の `idPrefix` / `idDigits` に従う**（A-18）
- **最大番号は `IdSequencer.maxProductNumber(prefix:in:)`**（`static`）
- **欠番は再利用しない**。「今の最大 + 1」なので自然にそうなる（A-18、C-1 #27）
- **桁数を超える場合は `nil`**。**エラーとして採番しない**（A-18）
- **販売系の採番は販売確定時**。**検証不通過では消費しない**（A-19-4）
- **`pad` は 1 か所**。`max(0, …)` 付きで桁数超過を切らない
