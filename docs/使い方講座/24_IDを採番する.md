# レッスン24: IDを採番する

元: `../siyou.md` A-19-4（採番規則）、A-19-10（野良の採番）、A-19-12（商品ID の採番）
`../siyou.md` A-16（実装要件）、A-18（データ作成ツール、Mac上）

**正は `base/2_型定義.md` の `IdSequencer` にあります。**

このレッスンは **`IdSequencer` の採番を1本につなぐ**だけのレッスンです。
`nextSaleID` / `itemID` / `nextMovementID` / `nextLogID` / `nextAdhocID` は
**base に実装があります**。ここではそれらを **1本のプログラムに並べて**、
採番が壊れたら何が壊れるかを確かめます。

---

## このアプリが振る番号は、5つだけ

**商品ID（`KH-008` など）はアプリが振りません。** それがこのレッスンの主題です。

| # | ID | 形式 | 例 | 何の番号か | 振る瞬間 |
| --- | --- | --- | --- | --- | --- |
| 1 | `sales.sale_id` | `S-YYYYMMDD-NNN` | `S-20231115-001` | **会計1回ぶん** | 販売を確定した時 |
| 2 | `sale_items.item_id` | `{sale_id}-{n:02}` | `S-20231115-001-01` | 会計の中の**明細1行** | 明細を作るとき |
| 3 | `stock_movements.id` | `M-{連番:06}` | `M-000001` | **在庫が動いた1件** | 在庫を動かすとき |
| 4 | `sync_log.id` | `L-{連番:06}` | `L-000001` | **外へ送った1件** | 送信するとき |
| 5 | 野良のカート行（`CartLine.id`） | `ADHOC-{連番:02}` | `ADHOC-01` | 登録に無い商品の**仮番号** | カートに追加した瞬間（A-19-10） |

**商品ID は本に貼ってあるバーコード**（本そのものに付いていて、貸す前から在る）。
**この5つは、貸すたびに生まれる貸出票の番号**です。

| | 商品ID | この5つ |
| --- | --- | --- |
| いつ決まるか | **販売の前**（印刷済みQRラベル・原本画像の名前） | **販売の途中**（会計した瞬間） |
| 誰が振るか | **A-18（Mac上のデータ作成ツール）** | **アプリ** |
| アプリに要るか | **要らない**（A-16「アプリ本体には含めない」） | **要る** |
| アプリの役割 | **検証だけ**（形式・一意性。A-1） | **採番** |

下の「わざと間違う①〜③」は、**この5つをアプリが正しく振るには何に気をつけるか**の話です。

## わざと間違う①: `String(format:)` を各所で使う

```swift NG
// わざと間違う版①：桁数がここで 3 に固定されている
func nextMovementIDV1(_ n: Int) -> String {
    return "M-" + String(format: "%03d", n)     // ← M-000001 ではなく M-001 になる
}
```

**A-19-4 の数列は、桁数が全部違います。**

| ID | 桁数 |
| --- | --- |
| `sales.sale_id` | **3**（`S-20231115-001`） |
| `sale_items.item_id` | **2**（`…-01`） |
| `stock_movements.id` | **6**（`M-000001`） |
| `sync_log.id` | **6**（`L-000001`） |
| 野良のカート行 | **2**（`ADHOC-01`） |

`String(format:)` を各所に書くと、**1 か所だけ桁数が違うまま残ります**
（`38` の JSON エンコーダの話と同じ）。

**正**は `IdSequencer.pad` **1 か所**です。

```swift 断片
// base/Types.swift の正：pad は 1 か所だけ
private func pad(_ n: Int, _ width: Int) -> String {
    let s = String(n)
    return String(repeating: "0", count: max(0, width - s.count)) + s
}
```

> **`max(0, …)` が無いと壊れます。** `n` が桁数を超えたとき `count` が負になって
> `String(repeating:count:)` が **クラッシュ**します。
> `M-1000000`（7桁）が採番されたときに初めて出ます。

## わざと間違う②: `saleCounters` を日付なしで持つ

```swift NG
// わざと間違う版②：日付を捨てて「通し」で数える
mutating func nextSaleID(at date: Date) -> String {
    seq += 1                              // ← 「今日が何番か」を覚えていない
    return "S-\(DayKey.string(from: date))-\(pad(seq, 3))"
}
```

**これで 2 日目以降が全部ずれます。**

`seq` は**アプリを起動してから何件目か**しか数えていません。だから 2 日目の最初の会計が
`S-20231116-002` になり、**その日の 001 が飛ばされます**。

**正**は**日付ごとの連番**を持ちます。

```swift 断片
private var saleCounters: [String: Int] = [:]   // "20231115" → その日の次番

mutating func nextSaleID(at date: Date) -> String {
    let day = DayKey.string(from: date)
    let n = (saleCounters[day] ?? 0) + 1
    saleCounters[day] = n
    return "S-\(day)-\(pad(n, 3))"
}
```

**辞書を 1 つ持つだけで「日ごとの採番」ができます。**
`movementSeq` / `logSeq` / `adhocSeq` は日付で切らないので `Int` 1 つで足ります。

> **`sale_id` の日付は `DayKey` 経由です。** つまり `S-…-YYYYMMDD` の `YYYYMMDD` は
> **端末のローカル日付**（A-19-5）。保存される `completed_at` は UTC なので、
> 画面に出る `sale_id` の日付と DB の文字列の日付は**一致しないことがあります**
> （東京 07:30 の会計 → `sale_id` は `…1116`、保存は `…1115T22:30:00Z`）。仕様どおりの挙動です。

## わざと間違う③: 検証より先に採番する

```swift NG
// わざと間違う版③：buildSale を先に呼んでいる
func commitSaleV1(cart: [CartLine], /* … */ ids: inout IdSequencer) -> CommitResult {
    let built = buildSale(cart: cart, ids: &ids, /* … */)   // ← ここで S-… を消費する
    let problems = checkStock(cart, inventory: inventory, types: types)
    guard problems.isEmpty else { return .failure(problems) }  // ← 失敗しても 001 は消費済み
    /* … */
}
```

**A-19-4** は「**販売系の採番は販売確定時（完了時）に行う。** 記録を残さない中断では採番しない
（**番号が飛ぶのを避ける**）」と書いています。

番号が飛ぶとは、「**使われない番号が残ること**」です。
在庫不足で会計をやり直したら `S-20231115-001` が永久に欠番になります。

**正**は `base/3_標準ロジック.md` §4 の `commitSale`。**検証 → 採番**の順です。

```swift 断片
// ① 在庫検証。1件でも失敗したら、以降の手順を全部飛ばす
let problems = checkStock(cart, inventory: inventory, types: types)
guard problems.isEmpty else { return .failure(problems) }

// ② 販売記録。**検証が通ってから採番する**（A-19-4）
let built = buildSale(cart: cart, ids: &ids, /* … */)
```

**この 2 行の順序が、A-19-4 の全部です。** 下の通しの確認【6】で確かめます。

## 1. `product_id` はここに無い（例外）

`IdSequencer` に **`nextProductID` が無い**のは、仕様どおりです。

| | 販売系の 5 種 | `products.product_id` |
| --- | --- | --- |
| 持ち主が現れる瞬間 | 販売の途中 | **販売の前**（印刷済みQRラベル・原本画像の名前） |
| 採番する場所 | アプリ | **A-18（Mac上のスクリプト）** |
| アプリは採番するか | する | **しない** |

**根拠は A-16（実装要件）です。**

> 商品IDの採番・原本画像のファイル名変更・商品マスタCSV雛形の生成・検証。
> **Mac上のスクリプトで行う（A-18、仮置き）。アプリ本体には含めない。**（A-16）

A-16 の「**アプリ本体には含めない**」が決定です。だから
**アプリの採番コードに `product_id` を入れてはいけません。**

A-1 の「IDは正規形のみ受け付ける。手動入力（A-2）と異なり、**補正しない**」も同じ方向を指します。
アプリは `product_id` を**検証するだけ**です。検証は `13_商品マスタCSVを取り込む.md` が担当します。

> **A-19-4 の表だけを読むと迷います。** そこには「商品ID の採番は CSV 取り込み時」とあり、
> アプリの取り込み時に採番するように読めます。ですがその「取り込み」は
> **A-18 の「取り込み」操作**（`inbox/` の写真を読んで一括採番する操作）を指します。
> `types.csv` を読むアプリ側の取り込み（A-1）は、**検証だけ**です。

## 2. 通しの確認

```swift

func p24(_ s: String) { print("  " + s) }

    ProductType(typeId: "sticker", name: "ステッカー", idPrefix: "ST", idDigits: 3,

            priceJpy: 800, priceSats: 1200, stock: 1),

func at(_ y: Int, _ m: Int, _ d: Int, _ h: Int) -> Date {
    var c = DateComponents()

print("【5】在庫不足の会計 → 販売ID を消費しない（A-19-4「検証 → 採番」）")
```

## できた合図

- **販売IDは日付ごとに 001 から**数え直す（同じ日 001・002、翌日 001）
- **明細IDは 2 桁**（`…-01` / `…-12`）、**在庫変動・送信ログは 6 桁**（`M-000001` / `L-000001`）
- **野良はカートに追加した瞬間**に `ADHOC-01`（A-19-10）
- **番号は消えない**。消費して捨てた `M-000003` の次が `M-000004`
- **在庫不足では販売IDを消費しない** → 次の販売は `S-20231115-003`（002 のままではない）
- **商品ID を採番する関数が無い**（採番は A-18 の Mac スクリプト。**アプリ本体には含めない**）

## まとめ

- **採番は「その持ち主が生まれる瞬間」**（A-19-4）。販売系は**確定した時**
- **販売IDは日付ごと**の連番（`saleCounters`）。在庫変動・ログ・野良は通し
- **`pad` は 1 か所**。`max(0, …)` 付きで桁数超過を切らない
- **検証を通ってから採番する**（`commitSale` の ①→②）。番号が飛ばない
- **取り消しても番号は戻らない**（A-19-4）
- **`product_id` は別物**。販売前に確定しており、採番は **A-18（Mac上のスクリプト）**（A-16、A-19-12）。
  アプリは**検証だけ**（A-1）
