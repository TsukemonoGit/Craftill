# 49. エラー処理を書く（throws・do-try-catch・Result）

元: `../siyou.md` A-1（取り込み時の検証）、A-7（在庫管理）

**ゴール**: これまでは `try?`（失敗したら `nil`）で流してきた処理を、
**なぜ失敗したか**を呼び出し側へ返せる形にする。
`throws` で投げ、`do-try-catch` で受け取り、`Result` で成功／失敗を**値として**返す。
題材は「商品の在庫検証」（A-7）と「CSVの1行検証」（A-1）。

## 前提データ（このまま貼れば動く）

```swift
import Foundation

// ── 在庫の扱い（種類ごと）──────────────
enum StockMode: String {
    case counted = "counted"   // 数量管理型
    case unique  = "unique"    // 一点物型
    case none    = "none"      // 在庫管理なし型
}

// ── 種類の定義（product_types 相当）────
struct ProductType {
    let typeId: String        // 例: "sticker"
    let name: String          // 例: "ステッカー"
    let idPrefix: String      // 例: "ST"
    let idDigits: Int         // 例: 3
    let stockMode: StockMode
}

// ── 商品（products 相当）──────────────
struct Product {
    let id: String
    let typeId: String
    let name: String
    let priceJpy: Int
    let priceSats: Int?   // nil なら sats単価なし（sats払いでも現金で受け取る）
    var stock: Int?       // none は nil
}

// 種類（../開発/6_データベース.md より）
let productTypes: [ProductType] = [
    ProductType(typeId: "sticker",   name: "ステッカー",   idPrefix: "ST", idDigits: 3, stockMode: .counted),
    ProductType(typeId: "keyholder", name: "キーホルダー", idPrefix: "KH", idDigits: 3, stockMode: .unique),
]

// 商品（DBのサンプルより。KH-003〜KH-020 も同様なのでここでは抜粋）
let products: [Product] = [
    Product(id: "ST-001", typeId: "sticker",   name: "ステッカー まる",     priceJpy: 300, priceSats: 500,  stock: 10),
    Product(id: "ST-002", typeId: "sticker",   name: "ステッカー さんかく", priceJpy: 300, priceSats: 500,  stock: 10),
    Product(id: "ST-003", typeId: "sticker",   name: "ステッカー しかく",   priceJpy: 300, priceSats: nil,  stock: 10),
    Product(id: "KH-001", typeId: "keyholder", name: "キーホルダー 01",     priceJpy: 800, priceSats: 1200, stock: 1),
    Product(id: "KH-005", typeId: "keyholder", name: "キーホルダー 05",     priceJpy: 800, priceSats: 1200, stock: 0), // SOLD OUT
    Product(id: "KH-008", typeId: "keyholder", name: "キーホルダー 08",     priceJpy: 800, priceSats: 1200, stock: 1),
]

/// 商品IDから種類定義を引く
func productType(of p: Product) -> ProductType {
    productTypes.first { $0.typeId == p.typeId }!
}
```

## 1. 独自のエラー型（`enum ... : Error`）

失敗の「種類」を `enum` で決め、`Error` に準拠させると **throw できる**ようになる。
`LocalizedError` も付けると、`errorDescription` が `localizedDescription` として使える。

```swift
/// 在庫検証で起きる失敗。`Error` に準拠させると投げられる。
enum StockError: Error, LocalizedError {
    case missingStock(id: String)
    case soldOut(id: String)
    case notEnoughStock(id: String, requested: Int, available: Int)
    case uniqueCount(id: String, requested: Int)

    /// 画面やログに出せる説明文（`LocalizedError`）
    var errorDescription: String? {
        switch self {
        case .missingStock(let id):
            return "\(id) は在庫管理ありなのに在庫値がありません"
        case .soldOut(let id):
            return "\(id) は SOLD OUT です"
        case .notEnoughStock(let id, let requested, let available):
            return "\(id) の在庫が足りません（希望 \(requested)、在庫 \(available)）"
        case .uniqueCount(let id, let requested):
            return "\(id) は一点物なので \(requested) 個は追加できません"
        }
    }
}
```

- `Error` … 「この型は throw してよい」という印
- `LocalizedError` … `errorDescription` を書くと、説明文を後から取り出せる
- 各ケースに**必要な情報**（ID・希望数・在庫）を持たせる。これが `try?` では消えていた「理由」

## 2. `throws` で投げる / `do-try-catch` で受け取る

```swift
/// 検証だけを行い、問題があれば StockError を返す（無ければ nil）
func stockProblem(_ product: Product, qty: Int) -> StockError? {
    let t = productType(of: product)
    guard t.stockMode != .none else { return nil }   // 在庫管理なし型は検証しない

    guard let stock = product.stock else { return .missingStock(id: product.id) }
    guard stock > 0 else { return .soldOut(id: product.id) }

    if t.stockMode == .unique, qty != 1 {
        return .uniqueCount(id: product.id, requested: qty)
    }
    guard qty <= stock else {
        return .notEnoughStock(id: product.id, requested: qty, available: stock)
    }
    return nil
}

/// 同じ検証を「投げる形」にしたもの
func validateAddToCart(_ product: Product, qty: Int) throws {
    if let problem = stockProblem(product, qty) { throw problem }
}
```

投げる処理は `try` を付け、`do-try-catch` で受け止める。

```swift
func tryAdd(_ id: String, qty: Int) {
    guard let p = products.first(where: { $0.id == id }) else {
        print("失敗: 商品 \(id) が見つかりません")
        return
    }
    do {
        try validateAddToCart(p, qty: qty)
        print("成功: \(p.name) ×\(qty) をカートに追加")
    } catch let error as StockError {
        print("失敗: \(error.errorDescription ?? "不明なエラー")")
    } catch {
        print("失敗: \(error.localizedDescription)")
    }
}

tryAdd("ST-001", qty: 2)   // 成功
tryAdd("KH-001", qty: 1)   // 成功
tryAdd("KH-005", qty: 1)   // 失敗: SOLD OUT
tryAdd("KH-008", qty: 3)   // 失敗: 在庫が足りない
```

**できた合図**:
```
成功: ステッカー まる ×2 をカートに追加
成功: キーホルダー 01 ×1 をカートに追加
失敗: KH-005 は SOLD OUT です
失敗: KH-008 の在庫が足りません（希望 3、在庫 1）
```

- `try` … 「失敗するかもしれない」と明示する。付け忘れるとコンパイルエラー
- `catch let error as StockError` … `StockError` だけを捕まえる。最後の `catch` は残り全部
- `try?` だと結果は `Void?` になり、**なぜ失敗したか**は消えてしまう

## 3. 複数のエラーを集めて一覧にする

1回の throw で投げられるエラーは**1つ**。でもCSVの1行は複数箇所が間違うことがある。
だから「まず集めて、最後に**まとめて1つのエラーとして投げる**」（A-1 の考え方）。

```swift
/// 複数の検証エラーをまとめて運ぶためのエラー型
struct RowValidationError: Error, LocalizedError {
    let row: Int
    let messages: [String]

    var errorDescription: String? {
        messages.map { "\(row)行目: \($0)" }.joined(separator: "\n")
    }
}

/// CSVの1行を商品に変換する。問題があれば一覧で投げる（A-1）。
func parseRow(id: String, typeId: String, name: String,
              priceJpy: String, priceSats: String, stock: String,
              row: Int) throws -> Product {
    var messages: [String] = []

    let type = productTypes.first { $0.typeId == typeId }
    if type == nil { messages.append("type_id「\(typeId)」は種類定義にありません") }
    if name.isEmpty { messages.append("name が空です") }

    let price = Int(priceJpy) ?? 0
    if price < 1 { messages.append("price_jpy「\(priceJpy)」は1以上の整数ではありません") }

    var sats: Int? = nil
    if !priceSats.isEmpty {
        if let s = Int(priceSats), s >= 1 { sats = s }
        else { messages.append("price_sats「\(priceSats)」は1以上の整数ではありません") }
    }

    var st: Int? = nil
    if let t = type, t.stockMode != .none {
        if let s = Int(stock) { st = s }
        else { messages.append("stock「\(stock)」が整数ではありません") }
    }

    guard messages.isEmpty else { throw RowValidationError(row: row, messages: messages) }
    return Product(id: id, typeId: typeId, name: name, priceJpy: price, priceSats: sats, stock: st)
}
```

わざと複数の問題を作って受け取る。

```swift
do {
    let p = try parseRow(id: "KH-021", typeId: "keyholder", name: "",
                         priceJpy: "abc", priceSats: "1200", stock: "x", row: 3)
    print("取り込みOK: \(p.id) \(p.name)")
} catch let error as RowValidationError {
    print("取り込みエラー:")
    print(error.errorDescription ?? "")
}
```

**できた合図**:
```
取り込みエラー:
3行目: name が空です
3行目: price_jpy「abc」は1以上の整数ではありません
3行目: stock「x」が整数ではありません
```

- 1つ見つけても止めず、`messages` に足してから最後にまとめて投げる
- `messages.map { ... }.joined(separator: "\n")` … 一覧を改行でつなぐ

## 4. `Result` で成功／失敗を返す

`Result<成功の型, エラーの型>` は、throw せずに成否を**値として**返す書き方。
成功は `.success(値)`、失敗は `.failure(エラー)`。`switch` で取り出す。

```swift
/// 商品IDから商品を探す。見つからなければ .failure
func findProduct(_ id: String) -> Result<Product, StockError> {
    guard let p = products.first(where: { $0.id == id }) else {
        return .failure(.soldOut(id: id))   // ここでは見つからない例として
    }
    return .success(p)
}

/// 在庫の検証つきで探す（成否を Result で返す）
func checkStock(_ p: Product, qty: Int) -> Result<Product, StockError> {
    if let problem = stockProblem(p, qty) { return .failure(problem) }
    return .success(p)
}

for (id, qty) in [("ST-001", 2), ("KH-001", 1), ("KH-005", 1), ("KH-008", 3)] {
    guard let p = products.first(where: { $0.id == id }) else { continue }
    switch checkStock(p, qty: qty) {
    case .success(let product):
        print("OK: \(product.name) ×\(qty)")
    case .failure(let error):
        print("NG: \(error.errorDescription ?? "")")
    }
}
```

**できた合図**:
```
OK: ステッカー まる ×2
OK: キーホルダー 01 ×1
NG: KH-005 は SOLD OUT です
NG: KH-008 の在庫が足りません（希望 3、在庫 1）
```

- `Result` は「成功したときの値」と「失敗したときのエラー」を**同じ型**で運ぶ
- `do-try-catch` は**その場で処理**、`Result` は**呼び出し側へ持ち帰る**のに向く
- 成功のときだけ値を使いたいので、`switch` がよく合う

---

## Svelte/TSでいうと

`throw` / `try-catch` は JavaScript とほぼ同じ。`Result` は TS の
`{ ok: true, value } | { ok: false, error }` のような**戻り値で成否を表す**書き方に近い。
`try?` は「失敗を握りつぶす」ので、理由を画面に出したい所では使わない。

---

## まとめ

- 失敗の種類は `enum ○○: Error` で作る。`LocalizedError` を足すと説明文を出せる
- `throws` で投げ、`do-try-catch` で受け取る。`try?` は理由を消してしまう
- 複数エラーは**集めて1つのエラー型に詰めて**投げる（CSVの一覧表示。A-1）
- `Result` は成否を**値**で返す。成功値を使うときは `switch` で取り出す
