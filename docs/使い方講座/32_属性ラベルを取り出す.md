# 32. 属性ラベルを取り出す

元: `../siyou.md` A-1（属性・種類定義）、A-3（商品パネルの文字表示）、A-14（`attrs` の位置）

**正は `base/2_型定義.md` の `Product.attrText(in:)` と `Product.attrs` です。**

**ゴール**: 種類定義の `attrLabel1〜3`（**左詰め**）と商品の `attr1〜3` を対応させ、
「**色:赤 模様:○**」のように表示する。
**ラベルがない属性に値がある**場合は、表示ではなく**エラー**として扱う。

> 属性は **2つの型に分かれて**います。ラベルは `ProductType`、値は `Product`。
> **片方だけ見ても表示は作れません。** これがこのレッスンの主題です。

---

## まず土台をペーストする

1. `base/Types.swift` の**型だけ**

> **`ProductType` / `Product` を書き写さないでください。**
> `attrLabel1〜3` も `attr1〜3` も `attrText(in:)` も **`base/Types.swift` に入っています**。

## わざと間違う①: `compactMap` で空を詰める

```swift NG
// わざと間違う版①：空を詰めてから並べる
let labels = [t.attrLabel1, t.attrLabel2, t.attrLabel3].compactMap { $0 }   // ["色", "模様"]
let values = [p.attr1, p.attr2, p.attr3].compactMap { $0 }                  // ← 空を詰める

for i in 0..<labels.count {
    print("\(labels[i]):\(values[i])")     // ← 位置がずれる
}
```

**`compactMap` は「空を取り除いて、残りを前に詰める」** 動きをします。
ラベルと値の**両方**が同じ位置で空なら問題ありませんが、**片方だけ空**だと崩れます。

| 商品 | `attr1` | `attr2` | `attr3` | `compactMap` 後 |
| --- | --- | --- | --- | --- |
| `ST-001` | 黄 | まる | nil | `["黄", "まる"]` ✅ |
| `ST-009` | 黄 | **nil** | nil | `["黄"]` ⚠️ |
| `ST-099` | 赤 | nil | **まる** | `["赤", "まる"]` ❌ |

`ST-009` は「模様が無い」だけなのに、**`values[1]` が存在しなくなります**。
`ST-099` はもっと悪く、**`attr3` の「まる」が `values[1]`（＝模様の位置）に来ます**。

**正は詰めません。** `base/2` の `Product.attrs` は **`[attr1, attr2, attr3]` のまま**返します。

```swift 断片
/// base/2_型定義.md の正。**空を詰めない**
var attrs: [String?] { [attr1, attr2, attr3] }
```

> これは `20_公開用スナップショットを作る.md` の `attrs` と同じ話です。
> **B へ送るときも、画面に出すときも、位置を保ちます**（A-14）。

---

## わざと間違う②: ラベルと値の数を突き合わせない

```swift NG
// わざと間違う版②：ラベルの数だけ見て、値の余りを無視する
for i in 0..<labels.count {          // labels は 2 個
    print("\(labels[i]):\(values[i])")   // ← attr3 の値を見ていない
}
```

**`ST-099`（`attr3` にだけ値がある）を見落とします。** ラベルが2個だから2回まわすと、
**3つ目の値は検査されません**。

**A-1 の規則**:

> `attr_1`〜`attr_3` | 任意 | 属性の値。**対応する `attr_label_*` がある列のみ値を入れられる**

つまり **`attr3` に値があるのに `attrLabel3` が無い**のは、**CSV の取り込みで弾く違反**です。
表示側でも「表示できない」ではなく「**エラー**」として扱います。

**正は3つ全部を見ます。**

```swift 断片
// base/2_型定義.md の正
for i in 0..<3 {
    switch (labels[i], attrs[i]) {
    case let (.some(label), .some(value)):
        parts.append("\(label):\(value)")
    case (.none, .some):
        return nil          // ← ラベルが無いのに値がある = 取り込みエラー（A-1）
    default:
        continue            // どちらも無い / 値だけ無い
    }
}
```

| ラベル | 値 | どうするか |
| --- | --- | --- |
| ある | ある | **`色:赤`** と出す |
| ある | ない | **何も出さない**（模様が未入力なだけ） |
| **ない** | **ある** | **エラー**（A-1 の違反） |
| ない | ない | 何も出さない |

---

## なぜ「エラー」を返すのか

`attrText(in:)` は `String?` を返し、**エラーのときは `nil`** です。

「エラー」を**文字列として混ぜない**のが大事です。もし `"エラー: ラベルがありません"` を
属性の文字列として返すと、**商品名や属性値と見分けがつきません**。`nil` なら呼び出し側が
「表示できない」と判断できます。

> `attrText` は**表示のため**の関数です。**取り込みの検証は別**（`13_商品マスタCSVを取り込む.md`）。
> ここで `nil` が返るのは「**その商品データは A-1 に違反している**」という合図で、
> 取り込み時に弾かれていれば**画面には出てこない**はずです。

## 1. 通しの確認

下のコードを、**土台（`base/Types.swift` の型だけ）の下に続けて置いて**、`swift` で動かします。

```swift

func p32(_ s: String) { print("  " + s) }

let types32: [ProductType] = [
    ProductType(typeId: "sticker", name: "ステッカー", idPrefix: "ST", idDigits: 3,
                stockMode: .counted, attrLabel1: "色", attrLabel2: "模様", attrLabel3: nil),
    ProductType(typeId: "keyholder", name: "キーホルダー", idPrefix: "KH", idDigits: 3,
                stockMode: .unique, attrLabel1: "色", attrLabel2: "模様", attrLabel3: nil),
    ProductType(typeId: "ticket", name: "入場券", idPrefix: "TB", idDigits: 3,
                stockMode: .none, attrLabel1: nil, attrLabel2: nil, attrLabel3: nil),
]
let products32: [Product] = [
    Product(id: "ST-001", typeId: "sticker", name: "ステッカー まる",
            priceJpy: 300, priceSats: 500, stock: 10, attr1: "黄", attr2: "まる"),
    // 模様だけ未入力（ラベルはあるが値が無い）
    Product(id: "ST-009", typeId: "sticker", name: "ステッカー 未入力",
            priceJpy: 300, priceSats: 500, stock: 10, attr1: "黄", attr2: nil),
    // 属性なしの種類
    Product(id: "TB-001", typeId: "ticket", name: "入場券",
            priceJpy: 1000, priceSats: nil, stock: nil),
]

print("【1】ラベルと値を同じ添字で対応させる（A-1）")
for p in products32 {
    if let text = p.attrText(in: types32), !text.isEmpty {
        p32("\(p.id)  \(text)")
    } else {
        p32("\(p.id)  （属性なし）")
    }
}

print("【2】値が無い属性は出さない。位置は詰めない（A-14）")
p32("ST-001 attrs: " + products32[0].attrs.map { $0 ?? "-" }.joined(separator: " / "))
p32("ST-009 attrs: " + products32[1].attrs.map { $0 ?? "-" }.joined(separator: " / "))
p32("ST-009 は「模様」を出さない: " + (products32[1].attrText(in: types32) ?? ""))

print("【3】わざと壊す: ラベルのない attr3 に値がある（A-1 違反）")
let bad32 = Product(id: "ST-099", typeId: "sticker", name: "こわれた例",
                    priceJpy: 300, priceSats: nil, stock: 1,
                    attr1: "赤", attr2: nil, attr3: "まる")
p32("attrText: " + (bad32.attrText(in: types32) ?? "nil（＝A-1 違反。表示しない）"))
p32("attrs は位置を保つ: " + bad32.attrs.map { $0 ?? "-" }.joined(separator: " / "))

print("【4】わざと間違う①: compactMap で詰めると位置がずれる")
let labels32 = [types32[0].attrLabel1, types32[0].attrLabel2, types32[0].attrLabel3]
    .compactMap { $0 }
let squeezed = bad32.attrs.compactMap { $0 }
p32("labels(詰めた): " + labels32.joined(separator: " / "))
p32("values(詰めた): " + squeezed.joined(separator: " / "))
p32("→ 「まる」が \(labels32.count > 1 ? labels32[1] : "?") の位置に来る（本来は attr3）")
p32("正しくは: " + (bad32.attrText(in: types32) ?? "nil"))

print("【5】属性を持たない種類（在庫管理なし型）")
let tbText = products32[2].attrText(in: types32) ?? "nil"
p32("TB-001 attrText: " + (tbText.isEmpty ? "（空文字＝属性なし）" : tbText))
p32("TB-001 attrs: " + products32[2].attrs.map { $0 ?? "-" }.joined(separator: " / "))

print("【6】種類が見つからない商品（データ不整合）")
let orphan32 = Product(id: "XX-001", typeId: "unknown", name: "種類なし",
                       priceJpy: 100, priceSats: nil, stock: nil)
p32("attrText: " + (orphan32.attrText(in: types32) ?? "nil（種類が引けない）"))
```

## できた合図

- **ラベルは `ProductType`、値は `Product`**。2つを**同じ添字**で対応させる
- **`compactMap` で詰めない**。`attrs` は `[attr1, attr2, attr3]` のまま（A-14）
- **値が無い属性は出さない**（`ST-009` は「色:黄」だけ。模様は出ない）
- **ラベルが無いのに値がある**と `nil`（＝A-1 違反。`ST-099`）
- **属性を持たない種類**（`none`）は空文字列（`TB-001`）
- **種類が引けない**商品も `nil`（データ不整合）

## まとめ

- 属性は **ラベル（`ProductType`）＋ 値（`Product`）** の2つに分かれている
- **左詰め**（A-1）なので、**同じ添字**で見れば足りる
- **`compactMap` で詰めない**。詰めると位置がずれる（A-14）
- **ラベルが無いのに値がある** → `nil`。これは A-1 の取り込みエラーと同じ規則
- 値が無い属性は**出さない**。属性を持たない種類は空
