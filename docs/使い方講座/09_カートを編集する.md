## わざと間違う①: `－` を押したら即削除してしまう

まず、もっとも tempting な書き方をします。`cart` を直接書き換えて、`String` を返す。

```swift NG
// わざと間違う版①：確認ダイアログを飛ばして即削除
func decreaseV1(at i: Int, cart: inout [CartLine], types: [ProductType]) -> String {
    let line = cart[i]

    guard stockMode(of: line, in: types) != .unique else {
        return "\(line.name) は一点物なので数量1固定です"
    }

    if line.qty - 1 <= 0 {
        cart.remove(at: i)                      // ★ 確認せずに消す
        return "\(line.name) を削除しました"
    }
    cart[i].qty -= 1
    return "\(line.name) ×\(cart[i].qty)"
}
```

`inventory` は `counted` の在庫判定にだけ使うので、`decreaseV1` には渡していません。

これを `ST-001` が 2 枚ある状態で 2 回押すと、こうなります。

```
【わざと間違う①】－ を2回押す
  1回目: ステッカー まる ×1
  2回目: ステッカー まる を削除しました
  → 2回目の瞬間、行はもう無い。cart は 0 行
```

**何が壊れているか**

C-6 #50 はこう書いています。

> 数量管理型・在庫管理なし型・野良商品の数量を「－」で0にする操作で確認ダイアログが表示される。

この実装には **確認ダイアログを出す場所がありません**。`String` を返した時点で
削除は済んでいるので、UI 側は「Warning か」と聞くことすらできません。

客が「やめた」と言ったとき、**元に戻せません**。これは「-accidentally delete」ではなく
「仕様どおりに動いていない」なので、直す必要があります。

### 直し方: 戻り値を3つの case にする

「すでにやった」「やる前に確認が要る」「できない」を、`String` 1 つではなく
**enum の3つの case** で表します。

```swift 断片
enum CartEdit: Equatable {
    case applied(String)            // そのまま実行した。表示するメッセージ
    case needsConfirm(CartDelete)   // まだ何も変えていない。ダイアログで OK なら performDelete
    case rejected(String)           // できない（一点物・在庫超過・範囲外）
}
```

**`needsConfirm` のときは `cart` を書き換えていない**のがミソです。
これがあれば、ダイアログで「キャンセル」を選んだとき、行がそのまま残ります。

## わざと間違う②: 全部 `needsConfirm` にしてしまう

今度は逆方向の間違いです。「消す時は確認」と気が早くなって、**すべての `－` で**
ダイアログを出すようにします。
```swift NG
// わざと間違う版②：0にならない増減でもダイアログを出す
func decreaseV2(at i: Int, cart: [CartLine], types: [ProductType]) -> CartEdit {
    let line = cart[i]

    guard stockMode(of: line, in: types) != .unique else {
        return .rejected("\(line.name) は一点物なので数量1固定です")
    }

    // ★ 0 になるかどうかを見ずに、必ず確認を要求する
    return .needsConfirm(CartDelete(index: i, name: line.name, qty: line.qty))
}
```

`ST-001` が 5 枚ある状態で `－` を 1 回押すと:

```
【わざと間違う②】ST-001 が5枚ある状態で「－」を押す
  needsConfirm(ステッカー まる ×5 を削除しますか)
```

**何が壊れているか**

C-6 #50 には**後半**があります。

> 数量が0にならない増減では表示されない

5 枚 → 4 枚は「0にならない増減」です。ここでダイアログが出るのは仕様違反です。
1 人営業だと、`－` を連打するたびにダイアログが出て、操作が止まらなくなります。操作が止まらなくなります。

### 直し方: 0 になるときだけ `needsConfirm`

```swift 断片
func decrease(at i: Int,
              cart: inout [CartLine],
              inventory: [Product],
              types: [ProductType]) -> CartEdit {
    guard cart.indices.contains(i) else { return .rejected("行がありません") }
    let line = cart[i]

    guard stockMode(of: line, in: types) != .unique else {
        return .rejected("\(line.name) は一点物なので数量1固定です")
    }

    if line.qty - 1 <= 0 {
        // ★ 0 になるなら行の削除になる。この return より先に 1 度も書き換えない
        return .needsConfirm(CartDelete(index: i, name: line.name, qty: line.qty))
    }

    // 0にならない増減はそのまま実行（確認ダイアログは出さない・C-6 #50）
    cart[i].qty -= 1
    return .applied("\(line.name) ×\(cart[i].qty)")
}
```

判定は **「減った結果が0か」** だけです。`qty == 1` を特別扱いしなくてよいので、条件がひとつ減ります。

> **考えてみる**: `increase` は `inout` を渡して即実行、`decrease` も `inout` を渡します。
> でも `decrease` は `needsConfirm` を返す **return の前で 1 行も書き換えません**。
> 同じ `inout` でも「実行済み」と「要求だけ」を返り値だけで区別できる。
> これが `CartEdit` を 3つの case にした理由です。

## わざと間違う③: `StockMode.none` と `Optional.none` がぶつかる

種類を引き出す関数をそのまま `switch` すると、**コンパイルエラー**になります。

```swift NG
// わざと間違う版③：コンパイルエラーになる
func increaseV3(at i: Int, cart: inout [CartLine],
                inventory: [Product], types: [ProductType]) -> CartEdit {
    let line = cart[i]
    switch stockMode(of: line, in: types) {   // ← Optional<StockMode>
    case .unique:
        return .rejected("\(line.name) は一点物なので数量1固定です")
    case .counted:
        if let s = currentStock(of: line, in: inventory), line.qty + 1 > s {
            return .rejected("在庫超過: \(line.name)（在庫 \(s)）")
        }
    case .none, nil:                          // ★ `.none` が2つある
        break
    }
    cart[i].qty += 1
    return .applied("\(line.name) ×\(cart[i].qty)")
}
```

```
error: switch must be exhaustive
  note: add missing case: '.some(.none)'
warning: assuming you mean 'Optional<StockMode>.none'; did you mean 'StockMode.none' instead?
```

`stockMode(of:)` は `StockMode?` を返します。その上で `switch` すると、

- `StockMode` の `case none`（在庫管理なし型）
- `Optional` の `case none`（種類が見つからない＝野良）

が **同じ `.none` という名前** になります。Swift はどちら GAMEか決められず、エラーになります。

### 直し方: `if let` で取り出してから `switch`

```swift 断片
// Optional<StockMode> の .none と StockMode.none は名前がぶつかる。
// if let で取り出してから switch する。
if let mode = stockMode(of: line, in: types) {
    switch mode {
    case .unique:
        return .rejected("\(line.name) は一点物なので数量1固定です")
    case .counted:
        if let stock = currentStock(of: line, in: inventory), line.qty + 1 > stock {
            return .rejected("在庫超過: \(line.name)（在庫 \(stock)）")
        }
    case .none:
        break                              // 在庫管理なし型は上限なし（A-1）
    }
}
// 上の if let が通らなかった＝野良。野良は種類を持たず上限なし（A-1）
```

`if let` が通らなかったのが「野良」、通って `case .none` に落ちたのが「在庫管理なし型」。
**両者は同じ扱い**（上限なし）ですが、**意味が違う**ので混ぜない方がよいです。

## 4. 画面側でどうつなぐか

ロジックは「ダイアログが要るか」を返すだけです。`.alert` を通すのは画面側です。

```swiftui
struct CartRow: View {
    let line: CartLine
    let onPlus: () -> Void
    let onMinus: () -> CartEdit

    @State private var pending: CartDelete?

    var body: some View {
        HStack {
            Text(line.name)
            Spacer()
            Button("－") { pending = handle(onMinus()) }
            Text("\(line.qty)")
            Button("＋", action: onPlus)
        }
        // needsConfirm のときだけダイアログを出す（C-6 #50）
        .alert("削除しますか", isPresented: Binding(
            get: { pending != nil },
            set: { if !$0 { pending = nil } }
        )) {
            Button("削除", role: .destructive) {
                if let d = pending { performDelete(d, cart: &cart) }
                pending = nil
            }
            Button("キャンセル", role: .cancel) {
                pending = nil                    // cart は一变わらない（§1 の性質）
            }
        } message: {
            Text(pending?.message ?? "")
        }
    }

    /// applied / rejected ならそのまま、needsConfirm ならダイアログ用として CartDelete を返す
    func handle(_ r: CartEdit) -> CartDelete? {
        switch r {
        case .applied(let m):  print(m);  return nil
        case .rejected(let m): print(m);  return nil
        case .needsConfirm(let d): return d
        }
    }
}
```

要点は **`.alert` を常に付けておいて、出るかどうかは `pending` が nil かどうかで決める**ことです。
C-6 #50「0にならない増減では表示されない」は、ダイアログを出す分岐を作らないのではなく、
**`needsConfirm` が返ってきたときだけ `pending` に入れる**ことで満たされます。

## ポイント

- ロジックは **`applied` / `needsConfirm` / `rejected`** の 3 つで「やった・確認が要る・できない」を表す
- **`needsConfirm` を返すときは `cart` を書き換えない**。だから「キャンセルで行が残る」が自然に成り立つ
- **数量が0になる `－` だけ** `needsConfirm`。0にならない増減は `applied`（C-6 #50）
- 行の削除ボタンはつねに `needsConfirm`（C-6 #49）
- `unique` は ＋／－ 両方 `rejected`（数量1固定・A-3）
- `counted` の `＋` は在庫を超えると `rejected`
- `none` と野良は上限なし（A-1）。でも「種類が無い」のか「在庫管理なし型」なのかは区別する
- 小計・合計は `base/2` の `CartLine.subtotalJpy` と `totals()` を使う。書き直さない
- 削除すると **後ろの行が前に寄る**ので `index` がずれる。画面では行ごとに操作するのが安全
