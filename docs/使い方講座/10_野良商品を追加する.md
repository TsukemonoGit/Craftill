# 追加レッスン: 野良商品を追加する

元: `../siyou.md` A-1、A-13、受け入れテスト C-6 #36・#41

`02_練習メニュー.md` の「10. 野良商品を追加する」。

商品マスタに無い商品を「野良」として追加します（A-1）。

| 項目 | 必須か | 未入力のとき |
| --- | --- | --- |
| 円価格 | **必須**（1以上） | エラー |
| sats価格 | 任意 | 「sats単価なし：sats払いでも現金で受け取り」 |
| 品名 | 任意 | 「野良」 |
| 数量 | 任意 | 1 |

---

## まず土台をペーストする

1. `base/Types.swift` の**型だけ**（`CartLine.adhoc(...)` と `IdSequencer` を含む）
2. `base/5_カート編集.md` の §2（`CartEdit`）

> **`AdhocResult` のような別の enum を作りません。** 追加の結果は `CartEdit` です
> （`base/00_README.md` のルール）。`CartEdit` は `applied` / `needsConfirm` / `rejected` の3つです。

## わざと間違う: 野良の ID を外から渡す

`CartLine.id` は**採番された値**です（A-19-10）。でも野良の ID は
「`"ADHOC-1"` って文字列を置いて渡す」書き方になりがちです。

```swift NG
// わざと間違う版：ID を呼び出し側から受け取る
enum WrongAdhocResult {
    case ok(CartLine)
    case error(String)
}

func makeAdhocV1(_ input: AdhocInput, id: String) -> WrongAdhocResult {
    // ... 検証して
    let line = CartLine(id: id, typeId: nil, name: name, unitPriceJpy: jpy,
                        unitPriceSats: input.priceSats, qty: qty, isAdhoc: true)
    return .ok(line)
}

// 呼び出し側
let line = makeAdhocV1(input, id: "ADHOC-1")
let line2 = makeAdhocV1(input, id: "ADHOC-1")   // ★ 同じ ID が2つできる
```

**何が壊れているか**

| # | 問題 |
| --- | --- |
| 1 | **同じ ID が2つできる**。削除や集計で片方だけ消せなくなる |
| 2 | 番号の管理が**呼び出し側に散る**。会計が変わると連番が残る／重なる |
| 3 | A-19-10 の規則（`ADHOC-{連番:02}`）から**外れる**。`ADHOC-1` は2桁ではない |

**直し方**: `IdSequencer` に採番を**預ける**。採番のタイミングも、
「野良をカートに追加したとき」と決めてあります（A-19-10）。

```swift 断片
/// 野良のカート行ID（A-19-10）。base/Types.swift の IdSequencer にあります
mutating func nextAdhocID() -> String {
    adhocSeq += 1
    return "ADHOC-" + pad(adhocSeq, 2)
}
```

## 1. 入力を受け取る形

任意の項目は `?`（nil かも）で表します。

```swift 断片
struct AdhocInput {
    var priceJpy: Int?     // 必須（nil はエラー）
    var priceSats: Int?    // 任意
    var name: String       // 任意（空なら「野良」）
    var qty: Int?          // 任意（既定1）
}
```

## 2. 野良のカート行を作る

返り値は **`CartEdit`** です。`CartEdit` には `CartLine` を入れる場所がないけど、
メッセージの中に必要な情報（品名・価格・数量）を入れてあります。

```swift 断片
/// 野良を検証してカート行を返す。採番は `IdSequencer` が行う（A-19-10）
func makeAdhoc(_ input: AdhocInput, ids: inout IdSequencer) -> CartEdit {
    // 円価格は必須・1以上
    guard let jpy = input.priceJpy, jpy >= 1 else {
        return .rejected("円価格は1以上で入力してください")
    }

    // 品名は空なら既定名「野良」
    let trimmed = input.name.trimmingCharacters(in: .whitespaces)
    let name = trimmed.isEmpty ? "野良" : trimmed

    // 数量は未入力なら1
    let qty = max(1, input.qty ?? 1)

    let line = CartLine.adhoc(id: ids.nextAdhocID(), name: name,
                              priceJpy: jpy, priceSats: input.priceSats, qty: qty)
    return .applied("\(line.name) を追加しました（ID \(line.id)）")
}
```

- `guard let ... else { return .rejected(...) }` … 必須チェックは**先に抜ける**（`01_初心者メモ.md`）
- `input.qty ?? 1` … 「nil なら 1」の意味（nil 合体演算子）
- `max(1, …)` … 数量が 0 や負だったときの保護。A-3 の表は「0以上」
- 野良は**種類を持たない**ので `typeId` は `nil`。`CartLine.adhoc(...)` がそういう形にしてくれる
- 野良は在庫を持たないので `addCheck` を通らない（A-7、`07_カートの種類ごとの追加ルール.md`）

## 3. 表示する

確認表示とカート行の2つを作ります。sats単価がないときは、両方に注意書きを付けます。

```swift 断片
/// 追加前の確認表示（金額を大きく見せる想定）
func confirmText(_ line: CartLine) -> String {
    var t = "金額 ¥\(line.unitPriceJpy)　品名 \(line.name)　数量 \(line.qty)"
    if line.unitPriceSats == nil {
        t += "\nsats単価なし：sats払いでも現金で受け取り"
    }
    return t
}

/// カート行の表示（野良は「野良」を付ける）
func rowText(_ line: CartLine) -> String {
    var t = line.isAdhoc ? "野良 " : ""
    t += "\(line.name)  ¥\(line.unitPriceJpy) ×\(line.qty)"
    if line.unitPriceSats == nil {
        t += "  ―（現金）"     // A-3 のカート表示に合わせる
    }
    return t
}
```

## 考えてみる（答えはない）

1. A-1 は野良の **円価格にも sats価格にも上限がない**と書いています。
   でも `sats価格` を入れると、その行は **sats払いでは sats で受け取られます**（A-6-1）。
   店員が**入力し間違い**で sats価格を入れてしまうと、客の請求額が変わります。
   仕様（A-1）は「金額を大きく表示した確認を挟む」とだけ書いています。
   **sats価格にも同じ確認を出す**ことで足りると思いますか。それとも別の対策が要りますか。
2. `makeAdhoc` は `CartLine` を作って `applied` で返しますが、
   **`CartEdit` には行を渡す場所がありません**。UI 側はどうやって行を受け取ればいいですか。
   `base/5` の `add(...)` は `inout` で `cart` を書き換えます。野良も同じ方式にそろえますか。
3. 野良の ID は `ADHOC-01` から**連番**です（A-19-10）。もし `IdSequencer` を
   セッションごとに作り直したら、**昨日の会計と今日で同じ ID が出**ます。
   A-19-4 は「番号は削除しない／再利用しない」と言っていますが、
   **アプリ再起動をまたいで一意**にするには、どこに状態を置く必要がありますか。

## ポイント

- 円価格だけが**必須**。`guard` で先にチェック
- 未入力を `??`（nil 合体）で既定値にする（品名 →「野良」、数量 → 1）
- **野良の ID は `IdSequencer.nextAdhocID()`** が採番する（A-19-10）。外から渡さない
- 返り値は **`CartEdit`**。`AdhocResult` を作らない
- 野良は**在庫管理の対象外**。`addCheck` を通らず、`stock_movements` にも記録しない（A-7）
- sats価格がないときは「**sats単価なし：sats払いでも現金で受け取り**」を
  **確認表示とカート行の両方**に出す（A-1、C-6 #41）
- カート行には「野良」を付ける（登録商品と区別する）
- 誤りは**行を削除 → 再追加**で直す（A-2 の対策 #16）
