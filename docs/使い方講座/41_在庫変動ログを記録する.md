# 在庫変動ログを記録する

元: `../siyou.md` A-7、A-19-1（現在庫の正）、A-19-4（採番規則）、A-19-5（日時）
受け入れテスト C-6 #81・#82

在庫が「いつ・どの商品が・いくつ増減したか」を**全部**記録します（`stock_movements`）。

**このログは4種類の記録が すでに残っています。** `base/3_標準ロジック.md` にあります。
このレッスンは **「どれが書いているか」「どこが正か」** を見るレッスンです。

| `reason` | いつ | `delta` | 書いている関数 |
| --- | --- | --- | --- |
| `initial` | CSV取り込みで新規登録した | ＋（在庫値） | `registerInitialStock`（`base/3` §3） |
| `sale` | 会計が「完了」した | −（数量） | `completeSale` / `commitSale`（`base/3` §3・§4） |
| `void` | 販売を取り消した | ＋（戻す数量） | `voidSale`（`base/3` §5-2） |
| `adjust` | 棚卸しで数量を直した | ＋／−（差） | `adjustStock`（`base/3` §6） |

## わざと間違う①: ID を自分で数える

```swift NG
// わざと間違う版①：3桁で採番する
var movementSerial = 0
func nextID() -> String {
    movementSerial += 1
    return String(format: "M-%03d", movementSerial)
}
```

**動く。でも A-19-4 に反します。** 仕様が決めたのは **`M-{連番:06}`** です。

| | この版 | A-19-4 の正 |
| --- | --- | --- |
| 1件目 | `M-001` | `M-000001` |
| 1000件目 | `M-1000` | `M-001000` |
| 桁数が揃わない | 3件で `M-004`、1000件で `M-1000` | **常に6桁** |

**桁が足りないのは `'M-001'` と `'M-000001'` が別のIDとして通ってしまうからです。**
エクスポート（`40_販売記録を書き出す.md`）でソートしても**時系列になりません**。

**正**は `ids.nextMovementID()`（`base/2`）。**採番は販売確定時に行われます（A-19-4）。

> **`%03d` は3桁、`%06d` は6桁**。`pad` の実装は
> `String(repeating: "0", count: max(0, width - s.count)) + s` です。
> `max(0, …)` が無いと、`n` が桁数を超えたときに**壊れます**。

## わざと間違う②: フィールド名を `productID` / `saleID` にする

```swift NG
// わざと間違う版②：大文字 I で始める
struct StockMovement {
    let id: String
    let productID: String     // ★ base は productId
    let saleID: String?       // ★ base は saleId
    let delta: Int
    let reason: MovementReason
    let at: String            // ★ base は Date
}
```

Swift の**名前付けの約束**（API Design Guidelines）に反します。

| 命名 | 由来 | 例 |
| --- | --- | --- |
| `productId` | **identity**（同一性） | `productId` / `saleId` / `typeId` |
| `productID` | **identifier** の略に見える | **`URL` などのフレームワーク名**だけ |

**見分け方**: 変数名の**後ろに来る名前**が名詞なら、小文字始まりの単語を並べます。
`ID` はその「後ろの名詞」なので、`Id` にします。

```swift 断片
// base/Types.swift の正
struct StockMovement: Codable, Equatable, Identifiable {
    let id: String
    let productId: String
    let delta: Int
    let reason: MovementReason
    let saleId: String?
    let at: Date              // ★ Date。文字列は SQLite に保存するときだけ（A-19-5）
}
```

**Swift の `struct` は `String` を持つ**ので、`"at": String` にすると
**`Codable` が壊れます**（ISO 8601 の文字列は `Date` のほうが安全）。

## わざと間違う③: 日時を `String` で持つ

```swift NG
// わざと間違う版③：日時を文字列で持つ
let t0 = "2026-10-13T10:00:00+09:00"
func makeInitial(_ p: Product, at: String) -> StockMovement? {
    StockMovement(id: ..., productId: p.id, delta: p.stock!, reason: .initial, saleId: nil, at: at)
}
```

**保存の規定**（`../開発/6_データベース.md`）は ISO 8601 の文字列ですが、
**Swift の `struct` は `Date` を持つ**ことにしました（A-19-5）。

| | SQLite | Swift の `struct` |
| --- | --- | --- |
| 日時 | **`TEXT`**（ISO 8601） | **`Date`** |
| なぜ | SQLite に型が無いから | ソート・比較・差分計算が `Date` なら使える |

**`Codable` で保存するときだけ** `dateEncodingStrategy = .iso8601` を効かせます
（`jsonEncoder` は `base/2` に用意済み）。

**文字列で持つと**：`"2026-10-13T10:00:00+09:00"` と `"2026-10-13T01:00:00Z"` の
**同じ瞬間**を文字列として**比較できません**。`Date` なら `==` が使えます。

## わざと間違う④: 現在庫をログの合計で求める

```swift NG
// わざと間違う版④：現在庫をログ合計から求める
func currentStock(_ movements: [StockMovement], productID: String) -> Int {
    movements.filter { $0.productID == productID }.reduce(0) { $0 + $1.delta }
}
```

**この計算は正しい**です。**でも「読み取り口」が違います**（A-19-1）。

| | ログ合計を「正」にする | **`products.stock` を「正」にする** |
| --- | --- | --- |
| 1件の読み取り | `movements` を**全件走査** | `inventory` を**1件引く** |
| ログが空のとき | **在庫 0 と出る** | 登録済みの在庫が**ちゃんと出る** |
| ログが壊れたとき | **全 进而全滅** | 1件だけ直せる |

**決め方**（`base/1_仕様調査.md` P1）:

> **現在庫の「正」は `products.stock`。`stock_movements` は監査用の追記ログ。**

**ログ合計は「自己点検」に使います**。下の通しの確認【6】を見てください。

## 1. 正: 4つの記録は `base/3` にある

**ログを作る関数を自分で書かない**。**在庫を動かす関数を呼ぶと、ログが自動で残ります**。

```swift 断片
// base/3 §3：初期登録。既存の商品IDは触らず、在庫管理なし型は記録しない
func registerInitialStock(_ newProducts: [Product],
                          inventory: inout [Product],
                          movements: inout [StockMovement],
                          ids: inout IdSequencer,
                          types: [ProductType],
                          at: Date)

// base/3 §4：販売完了。検証→記録→減算→ログ の4手順を1本にする
func commitSale(cart: [CartLine], inventory: inout [Product], movements: inout [StockMovement],
                sales: inout [Sale], items: inout [SaleItem], ids: inout IdSequencer,
                types: [ProductType], chooseSats: Bool,
                receivedJpy: Int?, confirmedAt: Date?, now: Date) -> CommitResult

// base/3 §5-2：販売取消。completed_at があるものだけ在庫を戻し、+ のログを残す
func voidSale(saleId: String, correctPIN: String, pin: String,
              sales: inout [Sale], items: [SaleItem],
              inventory: inout [Product], movements: inout [StockMovement],
              ids: inout IdSequencer, types: [ProductType], at: Date) -> VoidResult

// base/3 §6：手動調整。差分を adjust として記録する（PIN 必須）
func adjustStock(productId: String, newStock: Int, reason: String,
                 correctPIN: String, pin: String,
                 inventory: inout [Product], movements: inout [StockMovement],
                 ids: inout IdSequencer, types: [ProductType], at: Date) -> AdjustResult
```

**共通点是3つです。**

| # | 共通点 | なぜ |
| --- | --- | --- |
| 1 | **`ids: inout IdSequencer`** を取る | 採番を `base/2` の数列に**寄せる**（A-19-4） |
| 2 | **`movements: inout [StockMovement]`** を取る | ログが1つの数列に**並ぶ** |
| 3 | **`inventory` も一緒に取る** | 在庫表が正。ログだけじゃなく**両方を更新する**（A-19-1） |

> **`movements` だけ取る関数を作らないでください。**
> 在庫表を更新せずにログだけ残すと、**不変条件 I1 が壊れます**。

## ポイント

- **ログを作る関数を書かない**。在庫を動かす関数が**自動で**記録する（`base/3`）
- **採番は `ids.nextMovementID()`**。`M-{連番:06}`・**欠番再利用なし**（A-19-4）
- **`productId` / `saleId`**。`productID` / `saleID` ではない（Swift の命名規約）
- **日時は `Date`**。SQLite では `TEXT`（ISO 8601）だが、`struct` では `Date`（A-19-5）
- **現在庫の正は `products.stock`**。ログ合計は**自己点検**用（A-19-1）
- **不変条件 I1**: `products.stock == Σ stock_movements.delta`。**毎会計確認する**
- **在庫管理なし型・野良はログを作らない**（A-1）
- **`movements` を取る関数は `inventory` も取る**。片方だけだと I1 が壊れる
- **4つの reason**：`initial` / `sale` / `void` / `adjust`（A-13 の値域）
