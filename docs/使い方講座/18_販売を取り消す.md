# 追加レッスン: 販売を取り消す

元: `../siyou.md` A-9、A-11、受け入れテスト C-6 #24・#52・#80
`../siyou.md` A-19-3（在庫を戻す条件）・A-19-4（ID の採番規則）
`02_練習メニュー.md` の「18. 販売を取り消す」。

完了した販売を**取り消して**、在庫を戻します（A-9）。**PIN必須**の管理操作です（A-11）。

**正は `base/3_標準ロジック.md` §5-2 にあります。**

| 対象 | `status` | `completed_at` | 在庫を戻す |
| --- | --- | --- | --- |
| 完了した販売 | `completed` | あり | **戻す**（`stock_movements` に `+qty`） |
| **sats受領済みで中断した会計**（A-4） | `voided` | **nil** | **戻さない**（減算していないので） |
| すでに取消済みの販売（A-9） | `voided` | あり | 戻さない（**二重に戻さない**） |

**1 本のルール**で全部分岐します。

```
在庫を戻す条件 ＝  completed_at がある voided
```

## わざと間違う①: `voided` なら全部在庫を戻す

A-9 はこう書いています。

> sats受領済みで中断した会計（A-4）は、**完了前のため在庫を戻さない**

「`voided` ＝ 販売取消」と読んではいけません。
**`voided` には2種類あります**（A-19-3）。

```swift NG
// わざと間違う版①：voided を全部戻す
func voidSaleV1(saleId: String, sales: inout [Sale], items: [SaleItem],
                 inventory: inout [Product], movements: inout [StockMovement]) -> [String] {
    guard let si = sales.firstIndex(where: { $0.id == saleId }) else { return [] }
    guard sales[si].status == .voided else { return [] }      // ★ これで足りないと破綻する
    var memo: [String] = []
    for item in items where item.saleId == saleId {
        guard let productId = item.productId,
              let pi = inventory.firstIndex(where: { $0.id == productId }),
              let current = inventory[pi].stock else { continue }
        inventory[pi].stock = current + item.qty               // ★ 中断でも戻してしまう
        memo.append("\(inventory[pi].name): 在庫 \(current) → \(current + item.qty)")
    }
    return memo
}
```

**何が壊れるか**

`sats受領済みで中断` した会計は、**在庫を一度も減らしていません**（A-4 のトランザクション）。

| 会計 | 完了時に減算 | この実装 | 正しい |
| --- | --- | --- | --- |
| 完了した販売 | した | 戻す ✅ | 戻す ✅ |
| **sats受領済みの中断** | **してない** | **戻す ❌** | 戻さない |

**在庫が「減っていないのに増える」**ことになります。C-1 #4 の「正データは端末内DBが唯一の正」を
壊しますし、A-19-1 の不変条件（`products.stock == Σ stock_movements.delta`）も**一致しなくなります**。

**直し方**: `status` ではなく **`completed_at` を見ます**。

```swift 断片
// base/3 §5-2 の該当部分
guard sales[si].status == .completed else {
    return .failure("この会計は販売取消できません（完了していない／すでに取消済み）")
}
// 上の guard を通れば completedAt は必ずあるが、A-19-3 の判定基準をコードにも書く
guard sales[si].completedAt != nil else {
    return .failure("この会計は販売取消できません（sats受領済みで中断した会計）")
}
```

> **「在庫を戻す条件は `completed_at` がある」** の1本に統一します。
> `09` / `56` の「中断では戻さない」と **同じルール**です（A-19-2、A-19-3）。

## わざと間違う②: 変動ログに `id` を付けない

```swift NG
// わざと間違う版②：ID がない
movements.append(StockMovement(productId: productId, delta: item.qty,
                               reason: .void, saleId: saleId, at: at))
```

**何が壊れるか**

A-19-4 で `stock_movements.id` は **`M-{連番:06}`** に決めました。
`id` なしの行は：

- **エクスポート（A-8）で列が足りない**（C-6 #27「エクスポートが日次集計と一致する」）
- **削除・重複チェック**ができない（A-18 `id_map.csv` と同じ考え方）
-  **`Identifiable`** がないので SwiftUI の `ForEach` で **クラッシュ**

**直し方**: `IdSequencer` に採番させます。

```swift 断片
movements.append(StockMovement(
    id: ids.nextMovementID(), productId: productId,
    delta: item.qty, reason: .void, saleId: saleId, at: at))
```

**同じ採番数列（`M-000001`…）を `completeSale` と共有する**のがポイント（A-19-4）。

## わざと間違う③: PIN の前に在庫を戻す

```swift NG

func voidSaleV3(saleId: String, pin: String, correctPIN: String, sales: inout [Sale], ...) {
    // 在庫を戻す処理…
```

**何が壊れるか**

**PINが間違っていても在庫が戻った状態で終わります**（A-11）。
割り込みが入ると、**在庫だけ戻った販売記録**が残ります。

**正**: PIN は**最初**（`22_在庫を手動調整する.md` の §わざと間違う② と同じ）。

```swift 断片
guard pin == correctPIN else { return .failure("PINが違います") }   // ★ 最初
```

## 1. 返金済みフラグ（sats分）は PIN 必須

A-9 はこう書いています。

> Lightning決済の返金はシステム外（WoS操作）で手動対応。
> 販売記録に返金済みフラグ（`refunded`。sats分）を保持。
> **返金済みフラグは、管理操作（PIN必須）で設定する**

```swift 断片
/// 返金済みフラグを立てる（A-9、A-11）
func markRefunded(saleId: String, pin: String, correctPIN: String,
                  sales: inout [Sale]) -> Bool {
    guard pin == correctPIN else { return false }
    guard let i = sales.firstIndex(where: { $0.id == saleId }) else { return false }
    sales[i].refunded = true                 // ★ Bool 1つ（`refunded: Int` ではない）
    return true
}
```

- **返金の金額は記録しません**（システム外・A-9）。
  `refunded` は **「sats分を返したか」だけ**の `Bool` です
- **併用会計の現金分の返金は記録しない**（仮置き・Q12）

## ポイント

- **在庫を戻す条件 = `completed_at` がある `voided`** の1本（A-19-3）
- `status == .voided` だけで戻すと、**sats受領済みの中断まで在庫が増えてしまう**
- **PIN は最初**に確認する（A-11）。在庫に触ってからだと記録のない変更が残る
- **PIN が違えば1行も変わらない**（C-6 #52）
- 戻すのは **在庫管理ありの登録商品だけ**。管理なし型・野良は `continue`（A-9）
- 戻すときは **`stock_movements` に `reason = .void` の `+qty` を1件**残す（A-7、A-19-1）
- **変動IDは `IdSequencer.nextMovementID()`**。`completeSale` と**同じ数列**（A-19-4）
- **二度と戻さない**。`status == .completed` の guard で弾く
- `refunded` は **`Bool`**。返金の金額は**記録しない**（システム外・A-9）
- 集計では `canceledSaleIDs` に入り、`suspendedSaleIDs` とは**別枠**（A-19-7、`17_集計する.md`）
