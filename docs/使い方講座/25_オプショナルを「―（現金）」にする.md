# 25. オプショナルを「―（現金）」にする

元: `../siyou.md` A-3（カート表示）、A-6-1（請求sats額・現金分）、A-13（`paid_in`）

**正は `base/2_型定義.md` の `PaidIn` と、`base/3_標準ロジック.md` §2 の `paidIn(of:method:)`。**

**ゴール**: `price_sats`（sats単価）が**空（nil）**の行を、画面では「**―（現金）**」と表示する。
その行は **sats払いでも現金で受け取る**（sats合計に入れず、**現金分**に入れる）。

そして —— **この「円で受け取る / satsで受け取る」は `PaidIn` という型で表します**（A-13 の `paid_in`）。
`satsLabel` の文字列は**表示**であって、保存する値ではありません。

1. `base/Types.swift` の**型だけ**
2. `base/3_標準ロジック.md` の §1（合計）〜§2（販売記録のうち `resolveMethod` / `paidIn`）

> `Totals` も `totals()` も `canPayBySats()` も **`base/Types.swift` に入っています**。

## わざと間違う①: `nil` かどうかを2か所で判定する

```swift NG
// 表示（画面）側
if line.unitPriceSats == nil {
    label = "―（現金）"
} else {
    label = "\(line.unitPriceSats!) sats"
}

// 合計（会計）側
if line.unitPriceSats == nil {
    cashForSats += line.unitPriceJpy * line.qty
} else {
    satsTotal += line.unitPriceSats! * line.qty
}
```

**同じ「`nil` かどうか」を 2 か所で見ています。** 片方を直し忘れると、
**画面は「1200 sats」なのに現金分に入る**行ができます。どちらが正しいか、もう片方からは検証できません。

**正は1か所です。** `base/3` §2 の `paidIn(of:method:)` が会計の `method` を見て `PaidIn` を返し、
`base/2` の `totals()` が**同じ条件**（`unitPriceSats != nil`）で合計します。

```swift 断片
// base/3_標準ロジック.md §2 の正。**ここだけ**が「どちらで受け取るか」を決める
func paidIn(of line: CartLine, method: PaymentMethod) -> PaidIn {
    if method == .cash { return .jpy }
    return line.unitPriceSats != nil ? .sats : .jpy
}
```

**会計の `method` で、その行の `PaidIn` は変わります。**

| 会計の `method` | sats単価ありの行 | sats単価**なし**の行（「―（現金）」） |
| --- | --- | --- |
| `cash` | `.jpy` | `.jpy` |
| `lightning` / `mixed` | `.sats` | **`.jpy`** ← sats払いでも現金で受け取る |

**不変条件 I5（`base/2_型定義.md`）**:

```
paidIn == .sats  ⟺  unitPriceSats != nil
```

つまり **`PaidIn` を見れば、`satsLabel` が「―（現金）」かどうかが分かります。** 逆も同じ。

## わざと間違う②: `!` で強制アンラップする

```swift NG
// わざと間違う版②：nil の行で落ちる
label = "\(line.unitPriceSats!) sats"     // ← ST-003 を入れた瞬間クラッシュ
```

「―（現金）」の行が**1つでも**あれば落ちます。オプショナルは `if let` / `guard let` で取り出します。

| | 取り出した値が使える範囲 | 向いてる用途 |
| --- | --- | --- |
| `if let` | `{ }` の中だけ | その場の条件分岐 |
| `guard let` | そのあと全部 | ダメなときは先に抜ける |

```swift 断片
// どちらでも同じ結果。**nil のときの値を先に決める**
func satsLabel(_ priceSats: Int?) -> String {
    if let sats = priceSats { return "\(sats) sats" }
    return "―（現金）"
}

func satsSubtotal(_ line: CartLine) -> Int {
    guard let sats = line.unitPriceSats else { return 0 }   // ← 先に抜ける
    return sats * line.qty
}
```

## 「―（現金）」は表示だけ。保存されるのは `PaidIn`

**ここが大事です。** 画面に出る「―（現金）」は**記号**で、DB には入りません。
A-13 の `sale_items.paid_in` に入るのは **`"jpy"` / `"sats"`** という文字列（`PaidIn` の `rawValue`）だけです。

| | どこに出るか | 値 |
| --- | --- | --- |
| `satsLabel(1200)` | 画面 | `1200 sats` |
| `satsLabel(nil)` | 画面 | `―（現金）` |
| `paidIn(of:method:)` | **DB** | `.jpy` / `.sats`（`rawValue` は `"jpy"` / `"sats"`） |

`satsLabel` の出力を保存してはいけません。**表示の言葉は、後で変わります。**
型（`PaidIn`）で持てば、表示を変えても記録は壊れません。

## 1. 通しの確認

下のコードを、**土台（`base/Types.swift` の型 ＋ `base/3` §1〜§2）の下に続けて置いて**、
`swift` で動かします。

```swift
// ════════ 通しの確認（「―（現金）」と PaidIn・A-3 / A-6-1 / A-13）════════

func p25(_ s: String) { print("  " + s) }

/// sats単価の表示（A-3）。nil は「―（現金）」。**画面のためだけ**
func satsLabel(_ priceSats: Int?) -> String {
    if let sats = priceSats { return "\(sats) sats" }
    return "―（現金）"
}

/// カート行の1行表示（A-3）。商品名・円単価・sats単価・数量
func rowText(_ line: CartLine) -> String {
    "\(line.name)  ¥\(line.unitPriceJpy)  \(satsLabel(line.unitPriceSats))  ×\(line.qty)"
}

let products25: [Product] = [
    Product(id: "ST-001", typeId: "sticker", name: "ステッカー まる", priceJpy: 300, priceSats: 500, stock: 10),
    Product(id: "ST-003", typeId: "sticker", name: "ステッカー しかく", priceJpy: 300, priceSats: nil, stock: 10),
    Product(id: "KH-001", typeId: "keyholder", name: "キーホルダー 01", priceJpy: 800, priceSats: 1200, stock: 1),
]
func line25(_ id: String, _ qty: Int) -> CartLine {
    CartLine(product: products25.first { $0.id == id }!, qty: qty)
}

print("【1】sats単価なしの行は「―（現金）」（A-3）")
p25("satsLabel(500) → " + satsLabel(500))
p25("satsLabel(nil) → " + satsLabel(nil))
p25(rowText(line25("KH-001", 1)))
p25(rowText(line25("ST-003", 1)))

print("【2】会計の method で、その行の PaidIn が変わる（A-13）")
let cart25 = [line25("ST-001", 1), line25("ST-003", 1), line25("KH-001", 1)]
for method in [PaymentMethod.cash, .lightning, .mixed] {
    let labels = cart25.map { paidIn(of: $0, method: method).rawValue }
    p25("\(method.rawValue): " + labels.joined(separator: " / "))
}
p25("↑ 左から ST-001 / ST-003（sats単価なし） / KH-001")

print("【3】不変条件 I5: paidIn == .sats ⟺ unitPriceSats != nil")
let i5 = cart25.allSatisfy { line in
    [PaymentMethod.lightning, .mixed].allSatisfy {
        paidIn(of: line, method: $0) == (line.unitPriceSats != nil ? .sats : .jpy)
    }
}
p25("sats払いでの判定が型と一致: \(i5)")
p25("PaidIn を保存したら、表示は satsLabel で作り直せる")

print("【4】ST-003 の 300円 は sats合計に入らず、現金分へ（A-6-1）")
let t25 = cart25.totals()
p25("Totals: sats=\(t25.sats) cashForSats=\(t25.cashForSats) cash=\(t25.cash)")
let (satsLine25, cashLine25) = totalLines(cart25)
p25(satsLine25)
p25(cashLine25)

print("【5】会計の method は resolveMethod が決める（A-13）")
p25("chooseSats=false → " + resolveMethod(chooseSats: false, cart: cart25).rawValue)
p25("chooseSats=true  → " + resolveMethod(chooseSats: true, cart: cart25).rawValue)
p25("sats払いを選べるか: \(cart25.canPayBySats())")
```

**期待される出力**:
```
【1】sats単価なしの行は「―（現金）」（A-3）
  satsLabel(500) → 500 sats
  satsLabel(nil) → ―（現金）
  キーホルダー 01  ¥800  1200 sats  ×1
  ステッカー しかく  ¥300  ―（現金）  ×1
【2】会計の method で、その行の PaidIn が変わる（A-13）
  cash: jpy / jpy / jpy
  lightning: sats / jpy / sats
  mixed: sats / jpy / sats
  ↑ 左から ST-001 / ST-003（sats単価なし） / KH-001
【3】不変条件 I5: paidIn == .sats ⟺ unitPriceSats != nil
  sats払いでの判定が型と一致: true
  PaidIn を保存したら、表示は satsLabel で作り直せる
【4】ST-003 の 300円 は sats合計に入らず、現金分へ（A-6-1）
  Totals: sats=1700 cashForSats=300 cash=1400
  sats払い　1700sats ＋ 300円
  現金　　　1400円
【5】会計の method は resolveMethod が決める（A-13）
  chooseSats=false → cash
  chooseSats=true  → mixed
  sats払いを選べるか: true
```

## できた合図

- sats単価が空（`nil`）の行は、画面で「**―（現金）**」と表示される（`satsLabel(nil)`）
- **同じ `nil` の行でも、会計の `method` で `PaidIn` が変わる**
  （`cash` → 全部 `.jpy` / `lightning`・`mixed` → sats単価のある行だけ `.sats`）
- **`paidIn == .sats` と `unitPriceSats != nil` は必ず一致する**（不変条件 I5）
- ST-003 の 300円 は **sats合計（1700）に入らず、現金分（300円）** になる
- 現金合計は全行の合計なので 300 + 300 + 800 = **1400円**
- **保存されるのは `PaidIn`（`"jpy"` / `"sats"`）**。「―（現金）」は表示だけ

3. 「―（現金）」は**表示の記号**です。DB には `paid_in = "jpy"` が入ります。

## まとめ

- **「円で受け取る / satsで受け取る」は `PaidIn` 型**（A-13）。表示の文字列ではない
- **決めるのは `paidIn(of:method:)` の1か所**。表示も合計も同じ条件から導く
- 「―（現金）」= `unitPriceSats == nil`。その行は **sats払いでも現金分へ**（A-6-1）
- **現金合計には全行**を足す（`totals().cash`）
- オプショナルは `if let` / `guard let` で取り出す。`!` は使わない
