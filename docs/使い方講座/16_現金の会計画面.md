## わざと間違う①: 請求額を手で足す

```swift NG
// わざと間違う版①：reduce で円合計を出す
let totalJpy = cart.reduce(0) { $0 + $1.unitPriceJpy * $1.qty }
```

**動きます。** でも `base/2` に **`cart.totals()`** があります。
`Totals` は **3 つ**を区別して持ちます（A-6-1）。

| | 式 | どこで使う |
| --- | --- | --- |
| `sats` | `Σ sats単価 × qty`（sats単価のある行） | sats払いの請求額 |
| `cashForSats` | `Σ 円単価 × qty`（**sats単価が無い行**） | **併用会計の現金分** |
| `cash` | `Σ 円単価 × qty`（**全行**） | **現金払いの請求額** |

`reduce` の1行は **`cash`** と同じです。でも **`cashForSats` が見えません**。
sats払いの会計で「現金で受け取る額」を出したいとき（`mixedCashInput`）、
この1行だと **sats分まで二重に要求**します（C-6 #77）。

**`totals` を1か所に集める**のはそのためです。UI も `move` も `cashDueJpy` だけを見ます（`base/6` §7）。

## わざと間違う③: `apply` を先に呼んでから `commitSale`

直しても動きません。

```swift NG
// わざと間違う版③：先に状態を移してから確定する
private func confirm() -> Move {
    let m = move(.confirmCash(cash.receivedJpy), in: ctx)
    apply(m, to: &ctx)                 // ★ ここで state が .done になる

    let r = commitSale(cart: ctx.cart, ...)     // ★ ここで在庫不足なら failure
    switch r {
    case .failure(let why):
        return .rejected(why)         // ★ でも state は .done のまま！
    case .success:
        ctx.cart = []
        ctx.state = .idle
    }
    return m
}
```

**`commitSale` が失敗しても `ctx.state` は `.done` になっています**（A-4 の4手順が1つ目から落ちた）。
結果：

- **`ctx.state` が `.done`**、なのに販売記録はない → **「中断しても売上に上がらない会計」**（A-19-2 の破綻）
- 次の `move(...)` が **全部 `rejected`**（「完了した会計は中断できません」）

**順序が正**: **`commitSale` を先に回して、成功してから `apply`**。
失敗したときは **`ctx` を1行も触りません**。

> 同じ形が `base/5` §4 の `decrease` にもあります。
> **`needsConfirm` を返す前に 1 行も書かない**のと同じ規則です。

## 1. `CashInput`：請求額は持たない

`base/6` §7 の教訓どおり、**導出できるものは持たない**（`19` の教訓）。
請求額は **`ctx.cashDueJpy`** が見ます。

```swift
/// 現金入力の状態（A-5）。**請求額は持たない**（`ctx.cashDueJpy` から導出・base/6 §7）
struct CashInput: Equatable {
    var receivedJpy: Int = 0          // 受取額（増える）

    /// 確定してよいか。**見た目の無効化**のために見るだけ。判定の正は `move`
    func canConfirm(due: Int) -> Bool { receivedJpy >= due }

    // 数字キー: いまの受取額の後ろに数字を1つ足す
    mutating func pressDigit(_ d: Int) { receivedJpy = receivedJpy * 10 + d }
    // 「00」キー
    mutating func pressDoubleZero() { receivedJpy = receivedJpy * 100 }
    // 1桁消す（⌫）
    mutating func backspace() { receivedJpy = receivedJpy / 10 }
    // 1,000 / 5,000 / 10,000 円ボタン
    mutating func addQuick(_ yen: Int) { receivedJpy += yen }
}
```

- `var changeJpy: Int { ... }` … **計算プロパティ**。持たずに毎回計算する
- `mutating func` … `struct` の中身（`receivedJpy`）を書き換える関数に付ける印
- `pressDigit(7)` で 3 → 37 のように、末尾に数字を足す

> **`canConfirm` は「見た目」だけ**です。判定の正は `base/6` §4 の
> `guard received >= ctx.cashDueJpy else { return .rejected(...) }` です（A-19-9 #9）。

## 2. 「確定」ボタンが呼ぶ関数

UI が **`move(...)` → `commitSale` → `apply` の順**に並べる、**1 か所だけ**の関数。

```swift
/// 「確定」ボタンが呼ぶ。**遷移は base/6、確定処理は base/3**（A-19-9 #9）
/// - 遷移が `rejected` なら **`commitSale` に進まない**
/// - `commitSale` が失敗したら **`ctx` を1行も触らない**（§わざと間違う③）
func confirmCash(received: Int,
                 ctx: inout SaleContext,
                 inventory: inout [Product],
                 movements: inout [StockMovement],
                 sales: inout [Sale],
                 items: inout [SaleItem],
                 ids: inout IdSequencer,
                 types: [ProductType],
                 now: Date) -> Move {
    let m = move(.confirmCash(received), in: ctx)
    guard m.nextState == .done else { return m }       // rejected はそのまま画面へ

    // ★ 先に `commitSale`。A-4 の4手順（検証→記録→減算→ログ）がここ
    let r = commitSale(cart: ctx.cart, inventory: &inventory, movements: &movements,
                       sales: &sales, items: &items, ids: &ids, types: types,
                       chooseSats: false,                // 現金払いなので sats は選ばない
                       receivedJpy: received, confirmedAt: nil, now: now)
    switch r {
    case .failure(let why):
        return .rejected(why.joined(separator: " / ")) // ctx はそのまま
    case .success:
        apply(m, to: &ctx)                             // 成功してから状態を移す
        ctx.cart = []
        ctx.state = .idle                              // 次の会計へ（A-4 の完了）
    }
    return m
}
```

- `chooseSats: false` … `resolveMethod`（`base/3` §2）が `method = .cash` になる
- `confirmedAt: nil` … 現金なので sats の確認時刻は無い（A-13）
- **成功后**に `ctx.cart = []` / `state = .idle` で次の会計へ戻る（A-4）

> **完了したら `SaleContextStore.clear()`** も呼びます（A-3、完了時は保存を消す）。
> それは `58_総合問題2_レジ画面を1本にする.md` の担当です。

## 4. 現金入力画面

請求額・受取額・お釣りを上に出し、下に数字キーと金額ボタン、確定ボタンを置きます。
**請求額は `ctx.cashDueJpy`、合計は `base/3` §1** から取ります。

```swiftui
struct CashInputView: View {
    @Binding var ctx: SaleContext
    @State private var cash = CashInput()

    /// `rejected` の理由を出す:A-19-9 #9。UI は `Move` の返り値を見るだけ
    @Binding var message: String

    private let keyRows: [[String]] = [
        ["7", "8", "9"],
        ["4", "5", "6"],
        ["1", "2", "3"],
        ["0", "00", "⌫"],
    ]
    private let quickButtons = [1000, 5000, 10000]

    var body: some View {
        VStack(spacing: 16) {
            // ── 金額の表示 ──
            VStack(alignment: .trailing, spacing: 8) {
                amountRow("請求額", ctx.cashDueJpy)                    // ★ 導出（base/6 §7）
                amountRow("受取額", cash.receivedJpy)
                amountRow("お釣り", cash.receivedJpy >= ctx.cashDueJpy
                                  ? cash.receivedJpy - ctx.cashDueJpy : 0)
            }
            .font(.title2)
            .frame(maxWidth: .infinity, alignment: .trailing)

            HStack(alignment: .top, spacing: 24) {
                VStack(spacing: 8) {
                    ForEach(keyRows, id: \.self) { row in
                        HStack(spacing: 8) {
                            ForEach(row, id: \.self) { key in
                                KeyButton(title: key) { press(key) }
                            }
                        }
                    }
                }
                VStack(spacing: 8) {
                    ForEach(quickButtons, id: \.self) { yen in
                        KeyButton(title: "+\(yen)") { cash.addQuick(yen) }
                    }
                }
            }

            // ── 確定（受取額 < 請求額の間は無効）──
            Button(action: confirm) {
                Text("確定")
                    .font(.title3).bold()
                    .frame(maxWidth: .infinity)
                    .padding(.vertical, 12)
                    .background(cash.canConfirm(due: ctx.cashDueJpy)
                                ? Color.accentColor : Color.gray.opacity(0.3))
                    .foregroundStyle(Color.white)
                    .cornerRadius(10)
            }
            .buttonStyle(.plain)
            .disabled(!cash.canConfirm(due: ctx.cashDueJpy))
        }
        .padding()
        .frame(width: 460, height: 520)
    }

    private func amountRow(_ label: String, _ yen: Int) -> some View {
        HStack {
            Text(label).foregroundStyle(.secondary)
            Spacer()
            Text("¥\(yen)")
        }
    }

    private func press(_ key: String) {
        switch key {
        case "⌫":  cash.backspace()
        case "00": cash.pressDoubleZero()
        default:   if let d = Int(key) { cash.pressDigit(d) }
        }
    }

    /// 「確定」。**遷移と確定処理は `confirmCash`（上の関数）に任せる**（A-19-9 #9）
    private func confirm() {
        switch confirmCash(received: cash.receivedJpy, ctx: &ctx,
                           inventory: &inventory, movements: &movements,
                           sales: &sales, items: &items, ids: &ids,
                           types: types, now: Date()) {
        case .allowed:                    message = ""            // → ctx は .idle
        case .needsConfirm(_, _),
             .needsPIN(_, _):            message = ""            // 現金では出ない
        case .rejected(let why):          message = why           // 在庫不足など
        }
        cash = CashInput()                                      // 受取額を戻す
    }
}
```

- `.disabled(!cash.canConfirm(...))` … **見た目だけ**。通せなく	else `move` が `rejected` を返す
- `@State private var cash` … 構造体ごと `@State` で持つ。書き換えると画面が再描画される
- `ctx` は **`@Binding`**。`send(_:)` と同じ流儀で、上から受け取る（`56_会計の状態を切り替える.md`）

## ポイント

- **請求額は `ctx.cashDueJpy`**（`base/6` §7）。`CashInput` に持たせない
- **合計は `cart.totals()`**（`base/2`）。`cash` と `cashForSats` を取り違えない（A-6-1）
- **`move(...)` は状態を書き換えない**。`apply(m, to: &ctx)` で移す
- **`commitSale` は `apply` より前**。失敗したら **`ctx` を1行も触らない**
- **確定で `print` しない**。販売記録・在庫減算・変動ログが要る（A-4）
- `.disabled(!canConfirm)` は**見た目**。通しようとしても `move` が `rejected` を返す
- `CashInput` には **`receivedJpy` だけ**。他は導出（A-19-9 / `19` の教訓）
- 完了したら **`ctx.cart = []` と `ctx.state = .idle`**、および保存の削除（A-3）
- 現金会計は**通信不要**で完了できる（A-10）
