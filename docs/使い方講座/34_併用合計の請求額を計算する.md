# 34. 併用会計の請求額を計算する

元: `../siyou.md` A-6-1（請求sats額・現金分）、A-4（済ボタン）、C-6 #77・#78

**正は `base/2_型定義.md` の `totals()`、`base/3_標準ロジック.md` §2 の `resolveMethod`、
`base/6_会計の状態機械.md` §6 の `markSatsConfirmed`・§7 の `cashDueJpy` です。**

**ゴール**: 併用会計の請求額を出す。

- **請求sats額** = sats単価のある行の「sats単価 × 数量」の合計
- **現金分** = sats単価の**ない**行の「円単価 × 数量」の合計
- 現金分が 0 なら**併用なし**（`lightning`）
- 全行 sats単価なしなら **sats払いを選べない**（`cash` のみ）
- **レート換算はしない**。野良商品も同じ扱い

**このレッスンの主題は「請求sats額を、いつ固定するか」です。**
合計の出し方（3つの数字）は `11` で済んでいます。ここで扱うのは
**「済ボタンを押した瞬間の額を、あとで変えさせない」**という話です（C-6 #78）。

## わざと間違う①: 請求額を毎回カートから出し直す

```swift NG
// わざと間違う版①：請求sats額を「そのときのカート」から毎回出す
let dueSats = cart.totals().sats      // ← 済ボタンのあとにも再計算してしまう
```

一見正しそうです。合計の出し方は `totals()` の1か所だからです。

**壊れるのは「済ボタンを押したあと」です。** 済ボタンは
「WoS で入金を確認した」という**客の申告**です。その時点で金額が確定します。
ところが完了までの間に**カートが変わると**（取消・追加・復元の不整合）、
`totals().sats` は**別の額**を返します。

| 時点 | `cart` の sats | `totals().sats` | 客が WoS で払った額 |
| --- | --- | --- | --- |
| 済ボタン | 1000 | **1000** | **1000** |
| 直後に1枚取消 | 500 | **500** ← 変わる | 1000 |

**請求額が 1000 から 500 に減ります。** 記録には 500 が残り、**500 sats のズレ**です。

**正は「済ボタンのときに1回だけ確定して保存する」。** `base/6` §6 の `markSatsConfirmed`。

```swift 断片
// base/6_会計の状態機械.md §6 の正
/// 済ボタン承認時。**請求sats額をこのときだけ確定させる**（C-6 #78）
func markSatsConfirmed(_ ctx: inout SaleContext, at: Date) {
    ctx.satsConfirmedAt = at
    ctx.confirmedSats = ctx.cart.totals().sats
}
```

`SaleContext` に `confirmedSats` があるのは**このためだけ**です。
**請求額を「保存する」のではなく、「確定した瞬間の値を控える」**のです。

| 値 | どこから | いつ変わるか |
| --- | --- | --- |
| `cart.totals().sats` | カート | カートが変わるたび |
| **`ctx.confirmedSats`** | 済ボタン | **一度きり。以後変わらない** |

## わざと間違う②: 3つの合計を2つで済ませる

```swift NG
// わざと間違う版②：現金分を作らず、satsと現金の2つだけで表す
struct Totals {
    var sats: Int = 0
    var cash: Int = 0        // ← 全行の円合計。現金分が無い
}
```

**`cash` は全行の円合計**です。sats で受け取る行の円単価も入っています。
現金分（`cashForSats`）を別に持たないと、**併用のときに sats 分まで現金で要求**します（C-6 #77）。

```swift 断片
// base/2_型定義.md の正。**3つある**
struct Totals: Equatable {
    var sats: Int = 0         // sats単価がある行の sats 合計
    var cashForSats: Int = 0  // sats単価が**ない**行の円合計（＝現金分）
    var cash: Int = 0         // 全行の円合計
}
```

| 会計 | `sats` | `cashForSats` | `cash` |
| --- | --- | --- | --- |
| satsのみ | 2200 | **0** | 1400 |
| 併用 | 1200 | **300** | 1100 |
| 現金のみ | 0 | 600 | 600 |

**`cash` と `cashForSats` は別物**です。`cash` は「全部を現金で払ったらいくら」、
`cashForSats` は「sats払いのときに現金で受け取る分」。**用途が違います。**

## わざと間違う③: 「sats払いを選べるか」を2か所で判定する

```swift NG
// わざと間違う版③：画面と move で別々に判定する
let canChooseSats = cart.contains { $0.unitPriceSats != nil }   // 画面

// move の中（base/6 §4）
guard ctx.cart.canPayBySats() else { ... }                       // ← 別の実装
```

**片方だけ直すと、押せるのに遷移しない**ボタンができます。

**正は `base/2` の `canPayBySats()` 1か所**。画面も `move` もこれを見ます。

```swift 断片
// base/2_型定義.md の正
extension Array where Element == CartLine {
    func canPayBySats() -> Bool { contains { $0.unitPriceSats != nil } }
}
```

そして**方法の決定も1か所**（`base/3` §2）。

```swift 断片
// base/3_標準ロジック.md §2 の正
func resolveMethod(chooseSats: Bool, cart: [CartLine]) -> PaymentMethod {
    guard chooseSats else { return .cash }
    return cart.totals().cashForSats == 0 ? .lightning : .mixed
}
```

| カート | `canPayBySats()` | `chooseSats` | `resolveMethod` |
| --- | --- | --- | --- |
| 全部 sats単価あり | `true` | `true` | **`lightning`**（現金分 0） |
| sats単価なしを含む | `true` | `true` | **`mixed`**（現金分 > 0） |
| 全部 sats単価なし | **`false`** | `true`（押せないはず） | **`cash`** ← 選ばせない |
| 全部 sats単価なし | `false` | `false` | `cash` |

**3行目が大事です。** `resolveMethod` は `chooseSats == true` でも
`sats` が 0 なら `lightning` にしません（`cashForSats` で判定するため）。
ただし `canPayBySats() == false` なら**そもそも `chooseSats` に来ない**ように
`move` が `rejected` します（`base/6` §4 の `choosingPayment`）。

## できた合図

- **3つの合計**が出る。satsのみ `sats=2200 / cashForSats=0 / cash=1400`
- **併用**（KH-002 ＋ ST-003 ＋ 野良1200円）は `sats=1200 / cashForSats=1500 / cash=2300`
- **表示は2行**。現金分が 0 のときは「sats払い　2200sats」だけ
- **`resolveMethod`** が `lightning` / `mixed` / `cash` を1か所で決める
- **`canPayBySats() == false`** のカートで sats を選ぶと **`rejected`**
- **`confirmedSats` は済ボタンで固定**。カートが変わっても再計算しない（C-6 #78）
- **`cashDueJpy`** は `satsWaiting` で現金分、`cashInput` で全行の円合計

## まとめ

- **3つの合計**（`sats` / `cashForSats` / `cash`）。`cash` と `cashForSats` は**別物**
- **円とsatsは合算しない**。レート換算もしない（A-6-1）
- **方法の決定は `resolveMethod` 1か所**、**選べるかの判定は `canPayBySats()` 1か所**
- **請求sats額は済ボタンで `confirmedSats` に固定**（C-6 #78）。以後 `totals()` を出し直さない
- **現金分の請求額は `cashDueJpy`**（`base/6` §7）。状態で変わる
- 野良は `unitPriceSats` が無いので**自動で現金分**に入る（A-1）
