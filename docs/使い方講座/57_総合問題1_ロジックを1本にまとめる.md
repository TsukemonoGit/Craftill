## わざと間違う①: 8つの関数を自分で書く

この大問の「自分で書く手順」は 8 個の関数を要求していました。

| # | 要求されていた関数 | **`base/` の正** |
| --- | --- | --- |
| 1 | `totals(_ cart:) -> Totals` | **`cart.totals()`**（`base/2`、`Array<CartLine>` の拡張） |
| 2 | `totalLines(_ cart:) -> (satsLine:, cashLine:)` | **`totalLines(_:)`**（`base/3` §1） |
| 3 | `normalizeProductID(_ raw:)` | なし（`31_全角のIDを半角にする.md` のみ） |
| 4 | `addToCart(_ p:, cart:) -> AddResult` | **`add(product:qty:cart:inventory:types:)`**（`base/5` §1） |
| 5 | `resolveMethod(chooseSats:, cart:) -> String` | **`resolveMethod(chooseSats:cart:)`**（`base/3` §2、**`PaymentMethod` を返す**） |
| 6 | `buildSale(...) -> (sale:, items:)` | **`buildSale(cart:ids:chooseSats:…)`**（`base/3` §2） |
| 7 | `completeSale(...) -> CompleteResult` | **`commitSale(...)`**（`base/3` §4。**採番も selling record も含む**） |
| 8 | `summarize(_ sales:, items:) -> DailySummary` | **`summarize(_:items:)`**（`base/3` §7） |

**8 個のうち 7 個は既にあります。** 3 番だけは既存にありません（種類定義が絡むので
`31_全角のIDを半角にする.md` の担当です）。

**なぜ「全部自分で書く」が悪いのか**:

| # | 自分で書くと | 実際に起きる |
| --- | --- | --- |
| 1 | `totals` を 2 か所に書く | 片方だけ直る。**合計が合わない** |
| 2 | `AddResult` を作り直す | `base/5` の `CartEdit` と**返り値の意味がズレる** |
| 3 | `method: String` にする | `resolveMethod` の **`PaymentMethod`（enum）** の恩恵を失う |
| 4 | `completeSale` を自分で書く | **販売記録と明細が無い**（在庫だけ減る・A-4 違反） |
| 5 | `summarize` を自分で書く | **`voided` を2つに分けない**（A-19-7 違反） |

**5 番が一番痛いです。** `#4` と同じ罠です。
在庫を減らし、販売記録を作り、`stock_movements` に `sale` を残す —— **3 つを 1 関数で**
網羅するのが `commitSale` です（`base/3` §4）。

## わざと間違う②: `method` を `String` にする

```swift NG
// わざと間違う版②：enum の代わりに String
func resolveMethod(chooseSats: Bool, cart: [CartLine]) -> String {
    guard chooseSats else { return "cash" }
    return cart.totals().cashForSats == 0 ? "lightning" : "mixed"
}
```

`base/3` §2 の **`PaymentMethod`（enum）** なら、`== .cash` と書けて
**取り違えがコンパイルエラー**になります。`String` だと **気づかないまま通ります**。

**同じ取り違えが `SaleItem.paidIn` と `SaleItem.itemType` にもあります**
（`PaidIn` / `ItemType`、A-13 の値域、P6）。

## わざと間違う③: `voided` を 1 つにまとめる

```swift NG
// わざと間違う版③：voided を 1 枠に
if sale.status == .voided {
    s.voidedSaleIDs.insert(sale.id)
    s.voidedSats += sale.totalSats ?? 0
    continue
}
```

**`voided` には 2 種類あります**（A-19-3）。

| 状態 | `completed_at` | 在庫を戻す | A-8 では |
| --- | --- | --- | --- |
| 販売取消（A-9） | **あり** | **戻す** | 売上に含めない（**別集計の指定は無い**） |
| **sats確認済みの中断**（A-4） | **nil** | 戻さない | 売上に含めず、**件数とsats合計を別に出す** |

`base/3` §7 は `canceledSaleIDs` と `suspendedSaleIDs` に分けています（A-19-7）。

- **A** … 一点物 `KH-001` を **2 回目は rejected**（`base/5` §1）
- **B** … `ST-003` は sats 単価なしなので **`mixed`** になる（`base/6` §7 の `cashForSats`）

## ポイント

- **8 個の関数を自分で書かない**。7 個は `base/` にある（`base/00_README.md` のルール）
