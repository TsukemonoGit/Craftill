## 判定の式は1つ

```swift 断片
// base/5 §1 の addCheck の該当部分
case .counted:
    let after = (inCart?.qty ?? 0) + qty      // ★ すでに入っている分を足す
    return after <= stock ? .ok : .overStock(current: stock, need: after)
```

**`after <= stock`** が1個あるだけです。

| 式 | 意味 |
| --- | --- |
| `inCart?.qty ?? 0` | カートにすでに入っている個数（無ければ 0） |
| `qty` | いま追加しようとしている個数 |
| `after` | この会計で合計何個になるか |
| `stock` | **いまの**在庫（`products.stock`・A-19-1） |

> **`cart[i].qty` ではなく `inCart?.qty`** です。
> カートは `Product` ではなく `CartLine` の配列なので、商品IDで引き直します。
> `08_在庫を読む` lesson（`08_在庫を減らす.md`）と同じ考え方です。**表から引く。**

## わざと間違う: 追加する個数だけを見て、「新しい行」として扱う

一番多い間違いは、`inCart` を無視して **新しい行を足す** ことです。

```swift NG
// わざと間違う版：すでに入っていることを見ない
case .counted:
    if qty > stock {                       // ★ カートに入っている分を足していない
        return .overStock(current: stock, need: qty)
    }
    cart.append(CartLine(product: p, qty: qty))   // ★ 2行目ができる
    return .ok
```

**何が壊れるか**

| 操作 | 正しい挙動 | この実装 |
| --- | --- | --- |
| 在庫3・カート2個・1個追加 | 合計3で `.ok`（`qty` が3になる） | `1 > 3` ではないので `.ok`。**でも新しい行ができる** |
| 在庫3・カート2個・2個追加 | 合計4で `.overStock` | `2 > 3` ではないので `.ok` ← **在庫を超える追加が通る** |
| 削除ダイアログで確認する量 | 1行 3個 | 1行2個 と 1行1個 が別々に見える |

3つとも壊れています。**`qty` だけを見ると、合計の一部しか見ていない**からです。

## わざと間違う: カートに持っている在庫を「いまの在庫」と見る

在庫は**いまの在庫表**から引きます。カートに入れた時点の値ではない（A-7）。

```swift NG
// わざと間違う版：在庫は表から引きます。ただし…
// 「カートに入れた時の数量」と「その時の在庫」を混同すると同じ事故が起きます
```

正しい版はこうです。

```swift 断片
// 在庫は.products から引く（base/2 の Product.stock）。カートは在庫を持たない（A-7）
guard let i = inventory.firstIndex(where: { $0.id == p.id }) else { return .ok }
let mode = inventory[i].stockMode(in: types)
guard mode != .none else { return .ok }     // 在庫管理なし型は上限なし
guard let stock = inventory[i].stock else { return .ok }
```

**3つの early return が「在庫管理なし型は上限なし」だけの意味を持ちます**。
`mode != .none` の判定は**種類から引いた**値です（`07` の §わざと間違う①）。

## 編集側（＋／－）も同じ上限で止める

`addCheck` は**追加**の入口です。`＋` ボタンを押すときは §3 の `increase` を通ります。

```swift 断片
// base/5 §3 の increase の該当部分
case .counted:
    if let stock = currentStock(of: line, in: inventory), line.qty + 1 > stock {
        return .rejected("在庫超過: \(line.name)（在庫 \(stock)）")
    }
```

**「追加」と「＋」は別の関数です。** でも同じ在庫表を見ています。
両方の式を並べて覚えておいてください。

| 操作 | 関数 | 式 |
| --- | --- | --- |
| 追加 | `addCheck` §1 | `(inCart?.qty ?? 0) + qty <= stock` |
| ＋ | `increase` §3 | `line.qty + 1 <= stock` |
| － | `decrease` §4 | 在庫は問題にならない（減らすだけ） |

`＋` は「1 個だけ増やす」ので、合計を計算し直す必要がありません。
`addCheck` は何個でも渡せるので、合計が必要です。

## ポイント

- 在庫超過の条件は **`(inCart?.qty ?? 0) + qty <= stock`** の1行（A-1、C-6 #7）
- 在庫は **`products.stock`（いまの値）** から引く。カートは在庫を持たない（A-7、A-19-1）
- 「在庫管理なし型は上限なし」は `guard mode != .none else { return .ok }` の1行
- 在庫管理のありなしは **`ProductType` から引く**。`Product` に持たせない（A-1）
- **追加は `addCheck`、`＋` は `increase`**。別の関数だが同じ在庫表を見る
- メッセージは `addCheckMessage` が1文に翻訳する（`overStock` には「在庫 ○○、合計 △△ 個」と出る）
- 検証は**完了時**にもう一度行う（A-4）。追加時の判定では代用できません
