# 50. プロトコルを使う（protocol・extensionによる既定実装・any・some）

元: `../siyou.md` A-1、A-3

**ゴール**: 「価格を持つもの」を表す `Priced` のような**プロトコル**を作り、
`Product`（登録商品）や**野良商品**（Adhoc）をそのプロトコルに準拠させる。
種類の違うものを**同じ関数**で合計できるようにする。

## 1. プロトコル（protocol）とは

**プロトコル＝「何を持っている／何ができるか」の約束**。
Svelte/JSでいう**インターフェース**（TypeScript）の考え方に近い。
型が共通の「仕事」（今回なら `価格` を返す）を約束する。

```swift
/// 「価格を持つもの」を表す約束
protocol Priced {
    var priceJpy: Int { get }
    var priceSats: Int? { get }
    var name: String { get }
    var qty: Int { get }
}
```

`{ get }` は**読み取り専用**。値を返すだけならこれで十分。

---

## 2. 準拠（conform）させる

`Product` と `Adhoc` を `Priced` に準拠させる。

```swift
extension Product: Priced {
    var qty: Int { 1 }   // 登録商品の1行は数量1としてカートに入れる想定
}

extension Adhoc: Priced {}
```

- `extension` で**後付け**でも準拠できる（後で紹介）
- `Adhoc` は定義に `qty` が既にあるのでそのままでOK
- `Product` に足りない `qty` だけ `extension` で補う

今これで両方が「**Priced である**」と見なせるようになった。

---

## 3. 種類が違っても同じ関数で合計する

約束だけを受け取る関数を書ける。`[Priced]` に入れれば、`Product` でも `Adhoc` でも計算できる。

```swift
/// sats払い時の合計を計算（A-3 の考え方）
func totalsForSats(_ items: [Priced]) -> (sats: Int, cashForSats: Int, cash: Int) {
    var sats = 0
    var cashForSats = 0
    var cash = 0
    for i in items {
        if let s = i.priceSats {                // sats単価あり → sats合計へ
            sats += s * i.qty
        } else {                                // nil → 現金分へ（A-6-1）
            cashForSats += i.priceJpy * i.qty
        }
        cash += i.priceJpy * i.qty              // 現金合計は全部
    }
    return (sats, cashForSats, cash)
}
```

混ぜて呼んでみる。

```swift
let p1 = products[0]  // ST-001 (sats: 500)
let p2 = products[2]  // ST-003 (sats: nil)
let a1 = Adhoc(name: "委託品A", priceJpy: 1200, priceSats: nil, qty: 1)
let a2 = Adhoc(name: "委託品B", priceJpy: 500,  priceSats: 800,  qty: 2)

let t = totalsForSats([p1, p2, a1, a2])
print("sats払い: \(t.sats) sats + \(t.cashForSats)円")
print("現金払い: \(t.cash)円")
```

**できた合図**:
```
sats払い: 2100 sats + 1500円
現金払い: 3600円
```

計算: sats - a2 が 800×2=1600 + p1 500×1=500 → 2100。現金分 - p2 300 + a1 1200 → 1500。現金合計 300+300+1200+1000=2800？ 300(ST-001)+300(ST-003)+1200(a1)+500*2(a2)=300+300+1200+1000=2800。

待ち合わせ: p1はqty1（Product.qty=1）なので300円+sats500。p2 300円+sats nil。a1 1200円+nil。a2 500円+sats800 qty2。sats合計 500 + (800*2)=2100。cashForSats 300+1200=1500。cash 300+300+1200+1000=2800。上の出力と合っている。

- **登録商品（Product）と野良商品（Adhoc）は別の型**でも、**同じ関数**で扱える
- 「種類が増えても強い」のは、この**共通の約束**でまとめられるから

## 4. extension で既定実装（default implementation）

プロトコルにメソッドや計算プロパティの**既定実装**を付けると、準拠側が書かなくても動く。

```swift
extension Priced {
    /// sats単価の有無を分かりやすくするラベル（A-3）。既定実装。
    var satsLabel: String {
        if let s = priceSats { return "\(s) sats" }
        else { return "―（現金）" }
    }

    /// この行が sats払いでも現金で受け取るか
    var requiresCashIfSats: Bool { priceSats == nil }
}
```

`extension Product: Priced` や `extension Adhoc: Priced` に書かなくても使える。

```swift
for item in [p1, p2, a1] as [Priced] {
    print(item.name, item.satsLabel)
}
```

**できた合図**:
```
ステッカー まる 500 sats
ステッカー しかく ―（現金）
委託品A ―（現金）
```

プロトコル拡張の良さ: 「共通の表示ルール」を**1か所**にまとめる。準拠する型ごとに同じ処理を書かずに済む。

## 5. any（存在型）と some（不透明型）の初歩

Swiftには「型を包む」2つの書き方がある。

### `any` … 「どの型でもいいけど、Priced という約束は満たす」
配列 `[Priced]` は実は「存在型 `any Priced`」の集まり。
`any` を明示すると「**この箱には、Priced に準拠した何かが入っている**」と分かりやすくする。

```swift
func printCart(_ items: [any Priced]) {
    for i in items {
        print("・\(i.name) ¥\(i.priceJpy)×\(i.qty) \(i.satsLabel)")
    }
}

printCart([p1, p2, a1, a2])
```

### `some` … 「関数の中で決まった1つの型」
`some View` の `some` は不透明型。返す「実際の型」は1つに決まっているが、呼び出し側には**中身を見せない**。
`any` と違って、Swift は**型を特定できる**ので、少し効率的なことが多い。

```swift
func makePricedLabel(_ item: some Priced) -> String {
    "\(item.name) / \(item.satsLabel)"
}

print(makePricedLabel(p1))
print(makePricedLabel(a1))
```

違いの簡単な説明:
- `any` … **型の束**。箱の中身は違う型でも入る
- `some` … **1つの型**。実際は同じ型だが、外からは隠す

まずは「`any` は存在型」「`some` は不透明型」と知るだけで十分。慣れてから深掘りしていく。

## Svelte/TSでいうと

- `protocol Priced` ≒ TypeScript の `interface Priced { ... }`
- `extension Priced { ... }` ≒ インターフェースに**デフォルト実装**を付ける（TS では `class` や `abstract`、ユーティリティ的に関数を書くなど）
- `any` は `any` 的だが、ここでは**約束を満たす何か**なので `Priced` 型の値
- `[Priced]` で混ぜて扱うのは「**共通のインターフェース**で同じ関数に渡す」の考え方そのもの

---

## まとめ

- `protocol` は「共通の約束」（何を持つか／何ができるか）を決める
- 異なる型（`Product`・`Adhoc`）を**同じ約束**でまとめ、同じ関数に渡せる（**後で種類が増えても強い**）
- `extension` で**後付け準拠**・**既定実装**ができる
- `any Priced` は存在型（中身は違う型でもOK）、`some Priced` は不透明型（1つの型だが外には見せない）
