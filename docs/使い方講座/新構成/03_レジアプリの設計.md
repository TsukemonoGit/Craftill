## レッスン1: Swiftの基本を一通り

以降のレッスンで使う部品だけを、1つのブック（Playgrounds）に順に書いて動かす。
Playgroundsのチュートリアルを進めてもよい。ここでは**このアプリで使うものだけ**に絞る。

### ① 変数と定数

```swift
let shopName = "ステッカー屋"   // let = 後から変えられない（定数）
var count = 0                   // var = 後から変えられる（変数）
count = count + 1
count += 1                      // 「足して代入」。上と同じ意味

let priceJpy: Int = 300         // 型を明示する書き方（Int = 整数）
let name: String = "ステッカー"  // String = 文字列

print(shopName, count, priceJpy, name)
print("\(name) は ¥\(priceJpy)")  // \( ) で文字列の中に値を埋め込む
```
- `let` を基本にし、変わる物だけ `var` にする
- 主な型: `Int`（整数）/ `String`（文字列）/ `Bool`（true / false）

### ② if（条件分岐）

```swift
let stock = 0

if stock > 0 {
    print("買える")
} else {
    print("SOLD OUT")
}
```
- 比較: `==`（等しい）`!=`（等しくない）`>` `<` `>=` `<=`
- 「かつ」は `&&`、「または」は `||`

### ③ 配列と for（繰り返し）

```swift
let prices = [300, 300, 800]

var sum = 0
for p in prices {      // 1個ずつ p に入れて繰り返す
    sum += p
}
print(sum)             // 1400
print(prices.count)    // 3（個数）
```

### ④ 関数

```swift
func addTax(_ price: Int) -> Int {   // (引数) -> 返す型
    return price * 110 / 100
}

print(addTax(300))   // 330
```
- `func 名前(引数) -> 返す型 { ... }`
- `_` を付けると呼ぶとき引数名を書かなくてよい（`addTax(300)`）

### ⑤ 構造体（struct）

```swift
struct Item {
    let name: String
    let priceJpy: Int
}

let a = Item(name: "ステッカー", priceJpy: 300)
print(a.name, a.priceJpy)   // .（ドット）で中身を取り出す
```
- 関連する値を1つにまとめる型。`Item(...)` で作る

### ⑥ enum（選択肢）

```swift
enum Pay {
    case cash
    case lightning
}

let pay = Pay.cash

switch pay {
case .cash:      print("現金")
case .lightning: print("ライトニング")
}
```
- 決まった選択肢のどれか1つ、を表す型。`switch` で分岐する
- `switch` はすべての `case` を書く必要がある

### ⑦ オプショナル（nil かもしれない値）

```swift
let satsPrice: Int? = nil     // Int? = 「Int か nil（値なし）」

if let s = satsPrice {        // 値があるときだけ中に入る
    print("\(s) sats")
} else {
    print("sats単価なし")
}

let shown = satsPrice ?? 0    // nil のときの代わりの値
print(shown)                  // 0
```
- `?` を付けた型は nil になりうる。使う前に `if let` か `??` で確認する

**できた合図**: ①〜⑦の各 `print` が、コメントに書いた結果と同じになる。

### このレッスンで読むべきこと

| 見る場所 | 何が分かるか |
| --- | --- |
| `Product` の `attr1` 以降に `= nil` がある | 値を入れなかった項目は既定値になる。**全項目を書く必要はない** |
| `Product` に `stockMode` が **ない** | 在庫の扱いは **種類** が決める（A-1、A-19-9）。`stockMode(in:)` で引く |
| `CartLine` に `stock` が **ない** | カートは在庫を持たない。現在の在庫は `products.stock` 側で見る（A-7） |
| `CartLine` に `isAdhoc` がある | 野良も同じ型で表す（A-1、A-13 の `item_type`） |
| `SaleState` が **8つ** | 中断（`suspended`）を落とさない（A-4） |
| `IdSequencer` | 販売IDは**完了時だけ**採番する（A-19-4） |

### カートの1行（`CartLine`）— 全レッスン共通

`base/Types.swift` に書いてあります。**ここには書きません**。
`CartLine(product: p, qty: 2)` でカートの行を作れます。

```swift
let line = CartLine(product: sticker, qty: 2)
print(line.name)                    // ステッカー まる
print(line.subtotalJpy)             // 600（= 円単価 × 数量）
print(line.itemType.rawValue)       // registered

// 野良も同じ型（A-1）
let adhoc = CartLine.adhoc(id: "ADHOC-1", name: "野良（販売した本）",
                           priceJpy: 500, priceSats: nil, qty: 1)
print(adhoc.isAdhoc, adhoc.typeId as Any)    // true nil
```

**できた合図**:
```
ステッカー まる
600
registered
true nil
```

この形にした理由（`../../siyou.md` より）:

| 方針 | 根拠 |
| --- | --- |
| **在庫を持たない** | 現在庫は端末内DBが唯一の正（A-7）。古い在庫をカートに持ち込むと二重管理になる |
| **商品名と価格を写して持つ** | 販売時点の値が残る（A-13 の `name_snapshot`・`unit_price_jpy`） |
| **`isAdhoc` で野良を表す** | 野良は商品マスタに無いので `type_id`・`product_id` を持たない（A-1、A-13 の `item_type`） |
| **平坦で持つ** | 4つの追加経路（QR・手動・商品パネル・野良）が、同じ1つの型で並ぶ（A-2） |

> `Product` を丸ごと `CartLine` に入れて持つ形もあるが、在庫・画像・属性まで一緒にコピーされ、
> 野良（商品マスタに無いもの）を表せません。「在庫は在庫表で引く」という A-7 とも合いません。

## レッスン3: テスト商品を配列で用意する

**配列**＝同じ型のものを順番に並べたもの。`[ ]` で囲み `,` で区切る。
`[Product]` は「**Product の配列**」という意味。

```swift
let products: [Product] = [
    Product(id: "ST-001", typeId: "sticker",   name: "ステッカー まる",     priceJpy: 300, priceSats: 500,  stock: 10),
    Product(id: "ST-003", typeId: "sticker",   name: "ステッカー しかく",   priceJpy: 300, priceSats: nil,  stock: 10),
    Product(id: "KH-001", typeId: "keyholder", name: "キーホルダー 01", priceJpy: 800, priceSats: 1200, stock: 1),
    Product(id: "KH-008", typeId: "keyholder", name: "キーホルダー 08", priceJpy: 800, priceSats: 1200, stock: 1),
]

print(products.count)   // 4（何個あるか）

for p in products {     // 1個ずつ取り出して繰り返す
    print(p.id, p.name, p.priceJpy)
}
```
- `products.count` … 配列の中身の**数**
- `for p in products { ... }` … 1つずつ `p` に入れて中を繰り返す（`for` 文）

**できた合図**: `4` と、4商品のID・名前・値段が並んで出る。

### このレッスンで読むべきこと

| 見る場所 | 何が分かるか |
| --- | --- |
| `for l in self` と `if let s = l.unitPriceSats` | sats単価の**有無**で足す先を分ける（A-6-1） |

## レッスン5: ID正規化（`"kh8"` → `"KH-008"`）

入力したIDを**決まった形**に直す。今回は「英字（接頭辞）＋3桁ゼロ埋め」。

```swift
import Foundation  // String(format:) を使うため

func normalizeID(_ raw: String) -> String {
    let upper  = raw.uppercased()                 // 小文字→大文字
    let letters = upper.filter { $0.isLetter }    // 英字だけ取り出す
    let digits  = upper.filter { $0.isNumber }    // 数字だけ取り出す
    let n = Int(digits) ?? 0                       // 数字にする（空なら0）
    return letters + "-" + String(format: "%03d", n) // 3桁ゼロ埋め
}

print(normalizeID("kh8"))     // KH-008
print(normalizeID("KH-020"))  // KH-020
print(normalizeID("st 1"))    // ST-001
```
- `.filter { }` … 条件に合う文字だけ残す
- `String(format: "%03d", n)` … 3桁にゼロ埋め（8 → 008）
- 全角の英字対応などは**後で**でよい（今は半角前提）

**できた合図**: `KH-008` / `KH-020` / `ST-001` が出る。

## レッスン6: 会計状態を `SaleState` で表す

会計の「今どの段階か」は `SaleState` です。型は `base/Types.swift` に8状態あります
（`base/6_会計の状態機械.md` は「遷移のしかた」の正で、型そのものは `Types.swift`）。
**ここでは書かず**、`switch` で分岐するところだけ練習します。

```swift
// ペースト済みならこれで動く（SaleState は base/Types.swift に 8 状態ある）
func describe(_ state: SaleState) -> String {
    switch state {
    case .idle:            return "レジ待機中"
    case .scanning:        return "商品をスキャン中"
    case .choosingPayment: return "支払方法を選んでください"
    case .cashInput:       return "現金を受け取り中"
    case .satsWaiting:     return "satsの入金待ち"
    case .mixedCashInput:  return "sats確認済み・現金を受け取り中"
    case .suspended:       return "中断しました"
    case .done:            return "会計完了"
    }
}

print(describe(.scanning))
```

**できた合図**: `商品をスキャン中` が出る。

- `switch` … 選択肢ごとに処理を分ける。`enum` と相性がよい
- `.scanning` は `SaleState.scanning` の省略形
- **8 状態を全部書かないとコンパイルエラー**になります。
  `case .suspended` と `case .mixedCashInput` を忘れないこと（A-4）

> **遷移の判断は `base/6` の `move(...)` が行います。**
> このレッスンでは「状態の名前を表示するだけ」です。
> A-4 の遷移表と、確認ダイアログ・PIN の考え方は
> `56_会計の状態を切り替える.md` で扱います。
