# 画面と保存 ― SwiftUIと永続化

> **前:** [レジアプリの設計](03_レジアプリの設計.md) ｜ **入口:** [はじめに](00_はじめに.md) ｜ **次:** [他言語から見たSwift](05_他言語から見たSwift.md)

基本レッスン7〜8。作ったロジックをSwiftUIの画面に出し、アプリを閉じてもデータが残るように保存します。
ブックとアプリの画面の出し方の違い、`Codable` / `JSONEncoder` / `UserDefaults` を扱います。

## レッスン7: SwiftUIでレジ画面を1枚

左に商品、右にカートという2列を出す（`../../開発/5_画面構成.md` の図）。
レッスン1〜6は関数を作って `print` で結果をコンソールに見るだけだったので、画面を出す必要がなく、書いてすぐ実行できる**ブック**で足りていた。
このレッスンで初めて**画面（UI）**を出す。画面を出すのは、最終的に作る**アプリ**の役目なので、ここからアプリで作る。
ただしブックとアプリでは画面の出し方が違う。同じ画面（`RegisterView`）を**両方で表示**して、それぞれのやり方と違いを押さえる。

### ① ブックで表示する
`PlaygroundSupport` で画面を表示できる（`01_Swiftの基礎.md` の**ブック**で）。

```swift
import SwiftUI
import PlaygroundSupport

struct RegisterView: View {
    let cart = ["ST-001 ステッカー まる", "KH-008 キーホルダー 08"]
    var body: some View {
        HStack {
            VStack(alignment: .leading) {          // 左: 商品
                Text("商品").font(.headline)
                Text("ST-001 ステッカー まる")
                Text("KH-008 キーホルダー 08")
            }
            .padding()
            Divider()
            VStack(alignment: .leading) {          // 右: カート
                Text("カート").font(.headline)
                ForEach(cart, id: \.self) { Text($0) }
                Text("合計 ¥1100").bold()
            }
            .padding()
        }
        .frame(width: 600, height: 320)
    }
}

PlaygroundPage.current.setLiveView(RegisterView())
```
- `HStack` … 横に並べる。`VStack` … 縦に並べる
- `ForEach` … 配列を1つずつ表示する
- `PlaygroundPage.current.setLiveView(...)` … 作った画面を表示する（Playground専用）

### ② アプリで表示する
これから本番で使うのはこちら。`PlaygroundSupport` と `setLiveView` を消し、代わりに **`@main` の入口**を付ける。起動すると画面が自動で出る（`01_Swiftの基礎.md` の**アプリ**で）。

```swift
import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            RegisterView()   // ← 起動時にこれが自動で出る
        }
    }
}

struct RegisterView: View {
    let cart = ["ST-001 ステッカー まる", "KH-008 キーホルダー 08"]
    var body: some View {
        HStack {
            VStack(alignment: .leading) {          // 左: 商品
                Text("商品").font(.headline)
                Text("ST-001 ステッカー まる")
                Text("KH-008 キーホルダー 08")
            }
            .padding()
            Divider()
            VStack(alignment: .leading) {          // 右: カート
                Text("カート").font(.headline)
                ForEach(cart, id: \.self) { Text($0) }
                Text("合計 ¥1100").bold()
            }
            .padding()
        }
        .frame(width: 600, height: 320)
    }
}
```
- `@main struct ...App` … アプリの**入口**（起動時に `WindowGroup` の中身が出る）
- `WindowGroup { RegisterView() }` … 出す画面を指定する

> ブックとアプリの一般的な違い（トップレベルに書けるか、画面の出し方、入口）は
> `01_Swiftの基礎.md` の「Playgrounds って？」にまとめてある。
> ここでの違いは **import が `SwiftUI` ＋ `PlaygroundSupport` か `SwiftUI` だけか**、そして**入口（`setLiveView` か `@main` か）**の2点。

**注意**: ②は**アプリを新規作成**して書く。ブックのファイル（レッスン1〜8を追記してきたもの）には**そのまま足せない**（トップレベル禁止。`01_Swiftの基礎.md` のつまずき①）。`RegisterView` は共通なので、入口だけ差し替えるイメージ。

**できた合図**: どちらでも、左に商品、右にカートが横並びで表示される。

## レッスン8: データを保存してアプリを閉じても消えないようにする（永続化）

ここまでのレッスンでは、プログラムを実行している間だけメモリ上に存在するデータを扱ってきた。
このレッスンでは、アプリを一度終了したり電源を切ったりしてもデータが消えないように、端末のストレージへ保存（永続化）して復元する手順を1ステップずつ組み立てていく。

> **これは「Swift の仕組みのお勉強」です。** 使うのは `UserDefaults` でも
> ファイルでも構いませんが、**実運用では使いません**。
> 営業中に強制終了されると、書き込みが失われることがあります（A-3 が要求する保持と矛盾）。
> 正しい保存は `base/6_会計の状態機械.md` §8 の `SaleContextStore`
> （`.atomic` でファイルに書き、失敗は `throws` で外へ出す）です。
> それは `19_会計状態をまるごと保存する.md` で扱います。

---

### ステップ1: 必要な道具箱の読み込みと、保存するデータの形（構造体）を決める

まずは、ファイルの冒頭で標準ライブラリ（道具箱）を読み込み、保存したいデータ（カートの1行分）の設計図を作る。

保存したいデータ（カートの1行分）の設計図は、**`base/Types.swift` の `CartLine` をそのまま使います**。ここで定義し直さないこと。

```swift
import Foundation

// base/Types.swift の CartLine を貼り付けてある前提。
//   struct CartLine: Codable { id / typeId / name / unitPriceJpy / unitPriceSats / qty / isAdhoc }
// Codable が付いていれば、保存・復元に必要な情報はすべて揃っています。
```

> `Codable` が無い構造体は `JSONEncoder` に渡せません。また、**保存したあとに項目を増やすと過去のJSONが読めなくなります**（→ `try?` が失敗を隠して、カートが空に見える。末尾の注意参照）。形を足すなら `CodingKeys` の `decodeIfPresent` を使い、既定値を埋める形にします。

* **`import Foundation`**: Swiftでファイルを扱ったり、エンコード処理をしたり、`UserDefaults` や `NSHomeDirectory()` を使うための基本的な道具箱を読み込む命令。これがないと保存・復元の機能が使えない。
* **`Codable`**: Swiftの構造体を、保存用のデータ形式（JSON）に変換したり、逆に元に戻したりするためのプロトコル（印）。これがないと `UserDefaults` に保存できない。

### ステップ3: データをJSONに変換して保存する

作成した構造体の配列はそのままではストレージに入れられないため、`JSONEncoder` を使ってバイナリデータ（JSON形式の `Data` 型）に変換し、`UserDefaults`（キー・バリュー形式の保存領域）に書き込む。

```swift
let encoder = JSONEncoder()
let userDefaults = UserDefaults.standard

do {
    let data = try encoder.encode(lines)
    userDefaults.set(data, forKey: "cart")
    print("保存した")
} catch {
    print("エンコード失敗: \(error)")
}

```

* **`JSONEncoder()`**: Swiftの構造体配列を、保存用のバイナリデータに変換する機械。
* **`try`**: 失敗するかもしれない処理（エラーを投げるかもしれない処理）を実行する印。失敗したときは `catch` に移る。
* **`do-catch`**: エンコードの失敗を受け止め、`error` として理由を表示する。`fatalError` で落とさない。
* **`UserDefaults.standard`**: アプリの軽量なデータを端末に保存するための標準ストレージ領域。
* **`userDefaults.set(data, forKey: "cart")`**: `"cart"` という名前（キー）をつけて、変換したデータをストレージに書き込む。

> `try?` で受けると、失敗したときに `nil` になるだけで**理由が消えます**。
> 学習中は `do-catch` で `error` を読むほうが、原因を見つけやすいです。

---

### ステップ4: 保存したデータを取り出して復元する

ストレージに保存したデータを `"cart"` というキーで呼び出し、今度は `JSONDecoder` を使って元の Swift の構造体配列に組み立て直す。

```swift
if let savedData = userDefaults.data(forKey: "cart") {
    do {
        let restored = try JSONDecoder().decode([CartLine].self, from: savedData)
        print("復元成功: \(restored)")
    } catch {
        print("デコード失敗: \(error)")
    }
} else {
    print("保存データなし")
}

```

* **`userDefaults.data(forKey: "cart")`**: 指定したキーに保存されているバイナリデータを、`Data?`（無ければ `nil`）で取得する。
* **`if let`**: 保存データがあるときだけ復元する。無いときは `else` で「保存データなし」と表示する。
* **`try`（通常の try）**: エラーを投げる可能性がある処理を、`do-catch` の中で実行する。失敗してもアプリ全体を落とさず、`catch` で受け止める。
* **`JSONDecoder().decode(...)`**: 取得したバイナリデータを読み込み、元の `[CartLine]` 型の配列に復元する。
* **`do-catch`**: デコード時に予期せぬエラーが起きても、エラー内容を表示して安全に対処するための構文。

### ステップ5: 保存場所（ストレージの基盤）を確認する（任意）

MacやLinux（VS Code・Docker等）で実行している場合、データがどこに書き込まれているのかを `NSHomeDirectory()` で確認できます。Swift Playgrounds では不要です。

```swift
print("Home Directory: \(NSHomeDirectory())")

```

* **`NSHomeDirectory()`**: 現在の実行プロセスにおけるユーザーのホームディレクトリの絶対パス文字列（Linux環境の場合は `/home/codespace` 等）を取得・出力し、ストレージの保存基盤を確認する。

---

### まとめと、触ってはいけない場所

- 保存は `JSONEncoder` でJSONにして `UserDefaults` に書き、復元は `JSONDecoder` で読み戻す。
- **復元できない理由の多くは「保存した時の形と、復元する時の形が違う」こと**です。

実際に起こる例:

```swift
// 保存した時（旧い形のイメージ）
struct OldCartLine: Codable {
    var id: String; var name: String; var priceJpy: Int; var qty: Int
}
// → {"id":"KH-002","name":"キーホルダー 02","priceJpy":800,"qty":1}

// 後から項目を増やした現在の形（イメージ）
struct NewCartLine: Codable {
    var id: String; var name: String; var unitPriceJpy: Int; var unitPriceSats: Int?
    var qty: Int; var isAdhoc: Bool
}
try? JSONDecoder().decode([NewCartLine].self, from: oldData)   // → nil（キー不足）
```

> 実際の `CartLine` は `base/Types.swift` にあります。ここでは「形が変わると読めなくなる」ことだけを見るため、`OldCartLine` / `NewCartLine` という別名で説明しています。

`Codable` は「キーが足りなければ失敗」とします。そして `try?` はその失敗を **nil に変えて黙る** ので、結果として**カートが空に戻ったように見える**だけのバグになります（`49_エラー処理を書く.md` の「`try?` は理由を消してしまう」）。

**対策**: ① 復元は `do-catch` で失敗理由まで読む（`19_会計状態をまるごと保存する.md`）。② 過去のデータにも対応したい場合は `init(from decoder:)` を自前で書いて、`decodeIfPresent` で既定値を埋める。

### 最終的な完成コード

ステップ1〜5をすべて繋げた、レッスン8の完全なコード。
**`CartLine` は `base/Types.swift` のものをそのまま使います**（下のコードは貼り付け済みの前提で、再定義しません）。

```swift
import Foundation

// 1. 保存するデータを作る（CartLine は base/Types.swift のもの）
let lines = [CartLine(id: "ST-001", typeId: "sticker", name: "ステッカー まる",
                      unitPriceJpy: 300, unitPriceSats: 500, qty: 2, isAdhoc: false)]

// 2. エンコードと保存
let encoder = JSONEncoder()
let userDefaults = UserDefaults.standard

do {
    let data = try encoder.encode(lines)
    userDefaults.set(data, forKey: "cart")
    print("保存した")
} catch {
    print("エンコード失敗: \(error)")
}

// 3. 保存データの取り出し（復元）
if let savedData = userDefaults.data(forKey: "cart") {
    // 4. デコード（構造体への復元）とエラーハンドリング
    do {
        let restored = try JSONDecoder().decode([CartLine].self, from: savedData)
        print("復元成功: \(restored)")
    } catch {
        print("デコード失敗: \(error)")
    }
} else {
    print("保存データなし")
}

// 5. 実行基盤のホームディレクトリ確認（Mac / Linux では確認用。Playgrounds では不要）
print("Home Directory: \(NSHomeDirectory())")
```

**できた合図**: `保存した`、`復元成功: [...]`、`Home Directory: ...` の3行が出る（配列の中身は環境で変わる）。
2回目に実行しても `復元成功` が出れば、保存が効いている。

### 補足: VS Code / Linuxコンテナで試す場合

Swift Playgrounds では意識しなくてよいが、Linux の Swift で `UserDefaults` を試すと保存先が気になることがある。

- **macOSとの保存先の違い**: macOSの標準アプリ（plistファイル等）とは異なり、Linux環境のSwift（CoreFoundation / Foundation）では、通常 `~/.local/share/` や、実行中のユーザーのホームディレクトリ配下の隠しディレクトリにデータベースやplistとして書き込まれる。
- **スクリプト実行時の挙動**: ターミナルで `swift ファイル名.swift` と直接スクリプト形式で実行した場合、プロセスごとに一時的な領域が使われるか、同じユーザーセッション内であれば同じ領域を共有する。そのため、2回目の実行時にデータが残っていて復元成功することがある。
- **確認方法**: `print(NSHomeDirectory())` でホームディレクトリを表示し、その下を探す。

> この保存はあくまで学習用。実運用では `SaleContextStore` のように、失敗を `throws` で外へ出し、`.atomic` でファイルに書く。
