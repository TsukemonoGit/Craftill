# 40. 販売記録を書き出す

元: `../siyou.md` A-8（エクスポート）、A-13（列名）
`../siyou.md` A-19-5（日時）、A-19-4（採番規則）、A-19-7（集計）
受け入れテスト C-6 **#27**（エクスポートが日次集計と一致）・**#70**（種類別に分けて表示される）

販売（`sales`）と明細（`sale_items`）を **JSON または CSV** で書き出します。
列名は **A-13** の項目名と同一です（A-8）。

**このレッスンは「書き出す」だけじゃない**。

> **C-6 #27**: エクスポートしたCSV／JSONの販売合計（現金・sats別。**併用会計は現金分とsats分に分けて**）が**日次集計と一致する**
> **C-6 #70**: 日次集計とエクスポートで、登録商品が**種類別に**集計・出力され、**野良商品と分けて**表示される

**元のパラメータにはこの2つの検証がありませんでした。** 正は `base/` にあります。

## まず土台をペーストする

1. `base/Types.swift` の**型だけ**（`Sale` / `SaleItem` / `IdSequencer` を含む）
2. `base/3_標準ロジック.md` の **§1・§2・§3・§4・§5-1・§6-0・§7**

> **列名（`sale_id` / `item_id`）は `CodingKeys` で決まっています**（§わざと間違う①）。

## わざと間違う①: `convertToSnakeCase` だけで 列名 assumptions する

```swift NG
// わざと間違う版①：Swift のプロパティ名をそのまま snake_case にする
let encoder = JSONEncoder()
encoder.keyEncodingStrategy = .convertToSnakeCase
```

**A-13 の列名**はこうです。

| Swift のプロパティ | A-13 の列 |
| --- | --- |
| `Sale.id` | **`sale_id`** |
| `SaleItem.id` | **`item_id`** |

**`convertToSnakeCase` だけだと `id` になってしまいます**（`id` に `_` は付かない）。

**実際に書かれるもの**:

```swift NG
{ "id": "S-20231115-001", "status": "completed", … }     // ★ A-13 と違う
```

**正**は `CodingKeys` です。**`base/Types.swift` に入っています。**

```swift 断片
// base/Types.swift の正
struct Sale: Codable, Equatable, Identifiable {
    let id: String             // Swift のプロパティは id
    …
    /// **A-13 の列名**に合わせる
    enum CodingKeys: String, CodingKey {
        case id = "sale_id"    // ★ id → sale_id
        case status, method, totalJpy, totalSats, receivedJpy, changeJpy
        case confirmedAt, refunded, completedAt
    }
}

struct SaleItem: Codable, Equatable, Identifiable {
    let id: String
    …
    enum CodingKeys: String, CodingKey {
        case id = "item_id"    // ★ id → item_id
        case saleId, itemType, typeId, productId, qty
        case unitPriceJpy, unitPriceSats, paidIn, nameSnapshot
    }
}
```

**Swift では `saleId` でも `id` でもなく `id`** に統一されています（A-19-9）。
`Identifiable` にも `id` が必要なので、その意味でも `id` が自然です。

## わざと間違う②: `refunded` を `Int` で持つ

```swift NG
// わざと間違う版②：返金済みフラグを整数で持つ
struct Sale: Codable {
    let refunded: Int          // 0 / 1
}
```

**フラグに `Int` は使いません。** `base/` は **`Bool`** です。

| | `Int` | **`Bool`** |
| --- | --- | --- |
| 書ける値 | **0, 1, 2, -1 …** | `true` / `false` |
| CSV | `String(refunded)` で **0/1/2** が出る | `refunded ? "1" : "0"` で**必ず 0/1** |
| 型検査 | 電卓でも通る | `if sale.refunded` で**書ける** |

**CSV に出る値が違う**のが実害です（A-8 のエクスポート）。

**正**: `Bool` のまま持ち、**CSV に書く時だけ** `"1"` / `"0"` に変換します。

## わざと間違う③: 明細の全行を足してしまう

**ここが一番危険**です。C-6 #27 / #70 の**中身**の話です。

```swift NG
// わざと間違う版③：sale_items.csv の全行を足す
var registered = 0, adhoc = 0
for row in itemsText.split(separator: "\n").dropFirst() {
    let r = parse(row)
    guard r.paidIn == "jpy", let price = Int(r.unitPriceJpy), let qty = Int(r.qty) else { continue }
    if r.typeId.isEmpty { adhoc += price * qty } else { registered += price * qty }
}
```

**`sales.csv` には `voided` の行も入っています**（中断の記録・A-19-2）。
**その明細まで足すと、日次集計と合わなくなります。**

| | 日次集計（`summarize`） | CSV 全文を足した版 |
| --- | --- | --- |
| 対象 | **`status == completed` だけ** | **全行**（`voided` も含む） |
| 登録 | 1700円 | **2000円**（`voided` の300円が混ざる） |
| 野良 | 1200円 | 1200円 |

**`voided` の明細を足した数が 300円**。**`total_jpy` は `sales` 側だけ見てると気づかない**ので、
**明細を足す側の判定が甘いと静かにズレます**（C-6 #27）。

**正**: **`sales.csv` の `status` を見て `completed` を選んでから、その明細だけ足す**。

```swift 断片
// 正：sales.csv の completed だけを選ぶ
let completed = Set(salesText.split(separator: "\n").dropFirst()
    .map { parse($0) }
    .filter { $0.status == "completed" }
    .map { $0.saleId })

for row in itemsText.split(separator: "\n").dropFirst() {
    let r = parse(row)
    guard completed.contains(r.saleId) else { continue }     // ★ voided を弾く
    …
}
```

> **「エクスポートは `completed` だけ」ではない**のが注意点です。
> **`voided` の行も書き出します**（中断の記録・A-19-2、A-19-7）。
> **読む側が `status` で選ぶ**。これが A-8 の「中断の記録を残す」の意味です。

## わざと間違う④: `csvField` を一部の列にしか通さない

```swift NG
// わざと間違う版④：文字列をそのまま連結する
var lines = ["sale_id,status,method,…"]
for s in sales {
    let row = [s.id, s.status, s.method, opt(s.totalJpy), …]
    lines.append(row.joined(separator: ","))      // ★ 引用符が無い
}
```

**`csvField` を通さないと**、値に **`,` `"` `\n`** が入った瞬間に**列がずれます**。

**デモでは野良商品名に `輸入品 A, B "特価"` を入れてあります**。
引用符を通すと `読み戻し → 元の文字列` に戻ります。

| | `csvField` あり | なし |
| --- | --- | --- |
| `輸入品 A, B "特価"` | `"輸入品 A, B ""特価"""` | `輸入品 A, B "特価"` → **列がずれる** |
| 読み戻し | **元と同じ** | **壊れる** |

**全列に `csvField` を通します。** `String` に限らず、**`Int` を `String` にしたあと**通します。

## 1. 日時と `voided` の扱い

| 列 | `Date?` の書き出し | A-19-5 |
| --- | --- | --- |
| `confirmed_at` | `nil` なら**空** | ISO 8601・タイムゾーン付き |
| `completed_at` | `nil` なら**空** | 同上 |
| `imported_at` | 同上 | 同上 |

**`voided` の行の空欄は「意味のある空」**です。

| 状態 | `completed_at` | `confirmed_at` | 意味 |
| --- | --- | --- | --- |
| `completed` | あり | 併用ならあり | 売上 |
| `voided`（販売取消） | **あり** | — | 売上から外す（在庫は戻す・A-19-3） |
| `voided`（**sats確認済みの中断**） | **空** | **あり** | 売上に含めない・別枠（A-19-7） |

**`voided` で `completed_at` が空**、というだけで **sats確認済みの中断**と判別できます（A-19-3）。

func csvField40(_ value: String) -> String {
    let needsQuote = value.contains(",") || value.contains("\"") || value.contains("\n")
    if !needsQuote { return value }
    return "\"\(value.replacingOccurrences(of: "\"", with: "\"\""))\""
}
func opt40(_ v: Int?) -> String { v.map(String.init) ?? "" }
func flag40(_ b: Bool) -> String { b ? "1" : "0" }

func salesCSV40(_ sales: [Sale]) -> String {
    var lines = ["sale_id,status,method,total_jpy,total_sats,received_jpy,change_jpy,confirmed_at,refunded,completed_at"]
    for s in sales {
        lines.append([
            csvField40(s.id), csvField40(s.status.rawValue), csvField40(s.method.rawValue),
            opt40(s.totalJpy), opt40(s.totalSats), opt40(s.receivedJpy), opt40(s.changeJpy),
            csvField40(isoDate40(s.confirmedAt)), flag40(s.refunded), csvField40(isoDate40(s.completedAt)),
        ].joined(separator: ","))
    }
    return lines.joined(separator: "\n")
}
func saleItemsCSV40(_ items: [SaleItem]) -> String {
    var lines = ["item_id,sale_id,item_type,type_id,product_id,qty,unit_price_jpy,unit_price_sats,paid_in,name_snapshot"]

            csvField40(it.paidIn.rawValue), csvField40(it.nameSnapshot),
        ].joined(separator: ","))
    }
    return lines.joined(separator: "\n")
}
func isoDate40(_ d: Date?) -> String {
    guard let d = d else { return "" }
    let f = ISO8601DateFormatter()
    f.formatOptions = [.withInternetDateTime]
    return f.string(from: d)
}

// ═══ 書き出した CSV を読み戻す（最小のパーサ）═══
func parseRow40(_ line: String) -> [String] {
    var out: [String] = []
    var cur = ""
    var inQuote = false
    var it = line.makeIterator()
    var pending: Character? = nil
    while let c = pending ?? it.next() {
        pending = nil
        if inQuote {
            if c == "\"" {
                if let next = it.next() {
                    if next == "\"" { cur.append("\"") } else { inQuote = false; pending = next }
                } else { inQuote = false }
            } else { cur.append(c) }
        } else {
            switch c {
            case "\"": inQuote = true
            case ",":  out.append(cur); cur = ""
            default:   cur.append(c)
            }
        }
    }
    out.append(cur)
    return out
}

## ポイント

- **列名は `CodingKeys`**。`convertToSnakeCase` だけだと `id` になる（A-13）
- **`refunded` は `Bool`**。CSV に出る時だけ `"1"` / `"0"` に変換
- **`voided` の行も書き出す**。**読む側が `status` で選ぶ**（A-19-2、A-19-7）
- **明細を足す前に `sales.csv` の `completed` で弾く**（C-6 #27、#70）
- **`csvField` は全列**。`,` `"` `\n` を**必ず**エスケープ
- **日時は `Date` → ISO 8601**。`nil` は**空**（A-19-5）
- **`voided` かつ `completed_at` が空** = **sats確認済みの中断**（A-19-3）
- **JSON はキー順が保証されない**。**期待される出力に全文を書かない**（`38` の教訓）
- **CSV と JSON の使い分け**。CSV は列がそろって**表計算**で見やすい
