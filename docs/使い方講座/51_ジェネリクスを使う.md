# 51. ジェネリクスを使う（型を引数にする・where・型制約）

元: `../siyou.md` A-8（集計）

**ゴール**: 「型そのものを引数にする」書き方＝**ジェネリクス**を身につける。

標準ライブラリの `max` / `min` / `sorted` / `contains` が実はジェネリクスであることを確認し、

## 1. ジェネリクスとは（型を引数にする）

`<T>` は「**型のプレースホルダ**」。呼び出し時に、Swift が実際の型を当てはめる。

```swift
/// 何であれ、渡された値をそのまま返す
func identity<T>(_ x: T) -> T {
    x
}

print(identity(300))        // Int として使われる
print(identity("KH-008"))   // String として使われる
```

- `func identity<T>` … `T` は「まだ決まっていない型」の名前。慣習で `T`（Type）
- 呼び出し側が値を渡すと、`T` が `Int` や `String` に**自動で決まる**
- だから `identity` は1つ書けば、どんな型にも使える

**ひとことで**: 「**型を書かない代わりに、使う側が型を決める**」書き方。

---

## 2. 実は身近：`max` / `min` / `sorted` / `contains`

標準ライブラリのこれらは、**全部ジェネリクス**。中身を見なくても「型を引数に取る」と分かる。

```swift
print([300, 800, 1200].max()!)                 // 1200
print([300, 800, 1200].min()!)                 // 300
print(["KH-008", "ST-001", "KH-001"].sorted()) // ["KH-001", "KH-008", "ST-001"]
print(["KH-008", "ST-001"].contains("ST-001")) // true
```

- `max()` は `[Int]` でも `[Double]` でも `[String]` でも使える → 型ごとに書いていない＝ジェネリクス
- `contains` も、`[Product]` に「この条件のものがあるか」というクロージャを渡せる（型は呼び出し側が決める）

---

## 3. 型制約（`T: Comparable` / `T: Equatable`）と `where`

`max()` は「どんな T でも」ではない。**大小を比べられる型**に限られる。その条件が**型制約**。

- `Comparable` … `<` `>` で比べられる（Int, String, Double …）
- `Equatable` … `==` で等しいか比べられる（Int, String, Bool …）

自分で「最大を返す」を書くと、制約が必要な理由が見える。

```swift
/// 最大値を返す（T は比べられる型でなければならない）
func largest<T: Comparable>(_ items: [T]) -> T? {
    guard var best = items.first else { return nil }
    for item in items.dropFirst() where item > best {
        best = item
    }
    return best
}

print(largest([1200, 500, 800])!)       // 1200
print(largest(["KH-001", "ST-001"])!)   // ST-001（文字列の比較）
```

`<T: Comparable>` は `<T>(...) where T: Comparable` と同じ意味。`where` は条件が増えたときに使う。

```swift
/// 同じものを where で書いた版（条件を並べやすい）
func largest2<T>(_ items: [T]) -> T? where T: Comparable {
    items.max()   // 標準の max に任せる（それも Comparable を要求する）
}
```

- 制約が無いと `item > best` がコンパイルできない（「比べられないかもしれない」ため）
- 制約は「**できること**」を増やす。`Comparable` を付けた瞬間、`<` `>` `max` が使える

## 4. 自作：重複除去 `unique`（`T: Equatable`）

`Equatable` の代表的な使い道。商品IDの重複を消す。

```swift
/// 重複を除いて、最初に出た順に返す
func unique<T: Equatable>(_ items: [T]) -> [T] {
    var result: [T] = []
    for item in items where !result.contains(item) {
        result.append(item)
    }
    return result
}

let rawIDs = ["KH-001", "ST-003", "KH-001", "ST-001", "ST-003"]
print(unique(rawIDs))   // ["KH-001", "ST-003", "ST-001"]
```

- `result.contains(item)` は `==` を使う → だから `Equatable` が要る
- `T` のまま書いてあるので、`[Int]` でも `[String]` でも同じ関数で重複除去できる

```swift
print(unique([3, 3, 8, 3, 8]))   // [3, 8]
```

## 5. 自作：汎用検索 `firstIndex(where:)` の自作版

標準の `firstIndex(where:)` と同じ動きを、ジェネリクスで書いてみる。

```swift
/// 条件に合う最初の要素の位置を返す（無ければ nil）
func selfFirstIndex<T>(of items: [T], where match: (T) -> Bool) -> Int? {
    for (i, item) in items.enumerated() where match(item) {
        return i
    }
    return nil
}
```

型を決めるのは**呼び出し側**。`Product` でも `SaleItem` でも同じ関数で検索できる。

```swift
// 商品IDの並びから位置を探す
let ids = products.map(\.id)
print(selfFirstIndex(of: ids, where: { $0 == "KH-008" }) ?? -1)   // 5

// 明細から「KH-005 の行」を探す
print(selfFirstIndex(of: saleItems, where: { $0.productId == "KH-005" }) ?? -1)  // 1
```

- `products.map(\.id)` … `[Product]` から `[String]` を作る（この時点で要素の型が決まる）
- `saleItems` を渡すときは `T` が `SaleItem` に決まる。関数側は変更不要

標準の `firstIndex(where:)` も同じ形。自作版と見比べると、`<T>` とクロージャ `(T) -> Bool` が対応している。

## 6. 自作：明細の集計（型を呼び出し側が決める）

「各要素から取り出す値をクロージャで渡す」と、集計もジェネリクスにできる。

```swift
/// items の各要素から数値を取り出して合計する
func sumBy<T>(_ items: [T], _ value: (T) -> Int) -> Int {
    var total = 0
    for item in items { total += value(item) }
    return total
}

// 円の合計（明細ごとに 単価 × 数量）
let totalJpy = sumBy(saleItems) { $0.unitPriceJpy * $0.qty }
print("円合計: ¥\(totalJpy)")   // 3700

// sats で受け取る行だけの sats 合計（A-6-1）
let totalSats = sumBy(saleItems.filter { $0.paidIn == "sats" }) {
    ($0.unitPriceSats ?? 0) * $0.qty
}
print("sats合計: \(totalSats) sats")   // 1200
```

- `sumBy` は `T` に何が入るか知らない。**取り出し方**（クロージャ）だけ受け取る
- `Int` にも `String` にも `SaleItem` にも使える。今回は明細の集計に使った（A-8）

**できた合図**:
```
円合計: ¥3700
sats合計: 1200 sats
```

計算: 円 = 300×2 + 800×1 + 800×1 + 300×1 + 1200×1 = 600+800+800+300+1200 = 3700。
sats = `paidIn == "sats"` の I-003（1200×1）= 1200。

## Svelte/TSでいうと

TSの総称型とそっくり。`func f<T>(x: T) -> T` は `function f<T>(x: T): T`。
呼び出し側が型を決める点も同じ。`T: Comparable` は TS の
`<T extends Comparable>`（制約付き総称）に近い。
違うのは、Swift は**コンパイル時に型が決まる**こと。実行時に型を消して混ぜる話とは別物で、
ジェネリクスは「型を保ったまま使い回す」仕組み。

---

## まとめ

- `<T>` は型のプレースホルダ。**型を書かない代わりに、呼び出し側が型を決める**
- `max` / `min` / `sorted` / `contains` は標準ライブラリのジェネリクス
- `T: Comparable`（比べる）／`T: Equatable`（等しい）で**できること**を増やす。`where` で条件を書く
- `unique`（重複除去）は `Equatable` の代表例
- `firstIndex(where:)` の自作版・`sumBy` のように、**取り出し方をクロージャで渡す**と汎用になる
