## 一点物型が `.duplicateUnique` になる条件

```swift 断片
// base/5 §1 の addCheck の該当部分
let inCart = cart.first { $0.id == p.id && !$0.isAdhoc }
switch mode {
case .unique:
    return inCart == nil ? .ok : .duplicateUnique
case .counted:
    let after = (inCart?.qty ?? 0) + qty
    return after <= stock ? .ok : .overStock(current: stock, need: after)
case .none:
    return .ok
}
```

読み方はこうです。

| 種類 | `inCart == nil`（未追加） | `inCart != nil`（追加済み） |
| --- | --- | --- |
| `unique` 一点物型 | `.ok`（数量1で入れる） | **`.duplicateUnique`** |
| `counted` 数量管理型 | `.ok`（`qty` 個で入れる） | `.ok`（合計が在庫内なら加算）／`.overStock` |
| `none` 在庫管理なし型 | `.ok` | `.ok`（無制限に加算） |

**一点物型だけ「すでに入っている」ことが拒否条件**です。
数量管理型は「入っていないこと」は問題にならない、というのが違いです。

## わざと間違う: `id` だけで照合して、野良と取り違える

野良の行の `id` は `"ADHOC-1"` のような文字列です。
商品ID（`"KH-001"`）と**形が似ている**ので、照合を甘くすると事故が起きます。

```swift NG
// わざと間違う版：照合が甘い
let inCart = cart.first { $0.id == p.id }              // isAdhoc を見ていない
```

- 商品ID は `base/5` の `IdSequencer` が `KH-001` の形式で振るので（A-19-4）、
  今の実装では衝突しません。
- **でも規則としては脆い**ので、`&& !$0.isAdhoc` を入れて **「商品IDを持つ行」だけ**を見るようにします。
- 将来「商品IDを採番しない野良」（IDが空行）が入っても、判定が壊れません。

> **照合の条件を1か所に!** `addCheck` の中の `inCart` が唯一の場所です。
> `08_在庫を減らす.md` の `stockTargets` と同じ考え方です（**表を引く**）。

## 一点物型の「数量1固定」は、判定ではなく編集で弾く

C-6 #6 は「同一会計で2回追加するとエラー」と言っています。これは `addCheck` で弾きます。

一方、A-3 の表は **`unique` は ＋／－ がない**（数量1固定）とも書いています。
これは別のルールです。`addCheck` では「追加時の重複」しか見ていません。

```swift 断片
// base/5 §3 の increase。一点物型は編集側でも弾く
guard stockMode(of: line, in: types) != .unique else {
    return .rejected("\(line.name) は一点物なので数量1固定です")
}
```

| どこで弾く | 何を弾く | 根拠 |
| --- | --- | --- |
| `addCheck`（§1） | 同じ商品を2回 **追加** する | A-1、C-6 #6 |
| `increase`（§3）／`decrease`（§4） | `＋`／`－` を **押す** | A-3 の表 |

**「追加」と「編集」は別の入口**です。両方を同じ関数に混ぜると、
どちらのルールも読みにくくなります。

## ポイント

- 一点物型の拒否条件は **「すでに入っている」ことだけ**（A-1、C-6 #6）
- 照合は `id` と `!isAdhoc` の両方。判定は `addCheck` の中の `inCart` の**1か所だけ**
- **「追加」と「編集」は別の入口**。追加は `addCheck`、数量は `increase` / `decrease`
- `unique` は数量1固定なので、`＋`／`－` も `rejected`（A-3）
- メッセージは `addCheckMessage` が作る。UI 側で文言を作らない
- コードを書かないレッスン就是为了**確認だけ**に済ませる（A-13 の CSV の検証、`30` の SOLD OUT などと同じ）
