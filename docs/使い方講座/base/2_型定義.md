## 1. 型の全体像

```
種類 ProductType ──┐
                   ├─→ Product ──┐
                   │              ├─→ CartLine ──(完了時)──→ Sale + [SaleItem]
在庫表 [Product] ──┘              │                            │
（在庫の正）                      │                            ├─→ [StockMovement]
                                  └─→ SnapshotProduct（B送信）  │
                                                                └─→ [SyncLogEntry]
```

- **在庫を持つのは `Product` だけ**。`CartLine` には在庫がありません（A-7）。
- `CartLine` と `SaleItem` は同じ形ですが、別々に定義します（`CartLine` には `saleId` が要らないため）。
- **商品IDの採番に使う `nextNo` は `ProductType` が持つ**（P8）。

## 5. 守る不変条件（型では強制できないもの）

Swift の型だけでは表現できないので、**ドキュメントとして残します**。

| # | 不変条件 | どこで壊れやすいか |
| --- | --- | --- |
| I1 | `stockMode` が `.counted`/`.unique` の商品は `stock` が非 nil | CSV 取り込み |
| I2 | `CartLine.isAdhoc == true` ⟺ `typeId == nil` | 野良の行を作る関数 |
| I3 | `SaleItem.productId`/`typeId` は `itemType == .registered` のときだけ非 nil | `sale_items` の組み立て |
| I4 | `method == .lightning` ⟹ `totalJpy == nil`／`method == .cash` ⟹ `totalSats == nil` | `buildSale` |
| I5 | `paidIn == .sats` ⟺ `unitPriceSats != nil` | 合計の判定 |
| I6 | 在庫減算は `SaleState == .done` の遷移時だけ | 完了処理の呼び出し側 |
| I7 | `StockMovement` は追記のみ（既存行を書き換えない） | 販売取消・調整 |
| I8 | カートに在庫を持たない。判定は必ず在庫表側 | 在庫チェック |
| I9 | `products[X].stock == Σ stock_movements[X].delta`（現在庫の正は `products.stock`。A-19-1） | 在庫を書く全処理 |
| I10 | `completedAt != nil` ⟺ 在庫減算済み。`voided` はこの値が `nil` なら sats確認済みの中断（A-19-3） | 販売取消 |
| I11 | ID の採番は販売確定時だけ。記録しない中断では採番しない（A-19-4）。ただし `product_id` は商品追加時に採番する（I16） | 完了処理の呼び出し側 |
| I12 | 日次集計の「日」は端末のローカル日付（A-19-5） | 集計の期間切り |
| I13 | 型の基本は `Equatable`。保存した値と復元した値を `==` で比べられる | 状態復元・テスト |
| I14 | `ProductType.nextNo >= 1`、かつ `nextNo` は減らさない（高水位） | 種類定義CSVの再取り込み、復元 |
| I15 | `nextNo` > その種類の現存商品の最大番号 | CSV取り込み、古いバックアップからの復元 |
| I16 | 商品IDの採番、商品のINSERT、`nextNo` の更新は同一トランザクション。`makeProductID(for:)` は状態を変えず、成功時の `nextNo += 1` は呼び出し側が行う | 商品追加処理 |

- I15 は、起動時の検証（`nextNo` の破損検出）にも使える。この検証は仕様書（siyou.md）に未反映。
